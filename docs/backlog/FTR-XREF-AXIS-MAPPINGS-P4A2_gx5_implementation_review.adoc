= GX-5 Implementation Self-Review: Grouped-XRef Workbook Adoption
:revdate: 2026-08-01
:toc:

Delta-only self-review of the GX-5 implementation against confirmation
`FTR-XREF-AXIS-MAPPINGS-P4A2_gx5_confirmation_001.adoc` (confirmation commit
`b33d5fd`, taken as the baseline `HEAD`, verified an ancestor before starting).
GX-1..GX-4 accepted foundations were not reopened; the confirmation was not
redone.

== Verdict

GX-5 makes the already-accepted grouped workbook carrier path publicly reachable
through four public gates, using the exact accepted inner composition/render and
exact reverse reconstruction paths unchanged. All required behaviours,
protected-surface constraints, and validation gates hold. One bounded,
user-approved scope deviation is recorded below (the carrier predicate lives in
the backend-neutral facade rather than in the two entrypoint savers, to satisfy
an existing adapter-contract boundary guard).

== Four public gates changed

. `configure_workbook_view` (`domain/workbook_views.py`): admits a selected
  `GroupedMatrix` frame; rejects grouped column-targeted options.
. `select_render_frames` (`rendering/frame_selection.py`): admits a
  `GroupedMatrix` by identity for selection/order/rename.
. Router savers `save_xlsx` / `save_ods` (`io_backends/.../*_backend.py`):
  preserve a `GroupedMatrix` through to the render path.
. Workbook View readback `apply_workbook_view_sheet_mappings` /
  `_normalize_visible_sheet_names` (`domain/workbook_views.py`): counts a
  `core.ExactTable` as a projected visible sheet.

== Accepted carrier sets

* `configure_workbook_view.sheets[*].frame`: `pandas.DataFrame | GroupedMatrix`.
* `select_render_frames` selected values: `pandas.DataFrame | GroupedMatrix`.
* Router write values: existing coercible values *plus* preserved
  `GroupedMatrix` (DataFrame and GroupedMatrix pass through by identity; all
  other non-reserved values keep `pd.DataFrame(...)` coercion).
* Workbook View visible read values: `pandas.DataFrame | core.ExactTable`.

No new type, carrier, step, parameter, metadata root, registry entry, or wrapper
was introduced.

== Grouped Workbook View behaviour

A grouped sheet supports the same authoritative selection contract as a
DataFrame: explicit inclusion, declaration order, physical sheet rename, and the
persisted visible-sheet -> logical-frame mapping. The carrier is retained by
identity — never unwrapped, copied, flattened, or converted — and is never
inspected for formulas (formula sheet-name rewriting stays DataFrame-only).
Missing-frame (`KeyError`) and duplicate-sheet-name (`ValueError`) rules are
unchanged and apply equally to grouped and mixed selections. Ordinary DataFrame
Workbook View behaviour is unchanged.

== Grouped-option rejection

A grouped sheet with non-empty `helper_columns`, `editable_columns`, column
`protection`, or a non-empty generic `options` mapping raises `ValueError`
("... unsupported in GX-5 ...") before any output. Rationale: those options use
flat string `header_map` identity, while grouped dynamic identity is the complete
visible tuple with possibly repeated leaf labels; silent leaf-only targeting
would be ambiguous. Empty option values remain no-ops, matching DataFrame
behaviour.

== Router saver behaviour

Exact conservative rule in both savers:

[source,text]
----
DataFrame       -> pass through unchanged
GroupedMatrix   -> pass through unchanged
other value     -> existing pd.DataFrame coercion
----

The carrier decision is delegated to the facade predicate
`spreadsheet_contract.is_render_carrier(value)` (see deviation). Direct backend
classes (`ExcelBackend.write_multi`, `OdsBackend.write_multi`) and persistence
semantics are otherwise unchanged; the preserved carrier reaches the existing
`build_spreadsheet_render_plan` path.

== ExactTable readback mapping

`_normalize_visible_sheet_names` now counts `pandas.DataFrame` *or*
`core.ExactTable` as a generic projected visible sheet. Re-keying preserves the
`ExactTable` unchanged under the logical frame name. Grouped-XRef configuration
is never interpreted in Workbook View code, and `exact_header_depths` remains
solely an input backend option at `input.options.extra.exact_header_depths`,
keyed by the physical visible sheet name; it is neither inferred nor duplicated.

== Public XLSX/ODS configured roundtrip

`tests/integration/pipeline/test_gx5_grouped_xref_public_roundtrip.py` drives the
public configuration path (`build_steps_from_config` + `run_pipeline`) and the
router-facing `save_xlsx`/`save_ods` + `load_xlsx`/`load_ods` seams — never the
composer directly. It proves, for XLSX and ODS: untouched relation identity; one
edited spreadsheet-boundary value survives back to canonical; repeated upper
labels; a literal `" / "` leaf label component; a renamed physical sheet; carrier
passage through the public router savers; and XLSX/ODS semantic parity. It does
not repeat the GX-3b/GX-4 parser or domain matrices.

== Failure atomicity

`test_gx5_pre_render_grouped_view_failure_is_atomic` proves that a pre-render
grouped Workbook View validation failure (duplicate visible sheet name reached in
`select_render_frames`) raises before publication, creates no target output file,
and leaves caller Frames and `_meta` unmutated. A unit-level twin
(`test_configure_workbook_view_grouped_rejection_leaves_frames_and_meta_unchanged`)
covers the configuration-time rejection path.

== Public/registry surface

Runtime registry unchanged. JSON registry `pipeline_step_registry.json`
descriptions updated for `configure_workbook_view` (forward values may be
DataFrame or GroupedMatrix; grouped column-targeted options unsupported) and
`apply_workbook_view_sheet_mappings` (visible reverse values may be DataFrame or
ExactTable). Registry mirror/signature/frame-contract guards pass. Transformation
catalog gains one practical configured grouped workbook roundtrip; active release
notes gain a GX-5 bullet; the parent FTR records GX-5 as implemented, acceptance
review 001 pending.

== Sizing

Runtime: 47 net LOC across five modules (the four confirmed modules plus the
facade predicate — see deviation), under the 60 net-LOC hard cap. No new public
type, step, parameter, metadata root, or schema-maintenance handler.

Tests: the two existing unit modules plus the one new integration module, ~630
net LOC — above the confirmation's 140--210 estimate. The overage is coverage,

(twelve Workbook View cases, ten frame-selection cases, the full public

or domain matrices. There is no hard test-LOC cap.

== Protected surfaces

Untouched: `grouped_xref`, `xref_crosstable`, `xref_axis_mapping`, `ExactTable`,
composer, WorkbookIR, render flow/passes, XLSX/ODS parsers and renderers,
pipeline runtime registry, persistence boundary, schema maintenance, application/

removed. `git diff --check` is clean and Ruff passes on all changed files.

== Deviations

One deviation from the confirmation, approved by the requester before
implementation:

* *Carrier predicate location.* The confirmation placed the carrier decision
  inside the two backend savers via a direct `GroupedMatrix` import. The existing
  guard
  `tests/architecture/spreadsheet_contract/test_adapter_contract_boundary_guards.py::test_backend_entrypoints_delegate_generic_orchestration_to_spreadsheet_contract`
  forbids `xlsx_backend.py`/`ods_backend.py` from importing
  `spreadsheet_handling.domain.*`, contradicting the confirmation's assertion
  that the adapter -> domain-carrier import is permitted for these entrypoints.
  Resolution: a one-line predicate `is_render_carrier` was added to the already
  imported, domain-permitted facade `io_backends/spreadsheet_contract.py`, and
  both savers delegate to it. This honours the entrypoint -> facade delegation
  the guard enforces and weakens no test, at the cost of touching one runtime
  module beyond the confirmed four (still within the net-LOC cap).

Minor note: `_normalize_sheet_specs` branch-complexity rose from a pre-existing
16 to 22 under the non-blocking source-style guard (WARN only, exit 0); no
abstraction was introduced, per the confirmation's LOC-over-abstraction guidance.
