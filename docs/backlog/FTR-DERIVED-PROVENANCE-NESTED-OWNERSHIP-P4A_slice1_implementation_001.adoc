== 3. Reproduced pre-fix behavior

The accepted authority's reproduction was rechecked against current source
before editing. `copy_reserved_frames` preserves the reserved `_meta` object by
reference and Enrich Lookup begins with `dict(frames)`. Each defective writer or
cleaner then made only a shallow top-level `_meta` copy and mutated an existing
`derived`, `sheets`, or sheet-entry mapping through the retained alias.

The observable pre-fix result was a new returned `_meta` mapping paired with a
caller-owned nested mapping that had gained, lost, or replaced provenance:

* FK write added/replaced `helper_columns` and stale-cleaned through the input;
* FK drop removed `helper_columns`, conditionally removed `enrich_lookup`, and
  pruned input containers;
* Enrich Lookup added/replaced the output's `enrich_lookup` record through the
  input mapping, reproducing `EL-HR-002`.

The input's final structure could even be restored after temporary
`setdefault`/prune work, which is why final equality without retained-reference
and changed-node assertions was insufficient. No persistence defect was
reproduced: the orchestrator boundary already removes `derived` for every
backend.

== 4. Implementation choice

*Selected alternative: family-local copy-along-path implementations.*

FK provenance owns one local lazy-detachment convention in `provenance.py` for
its writer and cleaner. Enrich Lookup performs the corresponding explicit path
copy in its own `_write_provenance`. This is the smallest coherent choice:

* it expresses the accepted family-spanning ownership contract without adding a
  new cross-family runtime dependency;
* it keeps FK stale-clean and presence-sensitive pruning next to their current
  owner;
* it keeps Enrich record construction and selected symmetric/asymmetric mode in
  the Enrich family;
* it exposes precisely which path nodes detach and allows identity assertions;
* it introduces no `frame_keys` responsibility, public helper, or metadata
  framework.

FK detachment is lazy so sheets whose producer-owned sub-key does not change
remain shared. On the first actual FK write/removal, `_meta.derived.sheets` is
copied and only each touched sheet entry is copied. Enrich always replaces the
named output record when fields are present, so `_meta`, `derived`, `sheets`,
and that output sheet entry are the changed path and are copied directly.

== 5. Alternatives considered

[cols="2,4"]
|===
| Alternative | Decision

| Neutral common copy/prune helper
| Rejected. Ownership is common, but FK cleanup/pruning and Enrich record
replacement are not one mutation algorithm. A neutral utility would add a new
boundary and coupling without reducing the load-bearing local distinctions.

| Family-local implementations
| Selected. Dependency direction stays unchanged; diagnostics, call order, FK
stale nuance, Enrich key-mode nuance, and local testability remain visible.

| Owned utility near `frame_keys` or a new meta module
| Rejected. `frame_keys` owns reserved-frame copying, not mutation policy for a
registered nested namespace. A new generic meta boundary would be larger than
the three-site contract and risk implying repository-wide immutable Frames.
|===

`derived_column_policy._strip_consumed_provenance` remained positive semantic
evidence and unchanged code; extracting it would have enlarged the slice.

== 6. Exact runtime changes

`fk_helpers/provenance.py::_write_helper_provenance` now:

* reads existing `derived` and `sheets` without mutating them;
* lazily copies `derived` and `sheets` before the first real change;
* copies a sheet entry only when FK-owned `helper_columns` is written, removed,
  or an empty stale entry is pruned;
* preserves untouched sheet-entry and unrelated subtree objects;
* retains current FK entry creation, stale-sheet scan, and empty-container
  pruning.

`fk_helpers/provenance.py::_clean_helper_provenance` now computes the existing
presence decisions first, detaches the path only if removal/pruning is required,
copies each touched sheet entry, and then performs the same guarded removal and
pruning. `drop.py` and its diagnostics/order remain unchanged.

`enrich_lookup/operation.py::_write_provenance` now copies `_meta`, `derived`,
`sheets`, and the named output sheet entry before assigning the fresh record.
Record construction and write timing remain unchanged.

No pandas DataFrame, whole Frames mapping, unrelated metadata subtree, or
untouched sheet entry is deep-copied for this contract.

== 8. Contract demonstration

For each affected operation, tests retain the caller's exact nested objects,
snapshot their structure before the call, and prove afterward that:

* the input Frames mapping still has the same keys and value objects;
* input DataFrames remain equal to deep snapshots;
* retained `_meta`, `derived`, `sheets`, and touched sheet mappings equal their
  independent pre-call snapshots;
* the returned payload contains the expected new record or removal;
* every changed output path node is distinct from its corresponding input node.

The FK no-op repetition additionally proves that after helper provenance is
already gone and a surviving Enrich record remains valid, `derived`, `sheets`,
and the sheet entry remain shared because none is changed. This distinguishes
copy-along-the-mutated-path from broad recursive copying.

== 9. Sibling and record-shape preservation

The tests preserve by value and, where untouched, by identity:

* unrelated top-level `_meta` values;
* unrelated `derived` namespaces;
* unrelated `derived.sheets` entries;
* FK `helper_columns` beside Enrich `enrich_lookup` on the same sheet;
* Enrich `enrich_lookup` beside FK `helper_columns` on the same sheet.

* Enrich symmetric: `{lookup, on, helper_columns}`;
* Enrich asymmetric: `{lookup, source_key, lookup_key, helper_columns}`;
* explicit asymmetric with equal source/lookup names: the asymmetric shape,
  never a synthesized `on` record.

Existing suites keep frame columns, order, values, formula specs, validation
precedence, durable policy fallback, and consumer behavior green.

== 10. Enrich repetition characterization

The complete required matrix preserves current results:

[cols="2,4"]
|===
| Case | Characterized result

| Same output, same helpers
| A fresh equal record replaces the owned output sub-key; no accumulation.

| Same output, changed helpers
| `helper_columns` is replaced by the new list; stale members are not merged.

| `output == source`
| The source frame and its named provenance record are replaced; caller source
and metadata remain unchanged.

| Changed output while old output remains
| Both frames and both descriptive records remain.

| Changed output after caller removed the old frame
| The pre-existing old record remains and the new record is added. This is the
already-authorized no-producer-stale-cleanup behavior; Slice 1 adds no scan or
cleanup and observed no new consumer or persistence harm.
|===

The last case is explicit evidence, not silent authorization to widen producer
ownership. It remains a within-run residue when a caller manually removes an
output mapping; persistence still strips the whole channel.

== 14. Residual risks

* Caller-driven removal of a prior Enrich output can leave its transient record
  until a current consumer removes it or persistence strips the namespace. This
  accepted repetition result has no newly observed harm and does not authorize
  producer stale cleanup.
* Producer/cleaner malformed-input diagnostics remain uneven with hardened
  consumers. That is the explicitly optional, unauthorized Slice 2 concern.
* The contract remains limited to maintained `_meta.derived` writers/cleaners;
  it does not establish global Frames immutability.
* Future producers must continue respecting sheet-local sub-key ownership and
  copy their changed path, but no generic governance framework is introduced.

No residual Slice 1 correctness issue is known. Independent review must still
try to falsify path identity, sibling preservation, stale-clean nuance,
diagnostic parity, and persistence separation.
