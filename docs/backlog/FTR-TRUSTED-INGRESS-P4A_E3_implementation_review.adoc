== 2. Accepted E3 contract reconstructed independently

Authority was reconstructed from current FTR sections 11, 15, 16, and the E3
slice; accepted design-review dispositions F4, F5, and F7; and the final census
grammar/dispositions, including acceptance commit `5139334` and
`TRUSTED-INGRESS-E3-CENSUS-FOLLOWUP-F1 -- RESOLVED`. The historical XRef debate
was not replayed.

The accepted common post-state is:

....
_meta root: absent / explicit None, or exact built-in dict
ordinary recursive containers: exact built-in dict and exact built-in list
ordinary dict keys: exact built-in str, with zero exceptions
ordinary leaves: E1-admitted ordinary Scalar
aliases: shared acyclic aliases permitted
cycles: rejected when an identity is already active on the current path
authoring exceptions: only statically named and governed delegates
delegate result: complete normalized output passes the same recursive post-check
....

Classification is by actual runtime type identity. Generic `Mapping`,
`Sequence`, subclass, iteration, duck-typing, and coercion do not establish the
common grammar. E3 does not define a generic metadata ontology or family
business schemas and does not implement controlled roles.

Delegate governance is independently load-bearing. A delegate is central and
static, works on a staged candidate, does not mutate caller input, safely
classifies before inspecting, is bounded to its named authoring root, and has
its complete result post-checked. The accepted FTR explicitly says the old
Legend Blocks normalizer is compatibility evidence, not an automatically
approved delegate, and E3 must migrate its Mapping acceptance, identity
resolution, shallow-alias behavior, and `str`/truthiness behavior under these
rules.

Ownership means staged publication and copy-along-the-mutated-path. It does not
mean blanket recursive deepcopy, unique identities, alias isolation,
concurrency isolation, or rollback of prior/plugin effects.

YAML Option A reserves exactly `_meta.yaml`/`_meta.yml`, safe-loads at most one
mapping-shaped sidecar at the backend boundary, rejects duplicate spellings or
a non-mapping root there, and passes the mapping directly as `Frames["_meta"]`.
It creates no saver/roundtrip promise.

== 3. Common metadata walker and E1 leaf reuse

`metadata_admission.py` was read in full. In isolation, its ordinary grammar is
correct:

* root admission is absent/`None` or `type(meta) is dict`;
* recursive dispatch is only `type(value) is dict` / `type(value) is list`;
* keys pass only `type(key) is str`;
* all remaining nodes are passed unchanged to `admit_ordinary_scalar`;
* no container/key/leaf coercion occurs; and
* success returns the original frames object.

Independent direct probes admitted exact `dict` and `list`; rejected a dict
subclass, list subclass, tuple, set, bytes, complex, opaque object, and an
object spoofing instance `__class__`; and produced the expected stable
`invalid_metadata_node` path for each nested failure. A non-dict `_meta` root
produces `invalid_metadata_root`.

Leaf classification is genuinely reused, not copied. Representative ordinary
strings/booleans/numbers, NumPy bool/integer/floating, NaN, `pandas.NA`,
`pandas.NaT`, date/datetime, timezone-aware `pandas.Timestamp`, and
`numpy.datetime64`/NaT were admitted by identity. Time, pandas Timedelta, and
NumPy timedelta were wrapped as `invalid_metadata_node` with E1's constant
`carrier_type_name == "unsupported runtime type"`. No normalization was
observed.

`_safe_admission_message` receives only stable failure kinds, paths built from
already-admitted exact strings/ordinals, constant expected-kind text, and E1's
constant safe carrier name. It retains no rejected object and does not bypass
E1's accepted error safety.

== 4. Paths and direct-walker diagnostics

The direct walker reports nested paths such as
`_meta.foo[2].bar`. Unsupported keys use the parent path plus zero-based entry
ordinal, e.g. `_meta.a[0].b[<entry 0>]`, and never render the key.

Exact-string probes produced deterministic paths for `"a.b"`, `"x[1]"`, the
empty string, whitespace-only text, Unicode, and an embedded newline. These
keys do not cause execution, rejection, or traversal changes. Direct rendering
means `"a.b"` is visually indistinguishable from two nested key segments and
an empty key renders as a trailing dot, but the accepted contract requires a
safe path made from admitted keys/ordinals, not a reversible path language.
This aesthetic ambiguity does not materially violate E3 and is not a finding.

The direct generic hostile-leaf probe reached
`MetadataSubstrateAdmissionError` with zero calls to candidate `__class__`,
`__repr__`, `__str__`, `__eq__`, `__hash__`, `__iter__`, truthiness, or array
protocols. The complete coordinator path is different for hostile keys and
Legend authoring candidates; see finding F1.

== 6. Delegate governance, safe inspection, and laundering

`INGRESS_RULES` places `legend_blocks_shape` before `metadata_substrate`.
That ordering correctly makes the delegate's returned tree the generic
post-check input, but output conformance alone does not establish a safe and
bounded delegate boundary.

Current `legend_blocks.py` still:

* uses `isinstance(meta, Mapping)` and membership lookup on unvalidated root
  keys;
* accepts arbitrary `Mapping` implementations and list subclasses;
* iterates unclassified mappings;
* obtains candidate-controlled type names on failure;
* compares unclassified block keys with `"resolved"`; and
* calls truthiness and `str()` on unclassified `name`/`id` values.

These operations are not an accepted grandfathered authoring contract. FTR
lines 1469-1473 explicitly require their E3 migration.

Independent complete-chain counterexamples:

* A hostile non-string key whose stored hash equals `hash("legend_blocks")`
  receives `__eq__("legend_blocks")` at the delegate's root-membership test.
  With raising equality, ingress surfaces the candidate's `RuntimeError`
  before E3; the same key with non-raising equality records one call before
  the walker eventually rejects it by ordinal.
* A list-form block with a hostile `name` executes candidate `__bool__` before
  the post-check.
* An unsupported Legend root whose real type uses a hostile metaclass executes
  metaclass `__getattribute__("__name__")` while constructing the old
  diagnostic.
* A non-string block key receives candidate `__eq__("resolved")` in
  `_strip_resolved` before E3 rejects it.
* A custom Mapping root records `__getitem__`, `__iter__`, and `__len__`
  protocol calls before being normalized.

The delegate also launders the common substrate. Each of the following was
admitted by `run_domain_ingress`, and its offending object was rebuilt as an
exact dict before E3 saw it:

* `_meta` as a dict subclass with a `legend_blocks` member;
* `_meta` as a non-dict `Mapping` with a `legend_blocks` member;
* `_meta.legend_blocks` as a dict subclass or custom Mapping;
* `_meta.legend_blocks` as a list subclass; and
* a Legend block mapping as a dict subclass.

The named exception permits Legend Blocks authoring normalization at that
semantic root. It does not authorize generic `_meta` root normalization or
Mapping/subclass-to-dict coercion, and the FTR specifically requires Mapping
acceptance to migrate. This is finding F2.

The generic post-check itself is complete over what remains in the delegate
result: independent/shipped probes with a retained unsupported nested tuple and
a non-string extra key reject with the same E3 error kinds/paths as ordinary
metadata. There is no stale-input bug in the coordinator's return-value flow.

== 15. Findings

=== TRUSTED-INGRESS-E3-IMPL-REVIEW-F1 -- Blocking -- the pre-E3 Legend delegate performs unsafe inspection on rejected candidates

*Exact evidence:* `legend_blocks.py:48-52` uses Mapping classification and
root membership/access before E3; lines 65-68 admit Mapping/list protocols;
lines 69-72 read candidate type-name metadata; lines 84-90 inspect list
members; line 103 calls truthiness and `str`; line 111 compares unclassified
keys. The complete-chain probes above execute hostile equality, truthiness,
metaclass, Mapping iteration, and key equality.

*Concrete counterexample:* construct a hashable unsupported metadata key whose
hash collides with exact string `"legend_blocks"` and whose `__eq__` raises.
After caller-side dict construction, `run_domain_ingress({"_meta": {key:
"x"}})` executes `key.__eq__("legend_blocks")` and surfaces its raw
`RuntimeError`; E3 never emits the required safe ordinal rejection. A hostile
list-form `name` similarly executes `__bool__` before later rejection.

*Accepted criterion violated:* FTR delegate governance requires classify-
before-inspect, forbids candidate-controlled `repr`/`str`/truthiness/equality/
hashing/iteration/protocol probing on rejected unsupported values, and
explicitly requires Legend's Mapping/identity/`str`/truthiness migration in E3.
The general diagnostic contract gives delegates no exception.

*Smallest correction:* migrate the existing Legend delegate in place to a
bounded, safely classified exact authoring grammar; safely establish root/key/
container/identity eligibility before membership, comparison, iteration,
truthiness, formatting, or type-name diagnostics. Add full-coordinator hostile
tests for the colliding generic key and each Legend-touched candidate position.
Do not move family semantics into the common walker.

=== TRUSTED-INGRESS-E3-IMPL-REVIEW-F2 -- Blocking -- Legend reconstruction launders globally invalid containers into the common substrate

*Exact evidence:* `legend_blocks.py:48-58` accepts any Mapping `_meta` root and
rebuilds it with `dict(meta)`; lines 65-79 accept/rebuild any Mapping Legend
root; lines 67/82-97 accept a list subclass; lines 106-111 accept/rebuild any
Mapping block. `metadata_admission.py:238-249` therefore receives only the
already-laundered exact dict and cannot detect the original violation.

*Concrete counterexample:* a dict-subclass `_meta` containing
`{"legend_blocks": None, "ok": 1}` is admitted by `run_domain_ingress` and
returned with an exact dict root. A non-dict Mapping root and nested
Mapping/list/block subclasses are likewise admitted after reconstruction. The
same root without `legend_blocks` correctly fails, proving the global language
widens solely because the named subtree is present.

*Accepted criterion violated:* the final census requires an exact built-in
dict root/containers, exact built-in lists, and exact strings, with zero generic
exceptions. A named delegate is bounded to its explicit authoring root, may not
bypass the global structural postcondition, and must migrate old Mapping
acceptance. This is unauthorized generic normalization, not legitimate Legend
list-to-canonical-mapping sugar.

*Smallest correction:* reject invalid global/root containers before any
delegate reconstruction and restrict Legend's exceptional input grammar to the
explicitly authorized safely classified authoring shapes. Ensure neither the
Legend root nor block/item containers can turn Mapping/list subclasses into
common exact containers. Add root-present/root-absent and nested laundering
regressions while preserving valid Legend sugar and retained acyclic aliases.

=== 17.2 F1 requested counterexample reproduction

The five exact original probes requested for this disposition improve as
claimed when counters are reset after fixture construction:

  `MetadataSubstrateAdmissionError(kind="unsupported_metadata_key")` at

  delegate `ValueError`, with zero metaclass `__name__` reads;
* a non-`str` block key reaches E3's ordinal-key rejection with zero candidate
  comparisons against `"resolved"`; and
* a custom `Mapping` Legend root produces the constant delegate `ValueError`,
  with zero `__len__`, `__iter__`, or `__getitem__` calls.

`_safe_find_str_key` itself has the intended bounded structure. Every caller
first establishes an exact built-in `dict`; the helper iterates that built-in
dict's items, checks `type(key) is str`, and only then compares the admitted
string key with the exact-string target. Its root, `name`, and `id` call sites
therefore avoid candidate Mapping protocols and hash-collision equality during
the lookup itself.

The helper does not, however, close the complete pre-E3 delegate path. Two
independent full-coordinator variants demonstrate the residual defect:

. An exact `_meta` dict containing both a hostile non-`str` key and a valid
  exact-string `legend_blocks` member activates the delegate. With the hostile

  construction, and equality armed to raise, the later
  `new_meta[_ROOT_KEY] = normalized` native assignment invokes the rejected
  key's `__eq__` once and surfaces its raw `RuntimeError`. The same candidate
  with recording equality reaches E3 only after that one ingress-time call.
. An exact list-form block containing an unsupported non-`str` key is copied by
  `_strip_resolved`'s dict comprehension. With hashing allowed for fixture
  construction, then counters reset and hashing armed to raise, the
  comprehension invokes candidate `__hash__` once and surfaces the raw
  `RuntimeError` before E3. `_normalize_mapping` has the same re-hashing shape
  when it inserts an unclassified mapping-form Legend identity key into its new
  dict.

These are boundary-time calls, not the unavoidable hash call made by the test
author while constructing the original dict. They are also not adjacent new
attack surfaces: they occur in the same Legend pre-postcheck staging path and
violate the same original F1 criterion. FTR section 11 requires a governed
delegate to avoid unsafe equality and hashing on a rejected unsupported value
beyond operations safe in an already-admitted container contract. An exact
dict does not make its unsupported non-`str` key admitted.

The smallest correction is to preflight exact-dict keys safely before any
delegate reconstruction and leave an ineligible dict/subtree untouched for the
generic post-check, or otherwise ensure reconstruction never inserts or looks
up against an unclassified key. Focused regressions must arm/count `__hash__`
after construction and must exercise the colliding-root case while a real
`legend_blocks` member activates staging. No generic E3 walker change is
needed.

Therefore `TRUSTED-INGRESS-E3-IMPL-REVIEW-F1` is *NOT RESOLVED* and remains
Blocking.
