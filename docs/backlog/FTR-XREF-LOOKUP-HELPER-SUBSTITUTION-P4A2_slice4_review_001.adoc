`pytest.raises(ModuleNotFoundError)` also does not pin the missing module name,
although that is secondary to the demonstrated masking. The Core CLI registry
is current and rejects the step, but the import path remains available to
Python consumers.

A clean wheel built from `git archive HEAD` under
`/tmp/xref-slice4-review001.BNLoF3` is correct: the archive contains no retired

match the retired name, and `build/snapshots/src_domain.txt` embeds a literal
copy of the deleted source module. These are not tracked release inputs, but
they corroborate that the claimed post-removal environment/build freshness was
not achieved.
Impact::
The core objective says the module must not be importable and specifically
requires no stale installed package. A normal repository CLI environment can
still serve the old callable to direct Python importers, and the maintained
negative test gives a false green because it bypasses the installed layer. This
is an install/packaging completion gap, not merely cosmetic cache cleanup.
Required correction::
Make the supported setup/refresh workflow remove obsolete package files and
finish as a genuinely editable current-source install (or recreate the venv in
the documented normal path). Add an installed/subprocess freshness check that
does not inherit pytest's `src` path and pins the exact missing module. Refresh
or remove stale ignored build/snapshot outputs, then prove `inspect.getfile`
resolves the intended current source/install, the distribution record contains
no retired module, direct import fails, and the CLI still starts. A clean-wheel
check should remain green.
Blocks Slice 4 / FTR closure:: Yes.
