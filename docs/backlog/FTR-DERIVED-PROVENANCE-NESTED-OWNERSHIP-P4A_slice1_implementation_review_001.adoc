== 3. Findings by severity

There are no Blocking or Important findings.

=== IR-001 — temporal caller mutation is not directly instrumented

*Severity:* Minor.

*Exact locus:* `tests/unit/domain/transformations/
test_derived_provenance_nested_ownership.py`, `_assert_input_frames_unchanged`,
the three primary ownership tests, and
`test_enrich_lookup_repetition_matrix_preserves_current_stale_behavior`.

*Concrete problem:* Retained references plus deep structural snapshots prove
the caller's post-call state, and changed output-node identity proves output
detachment. They would not detect an implementation that temporarily mutated a
caller mapping, restored it, and then returned a detached output. On an
identical Enrich repetition, replacing a caller-owned `enrich_lookup` member
with a different but equal dict could likewise escape the repetition test.

*Evidence:* Definition Review 001 explicitly distinguishes this temporal case
from final structural equality. The new tests use ordinary dicts and only
post-call assertions; they do not use a mutation-recording mapping. Complete
inspection of the implementation shows no mutate/restore behavior: FK reads
the original nodes until `copy_derived_path()` installs detached ancestors,
and Enrich copies all ancestors before assignment. Independent retained-object
probes also found no caller change.

*Correction/refinement:* A future test-only refinement may use a small
mutation-recording dict subclass for the touched path and assert that no
`__setitem__`, `pop`, or `__delitem__` reaches caller-owned nodes, including an
equal-record repeat.

*Acceptance gate:* No. The current implementation is directly proven not to
perform the hypothetical mutation.

=== IR-002 — DataFrame no-copy assurance is indirect in the new test

*Severity:* Minor.

*Exact locus:* `test_derived_provenance_nested_ownership.py`,
`_snapshot_data_frames`, `_assert_input_frames_unchanged`, and the FK/Enrich
ownership tests.

*Concrete problem:* The helper proves that input DataFrames retain their input
mapping identities and equal deep value snapshots. It does not directly assert
the output identity rule: unchanged DataFrames remain shared, while only the
frame whose columns/results actually change is replaced.

*Evidence:* Source inspection shows FK passes frames with no current FK/drop
work through by identity, and Enrich begins with `dict(frames)` before replacing
only `output`. An independent identity probe confirmed FK enrichment and drop
share the untouched target frame, Enrich with a distinct output shares source
and lookup, and `output == source` replaces source while sharing lookup.

*Correction/refinement:* Add explicit output/input identity assertions for one
unchanged FK target frame, FK-cleanup sibling frame, Enrich source/lookup with a
distinct output, and Enrich lookup with source replacement.

*Acceptance gate:* No. Runtime and direct probes establish the required no-copy
behavior.

== 5. FK provenance writer

`_write_helper_provenance` satisfies copy-along-the-mutated-path:

* it reads original `derived` and `sheets` without mutation;
* the first actual write, removal, or empty-record prune calls
  `copy_derived_path`, copying `derived` and `sheets` once and installing them
  into the already-shallow-copied top-level `_meta`;
* every touched sheet entry is copied before assignment, `pop`, or deletion;
* subsequent mutations use the detached `derived_sheets` closure variable;
* untouched nonempty sheet records remain shared, while touched records are
  distinct;
* top-level metadata siblings, unrelated derived namespaces, other producers,
  and unrelated sheets survive by identity and value;
* helper replacement remains key-selective and preserves same-sheet
  `enrich_lookup`.

The guard
`if "helper_columns" not in sheet_entry and sheet_entry: continue` is correct
for valid mappings. A nonempty record owned only by another producer is a true
no-op and stays shared. An empty record is pruned, so detachment is required.
A record with `helper_columns` is copied and has only that key removed; a
remaining producer sub-key survives. The same cases hold for a current sheet
with no definitions and a stale sheet absent from `fk_defs_by_sheet`.

The stale-key list is formed from the current `derived_sheets` binding. If a
prior current-sheet operation has detached the path, the stale scan therefore
uses the detached mapping; if it has not, the first stale mutation detaches it
before access continues. No closure path mutates the original after detachment.

The empty-container tail preserves prior results: empty `sheets` is removed,
empty `derived` is removed, unrelated derived keys prevent the latter prune,
and a missing `sheets` member does not create a spurious namespace. A complete
matrix probe covered current-with-definitions, current-without-definitions,
stale-absent, FK-only, FK-plus-Enrich, other-producer-only, empty records,
empty `sheets`, empty `derived`, and unrelated derived keys. All valid cases
matched pre-fix returned semantics while leaving input nodes unchanged.

== 6. FK cleanup through `drop_helpers`

`drop_helpers` still resolves policy/provenance and determines columns before
copying reserved frames. Its diagnostics, validation precedence, DataFrame
column order, and cleanup timing are unchanged. `_clean_helper_provenance` now
decides removals against the original valid record and already-cleaned output
frame, then detaches before any `pop`, `del`, or prune.

The guard
`if not (remove_helper_columns or remove_enrich_lookup or not sheet_entry):
continue` preserves the full valid matrix:

* an empty record is pruned;
* a nonempty other-producer record is untouched and shared;
* FK-only is removed unconditionally because FK owns that key;
* Enrich-only is retained when any declared helper remains and removed only
  when none remains;
* combined FK/Enrich always loses FK and conditionally loses Enrich under the
  same narrow rule;
* a missing frame gives an empty present-column set and removes Enrich;
* an empty Enrich helper list is removed;
* a still-present Enrich helper retains its record;
* later iterations operate on detached `derived_sheets` after the first change.

Independent probes confirmed caller `_meta`, `derived`, `sheets`, and every
retained touched sheet record remain structurally unchanged. Changed output
ancestors and records are distinct; untouched records may share. Empty sheet,
`sheets`, and `derived` pruning is exact, and a second cleanup with only valid
surviving Enrich provenance performs no nested copies.

== 7. Enrich Lookup provenance writer

`_write_provenance` returns immediately when `fields is None`, leaving metadata
untouched. Otherwise it copies `_meta`, `derived`, `sheets`, and the named
output sheet entry before assigning a fresh `enrich_lookup` record. It preserves
unrelated top-level metadata, derived namespaces, sheets, and FK
`helper_columns` on the same sheet.

Record parity is exact:

* symmetric mode writes `{lookup, on, helper_columns}`;
* asymmetric mode writes `{lookup, source_key, lookup_key, helper_columns}`;
* explicit asymmetric mode with equal key names remains asymmetric.

The writer does not scan or remove another sheet, does not merge old helper
members, and does not change write timing: it runs only after result-frame
construction and `out[output]` assignment. `out = dict(frames)` and the
pre-existing merge/formula paths are unchanged, so source replacement, frame
results, formula specs, order, and validation timing remain intact.

== 8. Changed-path ownership, identity, and siblings

For each actual metadata change, returned `_meta`, `derived`, `sheets`, and the
touched sheet record are distinct from the corresponding input nodes. Caller

subtrees, and sheet records may and do remain shared. No whole-Frames deep copy

assignment; Enrich shallow-copies Frames and replaces only `output`.

== 12. Copying and performance

FK copies the `derived` and `sheets` mappings at most once per call and copies
one sheet record per sheet actually written, removed, or pruned. Its no-op path
does not copy nested provenance. Enrich performs one unconditional shallow copy
per changed ancestor because a non-`None` field list always replaces its named
record. Complexity remains linear in the existing sheet/definition scans; no
quadratic scan, recursive/deep metadata copy, whole-Frames copy, or DataFrame
copy was added.
