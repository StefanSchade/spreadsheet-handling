This confirmation settles the exact contract the implementation must hit.

== Public and internal callables

* Retire public step `project_by_role`
  (`domain.transformations.project_by_role:project_by_role`).
* Reuse public step `add_lookup_helpers`
  (`domain.transformations.enrich_lookup:enrich_lookup`).
* Reuse public step `apply_derived_column_policy`
  (`domain.transformations.derived_column_policy:apply_derived_column_policy`).
* Retain internal `domain.column_roles.resolver:resolve_column_roles` (second
  consumer: `domain.validations.validate_columns`).

== Pipeline steps (per surface)

* Outbound: `contract_xref` -> (symmetric-key `title` source) ->
  `add_lookup_helpers`.
* Inbound: `apply_derived_column_policy` (drop, durable binding) ->
  `expand_xref` / `expand_compact_multiaxis`.

== Parameters

* `add_lookup_helpers`: `source`, `lookup`, `output`, `key` (or new
  `source_key`/`lookup_key`), `helpers: {fields: [title]}`,
  `order: {helper_position: before_key}`, `missing: empty`,
  `helper_value_mode: values`.
* `apply_derived_column_policy`: `source` (sheet-name-addressable frame),
  `policy: drop`.

== Metadata paths

* Transient (in-run): `_meta.derived.sheets.<output>.enrich_lookup.helper_columns`.
* Durable (roundtrip): `_meta.sheets.<sheet>.helper_columns` from
  `configure_workbook_view` — the binding carrier for inbound removal.

== Ordering

Outbound `[title, story_id, <dynamic matrix cols in contract_xref order>]` via
`before_key`. Inbound `[story_id, <dynamic>]` via order-preserving drop. No
reorder step, no static list.

== Helper authority

`title` is a read-only display helper; `stories.id` authoritative.

== Edited-helper behaviour

Dropped inbound without value comparison; not melted; not written back.

== Mutation / copy behaviour

`add_lookup_helpers` produces a new `output` frame; `apply_derived_column_policy`
returns a copy with a caller-safe `_meta` update. Neither mutates the input
frame in place (unlike `project_by_role`, which reordered in place — an
acceptable behavioural difference because downstream consumers reference the
named output frame).

== Errors

* `add_lookup_helpers`: duplicate lookup key -> raise; missing key column ->
  `KeyError`; helper field already present -> conflict raise; `missing: fail`
  with unmatched rows -> raise. (`missing: empty` chosen to match the current
  join's left-join-with-blank-fill semantics.)
* `apply_derived_column_policy`: malformed provenance -> clear `ValueError`;
  missing provenance -> safe no-op (hence the durable-binding requirement).

== Normal XRef treatment

`expand_xref` receives `[story_id, <dynamic>]` and melts non-key columns
unchanged.

== Compact-multiaxis treatment

`expand_compact_multiaxis` (story_group surface) receives the same shape and is
unaffected.

== Grouped-XRef non-impact

No grouped-XRef code path is touched.

== Worldbuilding migration

Ten sites rewritten per FTR sections 7–8; export/reimport parity required;
worldbuilding stays clean. Migration lands in the worldbuilding repo separately.

== project_by_role fate

Removed after migration, with its registry/impl-unit/doc records and four tests.

== Dogfood migration

Update `pipeline_step_registry.json`, `implementation_units.json`, and
current-state docs; rebuild generated domain-contract tables; PM current-state
update deferred to a separate gated PM change.

== Slices

Slice 1 (asymmetric key) -> Slice 2 (inbound binding) -> Slice 3 (WB migration)
-> Slice 4 (removal). Slices 1–2 are behaviour-additive and independently
shippable; removal (Slice 4) is gated on migration (Slice 3).
