== 3. C11 controlled-exit verification

The corrected standalone `GroupedMatrix` cases match current transition code:
retain-mode expansion carries the role; drop-mode expansion ends carrier
identity and leaves ordinary restored state; workbook projection terminates
the outer role. The nested retain/drop products, reverse-drop relocation,
derived output role, projection relocation, capable-adapter restriction, and
outer-role termination also match `grouped_matrix.py`, `projection.py`, and
the accepted final authority. Pending cleanup is correctly described as live
state rather than termination. The manifest exit statement remains consistent
with accepted authority.

Two exact lifecycle facts are still missing:

* `compose_formula_to_grouped` marks every retained source helper role
  `pending_cleanup=True` when the *forward* grouped producer uses
  `drop_source=true`; those roles stay published until final cleanup removes
  their source frame. The permanent prose says only that they remain live.
* A standalone `LookupFormulaSpecRole` that survives cleanup is authorized for
  XLSX/ODS before saving and is then consumed/terminated by that capable
  adapter. The new paragraph says the adapter may receive it, but names only
  whole-frame cleanup as termination. Accepted authority and the maintained
  flow table explicitly identify the capable adapter as the positive exit.

The smallest C11 correction is to state those two facts. No other role kind,
general role algebra, or controlled-state redesign is needed.

== 4. Manifest authority verification

`description_authorization.py` confirms the promoted contract. With no
`output_dir`, `manifest_path` and `checksum` must also be absent and the step
remains in-memory/no-I/O. Output mode passes the same exact canonical-root
membership check used by the other output producers. A supplied
`manifest_path` must be an exact string whose resolved relative target remains
under that root. Only after those checks may `checksum: sha256` require the
separate conjunctive `allow_checksum_reads` permission; denial occurs before
binding or file access.

The phrase "exactly like the other two writers' paths" is accurate at the
stated authority level: all writer-produced paths must be relative and
contained under the exact authorized root. It does not assert identical code
timing; key-value paths are rendered and containment-checked later by the
writer, whereas the static manifest path is checked during description
authorization. No filesystem-sandbox or hostile-symlink guarantee was added.

== 5. Stale-current verification

The corrected Internal Scalar Value Model and `scalar_values.py` now clearly
say Phase E is complete and owns admission/classification, not general carrier
normalization. Most later ch04 status passages are likewise corrected.

The bounded scan nevertheless finds active contradictions in the historical
concept:

* section 10, "Existing `domain.ingress` assessment", still labels the
  Legend-Blocks-only behavior its "Current exact responsibility" and says it
  "Does not yet establish trusted Frames generally"; and
* section 13, "Current gaps", still says "Mandatory ingress enforcement ...
  still do[es] not exist."

The document-level historical banner does not close these statements: it says
obsolete present-tense claims are qualified in place, while these explicitly
current-labelled passages are not. They can still be read as current
contradictions to the canonical links.

In addition, both `internal_value_model.adoc` and `scalar_values.py` say the
still-undecided normalization question is not owned by "any current or future
Phase." Current non-ownership is supportable; ownership by every possible
future phase cannot be decided in advance and conflicts with calling the
question undecided. The smallest correction is to say no *currently
authorized/planned* phase owns it.

== 6. Frozen-snapshot verification

The corrected high-level mechanism is partly accurate:

* `_freeze_effective_value` copies exact `dict`/`MappingProxyType` containers
  to owned mapping proxies, copies exact `list`/`tuple` containers to tuples,
  and retains every other leaf by reference;
* `_thaw_effective_value` materializes fresh invocation-local dict/list
  containers from the frozen container snapshot; and
* classifiers inspect the frozen `call.kwargs`, while execution derives its
  invocation-local structure from that same container snapshot. The mapping
  object passed into the target is not literally the classifier's mapping.

The proposed certifiability boundary is false. `_CONTRACT_KNOWN_KEYS` admits
`fill_value`, while `_classify_contract` neither snapshots nor type-checks that
field. A direct diagnostic probe constructed an authentic
`BoundFramesTargetCall(contract_grouped_xref, ...)` with a custom mutable
object as `fill_value`. The object remained present by identity in frozen
`kwargs`; `classify_grouped_producer_step` returned
`GroupedProducerCertificate` both before and after the caller mutated it; and
the value later supplied to execution reflected the mutation. Thus at least
one certifiable configuration contains a mutable arbitrary object by
reference, exactly the counterexample the follow-up criterion requires this
review not to accept.

This contradicts the corrected module docstring's statement that no E4
classifier certifies such a shape and the permanent model's claim that a
caller-held nested alias cannot alter certified execution semantics. Residual
source prose also remains inconsistent: `resolve_trusted_call` still describes
`__call__` as directly expanding `self.kwargs`, `formula_helper.py` calls the
frozen mapping "the exact mapping" execution uses, and
`BoundFramesTargetCall` says its stored structures share no mutable object
with the caller. The last statement is contradicted by that class's own
correct `_freeze_effective_value` documentation.

This is load-bearing binding authority, not a wording preference. Resolution
must make every certifiable configuration's relevant effective graph
immutable (or reject unsupported by-reference leaves before certification)
and then align the remaining docstrings. Merely weakening the permanent prose
would no longer promote the accepted executable-binding invariant.

== 8. Findings

=== Blocking B-1 -- I-5's certifiability premise is false

An E4 classifier certifies a grouped-producer binding containing a mutable,
by-reference arbitrary `fill_value`. Caller mutation can therefore change
execution after certification while the certificate remains unchanged. This
invalidates the promoted claim that classification and execution consume one
deeply immutable effective binding state. Close or reject by-reference shapes
at the certifiability boundary, then correct the residual same-mapping/no-alias
docstrings.

=== Important F-1 -- C11 still omits two exact FormulaSpec exits

State that forward grouping with `drop_source=true` leaves the retained source
helper roles pending cleanup, and that a standalone FormulaSpec surviving
cleanup terminates by capable XLSX/ODS adapter consumption. No other C11
rewrite is required.

=== Important F-2 -- Stale-current Phase-E claims remain

Correct ch04 sections 10 and 13 so they cannot present the pre-Phase-E ingress
state as current. Bound the new normalization non-ownership statement to
currently authorized/planned work rather than all possible future phases.

Finding count: *1 Blocking, 2 Important, 0 Minor*.
