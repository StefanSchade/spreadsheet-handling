== Pairing mechanism

`GroupedMatrix` remains `@dataclass(frozen=True, eq=False, init=False)` with
exactly `frame` and `header` fields. Its custom `__init__` rejects every ordinary
direct call without inspecting arguments. `_from_validated_pair` is private and
uses `object.__new__` / `object.__setattr__` only after feature-owned validation.
It is not exported.

`grouped_matrix_from_canonical(frame, header, *, mapping)` is exported from the
feature package. `_validate_canonical_pair`:

. requires a pandas DataFrame and exact `GroupedHeader`;
. extracts exact row-key labels from the descriptor's `RowKeyColumn` entries;
. calls accepted GX-1 `build_grouped_header` on the *current* canonical flat
  frame, using the supplied exact `ResolvedAxisMapping` and carried level names;
. requires the resulting frozen descriptor to equal the carried descriptor;
. raises one deliberate `GroupedXrefError` when valid components do not describe
  the same exact pair.

Malformed canonical frames/mappings retain GX-1/resolver exception ownership
(`GroupedHeaderError` / `AxisMappingError`). There is no broad exception
translation. `expand_grouped_xref` invokes the same validator immediately after
its one live mapping resolution and before `restore_flat_matrix`, local rebinding,
or `expand_xref`.

Exact re-derivation proves the semantic relation directly. It uses no stored
column snapshot, mutable-content hash, collision-prone fingerprint, object token,
sidecar, `_meta`, persisted mapping, or `MultiIndex` source of truth.

== Pairing regression closure

Committed regressions prove:

* direct raw construction fails and points to the public factory;
* exact canonical forward pair/factory construction succeeds;
* identity equality and identity hash remain unchanged;
* edited cell values with unchanged headers remain valid;
* reordered dynamic columns fail exact pair equality;
* a moved row-key column fails because `RowKeyColumn.position` changes;
* an unrelated same-width frame fails because its canonical schema projects to a
  different descriptor;
* changed mapping labels make the old descriptor stale and fail pair equality;
* `MultiIndex` and altered/unknown headers fail through GX-1/resolver before
  construction/restoration;
* mutating a valid carrier's DataFrame columns after construction is caught by
  inverse revalidation before output, metadata, cleanup, or value swap;
* inverse moved-row-key, `MultiIndex`, and altered-header probes fail before
  wrapped `expand_xref`.

The original silent corruption (`k1=A1`, `k2=A2` becoming `k1=A2`, `k2=A1`) is
no longer representable through the public factory and cannot survive inverse
revalidation. An unrelated DataFrame with the *same exact canonical schema and
mapping* remains intentionally compatible: canonical physical headers still
bind every value to the correct key. Cell/data provenance is not the pairing
contract and values must remain workbook-editable.

== GX-3/GX-4 compatibility

The public factory is the only future carrier construction seam. GX-3/GX-4
readback will:

[source,text]
----
parse exact visible tuples and physical positions
-> resolve the configured live mapping once
-> map each complete tuple to its canonical string key
-> build the canonical flat DataFrame in retained physical order
-> grouped_matrix_from_canonical(frame, parsed_header, mapping=mapping)
----

Reordered/deleted valid workbook columns therefore construct a smaller/reordered
but exactly paired carrier; unknown, duplicate, partial, incomplete, or
depth-changed tuples fail before factory success. XLSX and ODS share this
backend-neutral rule. Nothing in `bc21216` implements workbook parsing,
rendering, merge geometry, or persistence, and no GX-3/GX-4 file changed.

== Row-key ownership

`_owned_row_keys` is deliberately container-only normalization:

* bare string -> one-element built-in tuple;
* list/tuple/other iterable -> one owned built-in tuple;
* one-shot iterable -> consumed exactly once;
* `bytes`, `bytearray`, and non-iterable -> safe `GroupedXrefError` with constant
  shape guidance.

It does not validate empty declarations, element types, duplicate fields, or
existence. Unchanged XRef and accepted GX-1 retain those semantics and
diagnostics. Both directions normalize once. Forward passes the same tuple
object to unchanged `contract_xref`, dynamic-header isolation, and GX-1 header
construction; inverse passes its owned tuple to unchanged `expand_xref`. Pair
validation derives authoritative descriptor row-key positions from the
descriptor, not by re-consuming caller input.

Tests cover string/list/tuple/generator forms, a two-key generator in both
directions, an iterator that raises if iterated twice, same-object forwarding to
XRef/GX-1, exact physical-order `used_keys`, safe unsupported containers, and
unchanged XRef duplicate-row-key ownership. The rejected false
`Used canonical axis key(s) ['rk1', 'rk2'] ... missing` path no longer occurs.

== Atomicity, nonmutation, metadata, and cleanup

Pair validation is read-only and occurs before inverse restoration/expansion.
On every pairing/schema failure:

* caller Frames and caller `_meta` are unchanged;
* the carrier's DataFrame is not further mutated;
* no canonical output is inserted;
* no XRef metadata entry or cleanup command is written;
* no transient flat/private frame exists.

Forward remains build-then-publish over unchanged `contract_xref`'s copied
Frames. Factory failure discards the interim output/metadata/cleanup copy.

Metadata ownership is unchanged: only XRef writes `_meta.xref_crosstable` and
only existing cleanup logic writes transient
`_meta.pipeline_cleanup.drop_frames`. `xref_config_id` chooses the XRef entry key
but adds no grouped metadata. `composite_metadata_policy: preserve_public`
remains accurate. Final cleanup still removes only caller-named `relation` /
`matrix` inputs after complete success and consumes the command. No mapping,
descriptor, header depth, schema, or fingerprint persists.
