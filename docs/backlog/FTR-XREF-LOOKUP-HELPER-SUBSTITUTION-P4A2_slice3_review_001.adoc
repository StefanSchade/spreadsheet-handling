==== XREF-S3-R001-MIN-001 — outbound configuration test does not pin exact cardinality or `missing: empty`

ID:: `XREF-S3-R001-MIN-001`
Severity:: Minor
Repository:: Worldbuilding
File / config / test::
`tests/test_dino_insel_matrix_helper_migration.py`,
`OutboundMigrationConfigTest.test_five_add_lookup_helpers_configured`;
`pipelines/dino_insel/json_to_spreadsheet.yaml`.
Evidence::
The test builds a dictionary keyed by `output` and checks the five expected
entries and their source/lookup/keys/helper/position. It does not assert the
enricher count is exactly five, so duplicate outputs are collapsed and an
unrelated extra enricher would not fail this test. It also does not assert
`step.get("missing") == "empty"`. Direct configuration inspection proves the
active file has exactly five distinct enrichers and every one explicitly has
`missing: empty`; active-loader construction, both exports, and old/new carrier
equivalence all pass.
Impact::
No current runtime or acceptance defect. A future redundant enricher or drift
away from the explicitly selected missing policy could evade this focused
configuration test; current end-to-end data has no unmatched story key and
therefore would not necessarily expose missing-policy drift.
Required correction::
When the test is next touched, assert exactly five enrichers, five unique
expected outputs, and `missing == "empty"` for every surface.
Blocks Slice 4:: No.

reproduction proves the edit is genuine, but the maintained test could give a
less direct diagnostic if its own editing helper later stopped persisting the
requested cell.

`ExcelBackend.read_multi`) and assert the sentinel before invoking reverse
orchestration.
