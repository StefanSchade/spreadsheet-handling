== Corrected contracts

=== Diagnostic safety

`_unsupported_type_detail()` returns a constant string and accepts no caller
object. Invalid values are never interpolated merely to explain their type.
The feature contains no remaining `type(value).__name__` diagnostic.

The exact NumPy type collection also uses identity-only containment. Thus the
required `type(value) in supported_types` form cannot dispatch through a
caller-controlled metaclass hash or equality implementation.

Deliberate missing/empty diagnostics retain their existing specificity.
Unrelated exceptions from the shared physical-label helper remain governed by
the previously corrected narrow `ValueError` translation.

=== Exact NumPy integer normalization

At import time, the resolver maps every code in
`np.typecodes["AllInteger"]` through `np.dtype(code).type`. A feature-local
identity collection removes aliases that resolve to the same exact class.

On the validation platform this yields ten distinct classes:

* `numpy.int8`, `numpy.int16`, `numpy.int32`, `numpy.int64`;
* `numpy.longlong`;
* `numpy.uint8`, `numpy.uint16`, `numpy.uint32`, `numpy.uint64`;
* `numpy.ulonglong`.

Platform aliases such as `byte`, `short`, `intc`, `int_`, `intp`, and their
unsigned forms collapse to those exact classes here. Other platforms derive
their own distinct set from the same NumPy-owned vocabulary.

Only exact class identity is accepted. `bool`, `numpy.bool_`, floats,
arbitrary values, and NumPy integer subclasses remain rejected before
conversion. Accepted scalars are converted to unbounded built-in `int`, so
signed/unsigned boundaries cannot overflow and mixed Python/NumPy integers
become one homogeneous order type.

=== Exact visible-label tuples

A visible-label tuple is now:

[source,text]
----
exact built-in tuple
  containing one or more exact built-in non-empty strings
----

Tuple subclasses are rejected before any overridable tuple operation. The
resolver already creates exact tuples; direct construction and inverse lookup
now enforce the same contract. A defensive revalidation in direct mapping
construction prevents a malformed exact member instance from introducing a
hostile labels container.

Member-collection iterables retain their documented contract: ordered
iterables are materialized once and unordered mappings/sets are rejected.

== Dependency and helper-placement decisions

Production code imports NumPy and defines behavior in terms of NumPy scalar
classes, so NumPy is a direct dependency rather than an undocumented pandas
transitive dependency. The lower bound matches the supported Python/pandas
environment without upgrading installed packages.

The diagnostic detail and exact NumPy collection remain inside
`xref_axis_mapping`. Repository search found no established second consumer
with the same hostile-caller contract. The configured-field matcher also
remains feature-local for the reasons recorded in acceptance review 002.

No generic helper was introduced across physical labels, configured field
references, canonical identities, visible labels, and ordering values; those
remain separate semantic contracts.

== Adversarial evidence

The new tests prove:

* hostile metaclass `__name__`, hashing, and equality are not invoked across
  nine direct-model/lookup cases and four resolver cases;
* every rejection is deliberate `AxisMappingError`, never raw `RuntimeError`;
* every distinct supported NumPy integer class survives pandas typed-array
  extraction with exact type preserved and orders its minimum/maximum values;
* all eight pandas nullable integer dtypes resolve concrete values;
* every supported NumPy class mixes with Python `int` without a false
  mixed-type failure;
* a hostile `np.int64` subclass is rejected without `__int__`;
* hostile/mutable tuple subclasses are rejected before length, iteration,
  hash, equality, or representation in direct member construction, defensive
  direct mapping construction, and inverse lookup;
* rejected tuple mutation cannot affect an existing Resolution; and
* direct and resolver-produced stored/returned labels and inverse keys have
  type exactly built-in `tuple`.

== Architecture and retained non-goals

The feature still imports only pandas, NumPy, shared domain/tabular boundaries,
and its own model. It adds no pipeline, registry, YAML, metadata, persistence,
schema-maintenance, rendering, adapter, XLSX, ODS, or grouped-header behavior.
Existing XRef operations and package surfaces are unchanged.

No release-note entry is required: this correction changes only an internal
Slice-1 domain contract and its direct dependency declaration. A later public
projection slice owns its own interface gate and release-note decision.

Deferred Slices 2-5 remain open. This correction does not mark the complete
FTR `Done`, remove its backlog include, or perform lifecycle cleanup.
