=== 3.2 Important findings

==== XREF-S2-R001-IMP-001 — the documented postcondition cannot detect the missing declaration it is said to expose

Severity:: Important
Affected::
`docs/user_guide/ch03_transformation_catalog/03_supporting_steps.adoc:312`;
`docs/release_notes/release_notes.adoc:68`;
`tests/integration/pipeline/test_xref_lookup_helper_inbound_binding.py:514`;
`domain.validations.reference_validations._validate_no_helper_columns` and
`_durable_helper_columns`.
Evidence::
Both `apply_derived_column_policy` and `no_helper_columns` identify helpers from
the same durable declaration,
`_meta.sheets[<visible-sheet>].helper_columns`. When the declaration is omitted,
cleanup obtains an empty helper set and safely does nothing; the guard also
obtains an empty helper list and returns no finding. The tracked negative test
stops after asserting that `title` survives and never runs the documented
guard. An independent real-XLSX probe ran the exact documented drop-plus-guard
sequence without the declaration and produced:

----
columns=['title', 'story_id', 'Alice', 'Bob', 'Carol']
helper_survives=True
guard_passed=True
durable={}
----

The release note says the missing declaration "must surface as an observable
failure", and the user guide says pairing the drop with `no_helper_columns`
makes the missing declaration an observable failure. Both statements are
false. The implementation artifact is otherwise more accurate: section 10
assigns declaration completeness to a Slice-3 consumer-owned static/config
guard.
Impact::
This is a real public-pipeline safety and contract gap before Slice 3. A
consumer following the public example could omit or mistype the only durable
helper declaration, receive a passing postcondition, and then melt `title`
into the canonical inverse. The generic guard is valid only for
declaration-present cleanup failures; it is not a declaration-completeness
guard.
Required correction::
Correct the public user guide, release note, implementation artifact residual
risk, and tests to state and prove the exact limitation: `no_helper_columns`
catches a still-present helper only when the durable declaration names it. Add
a tracked negative that runs drop plus guard with the declaration absent and
asserts the current pass-plus-survival behavior. Preserve the Slice-3 gate that
a consumer-owned static/configuration check verifies all five declarations;
do not add name inference or new Core runtime behavior unless scope is
reconfirmed.
Blocks Slice 3:: Yes. Slice 3 must not rely on the documented postcondition as
the declaration guard.

==== XREF-S2-R001-IMP-002 — no maintained end-to-end public orchestration test covers the exact selected route

Severity:: Important
Affected::
`tests/integration/pipeline/test_xref_lookup_helper_inbound_binding.py:170`;
the public configured/CLI acceptance evidence for Slice 2.
Evidence::
The new test correctly builds every domain step through
`build_steps_from_config` and uses real `ExcelBackend`/`OdsBackend` write/read,
but its `_persist_and_reload` helper manually calls the orchestrator-internal
`project_meta_to_persistable_contract`, then directly invokes the backends.
Inbound steps are executed in several separate `run_pipeline` calls. No test
runs the exact forward and reverse configuration through `orchestrate()` or the
public YAML/CLI entry point across a carrier. Existing `tests/roundtrip/`
coverage reaches the CLI for FK helpers, and the configured Workbook View test
reaches direct backends for mapping, but neither composes asymmetric
`add_lookup_helpers` + visible-sheet durable cleanup + guard + mapping + XRef
inverse. The implementation artifact itself records this boundary at section
25.
Impact::
The route is expressible and direct evidence says it works, but Slice 2's
central claim is a stable *public pipeline* binding. There is no maintained
test that would catch a regression in the real orchestrator macro sequence,
its saver/loader routing, YAML binding, or step ordering for this exact route.
That is a concrete public-pipeline proof gap before five consumer sites are
migrated.
Required correction::
Add at least one maintained end-to-end configured test through `orchestrate()`
or the public CLI/YAML entry point. It must use a visible sheet name containing
spaces and execute the exact route in one reverse configuration: visible-name
drop, declaration-present `no_helper_columns`, mapping to a distinct logical
name, and an inverse. It must traverse an actual spreadsheet carrier and prove
canonical equality and edited-title discard. Keep the existing direct
XLSX/ODS test for backend parity; duplicating every inverse across every
carrier is unnecessary.
Blocks Slice 3:: Yes. The selected public route needs one maintained macro-flow
proof before consumer migration.

== 8. Cleanup behavior

With durable `helper_columns=[title]`, `policy: drop` removes exactly the
declared helper and preserves the order of all other columns. The ordinary and
dynamic fixtures establish:

----
[title, story_id, Alpha, Beta]
  -> [story_id, Alpha, Beta]

[title, story_id, Beta, Gamma, Delta]
  -> [story_id, Beta, Gamma, Delta]
----

The declared helper's value is irrelevant: `EDITED-TITLE-XYZ` is discarded.
`story_id`, dynamic axes, row order, and relation values remain. The lookup
frame stays `First Story`, `Second Story`. The inverse receives no static
`value_columns` list.

When no durable declaration exists, `title` is not inferred or dropped. This
is the correct generic ownership rule. Existing derived-policy tests establish
copy/caller-safety behavior: cleaning returns a copied frame and outer mapping;
failed validation does not mutate caller frames or metadata.

== 9. Ordering contract

The correct order succeeds:

. drop by visible `Matrix View` while `_meta.sheets` is addressable;
. validate declaration-present helper absence;
. map `Matrix View -> role_matrix`; and
. inverse `role_matrix`.

The wrong-order test maps first, then asks cleanup for logical `role_matrix`.
Because `_meta.sheets` remains keyed by `Matrix View`, cleanup is a safe no-op,
`title` remains, and `expand_xref` melts it into `character_name`. The test also
executes the correct visible-name drop as a control. Public docs explicitly
state cleanup-before-map and explain why logical cleanup is not equivalent.

The negative is load-bearing: it proves the exact noop and concrete downstream
harm, rather than only asserting that ordering differs.

== 10. Postcondition guard

With the durable declaration present, `no_helper_columns`:

* fails before cleanup when `title` remains;
* passes after cleanup;
* uses visible `Matrix View` before mapping;
* returns the diagnostic
  `no_helper_columns Matrix View(title): Helper columns must be absent after cleanup`;
* is registered through `validate_references`; and
* does not mutate caller payload or metadata on failure.

It catches an omitted cleanup or a cleanup that leaves a *declared* helper.
It does not infer helper identity, detect an omitted declaration, or detect a
post-mapping logical frame against visible-keyed metadata. Public docs must
make that boundary explicit (R001-IMP-001).

== 11. Missing declaration negative
