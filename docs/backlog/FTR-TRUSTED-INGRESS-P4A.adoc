==== 2. Problem statement and contract vocabulary

Current framework-managed execution has a load-time function named ingress,
but that function establishes only one `_meta.legend_blocks` shape. It does
not establish a scalar grammar, general metadata substrate, DataFrame or
`ExactTable` carrier contract, policy result, or post-step payload guarantee.
`run_pipeline` is intentionally step-only, and executable steps may replace
payload after the initial seam.

This design makes the following statement precise:

[source,text]
----
Successful Trusted Ingress establishes assumptions that downstream ordinary
Domain code is entitled to rely on.
----

The following terms are used normatively in this design:

* *Trusted Domain Payload* is a conformance postcondition over one payload
  state. It is not the payload-authority trust dimension, not a security level,
  and not proof that its author is trustworthy.
* *ordinary Domain operation* is a transformation, cleanup, validation, or
  reconstruction consumer that declares the Trusted Domain Payload contract as
  its general payload precondition. Family-specific preconditions remain
  additional.
* *trust epoch* is the period during which a particular payload state remains
  inside framework/caller ownership and is changed only by producers whose
  contracts preserve or re-establish Trusted Domain Payload.
* *preserving producer* is a reviewed producer whose explicit contract says
  that, for Trusted Domain Payload input, every returned/replaced payload state
  also satisfies that contract. Being built-in, registered, or importable is
  not sufficient by itself.
* *uncertified producer* is an executable step without that reviewed producer
  contract. Dotted plugins, generic custom callables, and caller-supplied
  `BoundStep` values are uncertified by default.
* *re-establishment* is a new successful Trusted Ingress pass over a producer's
  returned candidate before the framework resumes ordinary Domain macro flow.

Four responsibilities remain independent throughout:

[cols="2,4",options="header"]
|===
|Responsibility |Owner and meaning

|Description / control input
|Structural parsing and authorization of what operation/capability may be
selected. This is the pipeline-description trust plane.

|Payload input
|Recognized structural carriers, scalar grammar, framework-owned metadata
substrate, and payload policy. This is Trusted Payload Ingress.

|Domain invariants
|Family- or reconstruction-local semantic validity, including reusable
Finding-based checks where appropriate.

|Output adaptation
|Persistence projection and sink-specific capability. Writers do not become
payload validators, and formula-looking text is not globally invalid.
|===

Runtime/operator trust remains a fixed precondition. Payload authority and
pipeline-description authority remain independent variables. Output-sink
capability remains separately owned. This design introduces no scalar trust
level.

==== 3. Current-state evidence to which the design responds

The accepted census establishes these load-bearing facts:

* router-backed high-level flows converge on `orchestrate`, whose fixed order
  is load, current ingress, linear steps, final Domain cleanup, metadata
  persistence projection, and save;
* `sheets-run` and `run_app` bind configured strings before payload load, so a
  dotted import can activate capability before any payload ingress occurs;
* the current ingress coordinator has three production call sites and one
  Legend Blocks rule;
* the shared six-category scalar classifier has no production caller;
* DataFrame cell carriers differ across XLSX/ODS, CSV, JSON, YAML, XML, and
  direct Python inputs;
* exact spreadsheet paths may carry `ExactTable` into reconstruction;
* metadata has initial parser origins plus post-load bootstrap/override origins;
* every executable step return is passed directly to the next step, with no
  automatic post-step ingress; and
* `run_pipeline`, supported lower-level APIs, mixed direct reachability, and
  importable internals do not have one uniform public contract.

Those facts show why “call `scalar_category()` once in `orchestrate`” cannot be
the contract.

==== 5. Coverage-model evaluation and decision

[cols="2,3,3",options="header"]
|===
|Model |Fit to repository |Decision

|A -- universal ingress
|A simple slogan, but it would either wrap every supported low-level call or
silently call importability public. It also obscures producer-created payload.
|Rejected. Too broad for the actual API and not the smallest truthful contract.

|B -- framework-managed guarantee
|Matches the main convergence seam and preserves `run_pipeline`, but by itself
does not answer replacement payload after a custom step.
|Necessary but insufficient alone.

|C -- capability/payload certification wrapper or type state
|Could track provenance across many producers, but current Frames APIs and
pandas-heavy transformations do not use wrapper state. Retrofitting it would
be a large API rewrite.
|Rejected for Phase E. No evidence justifies the complexity.

|D -- hybrid
|Framework-managed load establishes the contract; reviewed producers preserve
it; custom producers trigger re-establishment; lower-level APIs state caller
preconditions.
|Selected. It covers the demonstrated gap without changing the basic Frames
API or pretending every Python call is managed.
|===

The selected coverage model is therefore:

[source,text]
----
framework-managed load
  -> establish Trusted Domain Payload
  -> preserving producer(s) keep the trust epoch
  -> uncertified producer return ends the epoch
  -> framework-managed re-establishment starts a new epoch
  -> final cleanup / persistence projection / saver

trusted programmatic composition
  -> caller supplies Trusted Domain Payload
  -> caller owns every preservation/re-establishment transition

supported lower-level Domain API
  -> local documented contract, including Trusted Domain Payload where the
     operation consumes ordinary payload
----

==== 6. Framework-managed definition and entry-surface guarantees

“Framework-managed” adopts the accepted census meaning:

[source,text]
----
A high-level entry is framework-managed when its fixed application macro flow
owns the loader, initial Trusted Ingress, final Domain cleanup, persistence
projection, and saver.
----

Delegating one or more of those responsibilities to an owned helper does not
change the definition. The definition is semantic, not tied permanently to the
current `orchestrate` function name.

Framework management does not make arbitrary plugin behavior safe or payload
conformant while the plugin is executing. It does require the enclosing macro
to apply the producer-transition contract to the candidate the plugin returns
before ordinary macro flow resumes.

==== 7. Payload grammar

The Phase-E cell-payload grammar is positive and closed:

[source,text]
----
CellPayload       ::= Scalar | DeclaredComposite
Scalar            ::= String | Boolean | Number | Missing | Date | DateTime
DeclaredComposite ::= <no admitted variants in Phase E>
----

Successful scalar ingress is defined by both:

. membership returned by the accepted `scalar_category(value)` classifier; and
. admission under the effective narrowing payload policy.

The globally supported carrier variants are exactly those owned by the current
Internal Scalar Value Model:

[cols="2,4",options="header"]
|===
|Category |Admitted carrier variants

|String
|`str`, including `numpy.str_` through its string-subclass behavior.

|Boolean
|`bool`, `numpy.bool_`.

|Number
|`int`, `float`, `numpy.integer`, `numpy.floating`, subject to the classifier's
explicit exclusions.

|Missing
|`None`, `""`, supported float/NumPy NaN, `pandas.NA`, `pandas.NaT`, and
`numpy.datetime64('NaT')`, exactly as recognized by
`is_missing_carrier`; `numpy.timedelta64('NaT')` is not admitted.

|Date
|`datetime.date` after DateTime precedence.

|DateTime
|`datetime.datetime`, `pandas.Timestamp`, and every non-NaT
`numpy.datetime64`, with no unit-based Date inference.
|===

`datetime.time`, Duration/Timedelta carriers, `FormulaSpec`, spreadsheet Error,
collections, bytes, callables, classes, modules, generators, file handles, and
opaque objects are not scalar payload. An unsupported carrier does not become
valid because pandas can store it in an object-dtype cell.

DataFrame axes use a separate structural label grammar, not `CellPayload`:

[source,text]
----
AxisAtom  ::= an admitted Scalar carrier
AxisLabel ::= AxisAtom | finite tuple[AxisAtom, ...]
----

The tuple branch exists for physical/MultiIndex labels and is not the future
cell-level `DeclaredComposite` branch. Column labels additionally satisfy the
established physical addressability contract; row-index labels need not be
unique because ingress uses positions and does not promote the index to Domain
data. Opaque/custom objects are not admitted as axis labels merely because they
are hashable.

Classification occurs before any policy decision and before any future
category-specific normalization. The current design performs no scalar
normalization afterward.

The classifier's bounded dispatch is the robustness boundary: it does not run
general equality, hashing, `repr`, string conversion, iteration, or NumPy array
protocols on an unsupported value. Trusted Ingress must not add such probes to
make diagnostics richer. It does not attempt to contain arbitrary hostile
Python already executing in process.

String content is never shape-guessed. Numeric-looking, boolean-looking,
date-looking, formula-looking, SQL-looking, shell-looking, and HTML-looking
strings remain String. Sink-specific interpretation remains sink-owned.

==== 8. Classification, normalization, and Missing

The scalar-normalization alternatives were evaluated as follows:

[cols="2,3,3",options="header"]
|===
|Alternative |Benefit |Disposition

|A -- validate only
|Preserves accepted carriers, pandas behavior, temporal precision/timezone,
and the established classifier boundary.
|Selected for scalar payload.

|B -- minimal canonicalization
|Could stabilize a demonstrated problematic carrier, but no such general
post-classification carrier is evidenced for this slice.
|Preserved as a future per-category option, not selected now.

|C -- full canonical scalar set
|Would simplify types superficially but force precision, timezone, Missing,
and pandas rewrite decisions without consumer evidence.
|Rejected.

|D -- category-specific policy
|Is the correct shape if a future category proves it needs conversion.
|Extension rule only; all six categories currently specify identity
preservation.
|===

Trusted Ingress therefore does not convert `numpy.int64` to `int`,
`numpy.bool_` to `bool`, `pandas.Timestamp` to `datetime.datetime`, or
`numpy.datetime64` to another carrier. It does not strip/convert timezone
information or reduce precision. DataFrame dtype behavior may still box values
according to pandas; ingress does not add another conversion.

Missing remains recognition, not representation. Every admitted Missing carrier
is preserved. In particular:

* `""` is not replaced by `None` or a sentinel;
* NaN/NA/NaT carriers are not globally unified;
* literal string `"nan"` remains String, not Missing; and
* ordinary empty domain text remains possible. Where `""` means missing,
  unresolved presentation, or legitimate empty text depends on the consuming
  feature's authority and context, not on a new ingress sentinel.

Successful ingress promises that every Missing-shaped cell is one of the
accepted recognized carriers. It does not promise representation equality
between Missing cells. Downstream generic code may use the accepted missing
predicate; family semantics such as unresolved FK authority remain unchanged.

Ingress may still perform two non-scalar forms of normalization:

* construct a new owned top-level Frames mapping and owned metadata containers;
  and
* apply explicit feature-owned authoring-to-canonical metadata rules such as
  the existing Legend Blocks rule.

Parser conversion and persistence-local conversion remain owned by their
respective boundaries and are not renamed scalar normalization.

==== 9. Traversal ownership

Trusted Ingress does not use one universal recursive walker.

|DataFrame ingress
|Every axis label and cell by physical row/column position
|Checks the DataFrame structural substrate, including the established physical
column-label contract (non-missing, hashable, deterministically comparable,
and unique), and the bounded axis-label grammar, then classifies every ordinary
cell without using row-label or rejected-value representation in diagnostics.
Axis addressability remains a separately named structural contract; it is not
cell scalar grammar.

|`ExactTable` ingress
|Header/geometry fields and every `data` cell
|Checks carrier self-consistency and the string header substrate, then applies
scalar grammar to row-major data. Reconstruction meaning remains local.

|Metadata ingress
|The `_meta` structural tree and explicit root delegates
|Uses metadata-only traversal over exact `dict`/`list` nodes, ownership copying,
cycle rejection, scalar leaves, and root-local normalization/validation.

|Trusted internal carrier constructor
|Carrier-specific fields
|Owns the carrier's construction invariant. No fallback recursively walks an
unknown object's attributes.
|===

Selected payload frames means every recognized payload carrier at the top level
other than `_meta`; there is no sample-based, dtype-based, or “pandas accepted
it” exemption.

==== 10. Structural-carrier contract

Ingress validity, reconstruction invariants, and transformation preconditions
remain different contracts.

[cols="2,2,3,3,3",options="header"]
|===
|Carrier |Allowed at initial ingress? |Shape owner |Scalar traversal |Local
invariants that remain local

|Frames mapping
|Yes, as an exact framework mapping with exact string names.
|Frames dispatcher; `_meta` is reserved. An empty exact string is not rejected
by the general ingress grammar merely by content; a loader or feature may own a
narrower naming rule. Duplicate names are impossible in the resulting exact
`dict`.
|Delegated per value.
|Feature frame presence, cleanup selection, workbook visibility.

|`pandas.DataFrame`
|Yes.
|DataFrame structural validator. DataFrame supplies rectangular storage;
physical column labels MUST satisfy the established scalar-addressability

not cell composites. Column and row-index labels MUST satisfy the bounded axis

cells by ingress.
|Every data cell, positionally.
|Required columns, key uniqueness, relation validity, ordering, family-specific
axis semantics.

|`ExactTable`
|Yes on explicit exact-table paths.
|ExactTable ingress verifies exact carrier identity, non-negative exact integer
geometry, `header_rows == len(header_grid)`, header/data row widths equal
`n_cols`, and string header cells.
|Every `data` cell.
|Workbook-view mapping, configured header depth beyond self-consistency, row
keys, visible tuple uniqueness, source-axis resolution, grouped reconstruction.

|Grouped/canonical carrier such as `GroupedMatrix`
|Not as an arbitrary externally supplied Frames root in Phase E.
|Its controlled constructor and family own invariants.
|No general ingress traversal; a later explicit adapter would have to define

|Geometry, bijection, projection/reconstruction invariants remain local.

|Future structured carrier
|No, until explicitly declared.

|===

Actual trusted carrier instances may be produced inside a trust epoch by their
validated constructors. External mappings that merely resemble them are never
promoted by shape. The implementation slice must compatibility-audit physical
DataFrame axes before tightening their structural vocabulary; this design does
not turn scalar cell categories into a new universal column-label type system.

==== 11. Metadata contract

`_meta` is part of Trusted Payload Ingress, but cell payload and metadata remain
different flows.

At a framework-managed external boundary, `_meta` MUST be absent or an exact
built-in `dict`. A DataFrame, scalar, list, mapping subclass, or opaque object
at the `_meta` root is an invalid metadata substrate. This deliberately exposes
the current `yaml_dir` `_meta.yaml` collision: that backend's ordinary DataFrame
projection does not create valid framework metadata merely because the
filename is reserved.

The central metadata postcondition is structural, not universal semantic
validity:

* the root and nested mapping nodes use owned exact built-in `dict` values with
  exact string keys;
* external sequence nodes use owned exact built-in `list` values; tuple, set,
  arbitrary `Sequence`, and arbitrary `Mapping` nodes reject unless an
  explicit root delegate owns and normalizes that exact shape;
* the graph is acyclic and contains only declared metadata container nodes,
  accepted scalar leaves, or values accepted by an explicit root-specific
  delegate;
* unsupported objects, callables, binary values, and undeclared container kinds
  are absent; and
* framework-owned authoring sugar is normalized only by the owning root rule.

The current-root compatibility census and any needed root-specific delegate are
acceptance work for the metadata implementation slice. The generic node
vocabulary itself is fixed here as `dict` / `list` / admitted scalar leaf; the
slice must start from current produced/consumed roots, not bind runtime behavior
to `meta_registry.yaml`, which is currently a manual review artifact and
explicitly forbids runtime binding.

Successful ingress does *not* mean every `_meta` root is semantically valid for
every family. Root-specific semantics, cross-frame references, configuration
conflicts, and family policy remain with the consuming family/configuration
step. The current Legend Blocks authoring-form normalization remains a
feature-owned ingress delegate; it is not evidence that every family schema
belongs in the central coordinator.

Bootstrap and YAML overrides MUST:

. build their merged candidate without mutating the published Frames graph;
. run framework substrate validation plus every relevant root delegate over the
  candidate metadata;
. apply effective payload policy where it applies to metadata leaves; and
. publish the candidate only on success.

Ordinary preserving producers may create framework/family metadata under their
reviewed output contracts. Uncertified producers returning metadata participate
in the same re-establishment rule as cell payload.

==== 12. Trust propagation and post-ingress producers

The evaluated alternatives are:

[cols="2,3,3",options="header"]
|===
|Alternative |Assessment |Disposition

|A -- trusted-step preservation
|Efficient for reviewed built-ins, but unsafe if “built-in” or “registered” is
treated as proof without an output contract.
|Adopt only with explicit producer certification.

|B -- revalidate after every step
|Simple but duplicates complete traversal after transformations already
required to preserve the grammar.
|Rejected as the universal rule.

|C -- producer classes
|Directly models the observed difference between reviewed framework producers
and arbitrary executable returns.
|Selected.

|D -- explicit token/type state
|Makes state machine visible but would reshape current Frames and step APIs.
|Rejected for Phase E; no evidence requires it.

|E -- arbitrary plugins outside all guarantee
|Truthful inside plugin execution but insufficient when macro flow passes the
return to later built-in steps/cleanup.
|Adopt only for calls made *inside* the plugin; returned candidates are
re-established before macro flow resumes.
|===

Producer treatment is:

[cols="3,2,4",options="header"]
|===
|Producer kind |Default class |Contract

|Reviewed built-in Domain transformation
|Uncertified until audited; then preserving if its explicit output contract
passes review.
|A preserving producer MUST return recognized structural carriers containing
only admitted payload/metadata and MUST not retain an out-of-band mutation path
that invalidates the state during the epoch.

|Framework infrastructure step
|Affected-state re-establishing when it introduces external/bootstrap/override
data; otherwise preserving only after review.
|Merge-before-publish and validate the introduced portion plus affected
structural roots. It cannot claim trust merely because it is infrastructure.

|Configured dotted plugin or generic dotted callable
|Uncertified.
|Within framework-managed flow, its returned candidate MUST pass full
re-establishment before any next ordinary Domain operation, final cleanup, or
save. Domain calls it performs internally are under the plugin's own stronger
caller precondition.

|Caller-supplied callable / `BoundStep` to `orchestrate`
|Uncertified unless it carries a framework-reviewed producer contract through
an implementation mechanism.
|Same returned-candidate re-establishment rule. Direct Python remains trusted
runtime capability, not automatically valid output.

|Callable / `BoundStep` supplied to `run_pipeline`
|Caller-classified.
|`run_pipeline` performs no automatic transition. The caller is responsible for
preservation or explicit re-establishment.
|===

“Custom output is automatically untrusted” is not the decision. Its authorship
may be fully trusted; its payload conformance is simply uncertified until
re-established. Likewise, “built-in output is automatically trusted” is not the
decision: it becomes preserving only through a reviewed contract.

The Trusted Domain Payload assumption remains valid only while:

* the payload is inside the current trust epoch;
* the owner/caller does not mutate it concurrently or out of band;
* every mutation/replacement comes from a preserving producer; and
* every uncertified producer return succeeds at re-establishment before later
  ordinary Domain use.

Framework-managed loaded DataFrames need not be deep-copied solely to establish
atomicity because scalar validation is read-only. Logical ownership transfers to
the macro for the duration of the call. An implementation may copy for another
documented reason, but this contract does not require a full DataFrame copy.

==== 13. Operator payload policy

Global framework capability and operator policy are different:

[source,text]
----
effective payload capability = globally supported payload grammar
                               narrowed by operator policy
                               narrowed by any authorized description request
----

The last term may only narrow and is evaluated per policy kind. Phase-E payload
policy needs only these kinds:

* allowed ordinary-cell scalar semantic categories -- subset/intersection of
  the six;
* allowed ordinary-cell carrier variants within a supported category --
  subset/intersection;
* allowed metadata-leaf semantic categories and carrier variants -- an
  independent subset/intersection, so a string-only cell policy does not
  accidentally prohibit a Boolean or Number used by valid metadata; and
* allowed recognized structural carrier kinds -- subset/intersection.

Unknown, contradictory, incomparable, or widening requests reject. Policy can
never make an unsupported object, undeclared collection, FormulaSpec, Time, or
Duration into valid scalar payload. A trusted-payload authority assessment does
not bypass the global grammar; framework-managed ingress establishes the same
bounded downstream contract for trusted and less-trusted payload origins.

Maximum bytes/cells/text lengths, parser limits, metadata-root authorization,
filesystem capabilities, formula policy, and custom-step capability are not
added to this payload policy without their own concrete owning use sites.
Parser/resource bounds and sink capability remain separately owned.

The operator supplies policy outside a less-trusted pipeline description.
Effective policy is immutable for a macro execution/trust epoch and must be
available to every re-establishment pass. This design does not choose CLI flag
syntax, environment variables, profile names, or a public policy class.

==== 14. Pipeline-description trust and capability activation

Trusted Payload Ingress and pipeline-description authorization are two
coordinated but separately owned subcontracts:

[source,text]
----
description/control plane:
  parse shape -> prepare/canonicalize identifier -> combine policy -> authorize
  -> only then import/bind/acquire/invoke governed capability

payload plane:
  parse/load carrier -> structural/scalar/metadata ingress -> ordinary Domain
----

Their execution order is not universally serial: current CLI and `run_app`
bind descriptions before loading payload. Therefore a later successful payload
pass cannot retroactively authorize an earlier import.

Phase E's minimum description seam is:

* an entry must state whether its description is trusted or less trusted;
* less-trusted description requests must be combined with operator policy
  outside that description;
* safe syntactic parsing, structural checks, static policy metadata lookup, and
  identifier canonicalization may occur before authorization;
* Python module import is capability activation and MUST NOT occur before an
  allow decision;
* direct Python callables and pre-bound `BoundStep` values are trusted
  programmatic capabilities, not a supported less-trusted-description format;
  and
* description authorization success does not establish payload conformance,
  and payload ingress success does not authorize the description.

Concrete description policy/allowlist/binding mechanics belong to a separate
Phase-E sub-slice after the still-open dotted-extension-surface architecture
assessment supplies its per-surface stability contract. Until that sub-slice is
accepted and implemented, `sheets-run` and `run_app` publish the Trusted Payload
guarantee only under a trusted-description precondition. This is a support
boundary, not a claim that less-trusted descriptions become safe after payload
ingress.

No attempt is made to sandbox trusted Python.

==== 15. Failure atomicity

An ingress attempt is atomic over the candidate Frames state it is asked to
establish:

* traversal and scalar classification are read-only;
* structural and metadata normalization are built in staged containers;
* the top-level candidate is not published to the caller, next step, cleanup,
  persistence projection, or saver until every required check succeeds;
* failure on cell N does not expose normalization performed for cells or
  metadata visited earlier;
* caller-owned input Frames, DataFrames, `_meta`, and retained nested metadata
  remain unchanged on failure; and
* no ordinary configured step or saver runs after an initial ingress failure.

This does not require transactional machinery. A staged top-level mapping plus
owned staged metadata and read-only cell traversal is sufficient under the
validate-only scalar decision. Input DataFrames need not be copied when they
are not mutated.

For re-establishment after an uncertified step, rejection prevents that
candidate from reaching the next ordinary Domain operation, final cleanup, or
framework saver. It cannot roll back mutations or external side effects the
custom callable already performed, nor prior successfully completed pipeline
steps. Plugins with such effects remain trusted-programmatic capability and
must document/own them.

==== 16. Error and diagnostic model

Boundary rejection raises exceptions; it does not emit reusable Domain
`Finding` values. Findings describe Domain semantic/invariant observations and
remain separately governed by severity policy.

The contract requires distinguishable failure kinds:

[cols="3,4",options="header"]
|===
|Failure kind |Required diagnostic context

|Unsupported scalar carrier
|Frame and positional column/row ordinal, or `ExactTable` data row/column
ordinal; constant safe detail. The rejected value is never rendered.

|Invalid structural carrier
|Top-level frame name when it is an exact validated string, carrier role, and
failed structural field/ordinal.

|Invalid metadata substrate
|Safe metadata path composed only from already-validated exact string keys and
container ordinals; expected node kind.

|Payload-policy rejection
|Safe location, classified semantic category/carrier kind, and policy kind
that rejected it. No value content is required.

|Pipeline-description authorization rejection
|Description location, declarative identifier/capability kind where safely
available, and policy reason. It is a description-plane exception, not an
ingress scalar error.
|===

A typed exception hierarchy or an exception carrying a stable `kind` field is
required by contract; exact class names are an implementation choice. The
boundary may fail fast at the first deterministic error. Multi-error collection
and report/result objects are optional later enhancements.

Diagnostics MUST NOT call `repr`, `str`, equality, hashing, iteration, or NumPy
protocols on a rejected unsupported value. Frame/row/column values that have not
themselves passed a safe structural contract are reported by ordinal/role, not
by content.

==== 17. Downstream postconditions

After successful Trusted Ingress, an ordinary Domain operation is entitled to
rely on exactly these general facts for the current trust epoch:

. the top-level payload uses recognized framework structural carriers;
. every DataFrame's physical column labels satisfy the established non-missing,
  hashable, deterministically comparable, unique addressability contract;
. every DataFrame column and row-index label is an admitted structural axis
  label rather than an opaque Python object;
. every ordinary DataFrame cell and every admitted `ExactTable.data` cell is a
  member of the accepted scalar grammar and effective payload policy;
. unsupported opaque Python objects, arbitrary collections, callables,
  modules, file handles, generators, FormulaSpec values, and unsupported
  temporal carriers are absent from ordinary cell payload;
. scalar carrier identity is preserved; no undocumented coercion to native
  Python or unified Missing representation occurred;
. `_meta` is absent or has the valid, owned framework metadata substrate;
. every applied framework-owned metadata authoring normalization has reached
  its canonical structural form;
. admitted structural carriers satisfy their generic carrier
  self-consistency checks; and
. the framework/caller producer chain owns keeping these facts true or
  re-establishing them before the next ordinary Domain operation.

This bounded postcondition is useful enough for later family hardening to
remove arbitrary-object/callable/container defensive code from ordinary cell
paths. It does not authorize removal of carrier-variant handling, Missing
recognition, family-specific label identity/role rules, or family semantics.

==== 18. Explicit downstream non-guarantees

Successful Trusted Ingress does not prove:

* required frames or columns exist;
* FK targets/references exist or resolve;
* values in key columns, visible tuples, or Domain mappings are unique;
* grouped geometry, header depth, row keys, or reconstruction bijection is
  valid beyond generic carrier self-consistency;
* a transformation can sort, compare, hash, or serialize every admitted
  category for its own semantics;
* family configuration or every `_meta` root is semantically valid;
* metadata is authoritative merely because it has framework shape;
* cleanup has been selected or output is canonical;
* a string is safe for every sink, including XLSX formula interpretation;
* persistence roundtrip preserves carrier identity, temporal precision, or
  timezone-name identity beyond each backend's own contract;
* the pipeline description is authorized, unless the separate description
  boundary has also succeeded;
* an arbitrary trusted callable cannot misbehave or perform side effects; or
* process, filesystem, network, container, or Python sandbox isolation exists.

Ingress validity is not reconstruction validity, transformation precondition,
Domain invariant validity, persistence projection, or sink safety.

==== 19. Bounded-composite extension seam

The `DeclaredComposite` branch in section 7 is intentionally empty. A future
bounded composite such as `List[Scalar]` can be added only by a separately
accepted contract that defines:

* a named composite kind distinct from arbitrary Python collection identity;
* a finite cardinality/depth/resource bound;
* the permitted scalar-leaf grammar and Missing behavior;
* an explicit carrier and ownership/copying rule;
* a schema/declaration and operator policy capability;
* ingress classification/normalization and safe path diagnostics;
* DataFrame/pandas interaction; and
* parser and persistence codecs/representations for every claimed external
  surface.

The extension must enter through Trusted Ingress and cannot make arbitrary
`list`, `tuple`, mapping, set, or object graphs valid by default. This seam does
not choose delimiter encoding, JSON encoding, Python list identity, spreadsheet
representation, or schema syntax. `List[Object]` and nested structured child
records remain `FTR-NESTED-LISTS` territory and do not use this scalar-composite
hook.

==== 20. Normative-style contract sentences for later promotion

If independently accepted, the following sentences are suitable for later
promotion into normative documentation:

* A framework-managed external entry MUST establish Trusted Domain Payload
  before invoking an ordinary Domain operation.
* Framework-managed means that the fixed application macro flow owns the
  loader, initial Trusted Ingress, final Domain cleanup, persistence
  projection, and saver; it does not mean arbitrary executable code inside the
  flow is framework-validated while it executes.
* A preserving producer MUST accept Trusted Domain Payload and MUST return a
  payload satisfying the same contract; no producer is preserving merely
  because it is built in, registered, or importable.
* A framework-managed flow MUST re-establish Trusted Domain Payload for an
  uncertified producer's returned candidate before any later ordinary Domain
  operation, final cleanup, or persistence.
* `run_pipeline` assumes its caller supplies Trusted Domain Payload and owns all
  preservation or re-establishment between supplied steps; `run_pipeline`
  performs no automatic Trusted Ingress.
* A documented supported direct Domain API states its local input contract and
  is not implicitly covered by framework-managed ingress.
* Arbitrary importable internals carry no framework entry, support, or stability
  guarantee.
* Successful Trusted Ingress establishes payload conformance, not payload
  authorship, pipeline-description authorization, Domain semantic validity, or
  sink safety.
* Operator policy may narrow globally supported payload capability but MUST NOT
  make an unsupported carrier valid.
* A less-trusted pipeline-selected capability MUST be rejected before
  capability activation; payload ingress neither performs nor substitutes for
  that authorization.

==== 21. API-shape implications

API shape follows the contract; it does not determine it.

[cols="3,2,4",options="header"]
|===
|Candidate |Classification |Reason

|One non-addressable Trusted Ingress operation over Frames plus effective
payload policy
|REQUIRED BY CONTRACT
|Framework-managed and explicit programmatic callers need a single semantic
operation that either returns a staged conforming state or raises.

|Carrier-specific dispatch for DataFrame, `ExactTable`, and `_meta`
|REQUIRED BY CONTRACT
|Traversal and diagnostics differ; unknown structural types must not fall into
generic recursion.

|`run_trusted_ingress(frames, *, policy=...)`
|LIKELY IMPLEMENTATION
|A plausible spelling for the required operation. Public export status is not
required by this design.

|Immutable payload-policy/context dataclass
|LIKELY IMPLEMENTATION
|Needed to propagate one effective policy to initial and later
re-establishment passes. Exact fields/transport remain implementation choices.

|Producer classification attached to bound/registered steps
|LIKELY IMPLEMENTATION
|The runner needs a reviewed way to distinguish preserving from uncertified
returns. The mechanism may use registry metadata, an internal wrapper, or
another bounded representation.

|`TrustedIngressResult`
|OPTIONAL
|Useful only if later callers need structured diagnostics/audit metadata;
exceptions plus returned Frames satisfy this contract.

|Public `normalize_scalar()`
|REJECT
|Scalar normalization is not selected; classification and policy admission are
the required primitive.

|Universal recursive sanitizer
|REJECT
|It would collapse cells, metadata, structural carriers, Domain invariants, and

|Public `TrustedFrames` wrapper/token/type state
|REJECT FOR PHASE E
|No evidence justifies reshaping current DataFrame/Frames APIs. Trust epochs and

|Automatic ingress inside `run_pipeline`
|REJECT
|Contradicts its step-only trusted-programmatic role and would hide policy and
ownership.

==== 22. Pydantic disposition

No concrete Phase-E payload use site justifies a Pydantic ADR.

Scalar semantics remain project-owned and already have a bounded classifier.
DataFrame/`ExactTable` traversal is carrier-specific, and the central metadata
promise is a small structural substrate plus feature-owned delegates. Dataclass
or custom validation is sufficient for those contracts. Adopting Pydantic here
would merge payload, metadata, and description errors without solving a
demonstrated problem.

A later description-plane slice may discover a concrete control/config parsing
use site. If it does, it must separately compare existing dataclass/ad-hoc
parsing, Pydantic, and another schema mechanism while keeping payload scalar
semantics and Domain Findings outside that decision. This design neither adopts
nor forbids Pydantic. No ADR stop condition is triggered now.

==== 23. Implementation slice plan (not authorized by this design)

Each slice requires the design to have passed independent review first.

===== E1 -- scalar grammar, payload policy, and safe error primitive

*Scope:* compose the accepted classifier with the narrow payload policy and
define stable failure kinds/location records. No orchestration wiring.

*Preconditions:* accepted Phase-D classifier and this reviewed contract.

*Acceptance criteria:* every accepted carrier/category pair is admitted under
default policy; policy narrows only; every unsupported carrier rejects without
value `repr`/conversion/protocol dispatch; no carrier is normalized.

*Test strategy:* focused unit matrix over six categories, variants, explicit
unsupported temporal/Formula/collection/opaque values, narrowing combinations,
and hostile `repr`/NumPy-protocol probes.

*Exclusions:* DataFrame traversal, metadata, public entry wiring, description
authorization, resource limits.

===== E2 -- Frames/DataFrame/ExactTable structural dispatch and atomic traversal

*Scope:* staged top-level mapping; complete positional DataFrame cells;
`ExactTable` generic self-consistency and data traversal; deterministic paths.

*Preconditions:* E1; compatibility census for current framework-produced
DataFrame axes and exact paths.

*Acceptance criteria:* complete traversal; unknown top-level carriers reject;
failure leaves caller Frames/DataFrames unchanged; no DataFrame deep copy is
required solely for validation; reconstruction invariants stay local.

*Test strategy:* multiple frames/dtypes, late-cell rejection, duplicate/odd axis
compatibility cases, valid/invalid exact geometry, and unchanged-caller-graph
assertions.

*Exclusions:* family semantic checks, grouped reconstruction changes, generic
structured-carrier registry.

===== E3 -- metadata substrate and post-load metadata introduction

*Scope:* `_meta` root contract, owned acyclic substrate, existing Legend Blocks
delegate, bootstrap/override staged validation, and invalid YAML `_meta`
behavior.

*Preconditions:* E1-E2; inventory of current runtime-produced/consumed metadata
node shapes.

*Acceptance criteria:* supported current metadata survives with owned
containers; opaque/cyclic/invalid-root structures reject atomically; Legend
Blocks behavior remains; family semantics are not centralized; no runtime
binding to the manual metadata registry.

*Test strategy:* external workbook/JSON metadata, bootstrap/override candidates,
deep late failure, alias/cycle cases, root-delegate failures, and no partial
publication.

*Exclusions:* Pydantic, all-family semantic schemas, resource ceilings,
persistence projection changes.

===== E4 -- producer contract audit and trust-transition representation

*Scope:* inventory registered built-in Domain/infrastructure producers; mark
only reviewed preserving or affected-state-re-establishing producers; define
uncertified default for plugin/dotted/direct BoundStep forms.

*Preconditions:* E1-E3; accepted step registry/current call-shape evidence.

*Acceptance criteria:* no built-in is trusted by name/registration alone; every
preserving declaration has payload/metadata output tests; unknown/custom forms
remain uncertified; the representation does not make ingress YAML-addressable.

*Test strategy:* registry/BoundStep construction tests and representative
producer-output contract tests, without a broad new architecture guard in this
slice.

*Exclusions:* family hardening, plugin sandboxing, description authorization.

===== E5 -- framework-managed macro wiring

*Scope:* initial ingress and producer-return re-establishment in the macro used
by `sheets-run`, `run_app`, `orchestrate`/shim, and schema maintenance.

*Preconditions:* E1-E4.

*Acceptance criteria:* all six router backend families reach initial ingress;
ordinary Domain does not run after rejection; preserving producers do not
incur universal post-step traversal; uncertified returns do; final cleanup and
save never receive a rejected candidate; effective policy is stable.

*Test strategy:* one focused end-to-end path per materially different carrier
behavior rather than a full Cartesian product; plugin/generic dotted/prebound
replacement probes; schema fixed-step path; ordering and atomic-save tests.

*Exclusions:* changing `run_pipeline` internals, sink policy, parser limits.

===== E6 -- programmatic-surface contract publication

*Scope:* document `run_pipeline`, documented builders, supported lower-level
Domain/backend APIs, and internal/importable-only distinction using the matrix
in section 6.

*Preconditions:* E5 behavior exists and has accepted evidence.

*Acceptance criteria:* library consumers can determine where ingress is
automatic, where Trusted Domain Payload is a caller precondition, and which
surfaces have no promise; no aggregate importability promotion.

*Test strategy:* public import/consumer documentation checks only where already
conventional; no direct-API behavior rewrite.

*Exclusions:* API removal/rename, universal Domain barrel, Maintainer Contract.

===== E7 -- less-trusted description authorization (separate Phase-E sub-slice)

*Scope:* after the dotted-extension architecture assessment, define and
implement operator-owned authorization for the supported declarative surface,
with rejection before import/binding/acquisition.

*Preconditions:* accepted per-surface extension assessment; an independently
reviewed narrow E7 design; operator policy representation for the relevant
capability kinds.

*Acceptance criteria:* supported less-trusted descriptions cannot activate a
forbidden capability; direct Python forms remain trusted-only; all four
payload/description authority combinations remain representable; payload
ingress tests remain independent.

*Test strategy:* import-observation probes, allowlist/parameter-policy
intersection, widening/unknown/contradictory rejection, and paired trusted/
less-trusted payload cases.

*Exclusions:* Python sandboxing, payload scalar changes, filesystem/sink policy
beyond capability kinds explicitly selected by E7.

E1-E6 establish the Trusted Payload contract for trusted-description entries.
E7 is required before any entry advertises safe less-trusted-description
execution; it is not hidden inside E5 merely because current binding precedes
load.

==== 26. Design acceptance criteria

Independent architecture review should accept this design only if it confirms:

. all 15 accepted census questions are answered without being merged;
. the hybrid coverage model is truthful for every named entry surface;
. `run_pipeline`, supported lower-level APIs, and internals have distinct
  contracts;
. successful ingress has a short, testable downstream postcondition;
. scalar grammar matches the accepted six categories and carriers exactly;
. validate-only scalar behavior preserves precision, timezone, and Missing
  representation;
. DataFrame, `ExactTable`, metadata, grouped/canonical carriers, and future
  carriers have distinct ownership/traversal rules;
. custom producer output cannot reach later ordinary macro flow without
  preservation or re-establishment;
. payload and description trust remain independent and capability activation
  cannot precede authorization in any less-trusted-description claim;
. failure is atomic over the candidate payload and diagnostics do not inspect
  rejected values unsafely;
. the bounded-composite seam is useful but chooses no representation;
. implementation slices are individually testable and do not hide a giant FTR;
  and
. no runtime, ADR, Technical Model, Project Memory, guard, D-T3, or family-pilot
  authority is implied by design acceptance alone.

==== 27. Explicit non-decisions

This design does not decide or authorize:

* implementation of any E1-E7 slice;
* a public `normalize_scalar`, `TrustedFrames`, policy class, CLI flag, profile
  name, or exception class spelling;
* normalization to native Python or a canonical Missing carrier;
* a scalar Integer/Float split, Error, Time, Duration, Formula, or composite
  category;
* a `List[Scalar]` carrier, schema, codec, or storage representation;
* broad parser/resource limits;
* a formula-output/sink policy;
* Pydantic;
* removal, renaming, or automatic ingress inside `run_pipeline`;
* forbidding direct Domain/backend composition;
* a new registry or runtime binding to the manual metadata registry;
* general family schema validation in central ingress;
* a guard;
* D-T3, D-T4, a family pilot, or Domain Maintainer Contract content; or
* Technical Model or Project Memory promotion/acceptance.
