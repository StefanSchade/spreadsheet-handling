== Corrected contracts

=== Exact strings

Canonical keys, visible labels, configured frame/field names, and lookup
strings must be exact built-in `str` values and must be non-empty after a
whitespace-only check. `str` subclasses are rejected by exact type before any
overridable `strip`, `repr`, `hash`, equality, or comparison method can run.

Leading/trailing whitespace in an otherwise non-empty exact string remains
part of the value. No normalization, stripping, case folding, delimiter
parsing, or coercion occurs.

Every returned `ResolvedAxisMember` contains exact built-in strings. Derived
forward and inverse maps therefore remain uniquely and safely derivable from
the immutable member tuple.

=== Configured ordering

`SOURCE_ROW` retains the supplied DataFrame row order only when explicitly
selected.

`COLUMNS` uses this deliberately narrow vocabulary:

* exact built-in `str`;
* exact built-in `int`, excluding `bool`;
* exact NumPy integer scalar carriers produced by pandas, copied immediately
  to built-in `int`.

Each configured order column must use one supported type across all rows.
Different configured columns may use different supported types. Floats,
infinities, NaN, booleans, subclasses, mutable values, mixed types within one
column, and arbitrary comparator objects fail with `AxisMappingError`.

Configured columns are compared in declaration order. The exact built-in
canonical key remains the final tie-breaker, so tied configured values are
valid. No caller-owned arbitrary comparison method is invoked.

=== Physical configured-field matching

The shared physical-label boundary still permits unrelated non-string physical
labels when they are non-missing, hashable, uniquely comparable, and
scalar-addressable.

Axis-mapping configured fields are narrower: they match only exact built-in
string physical labels. Matching therefore uses exact built-in string equality
and never unusual-label equality. Missing configured fields and ambiguous
duplicate exact matches fail before positional pandas reads.

=== Direct model construction

`AxisMappingIntent`, `ResolvedAxisMember`, and `ResolvedAxisMapping` enforce
their invariants independently of the resolver:

* configured values and member text use exact built-in strings;
* positions use exact built-in integers and the mapping requires contiguous
  zero-based positions;
* member label tuples must have the declared arity;
* duplicate keys and duplicate complete label tuples fail;
* ordered accepted containers and generators are copied to tuples;
* unordered member containers are rejected;
* members must be exact `ResolvedAxisMember` values;
* lookup validation uses the same exact-string contract.

Frozen dataclasses, exact immutable leaf values, tuples, private copied
containers, and mapping proxies now provide effective immutability. Excluding
derived lookup maps from equality is sound because validated members uniquely
determine both maps.

== Finding disposition

I-1 -- unsafe configured ordering domain:: Closed.
The resolver no longer observes arbitrary comparison behavior or tries to
infer totality from repeated sorting. It rejects cyclic, asymmetric,
non-transitive, stateful, and exception-raising comparator objects by exact
type before invoking `<`. Homogeneous exact string/integer columns sort by
built-in total comparisons, followed by exact canonical key.

I-2 -- unusual physical labels impersonate configured fields:: Closed.
Configured fields now match only physical labels whose type is exactly `str`.
The equal-to-every-string probe no longer satisfies either missing configured
field, and its equality implementation is not called for configured matching.

I-3 -- hostile or mutable `str` subclasses:: Closed.
Every model, source, used-key, and lookup text boundary rejects subclasses
before hostile `strip`, `repr`, or `hash` can run. Resolutions contain exact
built-in strings only; mutating a rejected subclass cannot alter Resolution
iteration, equality, hashing, or either lookup.

I-4 -- missing adversarial tests:: Closed.
The focused suite increased from 64 to 94 tests. Thirty separately runnable
adversarial/direct-model tests cover all requested comparator families,
unsupported and mixed order types, canonical-key tie-breaking, physical
aliases, hostile string methods, mutable hash state, direct construction,
both lookup directions, copied containers, derived-map equality, caller graph
state, and exception classification.

M-1 -- over-broad physical-label exception translation:: Closed.
The resolver catches only the shared helper's documented `ValueError`.
A simulated `AssertionError` now propagates unchanged instead of being
relabelled as `AxisMappingError`. `KeyboardInterrupt` and `SystemExit` remain
outside that catch as well.

== Adversarial, atomicity, and immutability evidence

The cyclic, asymmetric, non-transitive, stateful, and exception-raising
objects each expose an instrumented `<`. Every probe failed with
`AxisMappingError` while its comparison count remained zero. The stateful
probe also retained the same source DataFrame, Frames entries, `_meta` object,
and nested metadata value.

The physical alias records comparisons against exact strings. A frame with
only that unusual label failed for missing `key` and `label`, with zero
string-comparison calls.

Hostile `str` subclasses instrument `strip`, `repr`, and `hash`. Direct model
construction, source validation, used-key validation, and both lookup
directions rejected them with `AxisMappingError` and zero hostile-method
calls. Exact-string lookup remained correct after caller-side mutation of the
rejected mutable-hash objects.

Direct construction tests also prove that mutating caller-owned lists after
construction does not change a Resolution and that generators are materialized
once into a private tuple.

The resolver contains no assignment into the Frames mapping, source DataFrame,
index, columns, `_meta`, or nested caller objects on success or failure.
