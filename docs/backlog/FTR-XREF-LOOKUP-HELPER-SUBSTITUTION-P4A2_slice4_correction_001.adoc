== 5. Setup/install root cause

`make setup` itself ends editable: `$(DEV_STAMP)` runs
`pip_install_spec.sh -s '.[dev]' -E` last. The defect is that a *separate*
maintained target reinstalls the package non-editable and clobbers it:

`registries`/`Makefile` `$(DOMAIN_CONTRACTS_STAMP)` (target
`domain-contracts-setup`, an order-only dependant of `$(DEV_STAMP)`) ran:

[source,make]
----
@tools/pip_install_spec.sh -p "$(PYTHON)" -s . $(PIP_VERBOSE_FLAG)   # non-editable
----

Running any `domain-contracts-*` target after `make setup` (Slice 4 ran
`make domain-contracts-check`) therefore reinstalled a *copied* package tree over
the editable install. Because setuptools-scm's dirty-tree local version does not
change with working-tree content, the copied tree carried a build made while the
module still existed, so the deleted `project_by_role.py` reappeared in
site-packages and its `RECORD`. `tools/pip_install_spec.sh` is not at fault: it
honours `-E` correctly; the divergent caller was the domain-contracts stamp
(`memory-setup`, by contrast, already used `-s '.[project-memory]' -E`). The pip
wheel cache was empty, confirming the copy came from the clobbering non-editable
install, not a cached wheel.

== 6. Supported-workflow correction

Smallest correction at the true ownership point: make `domain-contracts-setup`
editable, matching `$(DEV_STAMP)` and `memory-setup`:

[source,make]
----
# Editable, matching $(DEV_STAMP) / memory-setup. A non-editable `-s .`
# here reinstalls a copied package tree over the editable dev install,
# which can resurrect source files deleted since the last build (see
# FTR-XREF-LOOKUP-HELPER-SUBSTITUTION-P4A2 Slice 4 Correction 001).
@tools/pip_install_spec.sh -p "$(PYTHON)" -s '.[dev]' -E $(PIP_VERBOSE_FLAG)
----

No general environment-management redesign was needed. `make setup` remains the
documented setup path; `make clean-stamps && make setup` remains the documented
refresh; the domain-contracts optional-tooling setup no longer downgrades it.
