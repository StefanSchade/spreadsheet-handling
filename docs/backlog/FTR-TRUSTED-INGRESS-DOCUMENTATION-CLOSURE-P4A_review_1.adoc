== Findings

=== R1 -- Blocking -- authoritative roadmap retains stale current lifecycle statements

*Observation:* The same active roadmap that declares the documentation gate
closed still says that documentation condensation/review/archival is the exact
next action, that E7 is unstarted and Phase E open, and that documentation
closure is the remaining gate.

*Evidence:* Current statements remain at
`docs/backlog/roadmap_domain_hardening_sequence.adoc` lines 435-439, 539-540,
636-640, 691-695, and 1395-1399, while lines 338-344, 644-672, and 1414-1429
state closure complete and the Domain Maintainer Contract next.

*Risk:* A maintainer or agent can follow the active roadmap and either repeat a
completed closure workstream or conclude that Phase E remains open. The
roadmap is therefore not a reliable lifecycle authority, and the next-stage
gate cannot be declared independently verified.

*Recommended action:* Curate every operative Phase-E/closure/sequence statement
to the same present state: Phase E and documentation closure complete; Domain
Maintainer Contract next and not started; Phase F / first family pilot only
after that contract; D-T3 merely a candidate. Preserve history only where it is
explicitly labelled historical.

=== R2 -- Important -- Project Evolution over-authorizes later stages

*Observation:* The new Phase-E paragraph says closure removed the block from
the Domain Maintainer Contract, Phase F, and D-T3 and that "those stages are
now authorized to begin."

*Evidence:* `docs/developer_guide/ch10_project_evolution/01_project_evolution.adoc`
lines 1194-1197. This conflicts with the governing sequence in
`ARCHIVE-DECISION-1` section 9/12 and with the corrected roadmap headline:
Domain Maintainer Contract -> Phase F / first family pilot -> D-T3 candidate.

*Risk:* Phase F or D-T3 can be started while the Domain Maintainer Contract is
still absent, bypassing the sequencing gate this closure was required to
preserve.

*Recommended action:* State that documentation closure unblocks the *next*
authorized stage, the Domain Maintainer Contract. Keep Phase F and D-T3 gated
behind that stage.

=== R3 -- Important -- new condensation delivery record points to a vanished path

*Observation:* Section 11 was newly authored as the current delivery record,
but its exact `ARCHIVE-DECISION-1` pointer uses the pre-move backlog path.

*Evidence:*
`docs/cold_storage/backlog/ftrs_done/FTR-TRUSTED-INGRESS-DOCUMENTATION-CONDENSATION-P4A.adoc`
line 346 names
`docs/backlog/FTR-TRUSTED-INGRESS-DOCUMENTATION-CONDENSATION-P4A_archival_decision.adoc`;
that path does not exist. The artifact is at the corresponding
`docs/cold_storage/backlog/ftrs_done/` path.

*Risk:* The final delivery record's governing-decision lookup fails at the
point intended to preserve traceability after archival.

*Recommended action:* Correct this newly added current pointer to the archived
path. Do not rewrite frozen historical path statements elsewhere merely
because they describe their original location.

=== R4 -- Important -- canonical current fields remain contradictory and uncondensed

*Observation:* The canonical Trusted-Ingress FTR `summary` still says "Phase E
remains Open" and calls E7 the current unstarted slice before later saying E7
and Phase E are complete. Its `implementation_notes` begins "E7 remains
unstarted; Phase E is not complete" and later says closure complete. The
active concern's `notes` likewise calls E7 the current unstarted slice before
recording it complete. The concern's current summary is 4,406 characters and
notes 8,291 characters.

*Evidence:* `project_memory/canonical/ftrs.json` lines 5976 and 5983;
`project_memory/canonical/concerns.json` line 117. This also misses
`ARCHIVE-DECISION-1` section 9's explicit requirement that Project Memory
become a concise orientation/lifecycle index, not a restatement of the FTR
construction narrative. The contradictions surface through generated context
and canonical queries even though posture and `next_action` are correct.

*Risk:* Consumers of canonical current-state fields receive mutually exclusive
lifecycle instructions and a replay of construction history rather than a
reliable orientation record.

*Recommended action:* Condense the affected current fields around accepted
current truth, permanent-owner pointers, archive location, independent
exclusions/debt, and the Domain Maintainer Contract next-stage statement.
Leave chronological history in the event stream and archived evidence.
