== 5. Declaration-completeness guard

`tests/test_dino_insel_matrix_helper_migration.py` adds the mandatory
consumer-owned static guard (`DeclarationCompletenessGuardTest`). It parses the
forward pipeline through the same `yaml.safe_load` on the `pipeline` key that
`build_steps_from_yaml` uses (no re-implemented parser), locates the single
`configure_workbook_view` step, and for each of the five surfaces asserts:

* the expected visible sheet is declared;
* it maps to the expected logical frame;
* its `helper_columns` is exactly `[title]`.

`test_guard_fails_when_a_declaration_is_omitted` proves the guard fails on an
omitted declaration, a misspelled helper (`titel`), and a missing visible sheet
(hard `KeyError`, not a silent empty list). Helper identity is read from
configuration, never inferred from runtime DataFrame columns.

== 6. Outbound migration per surface

Each `join_frames(+title)` + `project_by_role(outbound)` pair was replaced by a
single `add_lookup_helpers` writing the same `<matrix>_view` output frame:

[source,yaml]
----
- step: add_lookup_helpers
  source: <pre-view matrix>
  lookup: stories
  output: <matrix>_view
  source_key: story_id
  lookup_key: id
  helpers:
    fields: [title]
  order:
    helper_position: before_key
  missing: empty
----

Value mode defaults to `values` (literal), matching the former `join_frames`
literal title. Verified per surface (section 14):

* `title` placed before `story_id`;
* `story_id` remains authoritative; lookup key `id` does not leak;
* dynamic columns keep their `contract_xref` order; no static list introduced;
* `missing: empty` matches the former left-join-with-blank-fill;
* `stories.title` unchanged;
* the generated Workbook View sheet still declares `helper_columns: [title]`.

Exactly one owner (`add_lookup_helpers`) performs helper insertion per surface;
no `project_by_role` remains adjacent as a fallback.

== 7. Inbound migration per surface

The five inbound `project_by_role` steps were removed. Cleanup + postcondition
were inserted at the top of the reverse pipeline, *before*
`apply_workbook_view_sheet_mappings`, addressing the *visible* sheet name:

[source,yaml]
----
- step: apply_derived_column_policy
  source: <visible sheet name>
  policy: drop
# ... five drops (Story Groups, Cast Roles, Cast Notes, Cast Development, Cast Crystals) ...

- step: validate_references
  mode: fail
  rules:
    - { type: no_helper_columns, frame: Story Groups }
    - { type: no_helper_columns, frame: Cast Roles }
    - { type: no_helper_columns, frame: Cast Notes }
    - { type: no_helper_columns, frame: Cast Development }
    - { type: no_helper_columns, frame: Cast Crystals }
----

Cleanup addresses the visible sheet name (durable carrier addressable there),
occurs before mapping, and the five explicit `no_helper_columns` rules give
per-surface diagnostics. The existing inverses (four `expand_xref`, one
`expand_compact_multiaxis`) run unchanged on the mapped logical frames and
receive `[story_id, <dynamic>]` — no `title`.

== 23. Complexity / readability assessment

Before, `project_by_role` implicitly combined helper identification, placement/
removal, role interpretation, and dynamic ordering. After, each concern has one
explicit owner: `add_lookup_helpers` (outbound insertion + placement),
`apply_derived_column_policy` (declaration-driven removal), `validate_references`
(`no_helper_columns` postcondition), `apply_workbook_view_sheet_mappings`
(identity), and the existing inverses (recomposition).

Line delta: forward config net roughly balanced (one `add_lookup_helpers`
replaces one `join_frames` + one `project_by_role`; added lines are mostly
explanatory comments). Reverse config grows by the five explicit drops and the
five-rule postcondition, which is the intended defense-in-depth and the reason
ownership and sequencing are now legible. Behavior ownership is clearer;
sequencing (cleanup by visible name before mapping) is explicit and documented.
Declarations are not excessively duplicated — the five surfaces are genuinely
distinct visible identities, and per-surface `no_helper_columns` rules improve
diagnostics. No macro/abstraction was introduced: explicit repetition across
five sheets is preferable here because the visible identities and per-surface
diagnostics matter.
