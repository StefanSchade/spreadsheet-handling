== Shared-resolver assessment

`pipeline.dotted_paths.resolve_configuration_callable` is the one function
that owns the complete configuration-derived string-to-callable sequence:

. parse and validate `module:function` or `module.function`;
. apply the configuration-addressability ownership rule;
. import the module;
. resolve the named attribute; and
. validate callability.

All maintained consumers converge:

* `make_plugin_step(dotted=...)` delegates directly;
* `resolve_registration(step_id)` delegates for direct colon-style factories;
* `_resolve_target(target)` delegates for a string target;
* both `make_frames_target_step` and `make_builder_target_step` use
  `_resolve_target`; and
* registry-owned `StepRegistration.target` strings are injected by
  `build_steps_from_config` into those same generic binders.

`build_steps_from_config` binds registrations but performs no import/getattr.
`StepRegistration` and `StepTarget` are carriers, not resolvers. The former
duplicate import/getattr logic is absent from `steps.py` and `registry.py`.
`ensure_configuration_addressable` remains a check-only helper over the same
parser and ownership data; it does not import or resolve a callable and is not
a competing resolver.

The implementation therefore satisfies the shared-resolver architecture.
M-1 concerns the future completeness of one static guard, not current
convergence.
