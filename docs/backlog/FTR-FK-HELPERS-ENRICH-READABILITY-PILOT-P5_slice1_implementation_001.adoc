== 9. Implementation alternatives considered

* *Form A — explicit resolved scalar locals at one commented boundary.* Two
  active-path scalars (`levels`, `helper_value_mode`) resolved together with a
  clear comment; enable gate named and kept first.
* *Form B — a private `_resolve_execution_options(defaults)` helper returning a
  tuple.* Adds a concept and passes the whole bag into a helper for only two
  reads; hides the reads behind a call.
* *Form C — a small immutable options value object.* For two scalars this adds
  conceptual overhead with no lifecycle-visibility gain; the FTR warns against
  defaulting to a value object.

== 10. Selected form and rationale

*Form A* was chosen. With only two active-path scalars, explicit resolved
locals win on _number of concepts introduced_ (zero new helpers/types) and
_call-site clarity_, while still making the raw→resolved boundary visible via a
comment that names exactly the three consumed keys. No value object, no resolver
helper, no framework. The one function that genuinely performs normalization and
validation (`_helper_value_mode`) was narrowed and renamed rather than expanded.

The public parameter `defaults` was *kept* (it is the re-exported,
meta-registry-referenced callable, always called positionally at
`pipeline/steps.py:156` and in tests; no keyword callers). A redundant
`raw_options` local alias was considered and rejected as noise; the boundary
comment supplies the "raw authored config" signal instead.

== 19. Error-order / lazy-resolution assessment

The central risk of "resolve configuration once" was changing lazy validation or
error precedence. It was avoided:

* the `detect_fk` enable gate stays *before* relation resolution, so
  `detect_fk: false` still returns `frames` by identity even when policy is
  missing (no missing-policy raise on the disabled path);
* `levels` (`int(...)`) and `helper_value_mode` (`_normalize_helper_value_mode`)
  stay *after* the missing-policy raise, so they are still never evaluated on the
  disabled path or the missing-policy path — an invalid `levels`/mode does not
  raise ahead of `MissingFkRelationPolicyError`;
* `int()` conversion timing, default timing, and mode-normalization timing are
  unchanged; the mode default merely moved from inside the helper to the call
  site with an identical resolved result.

No output or exception drift is introduced.
