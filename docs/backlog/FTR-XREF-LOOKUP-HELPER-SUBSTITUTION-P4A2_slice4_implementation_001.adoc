== 18. Deliberate compatibility impact

This is a deliberate, gated public-step removal.

* `project_by_role` was a gated YAML surface
  (`interfaces_and_gates.adoc`) introduced by
  `FTR-DYNAMIC-FRAME-PROJECTION-IMPL-P5`. The parent FTR selects removal after
  consumer migration, so the gate is satisfied by the accepted FTR.
* The project is pre-beta (`v0.2.x`); per `interfaces_and_gates.adoc`, misleading
  or superseded historical surfaces may be removed once the developer accepts
  the breaking change. No repository-wide compatibility policy requires a
  deprecation wrapper or a fixed external deprecation period, so none was added.
* External impact: any external pipeline configuring `step: project_by_role`
  now fails with the normal unknown-step diagnostic and must migrate to the
  explicit lookup/helper composition (outbound `add_lookup_helpers` with
  `helper_position: before_key`; inbound `apply_derived_column_policy(policy:
  drop)` bound to the durable helper carrier before the XRef inverse).
* Release-note requirement satisfied by the new current entry.

No stop condition applies; the removal is safe inside the repository.
