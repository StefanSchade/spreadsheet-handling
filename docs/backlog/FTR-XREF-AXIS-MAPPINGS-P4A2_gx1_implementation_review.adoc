== Conformance to the GX-1 confirmation contract

=== Model (questions 1-3)

* `GroupedHeaderError(ValueError)`; `RowKeyColumn(label, position)`,
  `DynamicColumn(labels, position)`, and
  `GroupedHeader(level_names, columns)` are all `@dataclass(frozen=True)`.
* Exact built-in values: strings validated with `type(value) is str` and
  non-empty; `labels` required to be an exact `tuple`; `position` required
  `type(value) is int` and non-negative.
* Immutable, hashable, value-equal: verified by
  `test_model_is_frozen_and_hashable_with_value_equality`
  (`FrozenInstanceError` on assignment; equal descriptors share a hash and
  collapse in a set).
* Caller-sequence ownership: `level_names` and `columns` are copied into owned
  tuples in `__post_init__`; `test_model_copies_caller_sequences_into_owned_tuples`
  mutates the caller lists after construction and proves the descriptor is
  unchanged.
* Contiguous positions (`position == index`), fixed dynamic arity
  (`len(labels) == len(level_names)`), non-empty and unique level names
  (`ensure_unique_field_declaration` reused), rejection of foreign column
  types -- all validated in `GroupedHeader.__post_init__` and covered by the
  model tests.
* *DataFrame kept separate from the descriptor*: no value object holds a
  DataFrame. *Canonical dynamic keys are not stored in the descriptor*;
  `DynamicColumn` carries only the visible `labels` tuple and its `position`.

=== Forward `build_grouped_header` (question 4, 6, 7)

* Consumes an already-resolved `ResolvedAxisMapping`; never calls
  `resolve_axis_mapping` (verified by import inspection and by the tests
  constructing the mapping themselves).
* Validates a flat physical DataFrame boundary: rejects non-DataFrame input, a
  `MultiIndex`, tuple-valued physical labels, and duplicate physical columns.
* Normalizes a bare-string `row_keys` to one declared key; rejects empty and
  duplicate row-key declarations; rejects missing declared row keys with a
  `GroupedHeaderError` *before* any dynamic resolution (safe presence precheck
  over exact-string labels).
* Classifies declared row-key columns explicitly and every other column as
  dynamic; *row-key classification takes precedence* over a would-be dynamic
  key (`test_forward_row_key_precedence_over_would_be_dynamic_key`).
* Resolves each dynamic canonical string header through `labels_for_key`
  (resolver-owned `AxisMappingError` on unknown keys).
* Defaults `level_names` to `mapping.label_columns`; rejects wrong-length level
  names; empty/duplicate level names are rejected by the model.
* Preserves physical column order and position; does not mutate or transform the
  DataFrame (`test_forward_does_not_mutate_frame_or_row_keys`); builds the full
  descriptor before returning.
* The grouped representation is the original flat canonical-string frame plus the
  descriptor only -- no temporary tuple columns, no `MultiIndex`, no delimiter
  string is ever produced.

=== Inverse `restore_flat_matrix` (question 5, 6)

* Treats the descriptor as the authoritative visible-header identity source; it
  ignores the frame's own column labels for identity.
* Validates descriptor/DataFrame column-count consistency (positions are already
  contiguous by model construction).
* Keeps each `RowKeyColumn.label`; restores each `DynamicColumn.labels` through
  `key_for_labels` (resolver-owned rejection of unknown, malformed, incomplete,
  and wrong-arity tuples); rejects duplicate restored canonical headers
  (covers duplicate complete tuples and row-key/dynamic collisions).
* Returns a *new* DataFrame (`frame.copy()` then positional relabel), preserving
  data, index, row order, and physical column order; never mutates the input
  (`test_inverse_does_not_mutate_input_frame`); builds the complete
  output-column sequence before creating the result.

=== Exactness

`test_exact_roundtrip_preserves_data_index_and_order` and
`test_roundtrip_independent_of_order_policy` prove
`flat -> build_grouped_header -> restore_flat_matrix -> flat` reproduces the
exact flat canonical matrix (`DataFrame.equals`, exact column order, exact
non-monotonic index) under both `source_row` and `columns` resolver order
policies. Arity 2 and arity 3, repeated upper-level labels with distinct complete
tuples, and literal `" / "` / `"."` inside components all round-trip unchanged.

== Model immutability, ownership, atomicity, safe diagnostics

* *No caller DataFrame mutation*: forward reads only; inverse copies. Proven by
  the two non-mutation tests and by a post-return mutation of the inverse result
  leaving the input frame unchanged.
* *No caller-container mutation*: `row_keys` and `level_names` are read and
  copied; the ownership test confirms.
* *Exact owned built-in values, frozen value objects*: see model section.
* *Build-then-return atomicity*: the descriptor / output frame is fully built
  before return; `test_inverse_atomic_on_failure` shows a mid-sequence resolver
  rejection leaves the input frame untouched and returns no frame. GX-1 writes no
  Frames mapping and no `_meta`, so its atomicity scope is exactly the returned
  descriptor / DataFrame.
* *Safe diagnostics*: type checks use `type(...) is ...`; rejected values are
  described with the constant `"unsupported value type"` detail and never have
  their `repr`/`eq`/`hash`/iteration invoked for reporting.
  `test_forward_safe_diagnostics_with_explosive_header` and
  `test_explosive_object_is_never_compared_during_forward` use an
  `_ExplosiveEquality` fixture (its `__eq__`/`__repr__` raise) and confirm a
  clean `GroupedHeaderError` without triggering the hostile methods. No
  in-process sandbox simulation is attempted (DBR level 4 stays out of scope).
* *Reuse, not duplication*: `ResolvedAxisMapping`, `AxisMappingError` (for
  resolver-owned lookups), and `domain.tabular.ensure_unique_field_declaration`
  are reused; the Slice 1 bijection is not re-implemented.

== Deviations from the confirmation contract

None material. One clarification of an ordering detail, consistent with the
contract: the *missing declared row-key* check runs as a safe presence precheck

requires) rather than falling through to an `AxisMappingError` from
`labels_for_key`. This preserves the intended forward diagnostic ownership and
adds no new behaviour.
