== Verdict

*GX-2 is accepted.* Correction commit `bc21216` closes exactly the three
findings from GX-2 acceptance review 001 (`95dbdda`) with bounded, understandable
mechanisms and introduces no regression, protected-surface change, or new public
defect:

* `GX2-A-B1` -- silent frame/header mispairing is closed. Raw `GroupedMatrix`
  construction now fails deliberately; the exported
  `grouped_matrix_from_canonical` factory and the inverse both re-derive the exact
  GX-1 descriptor from the current canonical flat frame under the one live mapping
  and require exact descriptor equality before construction/restoration. The
  original `k1=A1,k2=A2 -> k1=A2,k2=A1` swap is no longer representable through any
  public path.
* `GX2-A-I1` -- one-shot `row_keys` iterables are owned exactly once at composite
  ingress as a single tuple that is reused by every downstream consumer; the false
  missing-used-keys failure no longer occurs, and XRef/GX-1 retain all semantic
  validation.
* `GX2-A-I2` -- the ambiguous grouped target `name` parameter is removed and
  replaced by `xref_config_id`. Direct Python and YAML both select XRef metadata
  identity through `xref_config_id`; YAML `name` is only the builder-owned step
  name. Two matching metadata entries are now publicly disambiguatable.

The correction stays within the provisional GX-2 surface. Accepted XRef, Slice 1
resolver, Slice 2, GX-1, and the merged grouped-XRef architecture are unchanged
and not reopened. GX-2 is accepted in review 002; the owning FTR stays open and
GX-3..GX-5 remain pending and unstarted.

== B1 reproducer result

The acceptance-review-001 reproducer was independently reconstructed against the
corrected code:

* direct `GroupedMatrix(frame=..., header=...)` raises `GroupedXrefError`
  naming `grouped_matrix_from_canonical`; no ordinary public constructor produces
  a carrier;
* the public factory rejects reordered dynamic columns, a moved row-key column,
  an unrelated same-width canonical frame, a stale descriptor after a live mapping
  label change, an altered/unknown canonical header (`AxisMappingError`), and a
  `MultiIndex` (`GroupedHeaderError`), all with `pairing does not match` /
  domain-owned diagnostics before canonical expansion;
* valid cell-value edits with an unchanged schema remain supported;
* the concrete corruption vector -- relabelling a valid carrier's DataFrame
  columns in place to a reordered canonical sequence and driving the inverse --
  now raises `GroupedXrefError("... pairing does not match ...")` *before*
  `expand_xref`, leaving the caller Frames without `rel_out` or `_meta`.

No value swap or silent canonical-identity corruption survived any probe.

== Carrier and factory assessment

`GroupedMatrix` remains `@dataclass(frozen=True, eq=False, init=False)` over
exactly `frame` and `header`. Its `__init__` rejects every direct call without
inspecting arguments; `_from_validated_pair` is feature-private, unexported, and
allocates via `object.__new__`/`object.__setattr__` only after validation.
Reference-freeze, identity equality, and identity hash remain honest; the
DataFrame is neither copied nor claimed immutable.

`grouped_matrix_from_canonical(frame, header, *, mapping)` is the single exported
construction seam. `_validate_canonical_pair` requires a DataFrame and exact
`GroupedHeader`, extracts row-key labels in physical order from the descriptor's
`RowKeyColumn` entries, calls accepted GX-1 `build_grouped_header` on the current
canonical frame with the supplied `ResolvedAxisMapping` and carried level names,
and requires exact descriptor equality. Malformed canonical frames/mappings
retain GX-1/resolver ownership; GX-2 owns only the deliberate `GroupedXrefError`
for two individually valid values that do not form the same exact pair. No stored
snapshot, content hash, fingerprint, object token, sidecar, `_meta`, persisted
mapping, or `MultiIndex` is introduced.

== Semantic-pair validation assessment

The chosen exact re-derivation proves the pairing relation the inverse depends
on. `restore_flat_matrix` relabels by descriptor position through
`key_for_labels`. Descriptor equality forces, at every position, that the current
physical canonical header resolves under the live mapping to exactly the carried
visible tuple (or that a row key sits at exactly its carried label/position).
Given the accepted Slice 1 resolver bijection, restoration then reproduces the
exact current physical column identities, so no value can be assigned to a
different key. The proof is contingent only on the already-accepted resolver
inverse property.

It detects dynamic-column reorder, row-key movement, stale mapping/header
pairing, altered physical labels, post-construction column mutation, and
unsupported `MultiIndex`. A different DataFrame with the *same exact canonical
schema, physical order, and live mapping* but different cell values is correctly
accepted: canonical headers still bind values to exact keys, and workbook cell
editing must remain possible. The contract deliberately does not demand row/data
provenance or cell immutability.

== Future GX-3/GX-4 seam

`grouped_matrix_from_canonical` is a coherent future construction seam: it accepts
a flat canonical-string-headed DataFrame, an exact `GroupedHeader`, and an
already-resolved mapping; it persists no mapping, fingerprint, or schema snapshot,
creates no `_meta` or sidecar, and performs no workbook parsing. The documented
readback flow (visible tuples -> live mapping -> canonical flat headers ->
factory -> `GroupedMatrix`) is viable and cannot bypass pairing validation. This
review confirms only that GX-2 provides a sound domain seam; no GX-3
implementation is required or begun.

== Inverse and atomicity assessment

`expand_grouped_xref` resolves the mapping exactly once, revalidates the current
carrier pair before `restore_flat_matrix`, publishes no private frame, and on
pair failure writes no canonical output, XRef metadata, or cleanup command and
does not mutate caller Frames, caller `_meta`, or carrier cell data. Independent
mutation probes (reorder columns, move row key, alter header, assign
`MultiIndex`) all failed before the wrapped `expand_xref`. With `drop_source=
False` the original carrier is restored under `matrix`; with `drop_source=True`
the carrier remains for final cleanup. A spy confirmed one resolver call and no
`used_keys` on the inverse.

== Row-key ownership assessment

`_owned_row_keys` normalizes container lifetime only: a bare string becomes a
one-element tuple; list/tuple/other iterables become one owned tuple; a one-shot
iterable is consumed exactly once; `bytes`/`bytearray`/non-iterable fail safely
with constant-shape guidance. Independent probes with a bare string, list, tuple,
a two-key one-shot generator, and an iterator that raises on a second iteration
confirmed: the caller iterable is consumed once; the *same* owned tuple object
reaches `contract_xref`, dynamic-header classification, and GX-1; forward
`used_keys` is exactly the physical-order dynamic headers excluding both row keys;
and the resolver runs once. Inverse one-shot iterables succeed with the owned
tuple reaching unchanged `expand_xref`. Semantic validation (duplicate/empty/
non-string/missing) remains XRef/GX-1-owned: a duplicate one-shot declaration
still raises the XRef `row_keys contains duplicate field(s)` diagnostic, not a
grouped fork.

== xref_config_id assessment

Both composites expose `xref_config_id: str | None = None`; the target `name`
parameter no longer exists in either signature; all other parameters/defaults are
unchanged. Direct probes confirmed forward `xref_config_id="wanted"` writes/selects
XRef metadata under `wanted`, inverse uses it to select the intended entry, and
invalid/empty IDs (`" "`, `""`, `1`) raise `GroupedXrefError` naming the field.
Direct `name=` now raises `TypeError` (removed parameter). Through public
`build_steps_from_config` + `run_pipeline`, YAML `name` becomes only
`BoundStep.name`, `xref_config_id` remains in target kwargs and reaches XRef as
its `name=`, and two matching metadata entries are disambiguated by
`xref_config_id`. Registry notes, user guide, release note, and runtime
docstrings consistently distinguish YAML `name` (step/log name) from
`xref_config_id` (XRef metadata identity) and direct-Python `xref_config_id`.
No active claim that grouped target `name` is forwarded remains; the historical
confirmation and original self-review carry prominent supersession banners.

== Normal-regression assessment

The accepted-positive behavior is intact: forward publishes one `GroupedMatrix`
with canonical-string headers and no private frame; inverse restores the exact
dense canonical relation; arity 2 and 3, repeated upper labels, literal delimiter
components, both order policies, mapping completeness, mapping-drift rejection,
`base_relation` scoping, `value_columns`, `drop_source` cleanup marking, and
XRef-owned metadata all behave as accepted. Sparse densification remains inherited
from XRef. No mapping, descriptor, header depth, or fingerprint is persisted and
no grouped `_meta` root appears.

== Mapping-resolution count

Exactly one `resolve_axis_mapping` call occurs per grouped composite invocation
in each direction (spy-verified). The factory calls `build_grouped_header` a
second time purely to prove the pair; it does not resolve again, call XRef twice,
persist the mapping, or introduce a second output. This extra pure header
re-derivation is implementation cost, not a defect.

== Errors and robustness

Direct carrier construction failure and valid-but-mispaired pairs raise
`GroupedXrefError`; malformed canonical frame/header inputs retain
`GroupedHeaderError`; unknown/altered canonical headers retain `AxisMappingError`;
XRef failures remain XRef-owned. Supported malformed public inputs did not leak
raw `KeyError`, pandas errors, or accidental `TypeError` (the only `TypeError`
observed is the deliberate removal of the `name` keyword). Diagnostics do not
inspect rejected values unnecessarily. The correction does not expand the threat
model beyond the documented competent-user boundary.
