= GX-5 Confirmation 001: Grouped-XRef Adoption and Public Render Reachability
:revdate: 2026-08-01
:toc:

Delta-only confirmation against current `HEAD` `253171e`, the full owning FTR,
GX-3b acceptance commit `909de2e`, and GX-4 acceptance commit `b844551`.
GX-1..GX-4 are accepted foundations and are not reopened. This confirmation is
documentation-only; no runtime, tests, registry, Project Memory, branch, or
sibling repository was changed.

== Verdict

*GX-5 is ready for implementation.* The accepted carrier works from a
`GroupedMatrix` passed directly to `build_spreadsheet_render_plan`, through
`compose_workbook`, `WorkbookIR`, `RenderPlan`, and both concrete renderers. The
remaining gap is earlier and smaller: the public router savers and explicit
Workbook View selection still admit only `DataFrame`, while Workbook View
readback counts only `DataFrame` values as visible sheets and therefore excludes
the accepted `ExactTable` read carrier.

Four bounded runtime edits make the already-accepted path publicly reachable.
One configured XLSX/ODS roundtrip then supplies the GX-5 adoption evidence. A
new grouped-view wrapper is not justified: the public chain is already explicit,
short, and config-addressable once these carrier gates admit the accepted types.

== Baseline and confirmed gap

[cols="2,4,3",options="header"]
|===
| Boundary | Current evidence | GX-5 disposition

| Frames -> public output
| `orchestrate -> router.get_saver -> save_xlsx/save_ods`; both savers call
  `_ensure_dataframe` for every non-reserved value. A real `GroupedMatrix`
  raises `ValueError: DataFrame constructor not properly called!` in both.
| Preserve an exact `GroupedMatrix` instead of coercing it; retain existing
  coercion for every other value.

| Explicit Workbook View
| `configure_workbook_view` rejects the carrier at `workbook_views.py:115-116`;
  `select_render_frames` independently rejects it at
  `frame_selection.py:57-60`.
| Admit the already-public `GroupedMatrix` carrier for sheet selection,
  ordering, and renaming. Do not broaden arbitrary Frames values.

| Accepted render path
| Direct probe produced 18 render operations. `compose_workbook` dispatches at
  `layout_composer.py:320-327`, projects through `grouped_matrix_to_exact_table`,
  and emits authoritative `TableBlock.header_grid`; `flow.build_render_plan`
  uses the accepted exact-grid branch. GX-3b/GX-4 integration tests render real
  XLSX/ODS successfully.
| No composer, IR, pass, render-plan, XLSX renderer, ODS renderer, or grouped
  projection change.

| Public readback
| Both backend option seams produce `ExactTable` under configured
  `exact_header_depths`, but `_normalize_visible_sheet_names` at
  `workbook_views.py:317-327` counts only `DataFrame`. A mapped exact sheet is
  consequently reported missing.
| Count only the two generic workbook projection results -- `DataFrame` and
  `core.ExactTable` -- as visible sheets. Re-keying itself already preserves the
  value unchanged.
|===

The existing GX-3b/GX-4 roundtrip tests bypass the two public gaps by calling
`build_spreadsheet_render_plan`/concrete renderers directly and by not using an
explicit Workbook View. They prove the accepted inner path, not public
`orchestrate`/router reachability.

== Reachability matrix at current HEAD

[cols="3,3,4",options="header"]
|===
| Entry/mode | Actual support now | GX-5 requirement

| Direct plan, no `workbook_view`
| *Supported.* Mixed `DataFrame` + `GroupedMatrix` renders in Frames insertion
  order; reserved values are skipped and unrelated unsupported values are
  ignored by the established composer policy.
| Preserve exactly.

| Direct plan, `workbook_view` mapping without `sheets`
| *Supported.* It is deliberately equivalent to no explicit selection: the
  mixed values render in Frames insertion order.
| Preserve exactly; no inference from other view keys.

| Direct plan, explicit `workbook_view.sheets`
| *DataFrame-only.* DataFrame entries support authoritative include/exclude,
  declaration order, and rename. Selecting a `GroupedMatrix` fails before
  composition; an explicit mixed list fails as a whole when its grouped entry
  is reached.
| Apply the same authoritative selection semantics to both accepted forward
  types. No partial plan/output is published on failure.

| Direct backend classes
| *Supported.* `ExcelBackend.write_multi` and `OdsBackend.write_multi` write a
  mixed ordinary/grouped workbook when no explicit grouped selection is used.
| Preserve exactly; these are the GX-3b/GX-4 proven Python seams.

| Router-facing Python savers
| *Not supported.* `save_xlsx` and `save_ods` fail during pre-backend
  `pd.DataFrame` coercion for a grouped value, for XLSX and ODS alike.
| Preserve the accepted carrier through sanitization for both outputs.

| Public pipeline config/YAML build and run
| *Partially supported.* `build_steps_from_config` + `run_pipeline` constructs a
  real `GroupedMatrix` through registered `contract_grouped_xref`; public output
  through `orchestrate` then fails at the router saver (and fails earlier if an
  explicit grouped Workbook View is configured).
| The same config-built carrier must reach `orchestrate` output for XLSX and ODS,
  including explicit selection/rename.

| Public XLSX/ODS read
| *Partially supported.* `options.extra.exact_header_depths` yields `ExactTable`,
  but explicit Workbook View reverse mapping misclassifies it as a missing
  visible sheet.
| Both loaders must feed the unchanged mapping -> reconstruction -> expansion
  chain.
|===

This matrix distinguishes the already-supported direct Python carrier path from
the incomplete public configuration/router path. GX-5 does not replace or
reimplement the former; it joins the latter to it.

== Smallest implementation seam

Exactly these runtime modules are in scope:

* `domain/workbook_views.py`: accept `GroupedMatrix` as a prepared forward sheet;
  accept `ExactTable` as a projected visible sheet during reverse mapping.
* `rendering/frame_selection.py`: allow the same `GroupedMatrix` accepted by
  `compose_workbook`; formula sheet-name rewriting remains DataFrame-only.
* `io_backends/xlsx/xlsx_backend.py`: widen the write annotation to Frames-like
  values and preserve `GroupedMatrix` through `save_xlsx`.
* `io_backends/ods/ods_backend.py`: identical preservation through `save_ods`.

The saver rule is exact and conservative:

[source,text]
----
DataFrame       -> pass through unchanged
GroupedMatrix   -> pass through unchanged
other value     -> existing pd.DataFrame coercion
----

This does not create a generic carrier protocol and does not make arbitrary
objects renderable. The outer adapter -> domain-carrier import direction is
permitted; the accepted composer already has the same bounded carrier dispatch.
No dependency cycle results because grouped-XRef imports neither rendering nor
I/O backends.

== Workbook View semantics

For GX-5 a grouped sheet supports the Workbook View responsibilities needed by
adoption: explicit inclusion, physical order, visible sheet naming, and persisted
visible-sheet -> logical-frame mapping. The selected mapping retains the same
carrier object under the visible name; it does not unwrap or copy the carrier.

The selection contract is identical across `DataFrame` and `GroupedMatrix`:

* absent `workbook_view`, or a view without `sheets`, includes every remaining
  renderable frame in Frames insertion order;
* an explicit `sheets` list is authoritative: declared entries alone are
  included, undeclared frames are excluded, declaration order fixes sheet order,
  and `sheet` (defaulting to `frame`) fixes the output name;
* a selected missing frame raises the existing `KeyError` before render-plan or
  file publication;
* duplicate output sheet names raise the existing `ValueError` before
  publication, regardless of whether the colliding inputs are ordinary or
  grouped;
* a mixed explicit list preserves each selected value under its output name and
  order. Formula sheet-name rewriting remains limited to copied DataFrames;
  grouped carriers are retained by identity and never inspected for formulas;
* reserved frame/sheet names and duplicate logical-frame selection retain their
  existing rejection rules.

Column-targeted Workbook View options (`helper_columns`, `editable_columns`, and
column protection) remain outside GX-5. They use flat string `header_map`
identity, while grouped dynamic identity is the complete visible tuple and leaf
labels may repeat. GX-5 must reject those options for a grouped sheet rather than
silently apply ambiguous leaf-only targeting. A non-empty generic `options` map
on a grouped sheet is likewise rejected in this slice; tuple-aware presentation
targeting requires a separately reviewed need. Ordinary DataFrame Workbook View
semantics remain byte-identical.

The readback order is explicit and unchanged:

[source,text]
----
XLSX/ODS input option exact_header_depths[visible sheet]
-> parser -> WorkbookIR -> workbookir_to_frames -> ExactTable
-> apply_workbook_view_sheet_mappings (visible name -> logical table name)
-> reconstruct_grouped_matrix (one live axis mapping)
-> expand_grouped_xref -> canonical relation
----

== Read-option ownership

`exact_header_depths` remains an *input backend option* at
`input.options.extra.exact_header_depths`, keyed by the physical visible sheet
name and containing a positive integer depth. It is not a pipeline parameter,
Workbook View field, metadata root, registry step parameter, or inferred value.
The parser must split header/data before Workbook View mappings and grouped
configuration are available; therefore automatic derivation from
`label_columns`, persisted metadata, or a prior carrier would cross the read
boundary and reintroduce inference. `reconstruct_grouped_matrix` continues to
cross-check exact depth against `len(label_columns)` and fails on disagreement.

== Adoption and wrapper decision

The maintained Core configured Workbook View roundtrip is the in-scope adoption
chain. GX-5 adds one public, config-built grouped variant which runs through
`orchestrate`/router savers and both carriers:

[source,text]
----
canonical relation + live axis source
-> contract_grouped_xref
-> configure_workbook_view (logical grouped frame -> renamed visible sheet)
-> orchestrate persistence boundary -> router saver
-> XLSX and ODS
-> orchestrate loader with exact_header_depths[visible sheet]
-> apply_workbook_view_sheet_mappings
-> reconstruct_grouped_matrix
-> expand_grouped_xref
-> canonical relation
----

The case must prove untouched identity plus one edited value, repeated upper
labels, a literal delimiter component, and a renamed physical sheet. This is a
real public configured pipeline and carrier roundtrip, not another direct
composer probe. The documented Story Cast repetition remains valid consumer
motivation, but changing the sibling repository is not required to prove this
Core public seam and is not authorized by this confirmation.

No wrapper is added. A wrapper could not own parser-time `exact_header_depths`,
would duplicate existing registered steps, and one adoption supplies no second
stable configuration vocabulary. Discriminator/facet multiprojection remains a
later decision, exactly as the parent FTR states.

== Public/API and documentation impact

There is no new callable, step, parameter, metadata root, carrier, registry
entry, schema-maintenance reference, or persistence rule. The behavioral API
widens only existing acceptance sets:

* `configure_workbook_view.sheets[*].frame`: `DataFrame | GroupedMatrix`;
* spreadsheet router write values: existing coercible values plus preserved
  `GroupedMatrix`;
* Workbook View visible read values: `DataFrame | ExactTable`.

The existing runtime registry stays unchanged. Update only the JSON registry
description/frame-contract wording for `configure_workbook_view` and
`apply_workbook_view_sheet_mappings`, the transformation guide's practical
roundtrip, and the active release note/known limitation. No schema-maintenance
change is due because no new persisted reference is introduced; existing
`workbook_view.sheets` and `sheet_mappings` references retain identical string
identity.

== Protected surfaces and required tests

Implementation acceptance requires:

* unit tests in `tests/unit/domain/test_workbook_views.py` for grouped selection,
  exact-table reverse mapping, carrier identity, ambiguous grouped sheet options,
  and unchanged DataFrame behavior;
* unit tests in `tests/unit/rendering/test_frame_selection.py` for grouped
  include/exclude/rename/order, missing selection, duplicate output name, mixed
  DataFrame/grouped selection, and unchanged formula rewriting/non-renderable
  rejection;
* one new
  `tests/integration/pipeline/test_gx5_grouped_xref_public_roundtrip.py` covering
  public build/run + `orchestrate`, router savers/loaders, renamed sheets,
  configured exact depth, edit, reconstruction, and XLSX/ODS parity;
* retained GX-1..GX-4, flat XRef/axis projection, configured Workbook View
  roundtrip, persistence-boundary/final-cleanup, XLSX/ODS, registry mirror,
  spreadsheet boundary, and leaf/layer architecture suites.

Failure tests must prove no caller Frames/meta mutation and no output file from a
pre-render validation failure. Ordinary saver coercion, legacy reads without the
exact gate, direct backend writes, and DataFrame Workbook Views must remain
unchanged.

== Sizing

Implementation budget is deliberately capped:

* runtime: exactly 4 existing modules above, *35--55 net LOC*;
* tests: exactly 2 existing test modules plus 1 new integration module,
  *140--210 net LOC*;
* contract documentation: registry JSON, transformation guide, release notes,
  and the parent lifecycle line, *20--35 net LOC*;
* public surface: 0 new types, 0 new steps, 0 new parameters, 0 new metadata
  roots, 0 new schema-maintenance handlers.

Exceeding 60 runtime LOC or touching `grouped_xref`, `xref_crosstable`,
`xref_axis_mapping`, composer/IR/flow/passes/renderers/parsers, pipeline runtime
registry, persistence, or schema maintenance requires stopping and reconfirming
scope.
