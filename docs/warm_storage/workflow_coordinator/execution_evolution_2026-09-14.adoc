== Generation 1 -- direct/manual provider execution

The earliest retained account distinguishes direct/manual provider invocation from the later fixed proof harness. These were tightly bounded experiments against disposable or explicitly prepared workspaces, not a general Coordinator ingress. The operator still selected and prepared the workspace, established baseline and task, invoked the provider, observed Git/process facts, preserved output, and decided which evidence was sufficient.

This was useful because it exposed real provider and host behavior before a general execution surface existed, and produced concrete reachability/failure evidence. It was not reusable: safety and reproducibility depended heavily on human orchestration, while one-shot consumption, dispatch truth, result correlation, Git facts, and durable state were not consolidated. The Slice-5A proof-readiness record preserves this retrospective distinction.

== Generation 2 -- deterministic Slice-4 proof harness

Slice 4 turned the experiments into a reproducible fixed proof environment. The real-adapter foundation landed in `60c6bf9f` on 2026-08-30; the deterministic harness followed in `fc53be37` that day and its truthfulness correction in `0b950dc4`.

The harness prepared a fresh disposable Git repository, fresh external proof root, fixed `WFC-S4-PROOF` WorkItem, and one-shot provider authorization. It made Run/Hop state, dispatch/result facts, Git inspection, and proof-summary evidence reconstructable. Failure preservation mattered: the FTR records that the harness had to retain bounded stdout/stderr tails and host/ancestor provenance so a failed process did not depend on terminal scrollback.

It proved deterministic fake-executable conformance mechanics and enabled bounded real-provider happy-path proof work. It remained proof-specific: its WorkItem, repository shape, `PROOF.md` target, and one-invocation authorization were fixed. FTR section 11.4.1 constrained it from becoming a second Coordinator or routine real-repository mechanism.

== Generation 3 -- fixed task-specific one-shot launchers

After the accepted N=1 path, commissioning and DMC dogfood used fixed Python launchers for concrete WorkItems. The retained sources are:

* `commissioning/launchers/dmc_fk_c2_wi01_20260907_launcher.py.txt`;
* `commissioning/launchers/dmc_fk_c3_wi01_20260911_launcher.py.txt`; and
* `commissioning/launchers/dmc_fk_c3_s1_20260911_launcher.py.txt`.

Each hard-coded repository, baseline SHA, external state root, WorkItem/Hop, model binding, task, selected governing inputs, authority/scope, and expected commit subject. It preflighted the exact repository/baseline/state combination, persisted launch provenance, made one real invocation, and deliberately had no retry. The agent was forbidden direct Git commands; the trusted Coordinator made the authorized mechanical commit after a correlated CommitIntent.

The launchers are therefore strong historical evidence: reviewers can inspect the exact launched composition and its external root retains Run facts. They also taught concrete lessons. The 2026-09-07 C2 assessment failed closed because `invocation_id` had not reached the provider prompt, despite matching `run_id` and `hop_id`; the consumed Run was neither resumed nor retried. This led to the identity-projection correction. On 2026-09-11, C3 assessment and C3-S1 implementation Runs completed through correlated result, CommitIntent, trusted Coordinator commit, and durable completed Run evidence. Subsequent independent reviews still separated mechanical success from semantic/lifecycle acceptance.

The Commissioning Diary then closed the ordinary fixed-launcher pattern. Their repeated boilerplate was re-expressing WorkItem, authority, scope, consumption, state root, provider binding, and expected result: useful governance, but accidental complexity when hand-coded every time. These sources remain evidence, not a supported runtime API or a template for another ordinary launcher.

== Generation 4 -- declarative generic N=1 operator

The replacement is `scripts/workflow_coordinator/operator.py`, introduced by `ac4c6baa` on 2026-09-11 and hardened by `5ec5a7d5` and `ac1fe738`. It created one generic executable path from repository-tracked declarative inputs:

* WorkItem;
* workflow profile;
* repository policy;
* component manifest and selected components; and
* task payload.

Instead of writing a launcher per WorkItem, an operator supplies those paths and a pinned expected Git head. The operator reads them from that committed revision, checks profile/policy/scope coherence and clean admission, and records the governing-input binding. It creates a one-shot state root and execution identity, retains trusted Git authority in the Coordinator, and writes durable plan/summary evidence around Run/checkpoint records. Provider invocation remains a bounded adapter boundary, not a provider/model-routing framework.

The first declarative dogfood clarified that `commit` names a workflow effect -- the Coordinator's trusted commit capability -- not permission for the agent to execute `git commit`. The subsequent action-authority correction required coherent `edit` and `commit` authority where a trusted commit is required; it granted no agent Git authority.

This was the transition away from ordinary bespoke launchers. The Diary called for generic N=1 execution through declarative human-authored configuration and one real dogfood, rather than another fixed composition. The retained Slice-5A readiness account records the N=1 dogfood `docs/ai_info/workflows/dogfood/dmc_fk_c3_wi02/` (prepared `80c22b96`, H001 `54c708ec`): configuration and pinned data now carried per-WorkItem provenance.

== Generation 5 -- bounded declarative N=2 serial operator

Slice 5A extended the same operator rather than introducing a launcher or a second Coordinator. Serial continuation was implemented in `ed33fbb2` on 2026-09-13, corrected in `59d8a8f2`, and its run-level summary presentation was corrected in `c11cc2f5`.

For an authorized `N=2` WorkItem, H001 begins at baseline A. After result reduction and durable Run/checkpoint/per-invocation publication, the Coordinator may make trusted A -> B Git commit when authorized. It then applies a deterministic continuation gate: revalidate checkout/Git at B, re-read governing inputs against B, and stop for a human if either fails. Only then may it create a fresh H002 invocation identity and invoke H002 with bounded H001 summary context. The budget is exactly two; no H003 path exists.

The first real-provider proof was accepted on 2026-09-14. Its one-shot authority was commit `58928229`; independent review `67226f6e` returned *A -- REAL N=2 PROOF ACCEPTED* for external root `/home/stefan/wfc-proofs/slice5a-live-n2-20260914-01`, Run `RUN-fd96ce89af1c4aaf8d2721ae683d4fda`. Consult that review and the Diary for detailed evidence rather than duplicating it: H001 began at A and made the authorized Coordinator-owned commit B; governing inputs remained stable; fresh H002 began at B with a distinct identity; two Hops exhausted the budget; no H003 was created.

The qualitative milestone was narrow but real: one maintainer operator launch resulted in two separately governed real agent Hops without human manual H002 dispatch. It does not generalize to routine N>1 work.

== Cross-generation synthesis

Earlier generations were commissioning stages, not mistakes. Direct work exposed provider/host reality; the harness made proof facts reproducible and failures durable; fixed launchers made productive N=1 runs exactly inspectable; declarative N=1 separated WorkItem data from executable mechanics; and bounded N=2 showed a fresh, revalidated second Hop under that same operator.

Semantic agent work became increasingly separate from deterministic orchestration, trusted Git authority, provider invocation, durable evidence, and human authorization. Repository evidence supports this principle: the ceremony contained useful governance; the problem was the human performing its mechanical parts. The Coordinator removed mechanical work while retaining explicit human authority for semantic choices and bounded live grants.
