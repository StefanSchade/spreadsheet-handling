== 1. Problem, evidence, and design forces

Serial agent work has repeatedly left the maintainer to establish Git truth,
collect evidence, assemble the next bounded prompt, validate results, and route
the next role. The proposed system automates those mechanics and narrowly
delegated routing for *one local repository, one worktree, one active run, and
one agent invocation at a time*. It does not automate new semantic authority.

The primary input,
`agent_workflow_coordinator_concept_2026-08-25.adoc`, is evidence-rich
hypothesis material rather than architecture. The decisive pressures are:

* Trusted-Ingress E4 needed more than three productive correction rounds.
* Trusted-Ingress E3/XRef escaped a local loop when contracts conflicted and
  semantic ownership changed.
* DMC F-002 separated adversarial search breadth from acceptance authority.
* DMC Cell Codec found an enclosing blocker after known findings closed.
* DMC deletion authority suspended parent work and required rebaseline after
  nested work.
* Routine work and accepted non-blocking minors falsify a mandatory full review
  chain.

Repository governance makes Git/committed artifacts the durable factual trail,
treats agent output as reviewable input, and reserves warm storage for this
unaccepted design. V1 seeks useful Verification Depth per unit of scarce human
attention; Verification Depth is an objective, not a V1 score.

V1 excludes a workflow language, database/event store, graph or DI framework,
plugin manager, queue, async/distributed execution, parallel workers/worktrees,
web UI, general sandbox, automatic workflow invention, multiple agent
providers, Sonar-specific code, vector retrieval, and Project Memory as run
storage.

== 2. Falsification pass and resulting simplification

[cols="2,3,3",options="header"]
|===
|Candidate |Challenge |Decision

|WorkItem / Run / Hop
|Work item names semantic intent; Run records an attempt; Hop is one agent
invocation. A mutable WorkItem duplicates its run specification.
|Work item is input data with a stable ID. Only Run and Hop are operational
records.

|EvidencePackage / ReviewPolicy / TransitionDecision / Checkpoint
|None has independent behavior or lifecycle.
|They are respectively an observation manifest, profile data, a history field,
and a generated view.

|Historical review taxonomy
|Names conflate purpose, breadth, authority, context, and lifecycle; states for
all of them would encode ceremony.
|A profile selects phases. Review dimensions are phase data, not generic states.

|DMC `family/cycle/slice`; Trusted-Ingress `E<n>`
|These belong to their programs.
|Profile labels and work-item IDs only; never generic primitives.

|Supervisor service
|Most safety routing is mechanical; an always-on LLM adds cost and ambiguous
authority.
|Supervision is engine behavior; an optional read-only routing-agent hop exists
only at declared judgment points.

|Persistent state
|Git already supplies commits, paths, and diffs.
|Store only policy pin, phase/status, budget, concise hop outcomes, finding
dispositions, suspension/re-entry, and stop reason.

|Coordinator-created content commits
|They obscure semantic authorship and expand recovery.
|V1 agents create content/review commits; coordinator state is transient by
default.

|Future providers/retrieval/parallelism
|They justify boundaries, not present machinery.
|Fixed provider callables and a narrow future context input; no discovery or
concurrency framework.
|===

The result is one serial process, one profile/config surface, one agent adapter,
simple evidence callables, and local artifact I/O.

== 3. Architecture and responsibility boundaries

[source,text]
----
versioned work/profile/prompt inputs
                  |
                  v
       serial coordinator process
       preflight/Git -> prompt -> agent -> result/evidence -> route -> state/report
                  |                    |
                  v                    v
             Git/worktree        maintainer stop
----

These are responsibilities of one process, not services or one class per noun:

[cols="2,4",options="header"]
|===
|Boundary |V1 responsibility and exclusion

|Engine/supervision
|Run the serial loop, enforce mechanics/budget, apply finite routes, write state,
and stop. It does not invent workflows or semantic acceptance.

|Agent adapter
|Invoke one configured local agent with prompt, repository, and existing
permissions; capture output. It is not a universal adapter, credential store,
or sandbox.

|Profile/repository policy
|Versioned ordinary data/files for phases, routes, review purpose, checks,
blocking policy, authorized scope/actions, prompt parts, and human gates. No
executable profile code or DSL.

|Prompt/result boundary
|Assemble ordered components and validate a small routing envelope. Critical
routes are never inferred from prose.

|Evidence boundary
|Observe Git and configured checks. Providers never grant semantic acceptance.

|Operational artifacts
|Maintain an atomic local run snapshot, compact hop data, and checkpoint; do not
mirror Git or store durable project meaning.

|Project Memory handoff
|At accepted completion, suggest a minimal curated promotion when warranted;
never store per-hop state or promote automatically.
|===

If implemented here, V1 belongs in `scripts/workflow_coordinator/`, because it
is initially repository-local. Profiles/prompts belong in
`docs/ai_info/workflows/`. Extraction to `tools/` waits until a sibling can copy
and run a proven dependency-light core unchanged. This task creates neither.

== 4. Minimal core model

=== 4.1 Work item versus Run

A compact run specification contains `work_item_id`, semantic task/authority
source, profile path and policy commit, authorized repository/scope, initial
phase/baseline, autonomy budget, and optional profile labels. WorkItem ID is a
durable semantic address, not a runtime entity.

A Run is one attempt for that work item. It has a unique `run_id`, may
pause/resume, and cannot silently change its policy pin or baseline. A new
attempt reuses the work-item ID but gets a new Run; return from nested work is an
explicit rebaseline within the parent Run.

=== 4.2 Three operational records

[cols="1,4",options="header"]
|===
|Record |Minimum V1 fields

|Run
|Schema and work-item/run IDs; profile/policy commit; repository identity;
initial/current HEAD; phase/status; hop limit/used; compact hop summaries;
findings; child/suspension reference; rebaseline generation; stop reason; next
allowed route keys.

|Hop
|ID/sequence; phase/role/context; start/end; known base and observed end HEAD;
actual commits; invocation/outcome; evidence refs; finding delta; applied
route/stop; short attributed rationale.

|Finding
|Stable run-local ID; concise invariant; `blocking`; status; introducing and
last-changing Hop; evidence refs; optional successor/external work item; short
disposition.
|===

Finding status is exactly `open`, `resolved`, `residual` (genuine but accepted
non-blocking), or `superseded` (replaced/reclassified with a reference). There
are no comments, assignees, due dates, or labels. Agents cite an ID or propose a
new finding; the coordinator assigns new IDs. An agent cannot silently rewrite
an invariant, change blocking authority, or close a finding; the applicable gate
or human validates that delta.

Review descriptors, observations, route decisions, prerequisite links, and
checkpoints remain nested data/views, not aggregate roots.

== 5. Profile, transitions, supervisor, and human authority

=== 5.1 Finite typed configuration

A profile is validated YAML/JSON loaded as typed data. It declares opaque phase
keys and routes with only five engine effects: `goto`, `complete`,
`await_human`, `suspend_for_prerequisite`, and `stop`.

[source,yaml]
----
implementation_review:
  role: reviewer
  review:
    purpose: falsify implementation against accepted design
    breadth: implementation
    authority: gate
    context: fresh
    blocking_policy: blocking_only
  routes:
    accepted: {goto: closure_assessment}
    correct: {goto: correction}
    advisory_probe: {goto: adversarial_advisory, trigger: risk_only}
    semantic_question: {await_human: true}
adversarial_advisory:
  role: reviewer
  review: {breadth: adversarial_implementation, authority: advisory, context: fresh}
  routes:
    return: {goto: implementation_review}
----

The data cannot express code, arbitrary conditions, fan-out, or computed graphs.
Loops are explicit route edges. New schema needs replay/implementation evidence.

=== 5.2 Decision precedence

. *Mechanical preemption:* malformed state/result, Git anomaly, policy mutation,
  or required-provider error stops; no supervisor overrides it.
. *Deterministic reduction:* outcome, review authority, blocking policy,
  findings, evidence, and current route table select the sole applicable route.
. *Optional supervisor:* only a declared judgment point may invoke a fresh,
  read-only routing agent with the finite allowed route keys.
. *Human:* ambiguity, undelegated semantics, or an undeclared route stops.

The supervisor receives the pinned profile excerpt, allowed route keys,
structured result, compact hop/commit/evidence and finding history, and one
question. It may classify productive convergence, goalpost drift, risk trigger,
or likely reclassification. It cannot invent routes, change policy/scope,
downgrade blockers, increase review authority, activate unauthorized work, or
claim a project decision. Its structured invocation consumes a hop.

V1 always stops for new/conflicting semantic ownership or authority; plausible
public/compatibility choices; trust/security redesign; capability deletion;
profile redesign; unauthorized scope; unapproved nested work; roadmap/Project
Memory governance; or anything not explicitly delegated. An agent assertion can
trigger a stop but cannot establish its own truth.

== 6. Review and convergence model

=== 6.1 Independent review dimensions

[cols="1,4",options="header"]
|===
|Dimension |V1 meaning

|Breadth/search scope
|Profile-defined falsification surface (for example broad discovery, design,
implementation, delta, integration, closure/counterexample, lifecycle) with
inclusions/exclusions. It selects context, never authority.

|Authority
|`advisory` or `gate`. An advisory result may add evidence/findings but cannot
advance/complete. A gate authorizes only routes declared for its phase.

|Context policy
|`fresh` starts without provider conversation history; `continuing` retains a
bounded finding thread. Context is not authority or independence.
|===

Independence means a gate does not reuse the author conversation. Provider/model
diversity is deferred. A profile review must state purpose, distinct
falsification/authority contribution, trigger, breadth, blocking policy, and
exit. Broad discovery, readiness, implementation, delta, adversarial advisory,
closure, and lifecycle review are optional capabilities, never an automatic
chain. Mechanical checks are providers.

Delta review normally stays with known findings/direct regressions. New material
evidence may escape the bound; an unrelated minor does not automatically reopen
the gate. The engine never inserts all reviews or computes a verification score.

=== 6.2 Finding identity and progress

Deterministic signals are finding status transitions/reopens, commit/path deltas,
validation changes, whether resolved findings remain closed, new material
finding count, route repetition, and scope/policy/baseline change.

Whether a mechanism materially changed, semantic scope narrowed, review
goalposts drifted, progress stalled, or the wrong owner/workflow is active
requires bounded supervisor judgment when delegated, otherwise human judgment.
Stable identity plus changed evidence/mechanism, narrowing residual scope, and
closed regressions supports continuation. Repeated unrelated demands without
new evidence suggests drift; conflicting contracts/ownership suggests
reclassification.

There is no `max_review_iterations` rule or convergence score. The supervisor
may stop for lack of material progress; the outer hop budget remains the safety
checkpoint.

== 7. Bounded autonomy

`max_autonomous_hops` is a positive Run value and can ramp 1 -> 2 -> 5 -> 10
without architecture change. Every adapter-accepted agent invocation consumes a
Hop whether successful, failed, or malformed; author, reviewer, correction,
rebaseline, curator, and supervisor all count. A local failure before provider
acceptance does not. Git/prompt/schema/evidence/routing/state/reporting and human
actions do not count. V1 has no hidden retry.

The coordinator stops early for mechanical anomaly, hard evidence gate,
forbidden/ambiguous route, explicit human/semantic escalation, human stop,
suspension, or lack of progress. At exhaustion it completes safe deterministic
post-hop work, records `awaiting_human_budget`, renders a checkpoint, and invokes
no agent.

Resume requires the maintainer to inspect the checkpoint, resolve any gate,
confirm actual HEAD/clean tracked state, optionally raise the limit, and issue an
explicit resume. Used hops never reset. With N=1 the Git/evidence/checkpoint
automation remains useful even when the maintainer chooses the next role.

== 8. Git transaction, commit ownership, and identity

[quote]
____
Every agent hop starts at a known Git commit and ends at a known Git commit with
a clean tracked worktree.
____

Before invocation the coordinator records HEAD, checks expected ancestry, and
requires no tracked or non-ignored untracked changes. After invocation it reads
HEAD and computes the actual `base..head`; agent-claimed commits are hints.

V1 agents create their own semantic content/review commits. A mutating successful
Hop normally makes 1..n atomic commits; observation-only/failed hops may have
`base == head`. The coordinator does not stage or synthesize content commits or
mix commit ownership within a Hop. Coordinator-owned content mode is deferred.

The next Hop is blocked by divergent/rewritten history, HEAD movement outside
the invocation window, dirty tracked/non-ignored state, forbidden merge commits,
out-of-scope paths, changes to pinned policy/prompt files, exceeded optional
commit safety cap, or unresolved repository/submodule/evidence identity. Claimed
versus actual mismatch is recorded; it becomes blocking when paired with hidden,
divergent, out-of-scope, or policy-forbidden change.

Ignored scratch does not affect Git cleanliness when confined to approved
scratch roots and free of retained secrets. V1 does not promise whole-filesystem
cleanliness.

`work_item_id` is stable semantic identity; `run_id` identifies one attempt;
`H001...` identifies Hops within it. Run evidence always carries all three.
Workflow commits put WorkItem/Hop in `git log --oneline` through a compact tag
compatible with Conventional Commits. Optional `Work-Item:`, `Workflow-Run:`,
and `Workflow-Hop:` trailers may carry full machine identity after separate
acceptance; V1 has no hook and does not retrofit history.

== 9. Prompt, result, and evidence contracts

=== 9.1 Prompt composition

The assembler concatenates an ordered manifest, not a template language:

. generated identity/Git/authority/output header;
. versioned base role;
. repository policy;
. profile/current-phase policy;
. task-specific natural-language semantics;
. bounded observations/repository refs;
. structured-result contract.

The Run pins component commits/digests. Fixed headers may be generated; no
user-defined conditionals/loops/includes exist. Identity, scope, routes, policy,
evidence refs, and output are structured; semantic argument remains prose. Git
state, paths, budgets, routes, checks, and schema are enforced in software, not
only requested from the LLM.

=== 9.2 Minimum result envelope

[source,json]
----
{
  "schema_version": 1,
  "outcome": "completed | changes_required | blocked | failed",
  "requested_route": "profile_route_key",
  "scope_changed": false,
  "requires_human": false,
  "escalation": null,
  "findings": [],
  "claimed_commits": [],
  "evidence_refs": [],
  "summary": "short routing rationale"
}
----

An escalation has class `scope`, `semantic_authority`, `public_surface`,
`trust_boundary`, `prerequisite`, or `operational`, plus a concise question. A
finding carries existing/null ID, invariant, blocking flag, proposed status, and
evidence refs. Free-form reasoning is separate and cannot supply a missing
route/outcome/finding status/human flag. “ACCEPT WITH MINOR CORRECTIONS” only in
prose is malformed for routing.

=== 9.3 Evidence providers

A fixed in-code registry maps trusted names to simple callables. Each returns
name, `pass|fail|error|not_run`, exact command/version, concise summary, artifact
ref, and digest. Initial observations are mandatory Git facts plus
profile-selected tests, architecture guards, source/style checks, and diff
hygiene. Trusted policy supplies exact argv/working directory; agent output
cannot request arbitrary execution.

A future static-analysis/Sonar callable can return the same observation and be
registered explicitly. No Sonar type, service, dependency, or plugin framework
exists now. Observations never grant semantic acceptance.

== 10. Persistence, Project Memory, and checkpoints

=== 10.1 Committed versus transient

Ordinary repository workflow commits profiles/policy/prompts/schema, semantic
task authority, agent content, and required durable review/design artifacts. A
compact run checkpoint is committed only when a maintainer deliberately promotes
it for durable handoff/history.

Default operational state is gitignored, for example
`.agent_tmp/workflow_coordinator/<run-id>/`: one atomically replaced `run.json`,
generated `checkpoint.adoc`, compact results/observation manifests, and optional
raw material. Expanded prompts, stdout/stderr, full logs, large diffs, and copied
files are transient, may be redacted/promoted selectively, and may be deleted.
Git already stores diffs; there is no append-only rule.

Active/paused material may be promoted as one warm-storage report if it has
durable reconstruction value. After consolidation it may move to cold storage
or be deleted when Git/durable artifacts suffice. V1 automates no
commit/archive/prune lifecycle.

=== 10.2 Project Memory

[quote]
____
Project Memory remembers what matters. The coordinator records what happened.
____

Project Memory is never run state and receives no per-Hop events. At accepted
completion, the coordinator may suggest `none` or `update_existing` with
WorkItem, accepted HEAD, durable decision/residual, and evidence refs. Canonical
curation stays an explicit maintainer-authorized Project Memory workflow.

Future retrieval may return bounded content plus path, commit, authority, and
lifecycle labels through a narrow context input. Embeddings, indexing, ranking,
and authority inference remain outside the coordinator.

=== 10.3 Checkpoint

The deterministic checkpoint contains identities/profile/policy commit,
baseline/current HEAD, status/stop/phase/rebaseline generation, hop budget, one
row per Hop (role, outcome, commits, finding delta, evidence, route), finding
statuses/origins, anomalies/human questions, and finite next allowed routes.
Semantic summaries are attributed, not presented as computed fact.

[source,text]
----
checkpoint -> hop/commit -> structured result/review -> observation/log/diff
----

It links rather than duplicates prompts, prose, diffs, or logs.

== 11. Failure, interruption, suspension, and resume

[cols="2,4",options="header"]
|===
|Condition |V1 behavior

|Invocation failure / malformed result
|If accepted by adapter, consume Hop; independently verify Git/evidence; record
diagnostic and stop without hidden retry/routing.

|Failed check/guard
|Record observation. A declared failed gate may route to correction; provider
error or hard invariant stops.

|Dirty/divergent Git
|Stop without reset, cleanup, or guessed ownership; report exact state.

|Unexpected commits
|Use actual range; stop on ancestry/linearity/scope/policy/safety failure,
otherwise record claim mismatch under policy.

|Unclassifiable supervisor / human stop / exhausted budget
|Persist state/checkpoint and invoke no next agent; show finite choices.

|Crash
|Before invocation atomically mark `invoking` with base HEAD. Restart reconciles
actual Git against it, checkpoints, and requires explicit resume; never replay
automatically.

|Prerequisite
|Only preauthorization or maintainer activates a separate child Run. Parent is
`suspended` with child/suspension HEAD and no stale next action.

|Nested return
|Parent enters `rebaseline`, increments generation, compares current
HEAD/governing artifacts/findings with suspension state, and selects a newly
valid route rather than restoring the old one.
|===

== 12. Trust/security boundary

V1 trusts the maintainer-selected repository, pinned policy/profile, local
Git/filesystem/process observations, configured adapter, and existing OS/tool
permission boundary. It is not a hostile-code sandbox.

Agent prose, claims, routes, findings, and facts are untrusted input. The engine
observes Git, validates schema, permits only current routes, and grants no extra
agent permissions. Agent-requested policy/workflow mutation is unauthorized.
The supervisor cannot create authority or turn advice into a gate. Secrets,
credentials, environment dumps, and credential-bearing output are never run
artifacts; raw output is deleted/redacted before promotion.

== 13. DMC first-profile mapping

[source,text]
----
assess -> design -> readiness_gate -> implement -> implementation_review
  -> correction -> delta_review --(while productive)--> correction
  -> closure_assessment -> closure_gate -> lifecycle_handoff -> complete
----

Optional declared routes are human semantic escalation; authorized
prerequisite suspension; risk-triggered adversarial advisory returning to formal
review; re-entry/rebaseline; and closure-discovered correction/handoff.

These phase names, family/cycle/slice, and DMC finding classes remain profile
vocabulary. The engine sees only phase keys, review descriptors, finite route
effects, findings, Git transactions, and authority policy. This demonstrates
representability; it neither designs nor starts Cycle 2.

== 14. Historical and simplicity replay

=== A -- Trusted Ingress E4

State before:: `delta_review`; F1 open, others resolved; >3 loops; budget remains.
Evidence/result:: Same F1, resolved IDs stay closed, tests pass, commits show a
materially different mechanism and narrowed scope.
Decision:: Mechanics preserve identity; bounded supervisor selects productive
continuation. Review count is irrelevant.
Transition:: `delta_review -> correction`.
Human:: None until budget, ambiguity, or semantic gate.
State after:: F1 has new evidence; resolved findings remain closed; next Hop
starts at verified HEAD. Continued convergence is permitted.

=== B -- Trusted Ingress E3 / XRef

State before:: Parent loops on a local correction.
Evidence/result:: Two accepted contracts conflict; likely wrong semantic owner;
result requests semantic authority/prerequisite.
Decision:: Mechanics stop; supervisor cannot choose a new contract.
Transition:: Maintainer authorizes child; parent suspends and local loop ends.
Human:: Required to authorize/scope the prerequisite.
State after:: Separate child Run; parent later rebaselines contracts, HEAD, and
findings before a new route. No stale action replays.

=== C -- DMC F-002 ultrareview

State before:: Narrow plausible design deviation; profile exposes risk advisory.
Evidence/result:: Structured deviation signal requests declared probe.
Decision:: Supervisor/maintainer selects broad, fresh, advisory review.
Transition:: Advisory findings return to formal implementation review.
Human:: Only for undelegated semantics or an unauthorized route.
State after:: Advisory cannot accept; fresh formal gate re-derives claims from
repository evidence.

=== D -- DMC Cell Codec

State before:: Known slice findings resolved; profile still requires closure
counterexample search.
Evidence/result:: Closure finds a new blocking shadow parser.
Decision:: Empty known-findings is not generic closure; gate remains unsatisfied.
Transition:: Bounded correction/handoff or human-authorized prerequisite.
Human:: Only if new semantic work is undelegated.
State after:: Parent remains open with new Finding/child. Profiles lacking this
closure requirement are unaffected.

=== E -- DMC deletion authority

State before:: Parent reaches substantial new deletion-authority architecture.
Evidence/result:: `blocked`, `requires_human`, semantic/prerequisite escalation.
Decision:: No local correction or supervisor-created workflow; maintainer scopes
child.
Transition:: Parent suspends; child completes; parent returns to rebaseline.
Human:: Required for child and new semantic gates.
State after:: Current HEAD/contracts/finding ownership determine a new route;
stale assumptions receive no implicit validation.

=== F -- tiny local change

State before:: `routine_local` authorizes one narrow implementation Hop, paths,
checks, and no semantic/public change.
Evidence/result:: Committed result; actual range/scope/tests/hygiene pass; no
finding/escalation.
Decision:: Deterministic completion; no design/readiness/adversarial/integration/
closure/lifecycle review inserted.
Transition:: `implement -> complete`; checkpoint.
Human:: Ex-post oversight under chosen delegation.
State after:: One-Hop completion, no ceremony, no Project Memory promotion.

=== G -- one non-blocking minor

State before:: Gate permits non-blocking residuals.
Evidence/result:: `completed`; one `blocking=false` Finding proposed residual.
Decision:: Blocking policy validates residual acceptance and its authority; no
prose inference.
Transition:: Advance/complete without correction.
Human:: Only if profile reserves residual acceptance.
State after:: Visible evidence-linked residual, not blocker or internal issue
tracker.

=== H -- `max_autonomous_hops = 1`

State before:: Any profile, budget one.
Evidence/result:: First invocation ends; Git/evidence/result/route are processed.
Decision:: Deterministic completion if no invocation remains; otherwise budget
preempts.
Transition:: `complete` or `awaiting_human_budget` with finite next routes.
Human:: Regains control; may stop, act, or raise budget.
State after:: Git/evidence packaging and checkpoint already make N=1 useful.

== 15. Decision register

=== Decided for V1

* Serial local engine, one adapter; WorkItem input plus Run/Hop/Finding records.
* Typed finite profiles; mechanical reduction, optional budgeted supervisor,
  explicit human authority; profile-selected review axes.
* Minimal findings, no fixed review limit; agent commits and Git-observed clean
  transactions.
* Atomic transient state/checkpoint; ordered prompts; small result; fixed
  evidence registry; exceptional curated Project Memory handoff.

=== Deferred intentionally

* Coordinator/mixed commit ownership; required trailers/hooks and exact ID
  grammar; multiple providers/models and diversity policy.
* Extraction to `tools`/package; parallel/remote/distributed operation; Sonar,
  vector retrieval, web UI; automated warm/cold lifecycle.
* Quantitative trust criteria beyond deliberate N=1 -> 2 -> 5 -> 10 trials.

=== Open / requires empirical or separate design input

* First local agent invocation API/permissions and measured diff-bounding policy.
* Whether first DMC dogfood needs continuing reviewer context.
* Which accepted task is safe for first dogfood; not Family Cycle 2 absent
  separate authorization.

== 16. Bounded implementation sequence

Implementation remains unauthorized pending review/acceptance. If authorized:

. *Reducer/replay proof:* typed model/profile, finite routes, deterministic
  reduction, atomic state/checkpoint, executable A--H tests; no real agent.
. *Git/evidence proof:* fixture repositories, transaction/scope/range checks,
  fixed observations, anomaly/crash reconciliation, progressive links.
. *N=1 vertical proof:* ordered prompt, result validation, fake/subprocess
  adapter, tiny fixture end to end.
. *Real local adapter at N=1:* disposable repository, then separately authorized
  routine documentation/tooling; no semantic Domain dogfood first.
. *Bounded multi-hop/DMC profile:* optional supervisor, N>1,
  suspension/rebaseline, then separately approved DMC-shaped dogfood. Increase N
  only from observed checkpoints; do not infer Cycle 2 authority.

Each slice must be independently useful/reviewable and may falsify later slices.

== 17. Rejected alternatives

* Workflow DSL/graph, database/event store, one class/service per noun: finite
  data, Git, and one engine cover the evidence.
* DMC generic states or Trusted-Ingress default chain: historical overfit.
* Mandatory review gates: capability is not obligation; each needs a distinct
  epistemic/falsification/authority purpose.
* Fixed review cap/convergence score: E4 falsifies the former; V1 cannot safely
  compute the latter.
* Always-on supervisor or coordinator semantic commits: duplicate mechanics,
  blur authority/authorship, and add failure modes.
* Per-Hop committed raw/manifests or Project Memory state: verbose duplicate
  history with retention/governance risk.
* Provider plugin/DI framework, universal adapter, concurrency/queues/distributed
  fault tolerance: no V1 evidence.

== 18. Risks and independent-review acceptance

The reviewer should attack whether profile data is already a disguised DSL;
Run/Hop/Finding duplicate Git; supervisor authority is too broad; agent commits
fit the adapter/failure model; gitignored state is sufficiently resumable;
profile authors can recreate ceremony; Finding identity survives
reclassification; adapter “freshness” is provable; policy-bounded routing is
mistaken for command containment; or DMC dogfood still overfits history.

The design remains proposed unless a fresh independent reviewer can establish:

* the reduced architecture follows the two waves rather than restating the
  hypothesis, and no remaining abstraction can be deleted;
* generic mechanics overfit neither DMC nor Trusted Ingress;
* supervisor choices are finite and below human semantic authority;
* E4 converges, E3/XRef reroutes, F-002 remains advisory, Cell Codec can discover
  closure blockers, and deletion-authority re-entry is safe;
* tiny work avoids ceremony, one residual minor can finish, and N=1 is useful;
* Git remains factual authority and state is minimal/reconstructable;
* Project Memory, run history, durable reviews, and transient material remain
  separate;
* future Sonar/retrieval cross narrow boundaries without present machinery;
* the five slices are materially smaller than the hypothesis space; and
* no wording grants implementation, DMC Cycle 2, Trusted Ingress, or
  architecture-acceptance authority.

Until that review completes and its findings are resolved, this is only a
proposed formal architecture design.
