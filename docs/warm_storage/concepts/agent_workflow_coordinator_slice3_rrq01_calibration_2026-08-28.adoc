== Method and sample

The eleven ranges below were chosen deliberately rather than by repository
census: Coordinator Slices 1--2, DMC Cycle-1 work, Trusted-Ingress
implementation/correction and documentation work, plus a small mechanical
Project-Memory documentation change. Measurements are reproducible at baseline
`a079a05` with:

[source,bash]
----
git rev-list --count BASE..HEAD
git diff --name-only BASE HEAD | wc -l
git diff --numstat BASE HEAD
git diff --binary BASE HEAD | wc -c
git diff --name-only BASE HEAD | awk -F/ '{print $1}' | sort -u
----

`Diff bytes` is the byte count of Git's binary diff representation, not a token
count. `Durable .adoc bytes` is the aggregate size at `HEAD` of changed `.adoc`
artifacts; it is measured artifact size, *not* reconstructed prompt context.
A dash means no changed durable `.adoc` artifact in that range.

== Observations

* Tiny and ordinary corrections in this sample are 9,786--62,325 diff bytes and
  3--13 files. Single substantial implementation Hops reach 98,964 bytes and
  10 files.
* Broad review/correction histories are materially larger (129,251--352,746
  diff bytes) and have durable documents far larger than a useful expanded
  prompt component. They demonstrate why references are preferable to copying
  whole historical records.
* The measurements support deterministic boundaries that exercise both inline
  and omission paths. They do not establish a model context window, semantic
  importance score, or a reason to reject a valid large change.

== Minimal V1 decision

[cols="2,3,4",options="header"]
|===
|Bound |Value |When exceeded

|Selected natural-language component inline size
|65,536 bytes (64 KiB) per component
|Do not expand that component. Record its path, pinned revision/digest, byte
size, and retrieval reference in the omission/reference manifest.

|All bounded evidence/context inline size
|196,608 bytes (192 KiB) total
|Stop adding optional bounded evidence/context; record every excluded item and
its usable repository/artifact reference in the manifest. The deterministic
selection order remains recorded.

|Inline Git diff evidence
|65,536 bytes (64 KiB) *or* more than 12 changed files
|Do not copy the expanded diff. Record base/head/range, changed-path list or
reference, measured size/count, and a usable Git retrieval reference in the
manifest.
|===

No retained raw-execution-output limit is adopted: the accepted architecture
already treats expanded prompts, stdout/stderr, full logs, large diffs, and
copied files as transient. A persistence limit would be an additional contract,
not a need demonstrated by this calibration.

These values keep normally sized, deliberately selected sources usable while
forcing the substantial and broad histories above through the visible-reference
path. The per-component limit admits each current Coordinator authority source
individually; the total permits their selected combination plus concise evidence
without making an entire repository history prompt material.

== Safety and portability

Exceeding a bound is *omission/reference*, never semantic rejection. The
coordinator, not an LLM, measures and records omissions. Routing-critical
structured identity, provenance, scope, routes, process, evidence references,
and output contract are outside this optional inline pool: they must be present
and validate, or the result fails closed. No item is silently truncated.

The values are V1 repository prompt/evidence hygiene only. They deliberately do
not encode GPT, Claude, or any provider context capacity, session window,
resume limit, or routing policy.
