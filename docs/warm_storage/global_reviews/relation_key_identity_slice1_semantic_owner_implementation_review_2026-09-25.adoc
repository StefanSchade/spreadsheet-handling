== Implementation assessment

The implementation satisfies the accepted relation-key contract:

* Missing returns no identity; String, Boolean, Number, Date, and DateTime
  identities are category-tagged, so native Boolean/Number and String/Number
  equality cannot leak into the relation.
* String payload remains exact, including whitespace.
* Number identities use exact integer or `as_integer_ratio()` material and
  handle infinity independently. Focused probes confirm the required
  float32/Python-float and int64/float64 non-promotion cases, plus
  `numpy.longdouble` without a lossy `float()` round trip.
* DateTime identities use exact rational day coordinates. Naive values use
  wall-clock coordinates; aware Python and pandas values use UTC-instant
  coordinates; Date remains separate. No NumPy cross-unit comparison is used.
* A frozen, opaque `RelationKeyIdentity` holds all component tokens, making
  collection hashing and owner equality one operation. Composite order and
  Missing-component rejection are covered.

The contract tests cover the accepted owner matrix, including Missing
carriers, category boundaries, exact Number behavior, equality/hash agreement,
the naive NumPy/pandas/Python non-transitive native DateTime triple, aware UTC
identity, Date/DateTime separation, and composites.
