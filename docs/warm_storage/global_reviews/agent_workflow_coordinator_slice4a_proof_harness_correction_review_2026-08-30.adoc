== 4. S4H-R2 -- operator exit semantics -- CLOSED

`proof_exit_status(result)` returns `0` only when the proof is an established,
completed Hop:

[source,python]
----
result.error is None
and real_hop is not None
and real_hop.vertical is not None
and real_hop.outcome is not None
and real_hop.outcome.acceptance == "established"
and real_hop.run.status.value == "completed"
----

otherwise `1`; `main()` now returns `proof_exit_status(result)`.

Traced (fake, no provider), matching the required operator semantics:

* *Authoritative success* -> `vertical` present, `acceptance=established`,
  `run_status=completed` -> exit *0*.
* *Post-spawn uncertain / `reconcile_required`* -> `vertical` is `None`
  (short-circuits before the `acceptance` check) -> exit *1*, while the durable
  summary still records `reconcile_required`, `hop_used=1`, retained dispatch.
* *Pre-spawn / local failure* -> `result.error` set -> exit *1*, durable summary
  with `hop_used=0`, no retained marker.

Confirmed this is *only* an operator signal:

* *Durable files remain authoritative.* The summary/provenance write path is
  unchanged (apart from the field rename); the exit code is derived read-only from
  the already-computed `ProofHarnessResult`.
* *Coordinator Run/reducer/result semantics unchanged.* In the uncertain path
  `result.error` is still `None`; the nonzero exit comes from inspecting
  `vertical`/`acceptance`/`run.status`, not from altering the reducer, the
  recovered Run, or `error`. `slice4.py` is untouched.
* *No retry behavior added.* `run_disposable_proof` still runs exactly one Hop;
  `proof_exit_status` performs no execution.
* *No new route/authority semantics.* The helper only maps an existing outcome to
  a shell code.

`S4H-R2` is closed.
