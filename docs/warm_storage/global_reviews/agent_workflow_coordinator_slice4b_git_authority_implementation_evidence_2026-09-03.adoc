== Implemented authority model

`RoutingResult` has one required nullable `commit_intent` field. When present,
it is exactly `{paths: [repository-relative paths], subject: string}`. It is
strictly validated and correlated by the existing structured-result envelope.
It is distinct from `claimed_commits`: claims still describe agent assertions
about commits that already exist. A Coordinator-created commit is observed Git
reality, not a manufactured agent claim.

The one trusted write surface is `trusted_commit()` in
`scripts/workflow_coordinator/git_facts.py`. It accepts a registered/expected
checkout, base HEAD, authorized scope, semantic intent, and WorkItem/Hop
identities. It exposes no arbitrary Git argv or command selection.

Before staging it verifies checkout identity, unchanged HEAD, submodule state,
the existing Conventional-Commit-compatible subject rule including WorkItem/Hop
tokens, normalized explicit paths, scope membership, no pre-existing staged
state, and an exact match between intent and all non-ignored dirty paths. It
rejects absolute, escaping, duplicate, and ambiguous paths. Unrelated tracked
or non-ignored untracked state fails closed and is preserved.

The only write commands are an explicit-path `git add -- <paths>` and one
ordinary `git commit -m <subject> --`. The boundary then independently observes
Git again and requires one non-merge base-to-HEAD commit, the exact intended
committed path set, requested subject, and a clean relevant worktree. The
observed commit hash is authoritative.

== Vertical ordering and failure containment

The vertical now performs validated result -> trusted intent disposition ->
trusted commit when valid -> authoritative Git observation -> existing reducer.
No intent on a clean tree remains observation-only. No intent on a dirty tree,
an invalid intent, a failed/blocked semantic result, or a trusted write failure
continues to the existing fail-closed mechanical preemption path. No reset,
restore, clean, retry, or automatic repair is attempted; any partial staged
state remains observable.

The Slice-4 registered-checkout association is revalidated immediately before a
trusted commit. The production Codex sandbox remains `workspace-write`; it was
not weakened, and the agent no longer needs direct `.git` write access for the
Slice-4B path.

== Tests and residual dispositions

Focused real-temporary-Git tests cover the worktree-only-agent happy path,
authoritative post-commit hash/subject/path facts, exact scope, path escape,
invalid subjects, unrelated tracked and untracked state, an explicit new file,
HEAD/repository preconditions, deterministic staging failure, no remote, and
observation-only/dirty-without-intent paths. The proof-harness fake success now
uses mutation plus commit intent rather than agent `git add`/`git commit`.

L4-R1 remains *WATCH*. Trusted commit failures are retained as mechanical
preemption facts and the correlated raw result remains durable in the existing
Slice-4 state. This bounded change does not redesign Finding/escalation ledger
promotion.

L4-R2 remains *MINOR*. `GitDelta.changed_paths` continues to mean committed
`base..HEAD` range paths, not dirty-worktree paths.

No generic privileged Git service, capability framework, push/fetch/pull,
remote mutation, credential, or SSH authority was introduced. Readiness is
*awaiting independent Slice-4B authority review*.
