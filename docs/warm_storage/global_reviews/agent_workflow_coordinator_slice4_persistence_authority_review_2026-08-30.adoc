== Findings and observations

Disposition classes: BLOCKER, BEFORE-AUTHORIZATION, MINOR, WATCH, NON-FINDING.

=== NON-FINDING A -- WFC-PERSIST-02 is now one coherent contract

The rewritten requirement states a single invariant set -- operational state
shall live on persistent local storage, be unambiguously associated with the
concrete checkout, remain coordinator-controlled, not contaminate repository Git
state, and have its storage/correlation boundary verified fail-closed before the
first Run write and each Hop -- then defines two *specializations* of it:

* *Repository-local ignored state* -- permitted "where the boundary-crossing
  process is trusted not to mutate coordinator state"; repository-specific,
  tracked-policy ignored, Git ignore-resolution preflight, local-exclude alone
  insufficient.
* *External trusted checkout-associated state* -- for the writable real-agent
  boundary; outside the agent-writable workspace, not re-exposed via writable
  additional directories, coordinator-controlled, durable opaque checkout ID,
  validated against current checkout/Git facts, fail closed on mismatch.

These are coherent specializations of the shared invariant, not competing
contracts. The architecture concept (sections R3, 8, and the operational-state
subsection) mirrors the same structure. *Coherent.*

=== NON-FINDING B -- external trusted state is unambiguously required for Slice 4

Section 11.4's new *Persistence boundary* is explicit: the Run snapshot, dispatch
marker, validated/pending result state, result schema/transport,
checkpoints/resume anchors, and other coordinator operational state "use the
external trusted checkout-associated root," and "The real agent receives no
writable exposure to that root." The architecture R3 row and operational-state
subsection likewise state the writable-real-agent boundary "must" use an external
root "that the agent cannot write." For Slice 4 the intended truth -- external
trusted state is REQUIRED -- is carried by the operative Slice-4 authority.

=== MINOR-1 -- "required/preferred" soft token in WFC-PERSIST-02

WFC-PERSIST-02's body says the external root "is required/preferred for the
writable real-agent Slice-4 boundary." Read in isolation, "/preferred" is softer
than "required."

Assessment -- *does not leave an authority hole*, for two independent reasons:
(1) section 11.4's Persistence boundary and the architecture both make the
external form mandatory for Slice 4; and (2) the repository-local form is gated on
"the boundary-crossing process is trusted not to mutate coordinator state," a
precondition the writable real agent fails by construction (the correction itself
states "Ignored-by-Git is not protected-from-agent-write"). So repository-local
writable-agent state is excluded for Slice 4 regardless of the soft token.

Recommended action (non-blocking, at implementer/maintainer discretion): drop
"/preferred" so the sole soft token cannot be quoted out of context. This is a
one-word clarity edit, not a contract change, and is not required for acceptance.

=== MINOR-2 -- residual "configured root" / "local state" phrasing in the architecture

In the architecture operational-state subsection, "Generated `checkpoint.adoc`,
compact results/observation manifests, and optional raw material share that
configured root" and "The resume promise is same-checkout only while this local
state persists" retain phrasing written for the single-root model. They remain
*coherent* -- "that configured root" resolves to whichever gated form applies, and
"local state" means local-storage state (WFC-PERSIST-01/02 sense), which the
external-to-workspace form still is (external to the workspace, still local disk).
No contradiction, but a future consolidation pass could disambiguate. WATCH-level
only.

=== NON-FINDING C -- checkout identity is minimal and sound; no registry subsystem

The V1 association is: canonical checkout path + Git common-dir/git-dir fact +
one coordinator-generated opaque checkout UUID, recorded in "minimal
coordinator-controlled persistent state outside the workspace," validated against
current checkout/Git facts and Run/Hop/HEAD correlation fail-closed, with
moved/renamed/mismatch requiring "explicit maintainer intervention/re-registration"
and *no automatic reassociation*.

Checklist:

* UUID is not treated as repository-identity proof -- "The UUID is not a security
  proof: authority also requires current fail-closed Git/checkout and Run/Hop/HEAD
  correlation." *Pass.*
* Canonical path alone is not sufficient authority -- authority additionally
  requires current Git/checkout facts and Run/Hop/HEAD correlation. *Pass.*
* Current Git reality independently rechecked before writes/Hops -- *Pass*
  (unchanged WFC-GIT-01/02 + WFC-PERSIST-06 restart revalidation).
* Same-checkout resume preserved -- *Pass* (resume promise explicitly same-checkout
  while state persists).
* Moved/renamed/mismatched checkout fails closed -- *Pass* (pending explicit
  maintainer intervention).
* Explicit maintainer re-registration acceptable for V1; no hidden automatic
  reassociation -- *Pass*.
* Smallest reasonable mechanism, not a registry-in-disguise -- *Pass*. Both FTR
  and architecture explicitly forbid a "repository registry service," database,
  event store, append-only log, automatic reassociation, cross-repository
  workflow, and multi-worktree orchestration, and defer them. The permitted small
  persistent mapping is bounded as an implementation detail, matching the
  reviewed-decision minimality.

=== NON-FINDING D -- trust boundary applied consistently

The architecture states plainly "Ignored-by-Git is not protected-from-agent-write"
and requires the enumerated trusted state (Run snapshot, dispatch/in-progress
marker, validated/pending result, schema/result transport, checkpoints/resume
anchors, other operational state) to sit outside the agent-writable workspace and
not be re-exposed via writable mounts/additional directories. Authoritative
trusted state therefore cannot be writable by the execution agent. This does not
claim whole-filesystem security and does not recast the Codex sandbox as a
hostile-code sandbox: WFC-SEC-01 ("not a hostile-code sandbox") is untouched and
"V1 does not promise whole-filesystem cleanliness" is retained. *Consistent.*

=== NON-FINDING E -- Slice-1/2/3 accepted proofs remain valid

The repository-local ignored-state form and its tracked-ignore / `git
check-ignore` / local-exclude-insufficient rules are preserved verbatim in intent,
so Slice-2's tracked-ignore fixtures (FTR 11.2) remain valid for the trusted/fake/
local boundaries where that form is permitted. Slice-2 evidence is not declared
obsolete. Slice-3 fake/subprocess mechanics are untouched. No historical proof is
retroactively falsified. External-form boundary validation is added as a *new
Slice-4 obligation* (FTR R3 correspondence and section 13 next-action list), which
is an implementation obligation, not a blocker to this authority correction.

=== NON-FINDING F -- atomic resume / reconcile authority not weakened

Moving trusted state outside the repository leaves intact: atomically replaced
`run.json`; atomically published dispatch/in-progress marker; result-never-a-trust-
anchor-merely-by-existing with restart schema-validation + identity correlation +
Git/evidence reconciliation + fail-closed-to-human; valid-but-unreduced result
reduced only after explicit resume and successful reconciliation; same-checkout
resume; no hidden retry; Git authoritative for repository mutation. A resumed Run
cannot rely on stale external metadata alone: WFC-PERSIST-02 now requires current
fail-closed Git/checkout and Run/Hop/HEAD correlation before writes/Hops, and
WFC-PERSIST-06 restart revalidation is unchanged. *Not weakened.*

=== NON-FINDING G -- Git-ownership separation preserved

The correction settles persistence authority only. Section 11.4 states "This
settles no Git-ownership decision: agent-owned Git commits are acceptable in
principle only for one disposable `N=1` proof and are not accepted for routine
real-repository use; coordinator-created semantic commits require a separate
architecture change." The architecture IMPORTANT block repeats this. No trusted
commit helper/broker, delegated identity, or bubblewrap architecture is accepted.
Option A (disposable-proof-only) / Option B (architecture change required)
distinction is intact. *Preserved.*
