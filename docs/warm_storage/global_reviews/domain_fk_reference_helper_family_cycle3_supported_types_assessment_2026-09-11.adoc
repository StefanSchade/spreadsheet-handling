== Authoritative value contracts actually relied upon

* *Ingress value grammar:* the accepted Domain scalar language is closed to
  String, Boolean, Number, Missing, Date, and DateTime
  (`docs/semantic_model/06_project_semantic_model.adoc`, "Domain scalar
  language").  `docs/technical_model/ch08_architecture_details/
  internal_value_model.adoc` owns concrete carrier variants and confirms that
  classification does not normalize: NumPy numerics, `pandas.Timestamp`, and
  `numpy.datetime64` remain their carriers.  Missing recognizes `None`, `""`,
  bounded NaN/`pd.NA`/`NaT` carriers; literal string `"nan"` remains String.
  Error, Time, and Duration are not currently admitted ordinary scalars.
* *Trust boundary:* Trusted Ingress establishes that grammar for managed paths
  (`docs/technical_model/ch06_architectural_layers/architectural_layers.adoc`,
  "Establishing and Re-establishing the Domain Scalar Language").  It neither
  proves FK/Lookup key validity nor performs family-specific resolution;
  direct primitives retain their documented caller precondition.
* *Physical labels and policy names:* a physical DataFrame label need not be a
  string globally, but must be non-missing, hashable, uniquely and
  deterministically comparable, and scalar-addressable
  (`docs/technical_model/ch04_concepts/crosstab_binary_xref.adoc`,
  "Physical frame column label").  FK/Lookup configuration and v2 provenance
  name source/target frames and columns by strings; that narrower configuration
  requirement is legitimate and is not a claim that all DataFrame labels are
  strings.
* *Family contract:* FK helpers materialize target payload next to a source FK,
  are derived presentation rather than canonical payload, and use v2 policy /
  current-run provenance for identity (`docs/technical_model/ch04_concepts/
  fk_helper_metadata.adoc`).  Resolution authority is source FK plus current
  target, never a helper cell.  A lookup miss produces `""`; a successful
  lookup may also legitimately produce `""`; therefore the cell cannot tell
  resolved from unresolved.
* *Sink representation:* visible spreadsheet payload is intentionally a string
  substrate; XLSX and ODS parsers stringify cell payload at their table-block
  boundary (`ADR-VISIBLE-CELL-TYPING-STRING-SUBSTRATE`).  This is an adapter /
  projection concern, not FK-family authorization to coerce canonical in-memory
  values.  `LookupFormulaSpec` is framework-authored controlled output Intent,
  not an ordinary input scalar.

== Mismatches and dispositions

. *Genuine defect -- FK validation does not implement the authoritative
  Missing set.* `check_unresolvable_fks` does not treat `""` as Missing even
  though the current scalar authority does; it consequently reports a blank FK
  as unresolvable unless the target happens to contain a blank key.  Its local
  normalizer also does not recognize `pd.NA`/`NaT` consistently.  The same
  narrow local test appears in `check_helper_values` and `_norm_key`.
  `check_duplicate_ids` is different: after `astype("string")`, supported
  Missing carriers are pandas `<NA>`, so its `str(idx) != "nan"` exclusion
  does not exclude them and multiple Missing target IDs are reported as
  duplicate findings.  Whether those IDs are invalid identity, ignored rows,
  or duplicate findings remains UNDECIDED; no change to
  `check_duplicate_ids` is authorized by C3-S1.  This is a target-key identity
  policy question, not a change to the accepted rule that an unresolved
  *helper* cell may visibly be `""`.
. *Missing/ambiguous family key contract.* FK enrichment stringifies keys but
  Lookup enrichment delegates native equality to pandas.  Neither public
  signature nor FK/Lookup reference documentation declares whether Number,
  Boolean, Date, DateTime, and String representations may share a key domain,
  whether trimming is permitted, or what collisions such as `1` / `"1"` mean.
  Existing tests establish no such matrix.  This is not evidence to add
  arbitrary-type support or to normalize globally.
. *Deliberate family narrowing.* Policy/provenance identifiers are strings;
  formula-mode values are controlled Intent rather than payload; unresolved
  helper misses use `""`.  These are current scoped requirements, not defects.
. *Inherited authoritative behavior.* Ingress acceptance, scalar carrier
  variants, no general normalization, and Date/DateTime category membership
  are already decided globally.  Family code may rely on them but must not
  revise them here.
. *Sink representation outside the family.* Spreadsheet readback turns visible
  payload into strings.  This explains why date/native type roundtrip is not a
  family guarantee; it does not justify pre-render coercion in FK helpers.

== Exactly one smallest safe next implementation slice

*SELECTED: C3-S1 -- make `check_unresolvable_fks` and `check_helper_values`
missing-aware using the accepted shared predicate; implementation is NOT
STARTED.*

This is safe because it changes only validation findings for values the
authoritative scalar model already classifies as Missing.  It does not choose
key equality for non-missing types, change enrichment/map materialization,
change v2 policy/provenance, alter a public signature, or modify adapters.

Likely files::

* `src/spreadsheet_handling/domain/validations/fk_helpers.py` -- replace the
  narrow local missing tests in `check_unresolvable_fks` and
  `check_helper_values` only.
* `tests/unit/domain/transformations/test_fk_helpers_*validation*.py` (or the
  existing FK validation test owner) -- focused boundary cases.

Acceptance criteria::

* `check_unresolvable_fks` produces no finding for every supported Missing
  carrier (`None`, `""`, float/NumPy NaN, `pd.NA`, `NaT`) and still reports
  literal String `"nan"` when it does not resolve.
* A non-missing unresolved FK remains a finding; source-FK/target resolution,
  not helper-cell text, remains authority.
* `check_helper_values` does not falsely compare a missing source FK; existing
  successful target-payload and unresolved-helper behavior remains unchanged.
* `check_duplicate_ids` remains unchanged.  Whether Missing target IDs are
  invalid identity, ignored rows, or duplicate findings remains UNDECIDED.
* Focused tests demonstrate no string conversion / trim policy is newly
  introduced, and the existing FK validation suite remains green.

Why Cycle 3:: it reconciles an actual family validation path with the already
declared supported Missing carrier set.  It is not a scalar-model redesign or
a general normalization utility.

== Unresolved / uncertain questions

* Should FK key identity be a declared subset (for example String-only) or
preserve selected non-missing scalar carriers?  If selected carriers are
allowed, what are equality and collision semantics across `1`/`"1"`, Boolean/
Number, temporal values, and whitespace?  Current FK string-map and Lookup
pandas-merge paths disagree.
* Are missing target-key values invalid identity, ignored rows, or duplicate
validation findings?  Current `check_duplicate_ids` is not a clear contract.
* Should a resolved target helper payload that is itself a Missing carrier be
preserved verbatim (current materialization behavior) or be normalized at a
defined projection boundary?  The accepted unresolved contract decides neither
this nor a new sentinel.
* What type-specific contract, if any, is required for Date/DateTime helper
payload before a string-substrate workbook roundtrip?  Global category
membership is settled; family behavior and sink fidelity are not.
* Lookup mismatch's textual, trimming comparator differs from pandas merge.
Its relation to Lookup public behavior needs a separate bounded decision.
* Spreadsheet Error has no current distinguishable admitted carrier; no family
support can be specified until a real boundary supplies one.
