== 3. Conformance review

=== 3.1 RepositoryPolicy v2

* Only `RepositoryPolicy` moves to v2 through the new `_policy_version()`; the
  shared `_version()` still accepts only 1 (probe: `_version(2)` rejects), so
  WorkItem, profile, manifest, result, Run, and dispatch schemas are unchanged.
* `governance_paths`, `work_item_scope_ceiling`, `max_autonomous_hops` are in the
  `_fields(required=...)` set; the dataclass has no defaults; no inference exists.
* v1 rejects with `repository policy schema_version 1 is unsupported; migrate to
  schema_version 2`, evaluated before field validation, so a v1 document fails on
  version rather than on missing fields. Version `3`, `true`, `'2'`, `2.0` reject.
* Unknown v2 fields (`evidence_commands`) and duplicate YAML keys still reject.
* `max_autonomous_hops` uses `_integer(positive=True)` (booleans reject) and is
  bounded by the named constant; `0`, `-1`, `6`, `True`, `'3'`, `null` reject and
  `5` is accepted.
* `scope` is still parsed by `_strings` and used only by `new_run()` as repository
  identity.
* Constructor migration is complete: every `RepositoryPolicy(` call site in
  production (`serialization.py`, `proof_harness.py`) and tests
  (`tests/utils`, `test_operator.py` x3, `test_slice5b.py` x3,
  `test_a1_admission.py`) passes all nine fields; no `schema_version: 1` policy
  YAML remains in the repository.

=== 3.2 Path-shape predicate

`serialization.a1_path_shape()` is one pure boolean predicate matching section
3.1 of the contract. Probes: `.`, `./a`, `a/.`, `..`, `a/..`, `a/b/../c`, `/`,
empty, leading/trailing whitespace, `a//b`, `a/`, `a\b`, `*`, `?`, `[`, `]`, and
non-strings reject; `a`, `a/b`, `.hidden/x` accept. It raises nothing; callers keep
their own exceptions (`ValidationError` in `_policy_paths()`,
`OperatorPreflightError` in `_admit_a1()`) and vocabularies.

It is applied only to the A1 operands: the two policy path fields, WorkItem
scope, phase `authorized_scope`, and governing paths inside `_admit_a1()`.
`_relative_path()`, `_repository_path()`, the component-manifest check,
durable-artifact validation, `git_facts._normalized_path`, CommitIntent, and
trusted-commit semantics are unchanged. The repository root has no accepted A1
spelling.

=== 3.3 Pure A1 admission

`_admit_a1(work_item, profile, policy, governing_paths)` performs no Git,
filesystem, state-root, clock, UUID, or adapter access (source inspection: no
`open`, `Path`, `_git`, `_pinned_text`, `subprocess`, `mkdir`, or `read_text`),
depends only on its arguments, and renders every multi-violation diagnostic from
`sorted(...)` (repeat probe gave identical output). It enforces, in order:

. A1 path shape on WorkItem scope, phase scope, and governing paths;
. containment of every governing path by some governance path via
  `_within_scope`;
. symmetric phase/governance exclusion as
  `_within_scope(p, (g,)) or _within_scope(g, (p,))`;
. `WorkItem.scope` domination by `work_item_scope_ceiling` via `_within_scope`;
. the independent hard Coordinator maximum; and
. `WorkItem.max_autonomous_hops <= policy.max_autonomous_hops`.

Sibling-prefix correctness holds: `_within_scope` is `/`-delimited, so governance
`docs/ai_info` and phase `docs/ai_info_extra/x` (and `docs/ai_info.yml`) do not
overlap. In-memory policies that bypass serialization (empty ceiling, `.`
governance) fail closed rather than admit.

=== 3.4 Preflight / side-effect boundary

`_preflight()` retains its original order: repository identity and read-only Git
observations, state-root absence, the five `_relative_path` inputs, `_pinned_text`
reads, parsing, existing phase/action/evidence/durable-artifact checks, then
selected component resolution and pinning. `_admit_a1()` is called immediately
after the component loop, before the timeout check and return. No side effect
moved earlier; `main()` still allocates the Run ID, calls `new_run()`, creates the
state root, writes `operator-plan.json`, and registers the checkout only after
`_preflight()` returns.

`test_a1_rejection_has_no_run_state_checkout_adapter_or_provider_effects` drives
`main()` with a committed policy that omits `work.yml` from governance and asserts
zero calls to `uuid4`, `new_run`, `register_checkout`, and `CodexCliAdapter`, no
state root, and no fake-executable marker.

=== 3.5 Governing-input set

The tuple passed is `(*input_paths.values(), *selected_component_paths)`: exactly
the five supplied inputs (WorkItem, profile, policy, components manifest, task)
plus each selected component path from `_selected_ids(profile)` resolved through
the manifest. Unselected manifest entries, durable artifacts, and Coordinator
facts are not included.

=== 3.6 WorkItem and Hop ceilings

`WorkItem.scope <= work_item_scope_ceiling` is a new, separate check; the existing
`Phase.authorized_scope <= WorkItem.scope` check in `_preflight()` is unchanged.
Equality and narrower accepted; outside and wider rejected; empty read-only
WorkItem scope accepted. Hop domination is checked against the policy and,
independently, against `COORDINATOR_HARD_MAX_AUTONOMOUS_HOPS`. The one constant
supplies policy validation, `_preflight()`, `_admit_a1()`, and
`run_serial_hops()`; no literal `5` Hop check remains. No budget semantics changed.
