== 1. Verdict

*B -- A2 IMPLEMENTATION ACCEPTED AFTER BOUNDED CORRECTION*

Commit `c5360442` implements the A2 trust boundary as contracted: RepositoryPolicy v3
is the sole command-definition authority, the fixed registry, `evidence_states`,
`supports()` and the registry-collision path are gone, selected commands are
coherence-checked and resolved in canonical preflight before any Run side effect,
execution is `shell=False` / repository-root cwd / `DEVNULL` / exact argv / one
immutable environment snapshot, no stream body is durable, the exact 25-key record
is written under execution-evidence and operator-summary v2, and the post-evidence
Git re-observation preempts terminal success. Consumer migration is exact and A1
still protects both policies. No authority bypass, side-effect-boundary defect,
or regression was found; the full core suite passes.

Two bounded precision gaps prevent a clean acceptance: the WFC-EVID-10 runtime
timeout guard is absent (M1), and the observation-validation seam no longer checks
outcome/audit coherence (M2). Both are local code+test corrections with no
architecture, contract, or documentation change.

=== 3.3 Environment and executable resolution

* One snapshot per Run: `dict(os.environ)` copied once, wrapped in
  `MappingProxyType`, shared by admission, runtime re-resolution and `Popen(env=)`.
  Absent PATH inserts `os.defpath` with source `os.defpath`; present PATH
  (including `""`) is preserved with source `inherited`. PATH digest is SHA-256 of
  UTF-8+`surrogateescape`; probe confirmed against a hand-computed vector including

* Absolute `argv[0]` bypasses PATH; relative-with-`/` joins repository root;
  bare names iterate `PATH.split(":")`, so `PATH=""` is exactly one empty entry

  directories named like the command are skipped (probe P3).
* Symlinks: the invocation spelling is executed and recorded, canonical path is
  `realpath`, fingerprint is the target's (test and probe P6).

* Two edge-case deviations from strict POSIX semantics are recorded as W1

== 5. Findings

=== A2-IR-M1 (MINOR) -- WFC-EVID-10 runtime timeout guard is absent

Observation:: `COORDINATOR_HARD_MAX_EVIDENCE_TIMEOUT_SECONDS` is used only by the
YAML parser (`serialization.py:228`). `prepare_evidence_commands` and
`ProductionEvidenceRunner` accept any `EvidenceCommand.timeout_seconds`.
Evidence:: WFC-EVID-10: "use that one named production constant for schema
validation and the runtime guard". Probe: in-memory definitions with `0`, `-5`,
`10000`, `True`, `1.5` are prepared and executed; `0`/`-5` produce a spurious
`timeout after 0s`/`-5s` error, `10000` runs past the hard maximum, `True`/`1.5`
are persisted as `timeout_seconds`. The Hop ceiling has the matching runtime guard
(`run_serial_hops`, `operator.py:521`; A1 review 3.6).
Risk:: The "hard maximum" is only a schema limit. Positional `RepositoryPolicy`/
`EvidenceCommand` construction (proof harness, tests, any future non-YAML caller)
bypasses it. No current canonical path is affected: YAML validates and the proof
harness hard-codes 10.
Correction (code + tests):: In `prepare_evidence_commands` (pre-Run), reject a
boolean, non-integer, or out-of-range `1..COORDINATOR_HARD_MAX_EVIDENCE_TIMEOUT_SECONDS`
timeout with `EvidencePreparationError`; one parametrized test with in-memory
definitions `0`, `901`, `True`.

=== A2-IR-M2 (MINOR) -- Observation validation lost outcome/audit coherence

Observation:: `observation_error` (`evidence.py:316`) checks identity/authority
fields, status vocabulary, non-empty summary, `command` item types and
`artifact_ref`. It does not check outcome versus exit/signal/error facts, the
stream null-versus-complete invariant, or that the executed argv tail equals the
authored tail.
Evidence:: The pre-A2 validator enforced `pass/fail requires digest` and digest
type; A2 removed `digest` without a successor rule and replaced that test case
with an argv-digest mismatch. 13.2 assigns `vertical.py` to "validate returned
observation shape"; WFC-EVID-02/08 define the null-versus-complete stream
invariant. Probe: 15 inconsistent observations are all accepted and would be
persisted in checkpoint and execution evidence.
Risk:: The exact-record invariants hold only by `ProductionEvidenceRunner`
construction. Any other runner can produce durable records such as `pass` with
`exit_code: 1` and null streams, `body_omitted` contradicting the count, or a
`command` unrelated to the authored definition, while the reducer routes on
`status`. Not reachable through `main()`, which hard-wires the production runner.
Correction (code + tests), local to `observation_error`::
. `pass` requires `exit_code == 0`, `fail` requires `exit_code > 0`; both require
  `signal is None` and complete stream facts (the successor of `pass/fail requires
  digest`); `error` requires a non-null `error_class`;
. each stream triple is all-`null` or (non-boolean integer `>= 0`, 64-character
  lowercase hex, `body_omitted == (count > 0)`);
. a non-empty `command` has `command[1:] == authored_argv[1:]`;
. extend the parametrized malformed-observation hard-stop test with one case per
  rule.
Keep it a small boundary helper; do not add type introspection beyond these
record invariants.
