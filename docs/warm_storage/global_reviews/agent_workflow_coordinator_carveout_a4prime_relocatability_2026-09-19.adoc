=== 2.2 Operated-repository paths are explicit, not self-location

Production paths fall into intentional caller-owned categories:

* the operator receives `--repository` and `--state-root`;
* WorkItem, profile, policy, manifest, task, selected components, and durable
  artifact values are normalized repository-relative inputs read from the
  supplied pinned Git revision;
* the proof harness receives `--proof-root` and constructs its disposable
  repository and trusted state below it;
* the smoke utility receives `--smoke-root` and constructs its disposable
  workspace/result directories below it;
* the Codex CLI receives the explicitly operated repository through `codex
  --cd` while its OS process cwd remains the Coordinator/CLI launch cwd; and
* A2 evidence resolution and execution deliberately use the canonical operated
  repository root as cwd.

These paths do not find WFC or Core. A caller may spell an explicit CLI root as
an absolute or relative filesystem path; normal relative-argument semantics are
caller choice, not hidden WFC discovery, but can depend on the explicit
source-root cwd. A4' acceptance therefore uses absolute operated-repository,
state-root, proof-root, smoke-root, and other explicit CLI filesystem arguments
where cwd ambiguity would matter. A2 evidence commands deliberately run with
the operated repository as cwd; this does not change provider or adapter cwd
semantics.

== 6. Import/invocation model

=== 6.1 Current embedded identity stays

The smallest truthful A4' model is the existing package identity:

----
scripts.workflow_coordinator
----

The lack of `scripts/__init__.py` means `scripts` is currently an implicit
namespace package. That is acceptable for the embedded source stage. Adding an
initializer merely to make the layout look packaged would not make it installed
or eliminate the import-root requirement; final layout and metadata belong to C.

Production intra-package imports become relative. Ordinary tests may keep their
current top-level imports. This distinction removes location coupling without
pretending the eventual standalone import name has already been selected.
Thus A4' retains `scripts.workflow_coordinator` only as the current embedded
source-tree identity at the external module-launch/import boundary, while
removing internal dependence on the implicit `scripts` namespace: production
imports are relative and production code neither discovers nor assumes a
`scripts/...` filesystem parent. The alternate-name `portable_wfc` proof
demonstrates that internal independence; C chooses the final standalone identity.

=== 6.2 One launch model

The supported model is:

[source,text]
----
<python> -m scripts.workflow_coordinator.operator ...
<python> -m scripts.workflow_coordinator.proof_harness ...
<python> -m scripts.workflow_coordinator.codex_adapter_smoke ...
----

The current source-tree import root is supplied explicitly as subprocess cwd
for the initial module lookup. A parent launcher/test can issue the identical
argv plus explicit source-root cwd whether its own cwd is Core root or an
unrelated directory. WFC itself neither discovers nor records Core as import
authority. The operated repository and output roots are separate explicit
arguments.

This is the limit of honest uninstalled-source execution. A bare `python -m`
from an arbitrary child-process cwd cannot resolve an uninstalled package unless
that package's parent is on `sys.path`. A4' must not conceal that Python rule
with `PYTHONPATH`, a `.pth` file, an editable install, a wrapper, or another
bootstrap. C's installed package/entry point is the correct place to remove the
source-root precondition.

The `PYTHONPATH` prohibition also prevents WFC source-root authority from
leaking into A2 evidence-command processes, which inherit the Coordinator
environment while operating inside consumer repositories.

=== 6.3 Relocation proof

The focused test should copy only tracked files belonging to the current WFC
package tree to a temporary neutral source root under a different package name
such as `portable_wfc`; it creates neither packaging metadata nor Git metadata.
Its decisive import sweep, module startup checks, and A3 resource load run in
fresh child Python interpreters, not in the pytest process. Those children
receive no `PYTHONPATH`/`PYTHONSAFEPATH` authority that can expose Core. With the
temporary root selected explicitly, a positive child should:

* import every relocated WFC package module;
* start operator, proof-harness, and smoke `--help` through
  `python -m portable_wfc.<module>`;
* change runtime cwd to an unrelated directory after import where useful and
  load the A3 resource with its accepted ID, version, byte-count, and SHA-256
  facts; and
* assert that `scripts` and `spreadsheet_handling` are not imported and every
  `portable_wfc`/`portable_wfc.*` module origin is beneath the temporary source
  root.

As a negative control, the same alternate package/module command from a neutral
child cwd without selecting the temporary source import root must fail to resolve
the uninstalled relocated package. This demonstrates that the positive result is
due to explicit source-root selection, not a hidden environment/import fallback;
it does not require arbitrary-cwd uninstalled execution.

The alternate name is test evidence that internal imports are truly relative;
it is not a supported compatibility alias or a decision about C's final name.
The test copies files only into pytest temporary storage and does not perform Git
initialization, history work, packaging, or target-repository mutation.

== 9. Operator/proof-harness disposition

Operator:: Remains the one ordinary source-tree execution surface. A4' changes
only import/launch mechanics. CLI flags, explicit path meanings, preflight,
A1/A2/A3, Run/Hop behavior, Git authority, provider binding, and persistence are
unchanged. Direct-file execution was internal/accidental and is removed.

Proof harness:: Remains a fixed historical/disposable regression seam, not a
second Coordinator. Its module/callable path remains testable with a fake
executable. Direct-file support has no value: it is broken today, has no live
caller, and would require exactly the path bootstrap A4' exists to remove.

Adapter smoke:: Remains a separately authorized diagnostic utility. A4' keeps
module startup but grants no live use. Direct-file support is removed for the
same reason.

All three converge on one mechanism: package import plus module execution. No
`__main__.py`, dispatcher, launcher class, shell wrapper, or compatibility shim
is warranted.

+ importlib.resources internal resource
+ test-file/imported-package fixture anchors
----

It deletes three bootstraps and one accidental invocation mode. It adds no
runtime abstraction. The only new test machinery is a focused temporary-copy
probe, which earns its place by directly proving the carve-out property.

Rejected alternatives:

* a launcher abstraction would become a second import authority;
* a root-discovery helper would preserve hidden Core-layout dependence;
* conditional relative/absolute imports would preserve two package models;
* direct-file compatibility would retain the standard-library shadow hazard;
* `PYTHONPATH`, `.pth`, editable install, or an A4' console script would either
  be environment magic or premature C packaging;
* a generic fixture/resource locator would add policy for two fixed test paths;
* renaming every current import would prematurely choose C's distribution
  identity.

Package/import vocabulary here describes a small engineering boundary. It does
not imply plugins, deployment orchestration, a general launcher platform, or a
product-scale CLI system.

== 16. Non-scope

* `git filter-repo`, history rewrite, extraction, copy/move into the target, or

* B anchor/manifest freeze;
