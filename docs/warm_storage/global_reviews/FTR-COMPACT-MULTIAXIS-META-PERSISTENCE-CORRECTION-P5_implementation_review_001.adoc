== Runtime changes

`compact_multiaxis.py` retains the accepted composition. Expand still derives
arguments locally, calls XRef then the historical Cell Codec, optionally
projects a Legend-backed or explicit group, and deletes its temporary frame.
Contract still calls the historical Cell Codec then XRef and deletes its
temporary frame. No public parameter, plan object, in-place mode, Sparse
Defaults call, or Compact metadata fallback was added.

The only compute-adjacent correction is feature-owned snapshot and
restore-to-prior handling for the XRef metadata root. The Compact trace writer
also deep-copies its completed payload before installing the same-ID
replacement.

== CM-1 restore-to-prior behavior

Before primitive delegation, `_snapshot_xref_meta` deep-copies the caller's
entire `_meta.xref_crosstable` root. After all primitive calls, temporary-frame
removal, and optional group projection succeed, `_restore_xref_meta` restores
that copy.

The cases are explicit:

* absent prior root: omit `xref_crosstable`;
* explicitly empty prior mapping: omit the structurally empty root;
* prior root without this `config_id`: restore all unrelated IDs exactly;
* prior root with this `config_id`: restore the caller-supplied entry exactly;
* nested caller mappings and lists: restore a defensive copy, with no alias
  back to caller-owned collections.

The implementation does not rewrite the internal XRef record to a plausible
public frame. Bare XRef is unchanged. Malformed caller state is neither
normalized nor silently repaired: primitive behavior remains authoritative,
and successful restoration preserves the snapshotted state.

== XRef ordering behavior after correction

Repository search and focused probes found no Demo, Worldbuilding, pipeline,
test, documentation, or other runtime consumer that depends on the accidental
same-run carry from Compact expand into Compact contract.

Post-correction precedence is:

. explicit `column_keys`;
. a legitimate caller-supplied, pre-existing same-ID XRef `column_keys`;
. XRef's existing first-occurrence order derived from the encoded relation.

An internal entry created by Compact expand is suppressed, so an expand then
contract sequence with the same ID uses relation-derived order unless one of
the two legitimate authorities is present. For ordinary dense rows, relation
order preserves physical matrix order. For sparse rows, derivation is
deterministic for a given relation row order but intentionally not invariant to
source-row reordering: first non-empty occurrence may produce `B,A` rather than
`A,B`. Repeated roundtrips converge to that derived order. Tests pin each case;
the diagnostics trace is not promoted to operative intent.

== Diagnostics-trace contract

`_meta.compact_multiaxis[config_id]` remains persistent, feature-owned, and
diagnostics-only. It records public input/output frames and the executed
high-level configuration. It is read by no runtime transformation and is not
configuration, inverse intent, precedence, or fallback.

`value_columns`, `column_keys`, and `canonical_order` record a defensive copy
when authored and the existing `None` omission representation otherwise. The
implementation never back-fills inferred XRef resolution into the trace.
Normalized fields record their effective executed representation, including
normalized `code_groups` keys. Collection and mapping fields are defensively
copied. The trace makes no Sparse Defaults claim and contains no internal frame
name.

== Trace lifecycle and deferred commands

Successful same-ID writes replace one mapping value atomically; different IDs
coexist; failed reruns do not install a new trace; and absence from a run does
not prune any entry. There is no execution-history list.

The repository has no existing feature-local command owner for exact trace
drop/rename. The implementation therefore follows selected outcome 3 and
creates
`docs/backlog/FTR-COMPACT-MULTIAXIS-TRACE-LIFECYCLE-COMMANDS-P5.adoc`. It
reserves explicit ID-keyed drop and collision-safe rename/migration, carrier
consumption, and schema-maintenance interaction while prohibiting staleness
inference, frame inference, a generic metadata collector, and a generic frame
ontology.

== Schema-maintenance behavior

`compact_multiaxis` moved from `BLOCKED_ROOTS_BY_NAME` to the explicit
ignored/non-blocking root classification. `ReferenceRoot.COMPACT_MULTIAXIS`
remains to avoid unnecessary compatibility churn, but has no blocking
registration. The canonical metadata-reference-surface registry matches the
runtime classification.

Tests now use a payload emitted by `expand_compact_multiaxis` and prove that
rename and drop are not blocked and do not pretend to maintain diagnostic
fields. XRef, Legend Blocks, Sparse Defaults, split-by-discriminator, plugin,
foreign-key, constraint, and lookup-policy behavior remains covered by the
unchanged schema suite.

== Registry and documentation alignment

`meta_registry.yaml` names both Compact directions as producers, names no
runtime semantic consumer, and distinguishes persistence carriers that merely
serialize/deserialize. It records diagnostics-only meaning, non-authority,
same-ID replacement, different-ID coexistence, no Sparse Defaults behavior,
non-blocking schema classification, and the deferred lifecycle FTR.

`pipeline_step_registry.json` now lists every parameter in both current public
signatures, including the historical Cell Codec arguments used by
Worldbuilding. Its composite contract records prior-XRef reads and internal
XRef suppression, rather than a persistent wrapped-leg write. A mechanical
architecture test prevents parameter/default drift.

Functional, User, and Technical documentation now explains the actual
XRef/Cell Codec/optional Legend composition, temporary-frame removal, internal
XRef suppression, diagnostic trace, and separately configured Sparse Defaults.
The `unknown -- planned` release-note section records the observable metadata
correction.

== Mutation and failure atomicity

The functions continue to return new frame mappings. The XRef snapshot and
Compact payload use `deepcopy`; intermediate primitive results are local; and
the trace replacement occurs only after primitive success and temporary-frame
removal. Group projection also completes before restore and trace installation.
No exception is caught or weakened.

Tests mutate authored nested collections after success and verify the trace and
restored prior XRef value do not alias them. Failure tests compare the whole
caller mapping with its pre-call copy and assert no target, temporary frame,
partial metadata, or cleanup directive appears.

== Persistence and carrier behavior

Structured JSON persistence contains the Compact diagnostics trace but no
internally-created XRef entry or temporary-frame string after either direction.
Final domain cleanup consumes its directive without pruning the diagnostic
trace or reintroducing a temporary reference. XLSX workbook metadata roundtrip
preserves the trace and the corrected omission. Current Worldbuilding XLSX and
ODS exports both normalize back to canonical data.

Old carriers may still contain inert dangling XRef entries produced before this
correction. No runtime reads those composed-leg entries and no migration is
required.

== Compatibility assessment

Bare XRef and Cell Codec APIs and metadata contracts are unchanged.
Caller-supplied prior XRef entries, including same-ID column order, are
preserved. Compact public signatures are unchanged; registry edits describe
already accepted parameters. Demo and Worldbuilding validation found no
consumer of the accidental same-run carry.

The pipeline binder's existing convention consumes a YAML step `name` as the
bound-step label rather than forwarding it as a callable kwarg. Direct calls
still accept `name`; pipeline config IDs therefore continue to default to the
function's existing output/relation rule. This was not changed because it is a
repository-wide binding convention, not a Compact metadata correction.
