== 3. Implementation shape

`git_facts.py` is a single small seam of direct `git` calls (`subprocess`,
`shell=False`). Every fact is read from Git, never from an invocation result;
the module never resets/cleans/merges/rebases. Public surface:

* `repository_identity` / `observe_repository` -- Git-observed identity, HEAD,
  tracked/non-ignored/submodule state.
* `preflight_hop` -- pre-Hop boundary (identity, HEAD, clean tree).
* `preflight_state_root` -- state-root must be ignored by a *tracked* `.gitignore`.
* `observe_hop` -- post-invocation `base..head` range, changed paths, ancestry,
  merge, scope, pinned-path, safety-cap classification; `claim_mismatch`.

`evidence.py` is a fixed two-entry in-code registry (`diff_hygiene`,
`git_version`) returning `Observation` only. `persistence.py` extends
`recover_uncertain_dispatch(...)` with `actual_commits` so an independently
observed range can be attached to the conservatively charged Hop.

`git_facts.py` and `evidence.py` are *standalone*: no reducer/persistence module
imports them. GitDelta anomalies and `claim_mismatch` are produced but have no
in-tree consumer yet -- consistent with Slice-2 scope (prove facts), with
enforcement wiring belonging to later slices.

=== S2-R1 (IMPORTANT) -- WFC-GIT-08 not exercised; coverage claim overstated

`agent_workflow_coordinator_slice2_implementation_2026-08-27.adoc` lines 30--45

trailers, or prospective subject convention were added." So WFC-GIT-08 is
neither implemented nor exercised, yet the evidence asserts "WFC-GIT-01..08
covered."

WFC-GIT-08 to be exercised and it is not; the committed evidence overstates
coverage. A reviewer cannot accept the slice against the contract as written
without either the code or the contract being corrected. Reinterpreting the
contract silently is disallowed.

Smallest correction direction:: Two admissible resolutions, both bounded:
(a) *Implement now* -- add a small subject-projection postcondition
(`git log --format=%s base..head`) and a real-Git test asserting subjects are
readable/Conventional-Commits-shaped; feasible because the FTR states subject
validation is a postcondition, but it presupposes a subject *convention* that
does not yet exist before the prompt/adapter (Slice 3). OR (b) *Formally defer*
-- amend FTR 11.2 acceptance item 1 to read "WFC-GIT-01..07 exercised;
WFC-GIT-08 subject-projection deferred to Slice 3 (no workflow-produced subjects
exist until an invocation boundary exists)", and correct the evidence claim to
"WFC-GIT-01..07 covered; WFC-GIT-08 deferred."

Architecture/FTR reopening:: YES for path (b) (amend accepted acceptance text +
evidence). The choice between (a) and (b) is a maintainer/architecture scoping

=== S2-R2 (MINOR) -- WFC-EVID-03 category population partial

`TRUSTED_EVIDENCE` registers `diff_hygiene` and `git_version`. WFC-EVID-03 names
categories: mandatory Git facts, profile-selected tests, architecture guards,
source/style checks, diff hygiene. Mandatory Git facts are legitimately produced
by `git_facts.py` rather than an `EvidenceCallable` (compliant). The evidence
*mechanism* -- fixed registry, trusted argv, trusted cwd, `pass/fail/error/
not_run`, and `selected=False -> not_run` (the profile-selection lever) -- is
fully proven, which is exactly what 11.2 acceptance item 5 requires. Profile-
selected tests are intrinsically tied to profile machinery (Slice 3), giving
implicit textual authority for their deferral. Nonetheless the blanket evidence
claim "WFC-EVID-01..04 covered" is slightly generous with respect to
WFC-EVID-03's category enumeration (architecture guards / source-style callables
are neither registered nor deferred in text). Correction: reword the evidence to
"WFC-EVID-01..04 mechanism proven; category population (tests/architecture/
source-style) follows profile-selection in Slice 3," or add one representative
argv entry. The registry need not be inflated; the mechanism satisfies 11.2.

=== S2-R3 (MINOR) -- misleading anomaly label for an invalid `base_head`

`observe_hop` runs `merge-base --is-ancestor base_head HEAD` with `check=False`
and treats any non-zero exit as "divergent or rewritten ancestry". Verified with
a real repo: a non-existent SHA (`0*40`) and a *tree* object both fail closed
(empty commits, anomaly present) -- correct fail-closed behavior -- but each is
labelled "divergent or rewritten ancestry", indistinguishable from genuine
history rewrite. Correction: pre-verify the anchor (`git rev-parse --verify
base_head^{commit}` / `cat-file -e`) and emit a distinct "unresolved base anchor"
anomaly. Non-blocking observability only; the coordinator still stops.

=== S2-R4 (MINOR) -- state-root policy trusted from working-tree content

Verified: a *tracked* `.gitignore` whose ignore rule exists only in an
uncommitted working-tree edit passes `preflight_state_root` (the source file is
tracked, so it qualifies), even though committed repository policy does not
contain the rule. `git check-ignore` reads working-tree content, and the tracked
check only confirms the *file* is tracked, not that the *rule* is committed. The
"trusted tracked repository policy" of WFC-GIT-06 is thus established from
working-tree content. This is mitigated only because `preflight_hop` separately
rejects the dirty tree (confirmed), but `preflight_state_root` is a standalone
public function and the two are not composed in Slice 2. Correction: document the
ordering precondition (state-root preflight runs only after a clean-tree
preflight) or additionally confirm the `.gitignore` is unmodified. The explicit
acceptance item -- local-exclude vs tracked policy -- is correctly enforced.

`scripts/workflow_coordinator/__init__.py` now holds two consecutive string
literals; only the first is `__doc__`, so the second ("Repository-local mechanics
...") is dead. Cosmetic; classify Minor at most.

== 9. Crash / reconcile

VERIFIED. `recover_uncertain_dispatch`:

* no marker -> Run returned unchanged, no charge (proven);
* marker -> conservative exactly-one Hop charge, `invocation_status=
  acceptance_not_disproved`, `outcome=uncertain`;
* `actual_commits` are attached from the caller's *independent* `observe_hop`
  observation, not from any marker/claim field (DispatchMarker carries no claimed
  commits, so a lying claim cannot contaminate `actual_commits`);

  charge (`hop_used` stays 1);

  replay; `resume_after_reconcile` requires explicit resume, clears anomalies
  precondition, and forbids stale-route return;
* `marker.base_head` is a trusted WFC-PERSIST-01 resume anchor and is used as the
  charged Hop's base; cross-check against Run `current_head` raises on mismatch.
