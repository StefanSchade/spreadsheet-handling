== 2. Verdict

*B -- A1 CONTRACT ACCEPTED AFTER BOUNDED CORRECTION.*

The authority design is sound and minimal: the governing-input set, symmetric
exclusion, both domination relations, policy-only v2, the migration values and
the `_preflight` refusal boundary survive falsification. No authority hole exists
in the normative text as written. The claim "unresolved A1 questions = none" is
falsified by four bounded gaps (findings I1--I4): a false factual premise about
repository-root handling, an over-broad and not behavior-neutral normalizer
consolidation, an unspecified admission surface for the consumer integration
test, and an omitted production seam (`proof_harness.py`). None requires
re-planning A1 or reopening the carve-out plan. A1 remains one bounded slice.

containment check can be stated over it directly.

* *unselected components:* correctly excluded. They are never read.
* *durable artifacts:* correctly excluded. They are phase-scoped mutation

  Coordinator as authority.
* *tests, Makefile, `conftest.py`, harness, provider config, evidence code:* not

== 4. Governance-path semantics

Accepted with correction I1.

* *Lexical only / no symlink semantics:* correct at this layer. All governing
  reads go through the Git object database at the pinned HEAD (`git ls-tree` exact
  match plus `git show rev:path`); all mutations land only through the trusted
  commit of lexically scoped intent paths plus the clean-worktree gate. `git add`
  refuses paths beyond a symlink, and an edit through a committed in-scope
  symlink leaves the governance target dirty and uncommittable, so the next
  preflight refuses. Filesystem resolution would add nothing. Case-insensitive
  aliasing is watch-only (W1).
* *No root spelling:* correct and necessary. A root governance path would
  overlap every mutation. A root ceiling would be maximal authority. But the
  premise that this "preserves the current strict normalizer" is false (I1).
* *Paths need not exist:* safe. Governance paths only bound other checks.
  Selected inputs still require exact tracked files. Needed for the A3
  reservation.
* *Rejecting overlapping governance roots:* this canonicalizes the value and
  does not change authority. It is not needed for safety, but it is harmless for
  all current data and makes diagnostics unique. Accept.
* *Deterministic diagnostics:* sufficient if sorted offending paths are
  reported, as the contract says.
* *One canonical normalizer:* not behavior-neutral; see section 11 and I2.

== 5. Symmetric phase/governance exclusion

Accepted. `overlap(p, g) = within(p, g) OR within(g, p)` with `/`-delimited
`_within_scope` closes the R3/F1 equality, ancestor and descendant cases.
Mutation authority is enforced only by phase scope: the trusted commit
(`_validated_intent_paths`) and post-Hop observation (`_observe_hop`) both use
`phase.authorized_scope`, and durable artifacts must lie in phase scope. So
checking phase scope, not WorkItem scope, is exact.

Protecting `docs/ai_info` covers every current bundle, sibling bundle, and
selected `docs/ai_info` component. The only non-`docs/ai_info` component (DMC
contract) is named exactly. Symmetric exclusion forbids no current work, and a
narrower governance root remains available by policy revision.

Residual limits that the mechanism does not claim to close, stated precisely in
M1:

* the invariant is relative to the *admitted policy's own* governance paths. A
  Run under a policy that declares different roots can mutate another bundle.
  Today both core policies declare `docs/ai_info`, so this is a consumer
  convention and not a Coordinator guarantee;
* a Hop can still author a *new* bundle inside its mutation scope whose policy
  self-declares governance. It gains authority only through external launch,
  which is consistent with plan 6.2/6.3.

== 6. WorkItem-scope ceiling

Accepted. The direction (`within(w, c)`), equality, the vacuous empty WorkItem
scope, the distinction from identity `scope` (still checked in `new_run`), and
retention of phase ⊆ WorkItem are all correct. Rejecting redundant ceiling
entries canonicalizes the value and does not reduce authority. The readiness
artifact says "should reject" while the FTR says "shall reject" (M2).

Migration cannot over-grant: ceilings copy current WorkItem scopes exactly. The
transitive effect of the ceiling syntax is to forbid the currently accepted `.`
WorkItem/phase scope (I1). That is a deliberate tightening and must be stated.

== 7. Hop ceiling

Accepted. Bool rejection, `1..5`, no default, equality, and an independent
hard guard in both `_preflight` and `run_serial_hops` are correct.
`min(policy, hard)` is the effective bound. The serialization-time upper bound
is therefore canonicalization rather than authority, and either schema or
admission placement is safe. Keep it in serialization, but no named hard-limit
constant exists today: two literal `5`s exist, and the contract's
`COORDINATOR_HARD_MAX_AUTONOMOUS_HOPS` is pseudocode. One shared constant must
feed all three sites (M3). This also keeps WFC-AUTO-01 (N=1→2→5→10 without
redesign) true.

== 8. RepositoryPolicy v2

Accepted. Required authority fields cannot be defaulted safely. Only two real
policies, one aggregate fixture, and bounded test fixtures exist, so rejecting v1
beats compatibility code. `_version()` is shared by all seven document loaders,
so policy-specific validation is the only way to avoid loosening other schemas.
`_fields()` already gives strict unknown/missing rejection. The A2 rule
(additive optional under v2, otherwise v3; no reinterpretation, no silent v1)
is a coordination constraint and does not pre-design A2. No A2 leakage was
found (section 14).

Hidden breakage: `RepositoryPolicy` is constructed *positionally* in production
`proof_harness.py:193` with `schema_version=1`, outside the enumerated seams
(I4). The remaining positional constructions are test-only and are covered by
the contract's fixture-migration clause.

== 10. Admission timing

== 12. Consumer integration-test assessment

The boundary is accepted: the file location, real committed YAML (not
duplicated), consumer IDs allowed in tests, and generic code kept free of DMC
terms. Two points are not settled (I3):

* `_preflight()` is unsuitable against the live repository. It requires a clean
  worktree, `HEAD == expected_head` and an absent state root, and it reads HEAD
  blobs. The test would therefore fail in every dirty development tree,
  including the A1 implementation's own pre-commit validation. It would also
  validate HEAD rather than the change under test;
* "the same admission relation used by `_preflight`" names no surface. None
  exists today.

The test must not reimplement the relations. It should read the worktree bundle
files, parse them with the public loaders, resolve selected components through
the manifest and `_selected_ids`, and call one pure admission function that
`_preflight()` also calls. The integration test then does not depend on DMC
semantics. It asserts only generic relations plus the core consumer convention
that both policies declare `docs/ai_info` and the A3 path.

=== BLOCKING

=== IMPORTANT

*A1-CR-I1 -- Repository root `.` is accepted today; the contract's premise is
false.*

* Evidence: `_relative_path(".")`, `_repository_path(".")` and the manifest
  check all return `.`. `git_facts._validated_intent_paths` treats scope `.` as
  the whole repository. `_within_scope` treats `.` literally, so `overlap(".", g)`
  is false for every `g`. Today a WorkItem/phase scope `.` passes preflight and
  holds whole-repo trusted-commit authority.
* Risk: the normative text rejects `.` for the new fields, and ceiling
  domination then closes the gap transitively. An implementer following
  "preserves the current strict normalizer" and reusing `_relative_path` would
  admit a `.` ceiling. The resulting root-authority phase would be invisible to
  the overlap check, which is an authority hole.
* Action: correct the premise. State that the A1 path predicate rejects `.` and
  that it applies to WorkItem scope and phase scope at admission (deliberate
  tightening). Add the `.` negatives from M5.

*A1-CR-I2 -- The "one canonical normalizer" mandate is broader than A1 and not
behavior-neutral.*

* Evidence: section 11 table.
* Risk: a hidden behavior and diagnostic change across four layers, plus an
  undecided question whether `git_facts` root semantics change.
* Action: bound the mandate. A1 requires one pure path-shape predicate, used
  for the three new policy fields and the operands of the A1 relations (supplied
  inputs, selected component paths, WorkItem scope, phase scope). Each layer
  keeps its exception type and existing diagnostic substrings. List the accepted
  tightenings: `.`; surrounding whitespace in manifest and durable paths; glob
  characters. Explicitly exclude `git_facts._normalized_path` (CommitIntent and
  trusted-commit layer) from A1.

*A1-CR-I3 -- The admission surface for the consumer integration test is
unspecified, and `_preflight` is unsuitable.*

* Evidence: section 12.
* Risk: the implementer either reimplements the relations in the test or
  couples the test to live-repo cleanliness and HEAD.
* Action: name one pure, I/O-free admission function in `operator.py` (parsed
  WorkItem, profile, policy, selected governing paths), called by `_preflight`
  after component resolution and by the integration test. Unit tests keep owning
  pinned/tracked and side-effect behavior.

*A1-CR-I4 -- The production seam `proof_harness.py` is omitted.*

* Evidence: `proof_harness.py:193` `RepositoryPolicy(1, …)` positional; it calls
  `new_run` directly, bypassing `_preflight`. The contract says "No other
  production architecture is required."
* Risk: required fields break compilation, and the implementer must invent
  values and the admission status of a second ingress.
* Action: add `proof_harness.py` to the seams. Declare it the closed historical
  disposable-proof ingress that performs no A1 admission and gains no authority
  from A1. Give it explicit schema version 2 and least values: ceiling equal to
  its WorkItem scope, Hops equal to its WorkItem request, and a governance path
  that does not overlap its scope. State that any reactivation must route
  through `_preflight` admission.
