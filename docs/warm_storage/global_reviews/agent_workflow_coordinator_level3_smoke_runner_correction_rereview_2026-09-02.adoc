== 2. L3SR-R1 -- CLOSED (IMPORTANT)

=== R1-A -- exception type soundness

`CodexCliError` now derives from the provider-neutral `ExecutionNotStartedError`
(`codex_adapter.py:34-35`; `ExecutionNotStartedError(ValueError)` at
`adapter.py:27`). Every `CodexCliError` raise site is genuinely pre-launch:

* unsupported result contract (`codex_adapter.py:149`);
* non-positive timeout (`codex_adapter.py:151`);
* the `except (OSError, ValueError)` wrapper (`codex_adapter.py:161-162`) around
  a `try` block that now contains *only* schema/result path construction,
  `atomic_write_json`/`atomic_write_text` setup, and `subprocess.Popen(...)`
  (`codex_adapter.py:152-160`).

The critical invariant holds. The setup writes are pre-launch. For
`subprocess.Popen.__init__` on POSIX: if `execve` in the child fails, the error
is relayed on the exec-status pipe and `__init__` raises `OSError`
(`FileNotFoundError`/`PermissionError`/...) *before returning*, and the target
provider program never executed; if `execve` succeeds the pipe closes empty and
`__init__` returns normally. A `ValueError` from `Popen` is invalid-argument and
strictly pre-fork. Therefore every `OSError`/`ValueError` caught by this block
implies the provider process did not begin -- the semantic claim behind
`ExecutionNotStartedError` is justified for the one-shot evidence purpose. A
forked child that fails `exec` ran no provider code, so classifying it as
not-started is correct; no lower-level process-state framework is needed.

Crucially, `child.communicate(...)`, `os.killpg(...)`, and
`result.read_text(...)` are all *outside* this wrapper, so no post-launch
failure can be retyped as `CodexCliError`/`ExecutionNotStartedError`.

=== R1-B -- post-launch failure classification

The runner now catches `ExecutionNotStartedError` first
(`codex_adapter_smoke.py:134-137` -> `local_pre_execution_error`,
`invocation_attempted=false`) and any other exception second
(`codex_adapter_smoke.py:138-142` -> `post_execution_error`,
`invocation_attempted=true`). Because `CodexCliError` is an
`ExecutionNotStartedError`, the ordering is correct. The old
`except (CodexCliError, OSError, ValueError)` catch is gone; no generic
`OSError`/`ValueError` catch around `execute()` remains.

Verified:

* *Non-UTF-8 `--output-last-message`* -> `result.read_text(encoding="utf-8")`
  raises `UnicodeDecodeError` (a `ValueError`), propagates raw (outside the
  pre-launch wrapper), hits `except Exception` -> `post_execution_error`,
  `invocation_attempted=true`. Covered by
  `test_post_launch_decode_failure_is_not_reported_as_not_attempted`, which
  launches once (marker written) and writes `b"\xff"` through the production
  result path.
* *Timeout-cleanup `os.killpg` `ProcessLookupError`* (an `OSError`) -> same
  classification. Confirmed by a deterministic monkeypatch probe forcing
  `codex_adapter.os.killpg` to raise `ProcessLookupError` under a 0.05s timeout:
  `smoke_status=post_execution_error`, `invocation_attempted=true`, exit 1, with
  the killpg message in `diagnostics`.
* *Arbitrary `RuntimeError` from the execution path* -> `post_execution_error`,
  `invocation_attempted=true`. Covered by
  `test_unexpected_execution_exception_writes_indeterminate_summary`.

=== R1-C -- pre-execution cases

== 3. L3SR-R2 -- CLOSED (MINOR)

`_write_summary_best_effort` (`codex_adapter_smoke.py:73-78`) wraps
`atomic_write_json` in a guard so recording failure evidence cannot itself raise,
and it is used on every post-root failure path (workspace setup 115,
pre-execution 136, post-execution 141, post-outcome processing 186). The
post-outcome region -- schema fingerprint read (`156`), unexpected
`validated_result` exceptions beyond `ResultValidationError`, and any other
processing error -- is now inside a `try` whose `except Exception`
(`codex_adapter_smoke.py:183-187`) sets `post_execution_error` and writes a
durable summary. The previously avoidable "root exists, provider may have run, no
`smoke-summary.json`" gap is closed.

Truthfulness checks: the original failure is not disguised as success (any
exception forces `post_execution_error` and exit 1); a summary-write failure is
swallowed rather than misrepresented (best-effort by design, the acceptable
unavoidable case); the terminal success write (`188`) is intentionally not
best-effort, which is correct -- if final persistence fails there is nothing
truthful left to persist. Universal crash-proof persistence is not demanded.

Non-blocking residual (WATCH, not a regression): on the `post_execution_error`
path the transport fields keep their `_summary_base` defaults -- `returncode`
`null` (honest unknown), but `timed_out=false` and
`candidate_result_present=false` asserted as known-false though unknown. In the
narrow killpg-on-timeout race the probe showed `timed_out=false` even though the
run actually timed out. This is subordinate to the dominant
`smoke_status=post_execution_error` signal and the `null` returncode, and it is
strictly better than the pre-correction false `local_pre_execution_error`. It
does not reopen R2 and, per the best-effort-semantics guidance, does not warrant
a generalized nullable evidence model. Recorded only as a watch item for a future
optional tightening (e.g. omit or null unknown transport fields when no outcome
exists).

*R2 disposition: CLOSED (one non-blocking residual WATCH).*

== 7. Direct regression review

Reviewed only direct regressions from `f0d79ea7`.

* *Slice-4 exception ordering (primary risk).* In `run_real_one_hop`
  (`slice4.py:188-195`) the handler order is now `ExecutionResultValidationError`
  -> `CodexCliError` -> `ExecutionNotStartedError` -> `Exception`. Because
  `CodexCliError` is now a subclass of `ExecutionNotStartedError`, placing
  `CodexCliError` first is *required and correct*: it preserves the prior
  `CodexCliError -> Slice4Error` translation (with `dispatch_path.unlink`), while
  other `ExecutionNotStartedError` still re-raises, and post-launch failures fall
  to `except Exception -> recover_uncertain(None)` (conservative uncertain
  dispatch retained). Had the old order been kept, `CodexCliError` would have been
  swallowed by the `ExecutionNotStartedError` branch -- the reorder prevents that.
  No regression; the fix is exactly the necessary one.
* `CodexCliError` remains a `RuntimeError` (multiple inheritance), so any
  `except RuntimeError`/`Slice4Error` expectations elsewhere still hold.
* No raw post-launch `ValueError`/`OSError` is retyped as pre-execution in either
  the adapter or slice4 (`except ExecutionNotStartedError` matches only instances
  of that class, not arbitrary `ValueError`).
* `AgentExecutionPort`, semantic validation/correlation, and transport-vs-semantic
  separation are unchanged.
* The runner still executes the adapter exactly once; no retry/resume; no
  Git/Run/Hop/reducer usage introduced (imports unchanged plus
  `ExecutionNotStartedError`).
* Success criterion unchanged: `returncode == 0` and not `timed_out` and a valid
  correlated result (`codex_adapter_smoke.py:172-176`).

No direct blocking or important regression. No new L3SR-R5+ finding warranted
(the R2 residual is a pre-existing default, not a regression).
