== 3. Current Cell Codec behavior [[sec3]]

=== 3.1 Current algorithm

[source,python]
----
def _reject_helper_participating_columns(
    frames: Mapping[str, Any],
    frame_name: str,
    participating_columns: list[Any],
) -> None:
    helper_columns = _helper_columns_for_frame(_meta_from_frames(frames), frame_name)
    rejected = [column for column in participating_columns if column in helper_columns]
    if rejected:
        raise ValueError(
            "helper or derived columns must not participate in Cell Codec "
            f"contraction by default: {rejected!r}"
        )


def _helper_columns_for_frame(meta: Mapping[str, Any], frame_name: str) -> set[Any]:
    helper_columns: set[Any] = set()

    sheets = meta.get("sheets")                                  # Workbook View
    if isinstance(sheets, Mapping):
        sheet_meta = sheets.get(frame_name)
        if isinstance(sheet_meta, Mapping):
            helper_columns.update(_column_name_set(sheet_meta.get("helper_columns")))

    derived = meta.get("derived")                                 # FK + Lookup
    if isinstance(derived, Mapping):
        derived_sheets = derived.get("sheets")
        if isinstance(derived_sheets, Mapping):
            sheet_meta = derived_sheets.get(frame_name)
            if isinstance(sheet_meta, Mapping):
                helper_columns.update(_column_name_set(sheet_meta.get("helper_columns")))       # FK
                enrich_lookup = sheet_meta.get("enrich_lookup")
                if isinstance(enrich_lookup, Mapping):
                    helper_columns.update(_column_name_set(enrich_lookup.get("helper_columns")))  # Lookup


def _column_name_set(value: Any) -> set[Any]:
    if value is None:
        return set()
    if isinstance(value, str):
        return {value}
    if isinstance(value, Mapping):
        return set(value)
    if isinstance(value, Iterable):
        return set(value)
    return set()
----

One generic parser is applied to three carriers with two genuinely different
owner shapes (plus the Workbook-View shape):

[cols="2,4",options="header"]
|===
| Carrier | Owner shape

| `_meta.sheets[frame].helper_columns`
| Workbook View, durable: `list[str] \| None` (`workbook_views.py::_optional_string_list`)

| `_meta.derived.sheets[frame].helper_columns`
| FK, transient: `list[{column, fk_column, target, target_key, value_field}] \| None`
  (`fk_helpers/provenance.py::_write_helper_provenance`, confirmed against
  `docs/technical_model/ch04_concepts/fk_helper_metadata.adoc`)

| `_meta.derived.sheets[frame].enrich_lookup.helper_columns`
| Lookup, transient: `list[str] \| None` (`enrich_lookup/operation.py:561`,
  `record["helper_columns"] = list(fields)`)
|===

`_column_name_set`'s `Iterable` branch (`set(value)`) is semantically valid
only for the two `list[str]` shapes (Workbook View, Lookup). For FK's
`list[dict]` shape it calls `set([{...}, ...])`, which raises
`TypeError: unhashable type: 'dict'` before Cell Codec's own domain
`ValueError` can ever run.

This confirms and *sharpens* the closure assessment's finding: the crash is
not scoped to selecting the FK helper column as a participating column. It
fires inside `_helper_columns_for_frame` while building the frame-wide
helper-identity set, *before* `_reject_helper_participating_columns` ever
filters by `participating_columns`. Consequence: today, `encode_cell_values`
cannot process *any* column -- helper or not -- on a frame that merely
carries current rich FK provenance, i.e. any frame that has ever had
`add_fk_helpers` run on it in the current pipeline invocation. This is a
correctness defect wider than "the helper column cannot be rejected
correctly"; it is "the frame cannot be encoded at all."

Lookup provenance does *not* currently crash (its `helper_columns` is
`list[str]`, which is hashable):

[source,console]
----
=== 3a. encode_cell_values on NON-helper column, frame carries Lookup provenance ===
SUCCEEDED: [{'id': 'd1', '_dept_name': 'Eng', 'compact': 'N1'}]

=== 3b. encode_cell_values targeting the Lookup helper column itself ===
RAISED ValueError: helper or derived columns must not participate in Cell Codec
contraction by default: ['_dept_name']
----

This does not make the Lookup branch of `_column_name_set` correct --
`_column_name_set` still privately assumes Lookup's shape rather than being
told it by Lookup -- it only means the current unsoundness happens not to
manifest as a crash for Lookup *today*, and would if Lookup's written
provenance shape ever changed (exactly the DMC's "one-sided representation
change would silently break the other side" material-handoff test, DMC
Section 5).

=== 3.3 A second, independent latent defect (informational, not the blocker)

`_column_name_set`'s `Mapping` branch (`set(value)` on a raw `Mapping`) and
its generic `Iterable` fallback (identical for a `dict`, since `dict` is
itself `Iterable`) both silently reinterpret a bare mapping's *keys* as
column names, rather than raising or returning empty:

[source,console]
----
=== 9. Current shadow _column_name_set behavior for comparison ===
  dict (workbook-view malformed hand-authored): OK -> {'a', 'b'}
----

No current producer of any of the three carriers ever writes a bare mapping
at the `helper_columns`/`enrich_lookup` leaf (FK and Lookup always write
lists; Workbook View always writes `list[str] | None`), so this is not
currently reachable through any accepted production path -- it is latent,
not the Cycle-1 blocker, and is noted here only as corroborating evidence
that `_column_name_set` is an unsound generic parser rather than a
deliberately-designed multi-shape reader. See <<sec17>> (F-2) for its
disposition.

=== 4.1 FK: `fk_helpers.validated_helper_columns`

`fk_helpers/policy.py:183-231`, exported via `fk_helpers/__init__.py`:

[source,python]
----
def validated_helper_columns(raw_helper_columns: Any, *, frame_name: str) -> set[str]:
----

* `None` -> `set()` (safe no-op).
* Not a `list`/`tuple` -> `ValueError("_meta.derived.sheets[{frame_name!r}].helper_columns must be a list")`.
* Any entry not a `Mapping` -> `ValueError("...helper_columns[{index}] must be a mapping, got {type}")`.
* Entry present but without a truthy `column` key -> silently skipped (matches its own documented, deliberate leniency for that one sub-field, "matching prior behavior").
* Takes only the already-extracted per-sheet raw value -- it does not walk
  `frames`/`_meta.derived`/`_meta.derived.sheets[frame_name]` itself. Container-shape
  validation above the leaf stays the caller's (F-CORR-1, confirmed unchanged
  and independently re-verified by the F-002 Slice-1 implementation review at
  the byte level).

Empirical confirmation against the identical raw value that crashed Cell Codec:

=== 4.2 Lookup: `enrich_lookup.validated_enrich_lookup_helper_columns`

`enrich_lookup/provenance.py:66-88`, exported via `enrich_lookup/__init__.py`:

[source,python]
----
def validated_enrich_lookup_helper_columns(record: Any, *, frame_name: str) -> tuple[str, ...]:
----

* `None` -> `()` (safe no-op).
* Not a `Mapping` -> `ValueError("..._meta.derived.sheets[{frame_name!r}].enrich_lookup must be a mapping, got {type}")`.
* `helper_columns` member present but not `list`/`tuple` -> `ValueError("...enrich_lookup.helper_columns must be a list")`.
* `helper_columns` absent or empty -> `()`.
* Every element is coerced with `str(...)`, never inspected for join-key form.
* *Deliberately does not resolve or validate `on`/`source_key`/`lookup_key`* --
  confirmed both by direct read of `_validated_enrich_record_shape` (which
  never inspects those members) and empirically:

[source,console]
----
=== 5. validated_enrich_lookup_helper_columns on a record with NO join-key form ({}) ===
Result (should not raise): ('_dept_name',)

=== 5b. interpret_written_enrich_lookup_provenance on the SAME malformed-key-form record ===
RAISED ValueError: _meta.derived.sheets['desks'].enrich_lookup has no join-key
form; a value-checked enrich_lookup record must declare either a symmetric
`on` list or an asymmetric `source_key`/`lookup_key` pair
----

This is the required empirical basis for Key Design Issue 4: Cell Codec must
call `validated_enrich_lookup_helper_columns`, never
`interpret_written_enrich_lookup_provenance`. The latter would make Cell
Codec spuriously raise `ValueError` for any record whose join-key form is
absent or malformed even though its helper *identity* is perfectly
resolvable and Cell Codec has no legitimate interest in key form at all --
turning today's silent-but-correct behavior into a *new, incorrect* failure
Cell Codec would own by mistake. `validated_enrich_lookup_helper_columns` is
exactly and only the shape/identity half F-002 Slice 1 split out for this
reason (`enrich_lookup/provenance.py`'s own module docstring, quoted in
<<sec7>>).

=== 4.3 Both facades are sufficient

No facade change is required. Both already return exactly what Cell Codec
needs (helper-column identity), already accept exactly the shape Cell Codec
can extract without interpretation (the already-extracted raw per-sheet
value), and already have independently-reviewed, byte-pinned failure
semantics (F-002 Slice 1 implementation review, Sections 4-7). Per this
task's own stop condition: *no facade change appears necessary; this design
does not widen the closure slice.*

== 5. Desired ownership boundary

Target local algorithm (mirrors the assessment's Section 14 sketch, now
concretized against actual signatures):

[source,text]
----
navigate shared _meta / _meta.derived / _meta.derived.sheets containers (lenient, Cell-Codec-local)
    -> ask FK owner for FK helper identity     (fk_helpers.validated_helper_columns)
    -> ask Lookup owner for Lookup helper identity  (enrich_lookup.validated_enrich_lookup_helper_columns)
    -> read explicit Workbook-View helper identity  (Cell-Codec-local, no owner facade exists)
    -> union names
    -> enforce Cell Codec's own no-helper-participation invariant (unchanged)
----

This is structurally identical to the already-accepted
`derived_column_policy.py::_resolve_derived_identity`, read in full in this
task (`derived_column_policy.py:263-305`):

[source,python]
----
def _resolve_derived_identity(derived_meta, *, frame_name):
    """...
    `_meta.derived.sheets[frame_name]` container-shape validation (this
    function's own `isinstance` check below, and `_safe_sheet_meta`'s
    equivalent checks one level up) stays here -- generic, shared by both
    sub-keys. Each sub-key's *own* shape and identity ... is owned by its
    respective package facade (F-002 Slice 1) ...
    """
    if derived_meta is None:
        return set(), None
    if not isinstance(derived_meta, Mapping):
        raise ValueError(...)

    helper_names = validated_helper_columns(derived_meta.get("helper_columns"), frame_name=frame_name)
    enrich_spec = derived_meta.get("enrich_lookup")
    enrich_names = validated_enrich_lookup_helper_columns(enrich_spec, frame_name=frame_name)
    helper_names |= set(enrich_names)
    return helper_names, enrich_spec
----

DCP's own docstring states the F-CORR-1 boundary in exactly the terms this
task asks Cell Codec to follow. This is not a new design decision for Cell
Codec; it is the same accepted seam, applied to a second consumer.

DCP also independently confirms Key Design Issue 5 (return-type
normalization): DCP explicitly writes `helper_names |= set(enrich_names)`
because Python's `set.__ior__` requires a set-like right-hand operand and
rejects a plain `tuple` (`enrich_names` is `tuple[str, ...]`) -- proving the
FK/Lookup return-type difference is real and DCP already had to normalize
it locally, at its own call site, with no shared protocol. See <<sec10>>.

== 8. Workbook-View handoff [[sec8]]

=== 8.1 Classification

The assessment's own three-way question: is Cell Codec's current read of
`_meta.sheets[frame].helper_columns`

. an intentionally simple public/durable handoff it may legitimately read;
. another private foreign-shape parser that should delegate; or
. something else?

*Answer: (C), refined.* There is no owner facade to delegate to --
`workbook_views.py` only *produces* this carrier
(`configure_workbook_view` -> `_normalize_sheet_specs` ->
`_merge_sheet_options`, via `_optional_string_list`/`_string_list`); it
exposes no reader. Concrete source evidence, read in full in this task,
that every current consumer of this exact carrier already implements its
*own* small local reader rather than sharing one:

[cols="3,5",options="header"]

| Consumer | Local reader

=== 8.2 A concrete, more direct precedent than Cell Codec's own history [[sec8-2]]

DCP's `_safe_durable_helper_names` (read in full, `derived_column_policy.py:332-356`)
reads the *identical* carrier and is already independently reviewed and
accepted (F-002 Slice 1, unmodified by that slice, pre-existing DCP code):

[source,python]
----
def _safe_durable_helper_names(meta: Mapping[str, Any], source: str) -> set[str]:
    sheets = meta.get("sheets")
    if sheets is None:
        return set()
    if not isinstance(sheets, Mapping):
        raise ValueError(f"_meta.sheets must be a mapping, got {type(sheets).__name__}")
    sheet_entry = sheets.get(source)
    if sheet_entry is None:
        return set()
    if not isinstance(sheet_entry, Mapping):
        raise ValueError(f"_meta.sheets[{source!r}] must be a mapping, got {type(sheet_entry).__name__}")
    raw_helper_columns = sheet_entry.get("helper_columns")
    if raw_helper_columns is None:
        return set()
    if not isinstance(raw_helper_columns, (list, tuple)):
        raise ValueError(f"_meta.sheets[{source!r}].helper_columns must be a list")
    return {str(column) for column in raw_helper_columns if str(column)}
----

This raises `ValueError` for a non-mapping container or a non-`list`/`tuple`
leaf, and never special-cases a bare string. Cell Codec's current
`_column_name_set`, applied to the same carrier, never raises for any of
those and additionally mishandles a bare `Mapping` (<<sec3>>, 3.3).

*This does not mean Workbook View is redesigned in this task* -- `workbook_views.py`
itself (the producer and only owner of this carrier's contract) is untouched,
and no consumer-facing behavior of that module changes. It means Cell
Codec's own *local* choice of how strictly to read this one carrier has a
closer, better precedent available than its own pre-existing code. This is
presented as an explicit open option for the implementer/independent
reviewer, not mandated here (<<sec17>>, OQ-1):

[cols="1,4,3",options="header"]
|===
| Option | Description | Recommendation

| W1
| Keep the current `_column_name_set` body verbatim, re-scoped to this one
  remaining call site (optionally renamed for Local Human Readability, since
  it now serves exactly one carrier, not three).
| *Default for this slice.* Zero behavior change for the one carrier that is
  not the Cycle-1 blocker; smallest possible diff; Workbook View is
  explicitly out of scope for redesign.

| W2
| Align with DCP's `_safe_durable_helper_names` tail (raise for non-mapping
  container / non-list leaf; `str()`-coerce and drop falsy elements; no
  bare-string sugar).
| Precedent-backed, closes the dict-keys latent hazard (<<sec3>>, 3.3) using
  an already-accepted sibling pattern rather than a new one. Reasonable if
  the independent reviewer prefers cross-consumer consistency over minimal
  diff. *Not required for Cycle-1 closure either way.*
|===

Either option keeps all navigation above the leaf (`isinstance(sheets, Mapping)`,
`isinstance(sheet_meta, Mapping)`) exactly as it is today; only the leaf-value
interpretation differs between W1 and W2.

== 10. Return normalization [[sec10]]

FK facade returns `set[str]`; Lookup facade returns `tuple[str, ...]`; the
Workbook-View local reader returns `set[Any]`/`set[str]`. Cell Codec needs
only membership testing (`column in helper_columns`,
`_reject_helper_participating_columns`'s only use of the result) -- ordering
is never observed, never returned to any caller, never serialized (Key
Design Issue 6: confirmed no ordering dependency anywhere in the file by
direct read of every remaining use).

*Decision: Option A (normalize locally, at the Cell Codec boundary), and no
new code is even required to do it.* Cell Codec's existing accumulation
idiom is `set.update(...)`, which -- unlike the `|=` operator DCP had to use
at its own analogous call site (<<sec5>>, `helper_names |= set(enrich_names)`,
required because `set.__ior__` rejects a plain `tuple`) -- already accepts
any iterable, `set` or `tuple` alike, with no wrapping:

[source,python]
----
helper_columns.update(validated_helper_columns(raw_fk, frame_name=frame_name))          # set[str]  -- fine
helper_columns.update(validated_enrich_lookup_helper_columns(raw_lk, frame_name=frame_name))  # tuple[str, ...] -- also fine
----

DCP's own call site is direct proof the type difference is real and matters
in general (DCP had to write `set(enrich_names)` explicitly); Cell Codec's
pre-existing `.update()` idiom happens to erase it for free. No shared
protocol, dataclass, or normalization helper is needed (<<sec15>>).
