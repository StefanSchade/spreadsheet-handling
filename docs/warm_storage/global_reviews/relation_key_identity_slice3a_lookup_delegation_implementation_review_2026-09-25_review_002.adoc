== Independent assessment

*Values-mode Lookup delegates relation identity.* `operation.py` derives a
collision-safe temporary `__relation_key_identity__` join column from
`relation_key_identity`, merges only those opaque owner identities, and drops
the column before publishing. It reads columns independently rather than using
`iterrows`, avoiding carrier loss before delegation. Lookup-frame rows whose
key identity is absent are excluded; source rows with absent identities remain
unmatched and follow the existing `missing` policy. No raw pandas key dtype
comparison decides the Domain outcome.

*Duplicate and mismatch paths agree.* `policy.py` builds duplicate detection
from the same owner identities, excluding Missing identities before its set
check. `mismatch.py` uses those identities for both the canonical lookup map
and payload-row selection, so its resolution rule agrees with enrichment and
duplicate detection. Its explicitly named
`_helper_payload_comparison_value` continues to be a separate Lookup-owned
display-value comparison after a target row has been selected; it is not used
to establish relation identity.

*Required relation semantics hold.* The value-mode tests exercise exact String
whitespace, Number/String and Boolean/Number separation, and exact integral
Number carrier equality. They cover empty-String and `None` Missing values;
the accepted owner tests cover the remaining admitted Missing carriers. Focused
direct Lookup probes additionally confirmed NaN, `pandas.NA`, and `NaT` are
unmatched, `numpy.int64(1)` matches `1.0`, temporary join columns do not
publish, and both input frames retain their caller-owned columns. Mismatch
probes confirmed Boolean/Number separation and exact whitespace key selection.
Mixed pandas Number/String dtypes route through `missing="fail"` as a Domain
unmatched-key error, not a pandas dtype error.

*Boundaries remain contained.* Formula authoring still takes its separate
formula branch. `derived_column_policy.py` was not changed and delegates to
`evaluate_lookup_mismatches`; the DCP test changes only exercise that delegated
behavior. The pre-existing whole-frame values-mode rewrite
`where(pd.notnull(enriched), "")` remains exactly in place and the temporary
join column has already been removed before it runs. Thus B-2 is neither
widened nor represented as fixed.

*Release note is truthful.* The active unreleased bullet describes Lookup
enrichment, duplicate-key detection, and mismatch verification only. It names
exact Strings, category separation, integral Number equivalence, Missing
exclusion, configured missing-key behavior for mixed pandas dtypes, and the
absence of general scalar normalization. It does not claim FK, reference/graph,
or general-scalar migration.
