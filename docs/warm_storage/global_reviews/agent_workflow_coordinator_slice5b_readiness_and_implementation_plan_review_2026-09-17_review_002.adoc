== 4. New findings introduced by the correction

=== P5B-D1 -- MINOR -- Three R2 predicates are not yet mechanically defined

Evidence::
. "a `changes_required` result that proposes resolution of the blocker it reports is
  outcome-incoherent and fails closed" (plan 609-613; test at 911). The Coordinator
  has no deterministic referent for "the blocker it reports": a result carries
  unordered `FindingDelta` proposals (`model.py:156-163`), not a verdict-to-Finding
  link. Readings diverge: any `resolve` delta in a `changes_required` result;
  contradictory same-ID deltas within one result; or "no open blocker remains after
  reduction". The first forbids a legitimate "F001 fixed, new blocker F002" rereview.
. Artifact-only scope is stated both as runtime eligibility (603-607: intent paths ⊆
  declared artifacts; anomaly before Git mutation) and as a preflight requirement on
  "a `changes_required` gate's writable/commit scope" (841-842). Preflight cannot know
  a runtime outcome; read as a preflight rule it becomes a general ban on gate
  payload scope for every gate with declared artifacts -- a new profile-authority
  rule beyond the fixture property the prior review requested.
. `blocked` applies "otherwise-authorized Finding proposals" before stopping (616-618);
  `failed` says "likewise" (619-622) without stating whether proposals apply.

Consequence if ignored:: The contract drafter chooses silently; different choices
yield different accepted/refused result sets in the section-13 matrix. All readings
fail closed; none grants authority. Hence MINOR.
Remaining correction (contract input, no plan revision required)::
. Drop the "blocker it reports" clause (gate authority, the `changes_required`
  terminal refusal, and the Run-wide blocker invariant already bound self-approval),
  or replace it with one mechanical predicate; do not link verdicts to Findings
  semantically.
. Place the exception check at runtime: CommitIntent paths ⊆ current phase's declared
  artifacts; keep "gate scope equals artifact set" as a fixture property. Any general
  preflight gate-scope rule must be justified explicitly in the contract.
. State whether `failed` applies authorized Finding proposals, identically to
  `blocked`.

=== P5B-D2 -- MINOR -- Finding `disposition` misclassified as agent-authored prose

Evidence:: Plan 402, 508, 573, 995 label "Finding invariant/disposition prose" as
agent-authored and untrusted. `disposition` is Coordinator-generated
(`reducer.py:148`, `:195`: `f"{authority.value}: {delta.proposed_state.value}"`);
`FindingDelta` has no disposition field (`model.py:156-163`). Conversely, Finding
`evidence_refs` and `successor_ref` are agent-supplied (`reducer.py:196`,
`evidence_refs` from `delta.evidence_refs`) but are not named in the untrusted list,
which names only result evidence refs.
Consequence if ignored:: A normative contract would under-trust a Coordinator fact
(which records who disposed a Finding -- the attribution P5B-R1 exists to protect)
and leave the agent-supplied Finding refs/successor labelling unspecified.
No authority leak.
Remaining correction (contract input):: Render Finding ID, state, blocking,
introduced/changed-by Hop, and `disposition` as Coordinator facts; render
`invariant`, Finding `evidence_refs`, `successor_ref`, Hop summaries, and result
evidence refs as attributed untrusted claims.

required). It therefore also changes the existing N=1/DMC shape (`review: null`

probe shows no accepted test depends on the old behavior; the contract should say
the invariant is not keyed to a declared `blocking_policy` and name the N=1 effect.

such a profile passes preflight (`operator.py:152-160`) and fails charged at H002.
