== 6. F1/F2 relevance without importing the Outer Loop

=== 6.1 Required before reusable extraction

The reusable inner operator must not export two unsafe implications.

F1 minimum:: Pinned consumer policy declares normalized repository-relative,
glob-free governance paths. Every selected repository-backed governing input --
the five supplied inputs, selected component sources, and the pre-split A3
contract resource path -- must lie within an admitted governance path. No phase
mutation scope may overlap a governance path in either direction: a phase scope
may be neither equal to, an ancestor of, nor a descendant of a governance path.
The check rejects before Run creation, state-root creation, or adapter entry.
The standalone product contract says that a committed WorkItem is accepted only
as externally authorized input; commit presence is not independent authorization.

F2 minimum:: Pinned consumer policy must place a ceiling over WorkItem path scope
and `max_autonomous_hops`, just as current checks already bound phase scope by
WorkItem and phase actions/evidence by policy. The hard rollout ceiling remains
an additional product limit, not the consumer authority ceiling. Its pre-split
justification is stable schema and authority boundaries across the split, not a
currently missing single-Run inner-executor check. A1 and A2 explicitly
coordinate schema-version evolution; C6 may share that revision if economical.

These are small schema/admission checks. They do not require identities,
signatures, IAM, a policy engine, a scope lattice, an Outer Loop, or automated
intake.

=== 6.2 Required only before automated outer-loop WorkItem authorship

The following remain later work: independently distinguish human/policy-approved
governing-input provenance from agent output across Runs; define who turns a
proposal into authority; govern candidate/backlog admission; authorize
materialization and child launch; propagate parent/child budgets; and prove that
harness-level instructions cannot become self-authored governance. These are the
future F1 transition-owner problem, not carve-out mechanics.

=== 6.3 Explicitly unsupported after carve-out

The initial standalone tool does not author, approve, select, or launch its own
WorkItems; does not operate an Outer Loop; does not pre-authorize child Runs; and
does not claim that any tracked YAML is independently authorized merely because
it is committed. Those unsupported capabilities may remain unsupported
indefinitely without invalidating the carve-out.

=== 8.3 Citation and commit-map rule

`spreadsheet-handling/core` is permanently authoritative for every pre-split SHA
citation. The standalone repository preserves selected history for blame and
navigation. Its rewritten SHAs identify rewritten commits only. The provenance
artifact provides old-to-new lookup but never substitutes a rewritten SHA into
an old citation or claims identity equivalence.

The provenance record names at least:

* incubator repository URL and immutable split HEAD;
* standalone rewritten split HEAD before bootstrap commits;
* first standalone bootstrap/provenance commit;
* full filter command, tool version, path-manifest digest, and commit-map digest;
* path exclusions that explain why consumer commits and citations may not exist;
* the statement that mixed historical commits are partial projections; and
* the accepted standalone distribution/version/source-identity scheme, PEP 610
  direct-reference capture when applicable, A3 contract version/digest, and a
  Phase-C evidence sample proving reconstruction; and
* the core consumer-reconnection commit once it exists.

=== 8.4 Remote, first branch, and retry

Phase C remains a discardable scratch-clone operation until independently
accepted and pushed. After local validation only, verify the GitHub target has
no refs. Add the exact
empty GitHub repository as `origin`; optionally add the incubator URL as a
fetch-only `incubator` remote with no push URL. The first pushed branch is
`main`. Its accepted HEAD is the rewritten split history plus small reviewed
standalone bootstrap/provenance/healing commits; it contains no consumer code.
Push without force because the remote is expected to be empty.

The source repository and empty target directory remain untouched throughout
scratch filtering and validation. On a failed validation, discard only the
temporary clone; core remains authoritative, `Open`, and frozen, so no lifecycle
lie exists. Rerun from the same split SHA and manifest only while that freeze is
current; after a lifted/changed freeze, establish a new anchor. Do not repair
the filtered history in place and do not rewrite the incubator. The intended
local target is populated only after standalone acceptance, preferably by
cloning the accepted remote into the still-empty directory. If the remote is
not actually empty, or its default-branch/protection state conflicts, stop before
push and obtain maintainer direction.

== 9. Minimum standalone package at extraction

Package creation belongs wholly to discardable Phase C after filtering and

  `workflow_coordinator`;

  product surface;

* Coordinator unit, integration/vertical, architecture/replay tests in natural
  standalone locations, with the carried FTR pytest marker registered or
  deliberately replaced; and

Phase C wires the A3 operating-contract resource as declared package data,

== 10. Core consumer reconnection

Reconnection follows a validated standalone commit, not a floating branch.

. During joint local development, install the sibling standalone repository
  editable into core's development environment. Do not commit an absolute local
  filesystem dependency.
. For the first reproducible committed consumer boundary, pin the exact
  accepted standalone Git commit through a development/tool constraints or
  dependency mechanism outside published core `[project]` metadata. In
  particular, no direct URL may appear in `[project]` or published optional
  dependency metadata. PyPI is unnecessary. Local editable installation may
  override that pin only for coordinated development. Target visibility and CI
  access are execution inputs that must be confirmed before reconnection.
. Keep core's DMC and IOR WorkItems, task payloads, component manifests,
  profiles, policy values, and evidence argv in core. Keep backlog/product
  prioritization and all consumer domain documents in core.
. Replace `python scripts/workflow_coordinator/operator.py` and direct
  `scripts.workflow_coordinator` imports with the installed `wfc` and named
  public Python package surface. The minimum supported Python surface is the
  `WorkItem`, `RepositoryPolicy`, `WorkflowProfile`, and
  `PromptComponentReference` schema types plus `component_manifest_from_yaml`,
  `work_item_from_yaml`, `repository_policy_from_yaml`, and
  `workflow_profile_from_yaml`; those loaders perform the supported coherence
  checks. All other modules are internal. No core test or tool may extend
  `sys.path` into a sibling checkout.
. Remove the incubator implementation subtree and generic Coordinator unit/replay
  tests from core after the dependency works. Preserve the focused consumer
  integration tests created during A1/A2: governing-input load/coherence,
  evidence-command ownership, dry/fake invocation through the installed package,
  and the expected consumer profiles.
. Update core setup/CI so the pin resolves in a clean checkout. Document the
  optional sibling editable workflow separately.
. Prove that current consumer workflow definitions load and that a fake/local
  consumer run uses core-owned profile/policy/evidence values without importing
  standalone internals.
. Add an architecture guard against `scripts.workflow_coordinator`, direct
  implementation-internal imports, `sys.path` repair, and sibling-source fallback.
. In the same truthful ownership boundary that removes the incubator
  implementation, transition its FTR from `Open`/frozen to `Superseded` and
  update navigation/backlog dispositions without transferring consumer dogfood
  authority.

The first consumer boundary should contain dependency pin, invocation/import
conversion, removal of superseded incubator code/tests, the fallback guard, and
the FTR `Superseded` transition atomically. Preparatory pin/integration work may
be reviewed separately while the old tree remains authoritative, but the final
removal and lifecycle transition are one truthful ownership change.

== 11. Bilateral healing

Healing is explicit and bounded. It begins after mechanical filtering and
consumer reconnection; it is not an excuse to move everything and defer all
ownership work.

=== 11.1 Required before first post-split commit acceptance

Standalone:: Import/package/CLI tests pass from an installed wheel, including A3
resource loading and neutral convergence through `wfc`; C6/C7/C10 are described
truthfully; provenance map and authority notice exist; current tree contains no
spreadsheet/DMC code or consumer governing values; README, license, test
configuration, and minimal CI/build metadata work from repository root; Run
evidence records distribution/version/source/direct-reference metadata where
available and operating-contract version/digest.

Core:: Exact dependency resolves outside published `[project]` metadata;
consumer governing inputs parse; invocation
uses the public package/application; no direct removed-path import exists; no
duplicate executable Coordinator remains; focused consumer integration tests and
diff hygiene pass.

=== 11.2 Required before carve-out closure

Standalone:: Tests live in natural locations; current normative docs describe
implemented 1--5B reality without treating imported incubator artifacts as
authority; historical links either resolve through provenance or are marked as
incubator links; source-style/architecture checks include the package; CI builds
and tests the distribution; repository navigation has no active incubator-path
assumptions; C6 is a policy value and model/reasoning configuration is handled by
ordinary reviewed work if still required.

Core:: Dead Coordinator implementation/test paths are removed; docs and Makefile
use `wfc`; cold historical records remain navigable; active backlog/FTR indexes
do not claim local implementation ownership; an architecture guard rejects
`scripts.workflow_coordinator` and sibling-source imports; the incubator FTR is
truthfully `Superseded`; core's full suite is green with the pinned dependency.

=== 11.3 Bounded follow-up debt

Cosmetic relocation of every imported review, perfect repair of every historical
cross-link, richer CLI ergonomics, public publishing, multi-platform installers,
TUI/assistant work, provider plugins, additional real consumers, and 5C+ may
remain debt or future product work. None prevents closure when both repositories
are truthful and independently runnable.

== 13. Concrete carve-out exit criteria

The carve-out is complete only when all statements below are true:

. `workflow-coordinator` builds, installs, imports, and runs through `wfc` as a
  native standalone repository, with its generic tests and neutral convergence
  proof green.
. `spreadsheet-handling/core` resolves an exact standalone commit and exercises
  its consumer workflows without local implementation imports or sibling paths;
  the reproducible pin does not depend on sibling layout or pollute published
  core `[project]` metadata.
. Coordinator schemas/mechanics/contracts live standalone; spreadsheet/domain
  values, WorkItems, policies, profiles, evidence commands, and priority remain
  in core.
. Incubator FTR authority changes to `Superseded` only when core becomes a
  consumer and removes the incubator implementation; standalone current authority
  does not pretend imported historical reviews/FTR are newly normative.
. The old-to-new commit map and both split/reconnection anchors reconstruct
  provenance, while core remains citation authority for pre-split SHAs. Post-split
  Run evidence identifies the standalone WFC distribution, version, immutable
  source identity/direct-reference metadata where available, and reconstructable
  A3 operating-contract version/digest.
. Accepted inner-loop capability, including deterministic Slice-5B convergence,
  remains green; both repositories pass their required focused and full-suite
  checkpoints.
. Neither repository depends on the pre-split filesystem layout, and neither has
  active dead topology that suggests the implementation still belongs to core.
. Package-data declarations and A3 resource loading have been proven from an
  installed wheel, not only an editable checkout.

Filter success alone satisfies none of these except history rewriting. Slice
5C--5F implementation, Outer Loop, automated authorship, assistant/TUI
productization, professional-trust completion, public PyPI publication, and a
second consumer are explicitly absent from the exit.
