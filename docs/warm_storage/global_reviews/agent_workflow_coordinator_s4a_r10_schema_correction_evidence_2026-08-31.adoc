== Implemented correction

S4A-R10 replaces Slice-4A's inline opaque provider schema for `result` with the
canonical `structured_result_envelope_schema()` builder in
`scripts/workflow_coordinator/serialization.py`. The builder wraps the canonical
strict `routing_result_json_schema()` and is the sole schema emitted by
`scripts/workflow_coordinator/slice4.py`.

The schema builders share narrow key constants with the existing Python
validators. They derive `Outcome` and `FindingState` enum values from the
accepted model and reuse the accepted escalation-kind vocabulary. This reduces
the chance that validator required keys and provider required keys drift apart
without introducing a generalized schema framework.

== Strict shape and preserved semantics

Every provider-schema object -- outer envelope, `result`, non-null `escalation`,
and a `findings` item -- declares `additionalProperties: false` and lists exactly
all of its properties in `required`.

The outer envelope remains exactly `schema_version`, `run_id`, `hop_id`,
`invocation_id`, and `result`, with `schema_version` fixed at `1`. No change was
made to adapter-side run/hop/invocation correlation or to result transport.

`escalation` remains `null` or a strict `kind`/`question` object. `finding_id`
and `successor_ref` remain string-or-null. The provider schema requires an
explicit non-nullable boolean `new_material_evidence`; Python validation still
accepts its omission and defaults it to `False`, preserving its existing contract.
The existing Python-side non-empty-string checks remain authoritative.
