== 5. Revised anchor-source design

Moving the intentional mutation out of the filter input and into a disposable
bare source that `filter-repo` never touches is both sufficient and minimal.

It is *sufficient* because the only predicates the old sequence violated were
properties of the filter input's own birth state -- ref matching, remote
presence and reflog shape. Restoring those by construction, rather than by
repair, is the only way to satisfy them without `--force` or reflog forgery.

It is *minimal* because the alternatives are strictly worse: repairing the run
clone in place would require synthesising `refs/remotes/origin/main` and
expiring reflogs to fake a freshness the repository does not have, which would
defeat the purpose of the pinned safety check rather than satisfy it; and no
smaller change exists, since Git cannot clone directly at an arbitrary
non-tip commit.

The design also *improves* object hygiene relative to the accepted sequence.
Under the old ordering the filter input physically contained Core's entire
post-anchor history. Under the revised ordering the post-anchor tail is removed
in the anchor-source before either run clone exists, so it never enters a filter
input at all. This strengthens, and does not weaken, the accepted
extraction-boundary invariants.

*Result: anchor-source design ACCEPTED as sufficient and minimal.*

== 9. `--refs`, partial mode and `origin/main` -- high priority

Verified both from pinned source and experimentally.

Immediately after filtering, in each run:

* local `refs/heads/main` was rewritten;
* `refs/remotes/origin/main` remained at the *unfiltered* anchor;

This last point is decisive and independently confirmed: a reachability or
sole-ref proof taken between filtering and cleanup would have observed the

stylistic, and is correctly placed in both the artifact and the FTR.

* `commit-map` contains only the two original-to-rewritten commit pairs;
* `ref-map` contains exactly one row, `refs/heads/main`;
* `changed-refs` contains exactly `refs/heads/main`.

B's accepted commit-map and backward-reference semantics are therefore
untouched by the retained origin topology.

No other untouched ref preserves unwanted reachability. In a
`--no-tags --single-branch` clone from a proven sole-ref source the only refs

=== 17.1 MINOR

*M1 -- section 6.2's assertion block is weaker than its own prose.*

Observation:: The prose requires verifying "no ... other local branch, or other
remote branch" and "the pinned packing predicate", but the shown block only
tests `refs/tags refs/replace refs/notes refs/stash` and merely *prints*
`git count-objects -v` without asserting on it.
Risk:: An implementation transcribing the block literally would not gate on
packing or on the exact ref set. The consequence is bounded: pinned
`sanity_check` enforces both itself, so the outcome is a tool refusal, which the
contract already treats as a stop. Fail-closed, not silent.
Smallest correction:: In the C synchronization, express the run-clone check as
an exact expected ref-set equality plus numeric assertions on `packs` and
`count`. Reopen-artifact section 10 item 4 already commits to adding packing
assertions, so this is a wording tightening inside work already scheduled.

*M2 -- section 3.1 slightly misstates the no-remote exception.*

Observation:: The artifact says the exception "applies only to a new bare
repository with no packs". The pinned source condition is
`output == b"origin" or (num_packs == 0 and not output)`; there is no bareness
term.
Risk:: Descriptive only. Both run clones always have one pack and one remote, so
the exception is unreachable in this contract and no behaviour depends on the
restatement.
Smallest correction:: Restate as "no packs and no remote" when the paragraph is
next touched.

*M3 -- an unstated precondition on the anchor-source clone.*

Observation:: `git clone --bare --single-branch --branch main` fetches only
`main`'s history, so the sequence silently assumes the extraction anchor is
reachable from Core's `main` at clone time. The contract does not state this.
Risk:: Low and fail-closed: if the assumption were ever false, `git update-ref`
would fail and the following `rev-parse` assertion would fail. Independently
confirmed true today -- `e4a0b20a` is an ancestor of Core `main`.
Smallest correction:: Add one assertion,
`git -C "$CORE" merge-base --is-ancestor "$ANCHOR" refs/heads/main`, to the C
plan's Core-recording step.

*M4 -- section 6.2's freshness loop is bash-only.*

Observation:: The reflog loop uses process substitution (`done < <(find ...)`)
inside a block labelled `[source,shell]`.
Risk:: A syntax error if C executes the block under `sh` rather than `bash`.
Smallest correction:: Either label the block `bash` or restructure the loop as a
`find -exec` test during C synchronization.

=== 17.2 INFO / WATCH

*I1 -- the pinned tool does not itself forbid a second pass.* After a successful
run, `.git/filter-repo/already_ran` exists and `_run_sanity_checks` skips
`sanity_check` entirely when `_already_ran` is true; the file's own text states
it exists "to allow you to filter again without `--force`". The accepted
"no second filter pass over one rewritten result" invariant is therefore policy-
and structure-enforced (one invocation per fresh run clone), never
tool-enforced. Unchanged by this delta, but worth carrying into C so the new
emphasis on tool-enforced safety is not over-read.

*I2 -- two undocumented but benign pinned-tool side effects.* In partial mode on
a non-bare repository the tool sets `repack = False` (no `gc`, no reflog expiry)
and `reset = True`, so it runs `git reset --hard` as its final step and writes
`ORIG_HEAD`. `ORIG_HEAD` was confirmed to point at the rewritten head. Both are
consistent with the documented physical-object tolerance.

*I3 -- scratch residue is reflog-held, not merely unreachable.* After cleanup the
run clone's `HEAD` and `refs/heads/main` reflogs still name the original anchor,
so `git fsck --unreachable` reports nothing and `gc` would not prune those
objects. This is strictly within the accepted, unchanged scratch tolerance, and
it cannot propagate: the scratch-to-staging transfer is an `upload-pack` clone,
and staging was independently proven to have exact physical/reachable equality
with the original anchor absent. Recorded so that no later C proof is written in
terms of reflog-aware reachability in scratch.

*I4 -- synthetic OIDs in artifact section 8 are not re-derivable.* See section 15.
Explicitly scoped as diagnostic; not a reconstruction blocker.
