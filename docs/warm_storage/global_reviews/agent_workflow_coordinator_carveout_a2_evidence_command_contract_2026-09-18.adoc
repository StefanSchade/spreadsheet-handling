== 2. Current evidence architecture

=== 2.1 Definition and reference today

`Phase.evidence` is `tuple[str, ...]`. WorkflowProfile YAML expresses it as an
ordered list under each phase. `RepositoryPolicy.evidence_states` is a second
tuple of allowed names. `evidence.py` then supplies the actual production
definition from the in-code `TRUSTED_EVIDENCE` mapping:

[cols="2,3",options="header"]
|===
|Name |Current argv

|`diff_hygiene`
|`git diff --check`

|`git_version`
|`git --version`
|===

Thus the current authority is split across a policy allowlist and a production
registry. The A2 contract replaces both with one policy mapping. It does not add
a parallel registry.

=== 2.2 Admission today

`operator._preflight()` reads the five pinned inputs, parses WorkItem/profile/
policy/manifest, and iterates every phase evidence name. It currently requires:

. membership in `policy.evidence_states`;
. `evidence_runner.supports(name)`; and
. for an injected runner, non-collision with production registry names.

These checks occur before `_preflight()` returns. Only after return does
`main()` allocate a UUID, call `new_run()`, create/write the state root, register
the checkout, or reach an adapter. This is the correct A2 pre-Run boundary.
Read-only repository and Git observations and pinned-file reads already occur
inside `_preflight()` before that boundary.

=== 2.3 Execution and classification today

`vertical.run_one_hop()` calls evidence after:

. the adapter returns a candidate result;
. the result is envelope/schema validated;
. trusted CommitIntent handling and independent Git observation complete; and
. post-acceptance artifact/subject diagnostics are computed.

It iterates `phase.evidence` in declaration order and calls
`evidence_runner.observe(name, repository)`. The production implementation uses
`subprocess.run(argv, cwd=repository, check=False, text=True, stdout=PIPE,
stderr=PIPE)`. It currently inherits the whole process environment, supplies no
stdin rule, has no timeout, and relies on Python's PATH resolution.

`evidence.py` maps return code zero to `pass`, any other returned code to
`fail`, and `OSError` to `error`. Its compatibility entry can return `not_run`
when explicitly called with `selected=False`. `observation_error()` rejects
provider mismatch, an unknown status, empty summary, malformed command/artifact/
digest, or pass/fail without a digest.

`vertical.py` maps `error` and `not_run` to
`MechanicalFacts.required_evidence_error`, and any `fail` to
`required_evidence_failed`. `reducer.py` gives an error mechanical-preemption
priority. A clean failure may use the gate's declared `failed_evidence_route`;
without one it stops `required_evidence_failed_without_route`. These reducer
semantics need no A2 redesign.

=== 2.4 Durable versus diagnostic today

`Observation` currently contains provider, status, command, summary,
artifact_ref, and one digest. The current checkpoint persists provider, status,
summary, artifact_ref, and digest for the current Hop. The cumulative atomic
`execution-evidence.json` additionally persists command argv for every completed
attempt; `operator-summary.json` projects those records.

Run/Hop JSON does not persist trusted Observation objects. `Hop.evidence_refs`
comes from agent structured output and remains agent-attributed. It must not be
silently repurposed as trusted execution evidence. Checkpoint prose and terminal
messages are diagnostic projections; the cumulative execution-evidence file is
the natural bounded audit record.

Current output handling hashes the concatenation of stdout and stderr and copies
the first output line into `summary`. The body is not otherwise durable, but a
single line is not length-bounded and can contain secrets. A2 can improve this
without a log subsystem by persisting no output-derived text and recording
separate full-stream digests/counts.

== 3. Trust model

The accepted R4 correction is the controlling distinction:

* trusted: the command definition originated in admitted, A1-protected consumer
  governance;
* not thereby trusted: executable bytes, interpreters, imports, repository code,
  command output, or semantic correctness; and
* trusted host action: the Coordinator attempts the definition through its own
  process boundary.

An evidence command can import or execute code modified by the immediately
preceding agent Hop. It runs outside the provider sandbox with Coordinator host
permissions. `shell=False` is necessary literal-argv behavior, not isolation.
Exit zero is an observed process fact, not proof of correctness. A command can
mutate the worktree, index, Git metadata, refs, repository configuration, or
other host state and can observe inherited environment values, including
credentials. A2 does not contain these capabilities; the accepted agent-side
`.git` restriction does not constrain this later evidence subprocess. A2 provides
no exfiltration or network containment and neither prevents nor disguises those
facts.

The FTR therefore states the grant narrowly: the policy authorizes an *attempt*.
Host containment, bwrap, OS identities, IAM, and professional-trust controls
belong elsewhere.

== 4. Policy schema

The minimum representation is a required finite `evidence_commands` mapping:

[source,yaml]
----
evidence_commands:
  diff_hygiene:
    argv: [git, diff, --check]
    timeout_seconds: 30
----

The mapping may be empty when a policy grants no evidence-command authority.
There is no inferred container and no command default. Names use the bounded
ASCII identifier pattern selected in the FTR. Duplicate mapping keys already
fail in `_StrictLoader` before model construction.

Each definition has exactly two fields. `argv` is non-empty, preserves exact
strings, permits an empty nonzero-position argument, and rejects NUL. Only
`argv[0]` must also be non-empty. This retains genuine argv semantics rather
than applying `_string()` to every argument. The timeout is a non-boolean integer
from 1 through 900.

Strict unknown-field rejection excludes cwd, environment, PATH, shell, stdin,
retry, user, alternate executable, output parser/plugin, and detach/background
authority. These are not “ignored extensions”; they are invalid policy.

== 5. RepositoryPolicy version decision

Decision:: *RepositoryPolicy moves to schema version 3.*

V2 cannot truthfully be extended here:

* its exact strict field set is already implemented and independently accepted;
* a new required field would give the same version number two incompatible
  exact shapes;
* an optional/default-empty field would silently change old v2 meaning; and
* keeping `evidence_states` beside the new mapping would preserve the double
  registry A2 is meant to remove.

V3 preserves all A1 fields and their semantics and replaces `evidence_states`
with `evidence_commands`. V2 rejection after atomic migration is preferable to
compatibility branches because only two real policies, one aggregate neutral
fixture, one closed proof-harness constructor, and bounded typed/unit fixtures
exist. V1 remains rejected.

This is schema truthfulness, not fixture avoidance. Policies without evidence
still write `evidence_commands: {}` explicitly.

== 6. Command references

Definition authority is the v3 mapping. Requirement/reference is the existing
phase `evidence` list. Execution result is an Observation. The three remain
separate.

The exact namespace is the command-name key space of the selected policy. A
phase list is ordered and contains no duplicate. Mapping order is irrelevant.
Unknown names fail pre-Run. Unused definitions are valid and remain unresolved/
unexecuted, allowing a bounded policy to serve more than one profile without
requiring all commands on every Run. A definition referenced by several phases
executes independently at each reached phase.

`serialization.py` is the sole owner of phase-list duplicate-reference
validation. The intended small production seam is a pure A2 cross-document
coherence helper in `operator.py`, analogous in reviewability to `_admit_a1()`
but not mixed with A1. It returns distinct selected names in first-reference
order. The operator then prepares those definitions under the host environment
policy. Injected runners no longer have `supports()` authority.

== 7. Execution semantics

The current evidence point is retained. A prepared command is attempted after
candidate-result validation and trusted Git handling, before evidence-dependent
route reduction completes.

Production execution uses an argv sequence, `shell=False`, canonical repository
root cwd, `DEVNULL` stdin, separate byte capture for stdout/stderr, the immutable
environment snapshot, and the command timeout. Only the resolved absolute
invocation path replaces authored `argv[0]`. Every later argument is passed
byte-for-string-equivalent through Python without parsing or interpolation.

The selected mapping is:

[cols="2,4",options="header"]
|===
|Outcome |Condition

|`pass`
|spawned and returned exit status 0

|`fail`
|spawned and returned an ordinary positive nonzero status

|`error`
|runtime resolution, spawn/permission, timeout, signal termination, or
subprocess communication/infrastructure failure

|`not_run`
|reserved existing deliberately-unselected diagnostic concept; invalid as the
result of a required phase attempt and therefore a hard evidence error
|===

Timeout terminates and reaps the direct child only. A2 creates no process group,
tracks no descendants, kills no process tree, and provides no descendant
containment; descendants may survive or retain pipes. There is no retry or
accepted nonzero-status list. Signal termination is not an ordinary clean test
failure.

== 8. Executable resolution and environment policy

=== 8.1 Resolution

Absolute `argv[0]` bypasses PATH. Relative values containing `/` resolve from
repository root. Bare values search effective PATH in order. Because subprocess
cwd is repository root, relative/empty PATH entries have that same base.
`PATH=""` is exactly one empty entry, so a bare name is searched in repository
root. Relative or empty entries may therefore resolve bare names to executable
repository files, including agent-modified content; this is audit disclosure,
not containment.

Resolution requires an executable regular file. The runner records the selected
absolute invocation spelling, canonical realpath, and a bounded
`os.stat(invocation_path)` fingerprint, following symlinks to the target
represented by that invocation spelling,
then executes the selected spelling. Symlinks and explicit repository-local
executables are supported; neither implies containment. Admission resolves all
selected definitions. Runtime repeats resolution because repository or host
state may legitimately change after preflight.

This yields an exact failure distinction: absent/non-executable during admission
is an admission refusal; disappearance, permission change, or spawn failure at
evidence time is runtime `error`. A changed path/target is recorded, not treated
as policy corruption, because A2 explicitly permits agent-modified code.

=== 8.2 Environment

`coordinator-inherited-environment-v1` copies `os.environ` once in canonical
preflight. It uses inherited PATH when present, including an empty value; only an
absent PATH is replaced with `os.defpath`. The same immutable mapping drives
admission resolution, runtime resolution, and subprocess execution.

This honestly preserves current host behavior. Git can depend on HOME and config;
tools can depend on locale and temporary-directory variables. A bounded allowlist
would be a new hermetic-environment design and is not justified by current
runtime evidence.

Only policy version, PATH source, and PATH SHA-256 are persisted. No environment
name/value list is recorded. The policy does not scan for or prove absence of
secrets. No virtualenv is implicitly discovered: activation affects inherited
PATH, while a repository `.venv` dependency must be explicit in argv.

== 9. Output bounding

Current durable state needs no raw stdout/stderr. A2 retains no stream body at
all. It records a digest and byte count for each complete captured byte stream
and marks a non-empty body omitted. A normally completed process has actual
count/digest facts for each complete stream and `body_omitted=true` exactly when
non-empty. Where no complete stream is available--resolution failure before
spawn, spawn failure, timeout, or communication/infrastructure failure--the
corresponding count, digest, and body-omitted fields are all `null`; an empty
digest represents only an actually captured complete empty stream. The summary
is synthesized from outcome facts rather than command output.

This gives a hard durable bound of zero retained stream bytes, avoids an
additional output-size constant, and prevents arbitrarily long first-line
summaries. Digesting the complete stream remains directly implementable with the
current full capture. That transient capture is not a hostile-output memory or
disk limit, and the contract says so rather than implying a sandbox.

== 10. Durable evidence facts

The minimum audit record groups facts rather than adding a general ledger:

Semantic:: command name and `pass|fail|error|not_run`.

Exact record shape:: `provider`, `status`, `command_name`, `command` (full executed argv),
`summary`, `artifact_ref`, `argv_digest`, `authored_argv0`, `timeout_seconds`,
`cwd_policy`, `invocation_path`, `canonical_path`, `stat_fingerprint`,
`environment_policy`, `path_source`, `path_digest`, `exit_code`, `signal`,
`error_class`, `stdout_byte_count`, `stdout_sha256`, `stdout_body_omitted`,
`stderr_byte_count`, `stderr_sha256`, and `stderr_body_omitted`. `command`
preserves an empty later argv item exactly; only item zero is non-empty. The old
combined output `digest` is removed, never repurposed. The changed record shape
requires `execution-evidence.json` schema version 2 and version 2 for every
`operator-summary.json` embedding/projection of attempts; there is no v1 reader
or migrator.

Definition/binding:: full executed argv, argv digest, authored `argv[0]`, explicit timeout,
repository-root cwd policy, environment-policy version, PATH source/digest.

Runtime resolution:: absolute invocation path, canonical realpath, and bounded
stat fingerprint.

Completion:: exit code or signal, stable error class, per-stream byte count,
per-stream full SHA-256, and body-omitted flags.

Diagnostic:: Coordinator-generated fixed summary and optional artifact ref;
never copied output or environment values.

The operator plan records admission preparation using selected command names,
argv digests, resolution, timeout, and environment/PATH facts; it has no
undefined "definition digest". Current-hop checkpoint evidence
and cumulative atomic `execution-evidence.json` record runtime observations.
The latter is published before another adapter call or ordinary return.
`operator-summary.json` may project the bounded records. Run/Hop schema and
agent-attributed evidence refs remain unchanged; duration is not currently an
evidence fact and A2 does not add it. After all required evidence attempts for a
Hop, before ordinary reduction/completion, one trusted existing-mechanism Git
re-observation requires HEAD equal the trusted pre-evidence Hop end HEAD and a
clean worktree under resolved-submodule semantics. Either difference projects
through existing `MechanicalFacts.repository_anomaly`. This prevents an
unattributed post-observation evidence commit from leaving `Run.current_head`
stale, recorded commits incomplete, governance mutation unattributed, or a
terminal completion falsely successful. It adds no state, reducer fact, authority
model, or second Git ledger. It neither detects nor contains ref changes leaving
HEAD unchanged, config/reflog mutation, or other invisible `.git` metadata; such
host-containment concerns are outside A2.

[cols="2,3,3",options="header"]
|===
|Stage |Examples |Disposition

|Pre-Run admission
|Malformed/missing/unknown policy field; invalid argv/name/timeout; duplicate or

|`OperatorPreflightError`; no Run UUID/model, state root, checkout, adapter,

|Executable disappears/loses permission; spawn failure; timeout; signal;
communication/infrastructure failure
|Observation `error`; existing required-evidence mechanical preemption

|Exit 0; ordinary positive nonzero exit

An executable that existed at preflight but changed later has not retroactively
corrupted admission. Runtime facts govern the attempt. This distinction avoids
both stale trust claims and false admission-corruption reports.
