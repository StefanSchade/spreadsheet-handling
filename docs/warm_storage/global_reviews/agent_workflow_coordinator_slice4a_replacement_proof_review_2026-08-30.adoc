== Missing process diagnostic -- proof-harness evidence defect (category A); root cause unavailable (category C)

The retained evidence persists `process_returncode=1` and `process_timed_out=false`
but not the bounded stdout/stderr tail. Narrowest supported classification:

* The implementation *does* capture a bounded diagnostic: `invoke_codex` builds
  `CodexOutcome(child.returncode, timed_out, acceptance, _bounded(stdout),
  _bounded(stderr), result_text, validated)` (slice4.py:186), with `_bounded`
  retaining a 16 KiB tail, and `run_real_one_hop` returns that `CodexOutcome` on
  the `RealHopRun`. So the stdout/stderr tail existed in-process.
* The coordinator's *durable persistence boundary* (Trusted Run snapshot, dispatch
  marker, result state/transport, checkpoints) intentionally does not carry raw
  process tails -- that is by design, not a defect.
* The disposable-proof *wrapper* that produced `proof-summary.json` read
  `returncode` and `timed_out` from the returned outcome but did not persist
  `outcome.stdout` / `outcome.stderr`. **The missing diagnostic is therefore an
  evidence-quality defect in the proof harness/wrapper (category A), not a
  material Slice-4A implementation defect (not category B).**
* Because the tail was not persisted, the *exact* cause of process exit `1` is
  *unavailable* from retained evidence (category C for the root-cause question).

Explicitly, per the review mandate: this failure is *not* attributed to the
historical nested-Codex read-only error -- that was a different Run in a different
declared environment. And exit code `1` is *not* inferred to be a coordinator
implementation defect: nothing connects the process failure to coordinator
mechanics; the coordinator's job on an unresolved result is exactly the
containment it performed.
