== 3. Owner delegation and composite boundary

=== 3.1 FK

Current `_helper_columns_for_frame` extracts only the raw FK-owned leaf:

[source,python]
----
sheet_meta.get("helper_columns")
----

and delegates it as:

[source,python]
----
validated_helper_columns(
    sheet_meta.get("helper_columns"), frame_name=frame_name
)
----

The symbol is imported from
`spreadsheet_handling.domain.transformations.fk_helpers`, the package facade,
not `fk_helpers.policy`. Cell Codec does not open an entry or name/interpret
the FK-specific `column`, `fk_column`, `target`, `target_key`, or `value_field`
fields.

=== 3.2 Lookup

Current `_helper_columns_for_frame` extracts the whole raw Lookup-owned value:

[source,python]
----
sheet_meta.get("enrich_lookup")
----

and delegates it unopened as:

[source,python]
----
validated_enrich_lookup_helper_columns(
    sheet_meta.get("enrich_lookup"), frame_name=frame_name
)
----

The symbol is imported from
`spreadsheet_handling.domain.transformations.enrich_lookup`, the package
facade, not `enrich_lookup.provenance`. Cell Codec no longer opens the raw
record's `helper_columns` member and does not inspect join-key form, formula
meaning, or any other Lookup semantics.

=== 3.3 Composite responsibility

Cell Codec still navigates `_meta`, `derived`, `sheets`, the requested frame,
and the two owner subkeys. That is shared-container extraction and owner
routing. Representation interpretation begins only after the extracted value
is handed to its owner facade. This is the same accepted composite/owner seam
used by the F-002 DCP implementation.

[.lead]
*FOREIGN ONTOLOGY REMOVED*

[.lead]
*DMC HANDOFF CORRECT*

Codec's existing participation `ValueError`.

No DCP strictness, Workbook-View facade, Workbook-View source edit, or malformed
Workbook-View hardening was introduced.

== 15. Findings

[[finding-001]]
=== FINDING-001 -- MINOR -- implementation record misstates the old non-mapping Lookup path

Location:: implementation record, Section 6, the `non-mapping enrich_lookup`
bullet.

Record wording:: the old non-mapping record was “silently misread through
`_column_name_set`'s permissive `Iterable` branch.”

Source authority:: before `cf0f0c3`, Cell Codec first checked
`isinstance(enrich_lookup, Mapping)`. A list or other non-mapping record failed
that guard and was silently skipped; it was never passed to `_column_name_set`.

Correction:: replace that parenthetical mechanism with “previously: silently
skipped by the outer `Mapping` guard.”

Impact:: documentation only. The record's observable before/after disposition
(silent absence -> owner-facade `ValueError`) is correct, the readiness review
explicitly accepted it, current source implements it correctly, and public
tests/probes confirm it. This does not block implementation acceptance or
Cell Codec blocker closure.

No MATERIAL finding. No unrelated cleanup finding is introduced.
