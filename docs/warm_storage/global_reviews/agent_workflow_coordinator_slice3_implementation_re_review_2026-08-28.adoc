== S3-R1 (IMPORTANT) -- CLOSED

The two post-acceptance postcondition classes are no longer raised before
`record_hop`. `_subject_anomalies` and `_durable_artifact_anomalies` now return
diagnostic strings that are merged with `observe_hop` anomalies into
`MechanicalFacts.repository_anomaly` and fed to `reduce_result` *after*
`record_hop`. Independent reproductions (accepted invocation that creates a real
commit) confirm, for an invalid subject, a missing durable artifact, and (for
consistency) an out-of-scope path:

[source,text]
----
status=awaiting_human  hop_used=1  hops=1  actual_commits=preserved
stop=mechanical_preemption:WFC-GIT-08 commit subject lacks WorkItem/Hop identity: feat: no identity
stop=mechanical_preemption:required durable artifact is missing, out of scope, or uncommitted
stop=mechanical_preemption:out-of-scope changed path: docs/leak
checkpoint_hops=1  checkpoint_stop=True  next_permitted_route_keys=[]
----

So each such failure now: charges exactly one Hop; preserves the actual observed
commits on the recorded Hop; records the Hop before reduction; flows through
`MechanicalFacts` -> `reduce_result`; enters the deterministic `awaiting_human`
mechanical-preemption stop; preserves a diagnostic `stop_reason`; renders a
checkpoint; performs no hidden retry; and infers no agent route (`route_key`
is `None`). The durable-artifact success path still `completed` in one Hop.

Pre-acceptance failures remain distinct: `preflight_hop` still raises
`VerticalRunError` before any Hop is charged. A dirty-tree reproduction confirmed
`non-ignored untracked state` raises with no Hop consumed, consistent with
WFC-AUTO-03. The scope-anomaly and postcondition-anomaly paths are now handled
uniformly, resolving the inconsistency that motivated S3-R1.

Result: WFC-AUTO-02, WFC-FAIL-01, and WFC-OBS-01 are satisfied for this boundary.

== S3-R2 (MINOR) -- CLOSED

WFC-GIT-08 subject validation is narrowed: `_CONVENTIONAL_SUBJECT`
(`^[a-z][a-z0-9-]*(?:\([^)]+\))?!?: `) requires a Conventional-Commit-compatible
`type: ` / `type(scope): ` prefix, and `_contains_identity_token` matches the
WorkItem and Hop identities as delimited whole tokens (negative look-around over
`[A-Za-z0-9_-]`). Independent token probes:

[source,text]
----
conv=1 WI-1=1 H001=1  valid  <- 'feat(workflow): WI-1 H001 ok'
conv=1 WI-1=0 H001=0  reject <- 'feat(workflow): WI-100 H0012 collision'
conv=0 WI-1=1 H001=1  reject <- 'not conventional: WI-1 H001'
conv=1 WI-1=1 H001=1  valid  <- 'fix!: WI-1 H001 bang'
conv=1 WI-1=1 H001=1  valid  <- 'chore(a-b): WI-1 H001 ok'
conv=1 WI-1=0 ...     reject <- 'feat(x): WI-1-extra H001'  (conservative, different token)
conv=1 WI-1=0 ...     reject <- 'feat(x): xWI-1 H001'       (conservative, different token)
----

`WI-1` no longer matches `WI-100`; `H001` no longer matches `H0012`; the intended
subject still passes; and non-Conventional prefixes are rejected. Adjacent-hyphen
and letter-prefixed variants are treated conservatively as distinct tokens, which
is the safe direction. No hook, trailer, message framework, or identity-schema
change was introduced -- the fix is a local regex plus a token predicate.
