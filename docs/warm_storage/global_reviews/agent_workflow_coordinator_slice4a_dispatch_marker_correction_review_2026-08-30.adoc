== S4A-R8 -- pre-spawn marker lifecycle -- CLOSED

*Correction.* The narrow `except Slice4Error: unlink; raise` clause is removed and replaced by a general terminal clause, and the pre-spawn discriminator now guards the `ResultValidationError` branch too:

[source,python]
----
except ResultValidationError:
    if adapter.outcome is None:
        dispatch_path.unlink(missing_ok=True)
        raise
    ... uncertain recovery ...
except Exception:
    if adapter.outcome is None:
        dispatch_path.unlink(missing_ok=True)
    raise
----

*Verification against the required invariant* (definitely no real process started -> no marker -> no Hop):

. A deterministic local failure after marker publication but before `_CodexAdapter.invoke()`/`Popen` -- e.g. `assemble_prompt` raising `ValueError("selected prompt component is unavailable...")`, the inner `preflight_hop` raising `VerticalRunError`, or a phase `KeyError` inside `run_one_hop` -- is not a `ResultValidationError`, so it reaches `except Exception`; `adapter.outcome is None` (nothing spawned) -> `dispatch_path.unlink(missing_ok=True)`. Marker removed. *Pass.*
. The original failure is re-raised unchanged by the bare `raise`. *Pass.*
. No Hop is charged (`run` is untouched; the function raises). *Pass.*
. No Git mutation is produced (failure precedes `adapter.invoke`). *Pass.*
. The fake executable is never invoked. *Pass.*
. Classification is general -- `except Exception` + `adapter.outcome is None` -- not a `ValueError` special case. *Pass.*
. After a post-spawn outcome exists (`adapter.outcome is not None`), an unexpected non-`ResultValidationError` exception reaches `except Exception`, the `adapter.outcome is None` guard is false, so the marker is *not* removed and the failure re-raises. A started (possibly accepted) invocation therefore keeps its uncertain anchor for restart reconciliation. *Pass.*

`adapter.outcome` is a truthful discriminator: `invoke_codex` returns a `CodexOutcome` whenever `Popen` succeeded (it catches `TimeoutExpired` internally and never re-raises post-spawn), and every `invoke_codex` raise path (`timeout <= 0`, `validate_checkout`, `Popen` `OSError -> Slice4Error`) is pre-spawn, leaving `adapter.outcome is None`. The launch-failure `Slice4Error` path -- formerly served by the deleted `except Slice4Error` clause -- is now correctly subsumed by `except Exception` (outcome `None` -> unlink -> re-raise), so `test_real_driver_preserves_no_hop_for_unlaunchable_executable` still passes.

== Direct regression check

* `except Exception` does not swallow or normalize the failure: the branch performs at most an `unlink` and then bare `raise`, re-raising the current exception unchanged. *No regression.*
* `KeyboardInterrupt`/`SystemExit`/`BaseException` are not caught by `except Exception` (they derive from `BaseException`), so they propagate unconverted; a mid-run interrupt leaves the marker, which restart reconciles conservatively. *No regression.*
* Post-spawn unexpected failure preserves the marker (`adapter.outcome is not None`). *No regression.*
* The success path still returns the same truthful `RealHopRun(vertical, vertical.reduction.run, vertical.checkpoint, adapter.outcome)`. *No regression.*
* Uncertain recovery still uses `observe_hop` / `recover_uncertain_dispatch` / `require_reconcile` unchanged. *No regression.*
* No retry path; no result-authority change (`validated_result` gating intact); no external-state-boundary change (`_require_external_state_root` intact); no Slice-4B/bwrap/commit-broker scaffolding. *No regression.*

*NEW MATERIAL DIRECT REGRESSION FOUND: NO.*

Non-blocking observation (not introduced by `4aa0859c`, not reopened): if `child.communicate` were to raise a non-`TimeoutExpired` error *after* a successful `Popen`, `adapter.outcome` would stay `None` despite a started process, and `except Exception` would remove the marker.
