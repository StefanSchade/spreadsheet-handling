=== 6.2 Exact operation family

The filter invocation is exactly this argv family, with only the absolute path
to the verified temporary path file varying:

[source,shell]
----
git filter-repo \
  --refs refs/heads/main \
  --paths-from-file /ABSOLUTE/SCRATCH/included-paths.txt \
  --preserve-commit-hashes \
  --preserve-commit-encoding \
  --replace-refs delete-no-add \
  --prune-empty auto \
  --prune-degenerate auto
----

`--refs refs/heads/main` implies filter-repo partial mode. C shall record the
tool's actual reported or effective option state, or otherwise record evidence
sufficient to show that partial mode is active; the contracted argv remains
authoritative. There are no `--path-rename` or `==>` rules. There is no `--force`,
callback, mailmap, message/text replacement, subdirectory filter, tag rename,
blob strip, or second filter pass over the same scratch clone / rewritten result.
If pinned git-filter-repo 2.47.0 refuses the contracted invocation because the
prepared scratch repository does not satisfy its fresh-clone safety check, C must
stop and B re-opens; C must not add `--force` or any other option on its own
judgment. All history outside the literal paths is dropped.

The metadata expectation is bounded: preserve author and committer names,
emails, timestamps, commit-message content/encoding, retained patch content, and
projected parent order as emitted by the pinned tool. Commit and tree IDs
necessarily change. Original cryptographic commit/tag signatures, excluded
parents/hunks, empty commits, degenerate empty merges, reflogs, replace refs,
branches, and tags are not preserved.
