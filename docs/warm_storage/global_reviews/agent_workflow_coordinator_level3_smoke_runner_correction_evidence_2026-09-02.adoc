== Boundary preserved

The runner remains limited to:

  Invocation -> AgentExecutionRequest -> CodexCliAdapter.execute()
    -> AgentExecutionOutcome -> validated_result() -> smoke-summary.json

It does not introduce or exercise Run/Hop lifecycle, reducer, Git,

== L3SR-R1 -- truthful pre- versus post-execution classification

Original defect:: The runner caught `CodexCliError`, `OSError`, and `ValueError`
around `execute()` and recorded all three as `invocation_attempted=false` /
`local_pre_execution_error`. A post-launch non-UTF-8 result decode or timeout
cleanup `ProcessLookupError` could therefore be recorded falsely as not started.

Correction:: `CodexCliError` now subclasses the existing provider-neutral
`ExecutionNotStartedError`, and the adapter emits it only from validation,
pre-launch setup, or failed `Popen`. Exceptions after successful `Popen` remain
outside that type. The runner classifies only `ExecutionNotStartedError` (and its
own pre-adapter directory setup failure) as `local_pre_execution_error`. Any
other exception from the execution path is recorded as `post_execution_error`
with `invocation_attempted=true`.

Tests:: A fake executable launches once, writes invalid UTF-8 to
`--output-last-message`, and exits; its summary is `post_execution_error`, not
not-attempted. A missing executable is a proven pre-launch failure. A monkeypatch
adapter seam that raises a generic execution-side `RuntimeError` writes the same
post-execution classification without a retry.

Resulting truthfulness semantics:: `invocation_attempted=false` and
`local_pre_execution_error` mean execution was positively proven absent. Unknown
or post-launch exceptions never make that claim.

== L3SR-R2 -- best-effort post-root durable summary

Original defect:: Unexpected exceptions after root creation could escape without
`smoke-summary.json`, despite persistence remaining possible.

Correction:: The runner uses a small local best-effort summary writer for
pre-launch failure, execution-side exception, and post-outcome processing
exception paths. It does not fabricate unavailable outcome facts and does not
mask the failure merely because writing evidence fails.

Tests:: The generic execution-side exception test proves a post-root summary is
written with only known facts and no second invocation.

Resulting truthfulness semantics:: When an outcome does not exist, return code,
timeout, provider diagnostics, candidate presence, and semantic result remain at
their known default/unknown values rather than being fabricated.

== L3SR-R3 -- remove real-provider compatibility overclaim

Original defect:: A fake executable could make
`real_provider_compatibility_established=true` in durable JSON.

Correction:: The field is replaced with
`configured_executable_smoke_succeeded`. It is true only when the configured
executable returned zero, did not time out, and produced a valid correlated
structured result.

Tests:: The fake-success test asserts the new field is true and asserts the old
real-provider claim is absent. Failure tests assert the new field is false.

Resulting truthfulness semantics:: Generic runner evidence establishes only the
configured executable's local smoke result, never real Codex/OpenAI
compatibility.

== L3SR-R4 -- record timeout

Original defect:: The durable summary omitted the timeout passed to the request
and adapter boundary.

Correction:: `timeout_seconds` is included in the summary base from the exact
`run_smoke()` value supplied to `AgentExecutionRequest`.

Tests:: The fake-success test supplies `1` and asserts the durable summary records
exactly `1`.

Resulting truthfulness semantics:: The executable, model, reasoning effort, and
timeout are all recorded as the actual configured smoke inputs.
