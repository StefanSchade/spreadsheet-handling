== Implemented boundary

The coordinator now dispatches through the provider-neutral
`AgentExecutionPort`. `AgentExecutionRequest` carries the invocation identity,
assembled prompt, repository, canonical result-contract identity, and timeout.
`AgentExecutionOutcome` returns candidate result text plus bounded transport facts
and diagnostics. It is deliberately pre-semantic: `vertical.py` remains the owner
of Python parsing, RoutingResult validation, and invocation correlation.

`CodexCliAdapter` is the sole current port implementation. It owns Codex argv,
model/reasoning configuration, sandbox/approval flags, output schema and final
message files, JSON/event CLI mode, process-group timeout termination, bounded
stdout/stderr, and transport diagnostics. The former mutable `adapter.outcome`
side-channel is removed. Slice-4 retains only checkout association and
provider-neutral dispatch/persistence/recovery composition.

== Contract and offline conformance

Canonical RoutingResult facts remain in the provider-neutral semantic serializer.
The Codex/OpenAI strict JSON-Schema projection is in `codex_adapter.py` and derives
its required keys, enums, and nullable facts from that canonical contract.

The named Level-1 offline conformance layer checks the exact emitted projection:

* every object is `type: object`, strict, and has `required == properties`;
* every non-composition node has an explicit supported type, including both
  `schema_version` const nodes;
* nested properties, arrays, and nullable `anyOf` branches are traversed; and
* unsupported schema constructs are rejected.

It catches both historical live defects offline: the opaque result object and the
untyped `schema_version: { const: 1 }` node. The corrected projection emits
`type: integer` with its `const: 1` value.
