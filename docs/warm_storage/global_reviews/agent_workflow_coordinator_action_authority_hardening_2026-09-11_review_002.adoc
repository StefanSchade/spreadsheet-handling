== Delta and implementation assessment

The baseline-to-target delta contains eight files: the strict serializer, the
runtime vertical, three focused test modules, FTR 11.4.7, the hardening note, and
the commissioning diary. That is bounded to the AAH-R1 correction and its
evidence. Review 001 is byte-for-byte unchanged.

=== Static coherence

`serialization._check_action_coherence()` computes `has_edit` and `has_commit`,
then rejects `edit` without `commit`, rejects `commit` without `edit`, and
separately rejects a required durable artifact unless both are present. Therefore
required-durable phases with neither, `edit` only, or `commit` only fail, while
`edit,commit` succeeds. A `review`-only phase with no durable artifact still
deserializes. The open descriptive action vocabulary is unchanged.

These are implementation checks in the strict `workflow_profile_from_yaml()` path,
not fixture conventions. The required-durable conjunction accurately implements
Review 001's accepted conclusion: producing the repository artifact exercises
`edit`, and landing it exercises `commit`.

=== Runtime trusted-commit boundary

`vertical.run_one_hop()` handles every non-null `CommitIntent` by deriving the
missing members of `(EDIT_ACTION, COMMIT_ACTION)`. Any non-empty missing set records
an authorization error and bypasses the only `trusted_commit()` call. Only the
empty set, together with the pre-existing permitted-disposition predicate, can
enter that call. Thus `edit` only, `commit` only, and neither fail closed; both
preserve the accepted path.

On refusal, the existing `observe_hop()` path observes the unchanged HEAD and
agent-created dirty file. The resulting repository anomaly retains the existing
mechanical-preemption precedence and human stop. The real-Git half-grant tests
confirm unchanged HEAD, retained dirty content, and `awaiting_human`. Source
control flow additionally establishes that `trusted_commit()` is not invoked.

=== Operator and success regressions

`test_commit_only_phase_rejects_before_provider` reproduces the precise AAH-R1
operator shape: phase `[commit]`, policy `[commit]`, and
`durable_artifact: none`. The pinned profile fails strict coherence with the
specific `commit`-without-`edit` diagnostic. The test asserts operator exit `2`,
fake-executable invocation count `0`, unchanged HEAD, and absence of the state
root; rejection therefore precedes Run/execution construction rather than arising
from a later accidental failure.

`test_coordinator_creates_one_authoritative_commit_from_worktree_only_agent`
remains the positive real-temporary-Git/fake-adapter proof. Its fixture phase grants
`edit,commit`; its completed, in-scope intent is permitted; the Coordinator creates
one commit, records the new HEAD, leaves the worktree clean, and completes the Run.
`test_required_durable_artifact_with_edit_and_commit_is_accepted` separately guards
the strict-profile positive case.

The focused tests would fail under each requested mutation:

* accepting `commit` without `edit` breaks both the serializer and operator tests;
* checking only `commit` at runtime lets the commit-only real-Git test move HEAD
  and complete, breaking its assertions;
* invoking the fake executable before operator rejection creates its counter,
  breaking the zero-invocation assertion;
* rejecting valid `edit,commit` breaks both the required-durable parse test and the
  successful trusted-commit path.
