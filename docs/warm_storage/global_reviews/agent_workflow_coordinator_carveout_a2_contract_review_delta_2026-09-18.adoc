The corrected M-findings were mirrored into WFC-EVID rows, but the post-evidence
Git re-observation lives only in 13.2 (normative) and its acceptance matrix; no

W-D2 (WATCH) -- `argv_digest` input spelling::
13.2 places the digest formula next to "full executed argv", while the operator
plan carries argv digests before execution. Either input is deterministic. For
plan/observation correlation the implementation should digest the authored
policy argv (the definition) and document that choice in code; the executed
spelling is already recorded in `command`.

W-D3 (WATCH) -- `provider` alongside `command_name`::
Both keys are retained. In current code `provider` is the phase evidence name
(`observation_error(..., expected_provider=...)`); the implementation should
keep them equal or document the distinction, without adding a new concept.
