== 3. Relocatability success claim

The success statement is truthful and useful as a _source-layout_ claim: after
A4' the package tree resolves its code through relative imports, its one
resource through `importlib.resources`, and its fixtures/scan through fixed
test-local anchors; the only remaining location input is the import root Python
itself needs for an uninstalled package. The statement explicitly disclaims
installation, distribution identity, and cwd-independent installed execution.
It does not silently strengthen into installed relocatability. Confirmed.

Precision gap: the phrase "does not ... inspect caller cwd" is true for WFC's
own code/resources, but the launch model makes the child cwd equal the source
import root, and relative CLI path arguments plus the Codex provider OS cwd do
bind to it (M2). This is not WFC self-discovery, but the text should say so.

== 4. Import/invocation model

Converting the three executable modules to relative imports is sufficient and
coherent. The scratch prototype applied exactly that edit (repair blocks deleted,
`from scripts.workflow_coordinator.` -> `from .`) to a copy named
`portable_wfc`: all three `python -m portable_wfc.<module> --help` returned 0,
all 14 modules imported, and `scripts` never entered `sys.modules`. No
conditional absolute/relative fallback and no import helper are needed. Nothing
imports `operator` as a library module, so `-m` execution as `__main__` creates
no double-import hazard.

Current package identity: retaining `scripts.workflow_coordinator` is correct.
It is an identity, not a filesystem search; the prototype proves WFC internals
no longer depend on it. Renaming now would pick C's name prematurely. Ordinary
test imports (including the four inline `import scripts.workflow_coordinator...`
statements) may remain.

Namespace parent: `scripts/` has no `__init__.py`; `-m` with an implicit
namespace parent works (probed on 3.13). Adding `scripts/__init__.py` would not
change relocatability: WFC's internal model is proven independent of the parent
by the top-level `portable_wfc` copy. The accepted carve-out plan listed
"elimination of reliance on implicit `scripts` namespace behavior" as a likely
A4' area; the contract discharges it substantively but does not say so (M3).

Python floor: only 3.13 is installed locally and CI pins 3.12, so 3.10 was not
executed. The mechanisms used (PEP 420 namespace parent with `runpy` `-m`,
relative imports, `importlib.resources.files`) predate 3.10; on 3.10
`collections` also imports `operator`, so the direct-file shadow is identical.
Recorded as INFO, not a finding.

== 5. Source-root/cwd boundary

The explicit child-cwd model is correct and is the smallest honest mechanism for
uninstalled source:

* Parent cwd and child import-root cwd are genuinely distinct: a parent in a
  neutral directory launching `-m` with `cwd=<Core root>` returned 0 for all
  three modules; bare `-m` from the neutral cwd fails with
  `ModuleNotFoundError: No module named 'scripts'`.
* After import, WFC consults no cwd for code, resources, or fixtures. Git calls
  use `-C <repository>`, A2 evidence uses `cwd=command.repository`
  (`evidence.py:259`), the local adapter uses `cwd=request.repository`.
* `PYTHONPATH` is worse than "environment magic": A2 evidence commands inherit
  the Coordinator environment (`coordinator-inherited-environment-v1`,
  `evidence.py:83-92`), so a `PYTHONPATH` launch contract would leak the WFC
  source root into every operated-repository evidence command (e.g. `pytest`)
  and into the provider. The cwd model leaks nothing into child environments.
* A `runpy`/`sys.path` wrapper is a launcher abstraction; editable install,
  `.pth`, or console script is C. No smaller non-packaging mechanism exists.

Residual truths the contract should state (M2): under this model the child cwd
_is_ the source import root, so relative `--repository`, `--state-root`,
`--proof-root`, `--smoke-root`, and `--executable` values resolve against it
(`operator.py:216,231` `.resolve()`), and `CodexCliAdapter` spawns the provider
without `cwd=` (`codex_adapter.py:164-167`), so the provider OS cwd is the source
root while `--cd` selects its workspace. Also (INFO) the model depends on
default `-m` path insertion: `PYTHONSAFEPATH=1` (3.11+), `-P`, or `-I` disables
it (probed: rc=1 with `PYTHONSAFEPATH=1`).

== 6. Direct-file removal

Verified: operator direct-file `--help` works from a neutral cwd only because of
its custom repair; proof/smoke direct-file fails at `import argparse` (before
their repair) because `collections` imports the sibling `operator.py`
(traceback captured). Module execution works for all three from the source
root. No live caller exists. Removal deletes three bootstraps and one
inconsistent invocation surface; retaining it would require exactly the path
repair A4' exists to remove. Removal simplifies the steady state. Accepted.

== 7. Alternate-package relocation proof

The probe design (copy only the package tree, alternate name, `-m` startup of
three seams, import every module, load the A3 resource) is the right proof and
is not C packaging. The scratch prototype confirms feasibility and that the
probe discriminates: the _unmodified_ copy fails all three startups with
`No module named 'scripts'`.

However, the specification leaves three demonstrable false-green paths open
(finding F1):

. *Inherited environment.* With `PYTHONPATH=<Core root>` inherited from the
  developer/IDE environment, the _unmodified_ copy starts with rc=0. The same
  inheritance makes A4P-02 pass regardless of the child cwd. The contract
  forbids the test from _setting_ `PYTHONPATH` but does not require an inherited
  value to be neutralized. `-E` restored the correct failure.
. *In-process sweep.* The pytest process has Core root importable and
  `scripts.workflow_coordinator.*` already loaded; an "import every module"
  sweep performed in-process would resolve a residual absolute import against
  original Core while every `portable_wfc.*` `__file__` still looks relocated.
  The contract does not require the sweep/resource load to run in a fresh child
  interpreter.
. *Undefined "no import from original Core".* The Core venv lives under Core
  root, so a Core-root prefix check wrongly flags `yaml` (observed); conversely
  the editable `.pth` places Core `src` on every child `sys.path`, so a future
  `import spreadsheet_handling` in WFC would pass the probe. A4P-03's claim
  "absence of Core source dependency" is therefore stronger than the specified
  evidence.

Copying with `__pycache__` present is low risk (identical sources) but pollutes
code-object origins; copying tracked files or ignoring `__pycache__` is cleaner.
A copy missing the resource fails red, not green.

== 8. Test/fixture handling

* Source scan anchored to the imported package directory plus a non-empty
  assertion: smallest truthful fix; closes the observed vacuous pass.
* Two fixture readers anchored to the test file's fixed location: smallest
  truthful fix; test-local and explicit. No generic locator is justified.
* String monkeypatch targets: they do not break alternate-package relocation
  (tests are not relocated in A4') and a textual rename in C would rewrite them
  anyway, so the benefit is modest (object reference fails at import time and
  survives refactoring tools). The change is plan-mandated and three lines.
  Object form preserves the exact seam: the string
  `...evidence.subprocess.Popen` already patches the shared stdlib
  `subprocess.Popen`, identical to `monkeypatch.setattr(evidence.subprocess,
  "Popen", ...)`; `ProductionEvidenceRunner.observe` maps to the class object.
  Keep; no finding.
* The new test must know the current source import root to set child cwd.
  Deriving it from the imported package directory and dotted depth, or from the
  test file's own fixed location, is test-local and legitimate; the FTR's
  structural-assertion bullet reads as if it could forbid this (M1).

== 9. A3 preservation

`prompt.load_agent_operating_contract()` (`prompt.py:49-62`) uses only

an import path, and needs no rename. Package-data metadata is correctly not
required. Both real policies keep the A3 reservation; the consumer-governance
test's Core `__file__` anchor legitimately remains until D.

* *C*: filtering, final layout/name, `pyproject.toml`, dependencies, pytest

* *D*: Core pin, import/invocation migration, embedded removal, generic test

  plan's D step "install the sibling standalone repository editable" does not
  conflict with A4' forbidding editable install as an A4' mechanism.

The corrections requested below add assertions to one test and sentences to
the contract; they add no machinery.

Implementation slice size: the eight predicted files (three production, four

there is no independent review boundary worth splitting. The new test fits

== 13. Findings

=== BLOCKING

None.

=== IMPORTANT

*F1 -- Relocation/neutral-cwd probe can false-green.*

Observation:: WFC-SYS-10 and A4P-02/03/04 do not require the probe child to be
isolated from inherited import-root environment, do not require the import sweep
and resource load to run in a fresh interpreter, and do not define "no import
from original Core". Probed: inherited `PYTHONPATH=<Core root>` lets the
unmodified copy start (rc=0); a Core-root prefix check flags venv `yaml`; Core
`src` is on every child `sys.path` via the editable `.pth`.
Risk:: The acceptance evidence can pass while residual absolute imports or a
new Core-library import exist, i.e. the probe proves less than A4P-03 claims.
Smallest correction:: Add to the 13.4 acceptance matrix (and readiness A4P-02/03/04):
(1) probe children run as fresh interpreters with import-root-affecting
environment neutralized -- `-E`, or `PYTHONPATH`/`PYTHONSAFEPATH` absent from the
child environment -- as test hygiene, not a launch mechanism;
(2) the all-module import sweep and A3 resource load run in that child from the
temporary root, never in the pytest process;
(3) the child asserts `scripts` and `spreadsheet_handling` are absent from
`sys.modules` and every `portable_wfc.*` `__spec__.origin` lies below the
temporary root;
(4) one negative control: the same `-m` argv from a neutral child cwd fails with
`ModuleNotFoundError`;
(5) copy tracked package files (or ignore `__pycache__`).

=== MINOR

*M1 -- FTR structural-assertion bullet over-reaches into tests.*

Observation:: The FTR matrix bullet bans "`sys.path` use, `__file__`
parent/split import repair, ... or string-form monkeypatch target under the
bounded WFC source/test set". Read literally for tests, it forbids the retained
Core consumer test anchor (`Path(__file__).resolve().parents[3]`), the required
test-file fixture anchors, and the new test's derivation of the current source
import root. Readiness A4N-01/02 is precise.
Risk:: Implementation/review dispute or an over-broad guard.
Smallest correction:: Align the bullet with A4N-01/02: `sys.path`/`__file__`/
root-search bans apply to production modules; the bounded tests are checked only
for string-form monkeypatch targets; tests may derive the source import root
and fixtures from an imported package or their own fixed location.

*M2 -- Child-cwd consequences and provider cwd stated inaccurately.*

Observation:: 13.4 says "provider cwd and A2 evidence cwd are the explicitly
operated repository" and that relative CLI values use "normal command-line path
semantics". A2 evidence cwd is explicit; the Codex provider process inherits the
launcher cwd (`codex_adapter.py:164-167`, no `cwd=`), with only `--cd` explicit.
Under the A4' model that inherited cwd, and the base for every relative CLI path
(`operator.py:216,231`), is the source import root.
Risk:: A false archaeology claim, and non-Core pre-C users would find relative
paths silently bound to the WFC source tree.
Smallest correction:: Restate truthfully in 13.4: provider workspace is selected
by explicit `--cd` while its OS cwd is inherited; under the source-tree launch
model relative CLI paths resolve against the child's source-root cwd, so
source-tree guidance uses absolute operated-repository/state/output/executable
paths. No code change in A4'.

*M3 -- Accepted-plan item not reconciled.*

Observation:: The accepted carve-out plan lists "elimination of reliance on
implicit `scripts` namespace behavior" as a likely A4' area; 13.4 retains the
namespace parent without saying how that item is discharged.
Risk:: Traceability gap at the B boundary check ("A4' relocatability checks
pass").
Smallest correction:: One sentence: WFC-internal reliance is eliminated by
relative imports and proven by the top-level `portable_wfc` relocation; the
remaining `scripts` namespace parent is Core's current layout identity, removed
by C's path transformation.

=== INFO/WATCH

* I1: The cwd model's strongest justification over `PYTHONPATH` is A2
  environment inheritance (section 5); worth one clause in 13.4, optional.
* I2: `PYTHONSAFEPATH`/`-P`/`-I` disable the source-root model (3.11+);
  acceptable pre-C, removed by C's installed entry point.
* I3: Python 3.10 floor not executed locally (3.13 only; CI release pins 3.12).
* I4: An identity-agnostic import guard (no level-0 import of the package's own
  root name, computed from `__package__`) would survive C's rename; optional.
* I5: Reintroduced cwd-relative fixture paths are caught only by neutral-cwd
  runs, not by normal Core-root runs; the non-empty scan covers the scan case.
