== Historical decisions not reopened

The following accepted decisions remain fixed:

* `xref_crosstable` remains a four-module package with a two-symbol facade. It
  is not merged back into a flat module and is not repartitioned for symmetry.
* `expand_xref` means matrix to relation; `contract_xref` means relation to
  matrix. Their names, signatures, registry targets, and error behavior are
  public contract surfaces, not local rename opportunities.
* Cell values remain opaque in the generic operation. Binary-marker semantics
  belong to the composing use case, not to this package.
* Duplicate coordinate pairs fail. Sparse, `drop_empty`, dense-axis, explicit
  column-order, `base_relation`, and `drop_source` behavior remain unchanged.
* `relation`, `matrix`, `row_keys`, and authored dense-axis sources remain
  persisted inverse intent. Top-level `column_keys` and
  `dense_axes.resolved` remain run-local Resolution and are removed by the
  orchestrator persistence boundary for every carrier.
* Physical relation/base-frame labels and carrier-stable matrix-axis identities
  remain distinct contracts with load-bearing validation order.
* Final-domain cleanup remains an explicit transient command written only after
  successful validation and output publication.
* Axis Mapping continues to compose around the unchanged public facade,
  resolves display-to-identity mappings live, and persists no label mapping.

Package formation at `bef201e` and subsequent accepted corrections are evidence
of current ownership, not invitations to replay historical alternatives. In
particular, `d2e8394`, `a0833b7`, `28decf3`, `d08f8a0`, `65f60bf`, `7a402a7`,
`9ea4b5a`, `f74f49e`, and `715eeed` established scoped recomposition, cleanup
coverage, minimal inverse intent, carrier-stable identities, validation
precedence, and shared tabular validation. This review does not reopen them.

== Forward/inverse operation phase map

The public directions and phase order are reconstructable without introducing a
new lifecycle object.

[cols="1,4,4"]
|===
| Phase | `expand_xref`: matrix -> relation | `contract_xref`: relation -> matrix

| 1. Invocation identity
| Resolve config id; reject same-frame `drop_source`.
| Resolve config id; reject same-frame `drop_source`.

| 2. Source boundary
| Require matrix and validate its complete physical header against the
carrier-stable string identity contract.
| Require relation and validate physical labels before pandas selection.

| 3. Required declarations
| Normalize/flatten/de-duplicate `row_keys`; require them in the matrix.
| Normalize/flatten/de-duplicate `row_keys`; require row, column-key, and value
fields and reject output-name collisions.

| 4. Precedence-sensitive validation
| Load and physical-validate optional `base_relation` before collision-set
construction; validate explicit value-column identities before overlap checks.
| Validate relation column-identity values before duplicate-pair hashing; reject
duplicate coordinates and unsafe `drop_source` extra fields.

| 5. Domain selection
| Select explicit or inferred value columns; enforce drop-source completeness.
| Resolve one authored dense descriptor from explicit config or metadata, then
resolve live/stored dense domains. Choose column order explicit -> dense ->
metadata -> observed relation and validate its identities.

| 6. Materialization inputs
| Walk matrix rows/cells, record in-scope addresses, and apply ordinary
`drop_empty` filtering.
| Select dense or observed row identities, validate relation membership in dense
domains, and enforce drop-source column coverage.

| 7. Recomposition
| Validate base required fields/identities and append only out-of-scope base rows
in original order.
| Build the coordinate lookup and ordered matrix rows, using `fill_value` for
unrepresented coordinates.

| 8. Publication
| Materialize relation; shallow-copy the frame mapping and publish output.
| Materialize matrix; shallow-copy the frame mapping and publish output.

| 9. Metadata lifecycle
| Carry prior authored dense intent and write minimal inverse metadata plus
run-local column-key Resolution.
| Write minimal inverse metadata, authored dense intent, and run-local resolved
dense payload.

| 10. Cleanup
| Only after success, optionally mark the matrix for final cleanup.
| Only after success, optionally mark the relation for final cleanup.
|===

This order explains most of the otherwise detailed comments. Moving validation
to reduce local line count would change which deterministic domain diagnostic is
raised before pandas hashing, membership, or cleanup side effects.

== File-by-file reader assessment

=== Facade

The three-line facade is exact: its exports match `__all__`, registry targets,
and production imports. No private dense or validation helper has leaked into a
production consumer. There is no reader benefit in changing it.

=== Operation

The public pair is deliberately inverse but not symmetric line-for-line.
`expand_xref` must validate every matrix header as a carrier-stable identity;
`contract_xref` accepts the weaker physical-label contract for the relation and
then validates identity values separately. `base_relation`, `drop_empty`, dense
domain construction, and coverage checks create genuine phase differences.

The long functions retain local phase visibility. Comments that may look verbose
record why validation occurs before a particular set, equality, membership,
pandas selection, metadata write, or cleanup command. Accepted corrections and
tests prove that this ordering is behavior, not commentary style. No extraction,
renaming, or local type expansion has a demonstrated net reader gain.

=== Dense axes

`dense_axes.py` owns one coherent concern: rebuilding complete row/column domains
from authored source descriptors or stored intent. Exact config-id precedence,
relation/matrix fallback, ambiguity rejection, live/stored source handling, and
payload construction are colocated. `dense_config` and `dense_resolved` are
truthful lifecycle names. The mappings are cohesive descriptors whose keys are
dynamic persisted vocabulary; replacing them with scalar signatures or an
unowned type hierarchy would obscure the boundary.

=== Primitives

The module is a true leaf for narrow shared guards and metadata selection. The
aliases to shared tabular validators deliberately preserve private XRef names and
accepted diagnostics while centralizing the implementation. The opening
docstring, however, still says the bodies are verbatim moves and only location
changed. Later accepted identity/ambiguity work and the shared-validator aliases
make that assertion false. This is XC-HR-001; it does not undermine the current
module seam.

== Recommended next step and stop-here option

*Recommendation: `Stop here — no xref_crosstable readability implementation currently justified`.*

The package has clear ownership, a minimal facade, truthful runtime names,
explicit lifecycle separation, and test-protected phase order. A runtime FTR,
module split, signature rewrite, type layer, or import normalization would add
more review surface than reader value.

XC-HR-001 and XC-HR-002 are real documentation defects. Correcting them is safe
only as a documentation-maintenance action that aligns prose with already
accepted behavior. They may be batched into a future independently justified
low-touch documentation slice; this assessment neither performs nor authorizes
those corrections. If a future runtime change touches any gated surface above,
it requires the named authority rather than relying on this review.

No implementation FTR, code change, test change, registry/YAML change, Project
Memory change, or style-guide document is warranted by this validation.
