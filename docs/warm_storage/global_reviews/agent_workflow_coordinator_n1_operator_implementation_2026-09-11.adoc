= Declarative N=1 Workflow-Coordinator Operator -- Implementation Evidence

Baseline:: `0b183375763f98d54d15596d0820731b452bcef0`.

Purpose:: Replace retired task-specific commissioning launchers with one small,
repository-controlled, declarative N=1 operator surface.  This implementation
was performed conventionally; no real provider invocation was made.

Implemented contract:: `scripts/workflow_coordinator/operator.py` accepts one
repository, new external state root, pinned full HEAD, WorkItem/Profile/Policy,
component manifest, task text, optional durable-artifact declarations, timeout,
and local executable boundary.  It creates fresh Run and invocation identities,
then composes only `new_run`, `register_checkout`, and `run_real_one_hop`.

Reused boundaries:: Existing strict WorkItem/Profile/RepositoryPolicy YAML
serializers, prompt assembly, Codex adapter defaults, external checkout
association, dispatch/checkpoint persistence, reducer, trusted Coordinator Git
commit, result validation, and reconciliation remain authoritative.

Component manifest:: Strict YAML `schema_version: 1` plus `components`, whose
non-empty IDs map to exactly one repository-relative `path`.  Duplicate keys,
unknown fields, absolute paths, and traversal reject.

One-shot semantics:: The root must not exist.  Inputs are read with `git show`
from the expected baseline after clean-HEAD/tracked-input preflight.  Exactly one
Hop is allowed; no retry, resume, supervisor, child Run, provider route, or N>1
loop is present.  `operator-plan.json` and `operator-summary.json` provide
compact operator evidence without copying prompts or Run state.

Deterministic validation:: Focused temporary-Git-repository tests use local fake
executables only, covering strict manifests, preflight rejection, N>1 rejection,
durable-artifact policy, and a successful correlated one-Hop Coordinator commit.

Non-scope:: No Slice 5, multi-Hop, real WorkItem, real provider call, Domain
runtime change, resume/reconcile command, routing/plugin mechanism, Project
Memory update, or broad Coordinator documentation was added.

Release notes:: No entry: this is internal developer-tooling mechanics and the
repository policy does not require a release note for this change.

Readiness:: Ready for independent N=1 operator review; routine real use remains
subject to maintainer authorization and independent review.
