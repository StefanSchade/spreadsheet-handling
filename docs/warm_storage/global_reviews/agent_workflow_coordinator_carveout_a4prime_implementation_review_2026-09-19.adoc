=== MINOR

*M1 -- Structural `__file__` guard does not cover WFC library modules (A4N-01 scope).*

Observation:: In `test_production_uses_one_relative_import_model_without_bootstrap`,
the checks `"__file__" not in executable_source` and the `PYTHONPATH` and
`PYTHONSAFEPATH` bans scan only `operator.py`, `proof_harness.py`, and
`codex_adapter_smoke.py`. Accepted row A4N-01 and the 13.4 acceptance bullet
require the guard to reject `__file__` split/parent repair in *WFC production
files*.
Evidence:: Scratch mutation of a relocated copy added
`_CORE_ROOT = Path(__file__).resolve().parents[2]` to `prompt.py`, with no
`sys.path` use. The structural test *passed*, and `-m portable_wfc.operator --help`
also passed. The same mutation in `operator.py` is caught. The current tree
contains no `__file__`/`PYTHONPATH`/`PYTHONSAFEPATH` token in any production
module, so the invariant holds today, but only by accident.
Risk:: A future Core-root or parent discovery in any of the 11 library modules
bypasses both the guard and the parse-only relocation proof. That is exactly
the hidden Core-location authority WFC-SYS-09 forbids, and B would inherit an
unguarded invariant.
Smallest correction:: In the existing per-file production loop, also assert
`"__file__"`, `"PYTHONPATH"`, and `"PYTHONSAFEPATH"` are absent from `source`.
Keep the `__package__` ban restricted to the three executable modules, because
`prompt.py` legitimately uses `resources.files(__package__)`. This is test-only;
no production change, no new helper. Current tree is verified to pass the
widened check.
