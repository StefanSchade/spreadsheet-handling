== 3. FINDING-001 closure -- fail-open gate regression [[sec3]] [[find-1-status]]

*`be774c4`'s finding, restated:* the payload-presence-filtered `helper_cols`
fed the early "nothing to check" gate, so a payload missing **both** a
declared join-key column **and** every declared helper column
simultaneously short-circuited to an empty report *before* the
missing-key-column check ever ran -- silently zero findings under
`warn_on_mismatch`, no raise under `fail_on_mismatch`.

Read `evaluate_lookup_mismatches` top-down at `06337c5`
(`mismatch.py:84-181`, full function, not the diff alone). Effective order:

. `lookup_df is None` -> `missing_lookup_frame=True`
. `not payload_keys or not declared_helper_cols` -> empty report
. missing payload-key / lookup-key columns -> `unverifiable_reason`
. `not present_helper_cols` -> empty report
. duplicate lookup keys -> `unverifiable_reason`
. multi-key + formula cell present -> `unverifiable_reason`
. canonical-map construction / per-column value-and-formula comparison

This is exactly this task's prescribed ordering, and exactly `be774c4`'s own
recommended action ("the gate ... should test emptiness against
`interpreted.helper_columns` (the declared, unfiltered tuple) ... the
payload-filtered variable should continue to be used only where it already
correctly is").
