== 15. Scratch to staging transfer

This was probed empirically with the pinned Git version in an isolated throwaway
repository pair, with no repository of this workstream involved.

Probe:: A repository with two commits was `git reset --hard HEAD~1`, leaving the
second commit unreachable but still referenced by the reflog. Cloning it with
`git clone --no-local --no-tags --single-branch --branch <b>` produced a target
whose entire object database was exactly three objects -- the reachable closure
-- and `git cat-file -e <unreachable-oid>` failed. `git remote remove origin`
then removed `refs/remotes/origin/*` including `origin/HEAD`, leaving a single
local ref.

Conclusions:

* `--no-local` does disable the local hardlink/copy optimization and forces
  upload-pack negotiation, so the transfer is reachability-scoped rather than an
  object-store copy.
* Unreachable original Core objects left by partial-mode filtering are therefore
  *not* transferred. Reflog-only references do not make objects transferable,
  because upload-pack negotiates over advertised refs, not reflogs.
* `--no-tags` with `--single-branch --branch main` prevents annotated and
  lightweight tag leakage; in this pipeline the scratch clone has no tags anyway.
* No alternates can survive, because none are created by `--no-local` clones.
* `git remote remove origin` is sufficient to clear the remote-tracking refs.

The guarantee does rest on upload-pack reachability semantics, so the exact
proof C should perform after cloning is named in M3.

Result:: *The transfer architecture is correct and does not need replacing.*

*I1 -- `tests.support` is importable only under `python -m pytest`.* Category A.

*I4 -- "C accepted" conflates candidate acceptance with C lifecycle closure.*

*I5 -- Fresh-clone-safety feasibility is asserted rather than determined before
the first run.* Category A; the underlying conflict, if real, is category B.
