== Finding dispositions

=== S4A-R1 -- pre-write external authority -- CLOSED

`_require_external_state_root(state_root, repository)` (slice4.py:64) resolves `state_root` and derives the canonical checkout from `_facts(repository)[0]` (`rev-parse --show-toplevel`, resolved), then rejects `root == checkout`, `checkout in root.parents` (state root below checkout), and `root in checkout.parents` (checkout below state root). It is invoked:

* in `register_checkout()` *before* the first write (slice4.py:75, ahead of the mapping write at :81);
* at the top of `validate_checkout()` (:89);
* in `invoke_codex()` before per-Hop state writes (:127).

Because the guard precedes every write, a rejected first registration leaves no trusted files. `test_state_root_nesting_is_rejected_before_any_trusted_write` proves both the equal/under-checkout case (`repository/"bad-state"`) and the checkout-under-root case (`tmp_path`), and asserts neither `checkout-association.json` nor `checkouts/` exists after rejection. The normal external topology (sibling `state_root` and `repository` under a shared `tmp_path`) is *not* rejected -- neither is an ancestor of the other -- and the remaining tests register successfully against it. *CLOSED.* Pre-write external authority sound: *YES*.

=== S4A-R2 -- strict result authority -- CLOSED

`invoke_codex` no longer derives acceptance from transport length. It computes `validated = validated_result(result_text, expected) if result_text else None`, catching `ResultValidationError` to `None`, and sets `acceptance = "established" if validated is not None else "uncertain"` (slice4.py:161-167). Every non-established path is therefore covered by the accepted Slice-3 validator: malformed JSON, malformed envelope, wrong `run_id/hop_id/invocation_id` (correlation check in `adapter.validated_result`), and invalid `RoutingResult` (via `routing_result_from_data`) all yield `None` -> `uncertain`. `test_nonempty_invalid_result_is_not_established` (malformed JSON and wrong `run_id`) and `test_nonzero_without_result_is_uncertain` confirm the return-value behavior.

Double validation -- `invoke_codex` then `vertical.run_one_hop` -- is harmless redundancy, not competing authority: both call the same `validated_result` with the same `Invocation(run.run_id, hop_id, invocation_id)` (`run_real_one_hop` builds the adapter's `expected` from the same `hop_id = f"H{run.hop_used + 1:03d}"` that `run_one_hop` recomputes), so the two checks are identical. *CLOSED.* Strict result authority sound: *YES*.

=== S4A-R3 -- real vertical composition -- PARTIALLY CLOSED

*Happy path -- CLOSED.* `run_real_one_hop` (slice4.py:192) constructs a `_CodexAdapter` and calls the sole accepted `vertical.run_one_hop`, so a valid correlated result flows through the established `prompt -> adapter -> validated_result -> observe_hop -> subject/durable checks -> run_evidence -> record_hop -> reduce_result -> checkpoint_projection` path with no duplicated reduction logic. `test_real_vertical_composition_uses_fake_cli_and_existing_reducer` exercises this committed composition end-to-end with a fake CLI that commits an in-scope change and writes a correlated result; it asserts `status == "completed"`, `hop_used == 1`, real `actual_commits`, the committed `PROOF.md` mutation, and the reviewed argv/`--cd`/external-path shape. This is a genuine single-path integration, not a second contract.

*Uncertain / failure path -- NOT CLOSED.* `_CodexAdapter.invoke()` raises `ResultValidationError("real adapter result is absent, malformed, or uncorrelated")` whenever `invoke_codex` returns no valid result (slice4.py:187-188). In `vertical.run_one_hop`, `adapter.invoke(...)` is called on the line that feeds `validated_result`, *outside* the sole `try/except GitPreflightError` (vertical.py:90). The `ResultValidationError` therefore propagates out of `run_one_hop` and out of `run_real_one_hop` unhandled. Consequently, for a real process that *started* and then produced no/malformed/uncorrelated result, timed out, or exited nonzero:

* no atomic dispatch marker is published before invocation;
* no Hop is conservatively charged;
* Git is not independently observed by the driver on this path;
* there is no `recover_uncertain_dispatch` / `require_reconcile` transition, no `reconcile_required` status, no `stop_reason` requiring explicit resume, and no checkpoint;
* the caller receives a bare exception.

`invoke_codex` itself correctly reports `acceptance == "uncertain"`, but that signal is discarded when `_CodexAdapter.invoke` converts it into a raised exception, and no committed outer boundary owns the recovery. The reusable machinery (`persistence.recover_uncertain_dispatch`, `reducer.require_reconcile`, `checkpoint_projection`) exists but is called by no committed real-execution code (only tests reference it). This is precisely the failure shape the first live proof produced, so the gap is material.

*Smallest deterministic correction (no live retry).* Make the committed real driver own post-spawn uncertainty end-to-end:

. before `adapter.invoke`, atomically publish the correlated dispatch marker (base HEAD, `budget_reserved=1`) and Run snapshot to the external state root, so an uncertain outcome has an anchor to charge (WFC-FAIL-04);
. on the adapter's uncertain outcome / `ResultValidationError` escape, independently observe current Git and route through the existing `recover_uncertain_dispatch` -> `require_reconcile` and `checkpoint_projection`, yielding `reconcile_required` + explicit-resume + one charged Hop + no retry -- rather than letting the exception escape;
. do *not* require `vertical.run_one_hop` itself to own uncertainty; a thin committed outer boundary in `run_real_one_hop` (or a sibling) owning it is acceptable, provided there is *one* committed, testable path where post-spawn uncertainty becomes the existing reconcile semantics.

*PARTIALLY CLOSED.* Real happy-path vertical composition sound: *YES*. Post-spawn uncertain path committed end-to-end: *NO*.
