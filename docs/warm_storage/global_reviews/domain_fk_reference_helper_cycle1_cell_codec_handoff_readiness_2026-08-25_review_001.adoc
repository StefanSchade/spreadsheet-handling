== 2. Defect reproduction

The public path was independently exercised through
`encode_cell_values(..., codec_intent=...)` with a frame carrying the current
rich FK provenance value:

[source,python]
----
[{"column": "_employees_first_name",
  "fk_column": "id_(employees)",
  "target": "employees",
  "target_key": "id",
  "value_field": "first_name"}]
----

Two separate calls produced:

[source,console]
----
ordinary participating column:
  TypeError: unhashable type: 'dict'

FK helper as participating column:
  TypeError: unhashable type: 'dict'
----

The failure occurs while `_helper_columns_for_frame` builds the frame-wide
set, before it compares the selected participating columns. The readiness
design correctly sharpens the governing finding: current rich FK provenance
prevents every position-based Cell Codec encode on that frame, not only an
encode selecting the helper itself.

*DEFECT CONFIRMED.*

== 3. Ownership-boundary review

The post-fix flow is correct under DMC Sections 2, 5, 6, and 9:

[source,text]
----
Cell Codec navigates shared containers
    -> raw FK helper_columns
       -> fk_helpers.validated_helper_columns
    -> raw enrich_lookup record
       -> enrich_lookup.validated_enrich_lookup_helper_columns
    -> Workbook-View helper identity
       -> unchanged Cell-Codec-local reader (W1)
    -> union identities
    -> Cell Codec applies its no-helper-participation policy
----

Cell Codec may know the shared `_meta`, `derived`, `sheets`, owner-subkey, and
Workbook-View carrier locations because it must compose the identities needed
for its own exclusion invariant. It does not need to know any FK rich-entry
field, relation meaning, Lookup join-key or formula meaning, deletion
authority, mismatch semantics, or provenance-truthfulness algorithm.

The direct Workbook-View leaf read is a separate, intentionally simple durable
handoff for which no owner facade exists. Retaining its current behavior does
not justify retaining either foreign FK/Lookup interpretation.

*OWNERSHIP BOUNDARY CORRECT.*

== 4. FK facade

`fk_helpers.validated_helper_columns(raw_helper_columns, *, frame_name)` is
exported from the package facade and has the exact required contract:

[source,text]
----
raw per-sheet FK helper_columns -> set[str]
----

The independent probe passed the identical rich FK value that crashes Cell
Codec and returned:

[source,console]
----
{'_employees_first_name'}
----

Current-source behavior was independently confirmed for the material states:

[cols="2,3,4",options="header"]
|===
| Raw value | Facade result | Review disposition

| `None`
| `set()`
| Correct absent-state no-op.

| `[]`
| `set()`
| Correct empty-state no-op.

| `list[str]`
| `ValueError` because the entry is not a mapping
| Accept. This is not current FK writer output.

| current `list[mapping]`
| set of truthy `column` values, coerced to strings
| Correct owner interpretation.

| non-list/tuple value
| `ValueError(...helper_columns must be a list)`
| Accept; no current FK producer writes it.

| non-mapping entry
| indexed `ValueError`
| Correct fail-clear owner behavior.

| mapping missing or having a falsy `column`
| entry skipped
| Accept the facade's established owner-local leniency; Cell Codec invents no
  rule.
|===

`fk_helpers/provenance.py::_write_helper_provenance` constructs `entries`
only as mappings containing `column`, `fk_column`, `target`, `target_key`, and
`value_field`, then writes that list at the FK leaf. No current writer branch
emits `list[str]` there. The old Cell Codec acceptance of `list[str]` was an
accidental shadow-parser behavior, not a producer/consumer contract. The DMC
does not require preserving it.

*FK FACADE SUFFICIENT.*

== 5. Lookup facade

`enrich_lookup.validated_enrich_lookup_helper_columns(record, *, frame_name)`
is the correct identity-only handoff. It validates the already-extracted raw
record and its `helper_columns` leaf, returns `tuple[str, ...]`, and never
resolves `on` or `source_key` / `lookup_key`.

Empirically, the identity facade returned `('_dept_name',)` for both a record
with no join-key member and a record with `on: None`, provided the helper list
was extractable. The full
`interpret_written_enrich_lookup_provenance` call on the record with no
join-key form raised the expected `ValueError` saying that a value-checked
record must declare a join-key form.

That difference is semantically necessary. Cell Codec needs identity for its
exclusion policy; it performs no Lookup value comparison. Calling the full
interpreter would make it depend on key-form semantics it does not own and
would reject records whose identity-only use is valid. The accepted F-002
Slice-1 split and DCP's unconditional identity path establish the same
precedent.

*IDENTITY-ONLY LOOKUP FACADE IS CORRECT.*

== 6. Failure compatibility

=== 6.1 Lookup strictness

Delegation changes one observable Cell Codec result:

[source,text]
----
present non-mapping enrich_lookup
    current Cell Codec -> silently absent
    owner facade       -> ValueError
----

*Disposition: ACCEPT.*

The reasoning in `216a999` is sound:

* the current Lookup writer always publishes a mapping;
* no legitimate producer state is rejected;
* DCP already passes this same raw value through this same facade and rejects
  the same malformed shape; and
* preserving Cell Codec's silent skip would leave an inconsistent private
  interpretation path solely for malformed state.

This is an explicit fail-clear alignment at an owner facade, not compatibility
loss for a supported state.

=== 6.2 Obsolete FK fixture

The current test fixture writes:

[source,yaml]
----
_meta:
  derived:
    sheets:
      expanded:
        helper_columns: ["b"]
----

Current FK source never writes this value. After delegation, leaving it in
place would raise the FK facade's malformed-entry `ValueError`. Because the
existing assertion merely matches `helper|derived`, that wrong error would
still make the test pass and conceal the actual Cell Codec rejection contract.
Replacing it with a rich writer-shaped entry is therefore required, not
optional cleanup.

*FIXTURE CORRECTION REQUIRED AND CORRECT.*

== 7. Workbook-View OQ-1

[.lead]
*OQ-1: W1*

The bounded implementation must retain the current permissive
`_column_name_set` implementation unchanged and call it only for
`_meta.sheets[frame].helper_columns`. This resolves the choice; the coder is
not to adopt DCP's stricter W2 behavior in this slice.

Reasons:

* W1 produces no Workbook-View behavior change.
* The current Workbook-View producer normalizes valid helper declarations to
  `list[str]`, so the latent bare-mapping behavior is not producer-reachable.
* W2 is defensible as separate hardening, but it changes malformed-state
  handling unrelated to the demonstrated FK/Lookup blocker.
* No Workbook-View facade currently exists, and adding one would widen owner
  source and review scope.

This is consistent with the DMC's bounded-scope and evidence-based
compatibility discipline. W1 does not ratify malformed Workbook-View mappings
as a permanent contract; it only declines to change them in this slice.

== 8. Return normalization

The FK facade returns `set[str]`; the Lookup facade returns
`tuple[str, ...]`. Existing `set.update(...)` accepts either iterable and
normalizes both into Cell Codec's local membership set without wrapping,
conversion helpers, or a shared value type.

Ordering is not observed from either facade. The final error lists rejected
columns by iterating the caller's ordered `participating_columns`, so the
existing public diagnostic order remains stable even though identity is held
in a set.

No generic helper-identity protocol, dataclass, common normalizer, or registry
is needed.

*LOCAL NORMALIZATION SUFFICIENT.*

== 10. Test plan

The proposed nine public-path cases are sufficient and correctly focused on
Cell Codec's handoff/composition seam:

. replace the obsolete FK fixture with a rich writer-shaped entry;
. prove an ordinary column succeeds with rich FK provenance present;
. prove the FK helper receives the Cell Codec `ValueError`, not the raw
  `TypeError`;
. prove writer-shaped Lookup metadata permits an ordinary column and rejects
  the Lookup helper;
. prove sibling FK and Lookup identities coexist and union correctly;
. prove a valid Workbook-View helper remains rejected under W1;
. pin malformed FK non-list handling;
. pin malformed Lookup non-mapping handling; and
. prove absent metadata remains unchanged.

`pytest.raises(ValueError, match=<Cell Codec vocabulary>)` already excludes a
`TypeError`; an additional type-negation assertion is not necessary, though a
test name or comment may state the regression explicitly.

The tests should not duplicate the owner packages' complete malformed-state
matrices. Those contracts already have direct facade tests. Rich
writer-shaped literals are adequate here: the FK and Lookup writers and their
facades are source-local and already covered, while Cell Codec needs small,
deterministic fixtures that isolate extraction, delegation, union, and its own
rejection policy. Full producer construction for every case would add setup
coupling without protecting a missing Cell Codec contract. The combined-owner
case is especially clearer as a writer-shaped sibling literal.

No Workbook-View malformed-state test is required because W1 deliberately
preserves that behavior; the valid writer shape remains covered.

*TEST PLAN SUFFICIENT.*

== 13. Rejected abstractions

The readiness design correctly rejects all proposed representation-unifying
machinery:

* a generic `HelperIdentity` protocol;
* a provenance registry;
* a global helper-carrier parser;
* a shared FK/Lookup helper dataclass;
* a new metadata ontology;
* package re-layout;
* public-surface consolidation; and
* a new Workbook-View facade in this slice.

The two owners already expose the narrow semantic values their consumer
needs, and `set.update` composes them locally. The carriers' different
representations express different ownership and lifecycle contracts; making
them look uniform would recreate the ontology pressure the DMC is removing.

*REJECTED-ABSTRACTION VERDICT: CORRECT; NO NEW ABSTRACTION.*

== 14. Cycle classification

This remains Family Cycle 1 because Cell Codec currently interprets two
foreign semantic representations to recover helper identity, and the FK
representation is already misunderstood. Delegating interpretation to the
owners removes that remaining ontology.

It is not Cycle 2 defensive/security work, Cycle 3 supported-type review,
Cycle 4 structural refactoring, surface consolidation, or merely an
owner-local generic bug. The crash is the observable consequence; the
architectural cause is a cross-owner shadow parser.

*CYCLE-1 BLOCKER CLASSIFICATION CONFIRMED.*

== 15. Findings

No MATERIAL or MINOR design finding remains after this review's binding OQ-1
decision.

NOTE-001:: The defect is frame-wide: any ordinary Cell Codec encode also
crashes when current rich FK provenance is present.

NOTE-002:: W1 intentionally leaves the pre-existing permissive Workbook-View
leaf behavior unchanged. This is not a claim that malformed bare mappings are
a supported producer contract and not an instruction to open a follow-up in
this slice.

NOTE-003:: The old FK `list[str]` fixture would misleadingly pass its loose
`helper|derived` exception regex after delegation. Writer-shaped replacement
is mandatory.
