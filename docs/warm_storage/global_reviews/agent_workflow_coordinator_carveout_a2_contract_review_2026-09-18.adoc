== 2. Verdict

*B -- A2 CONTRACT ACCEPTED AFTER BOUNDED CORRECTION*

The A2 contract is internally consistent on schema, sole command authority,
reference coherence, pre-Run admission, environment policy, resolution, outcome
taxonomy, output omission, consumer migration and slice shape. It creates no
second registry, no plugin/task-runner subsystem, no compatibility default, no

consumer-defined, possibly agent-modified repository code with Coordinator

== 3. Schema and authority review

=== 3.1 RepositoryPolicy v3

* *v3 warranted.* `repository_policy_from_yaml()` uses `_fields()` with an exact
  required set (`serialization.py:348-379`); v2 is an exact strict shape. A
  required new field under v2 would give one version two exact shapes; an
  optional/default field would silently change old v2 meaning; retaining
  `evidence_states` would keep two registries. The A1 contract
  (FTR 13.1, "A2 shall later declare an additive v2 extension only if ...
  otherwise A2 shall use v3") pre-authorized this choice. Accepted.
* *v1/v2 fail closed.* `_policy_version()` is already document-specific
  (`serialization.py:173-181`); moving it to accept only 3 with an explicit
  migration diagnostic for 2 and 1 is a local change. No default or in-memory
  migration is permitted (WFC-POLICY-09). Accepted.
* *Required, possibly empty, exact fields.* `evidence_commands` required with no
  default; each value exactly `argv` + `timeout_seconds`; forbidden
  extension fields reject because `_fields()` rejects unknowns. Accepted.
* *Name grammar* `[a-z][a-z0-9_]{0,63}` is bounded; duplicate keys already fail in
  `_StrictLoader` (`serialization.py:97-118`). Non-string YAML keys
  (`yes`, `1`) already fail in `_mapping()`. Accepted (see W3 on `fullmatch`).
* *argv exactness.* Non-empty list; every item an exact `str` without NUL; only
  `argv[0]` non-empty; empty later items preserved; no `_string()`
  trimming/strip semantics. This deliberately differs from `_strings()` and is
  correct argv semantics. YAML-typed scalars (int, bool, date, null) are not
  strings and therefore reject rather than coerce. Accepted.
* *Timeout.* Non-bool integer in `1..900`, one named constant used for schema and
  runtime guard (WFC-EVID-10), no default. Accepted.
* *No second registry survives.* `TRUSTED_EVIDENCE`, `TrustedEvidenceRunner`,
  `supports()` authority and `evidence_states` are all removed; the
  production-registry collision check in `_preflight()` (`operator.py:238-244`)
  becomes meaningless and disappears with it. Accepted.

=== 3.2 Definition / reference / result separation

Definition = policy mapping; reference = `Phase.evidence` (ordered, unique);
result = `Observation`. Checked adversarially:

* duplicate references reject; unknown references reject pre-Run; unused
  definitions are admitted, unresolved and never executed; reuse across phases
  executes once per reached phase; mapping order has no meaning, phase-list order
  is execution order (matches `vertical.py:243-245`).
* injected runner: with `supports()` removed there is no API through which a
  runner can advertise a name. Admission and resolution are Coordinator-owned
  and happen before a runner is consulted; a fake receives only an
  already-prepared definition. The contract's statement that an injected runner
  "may neither advertise supported names nor grant command authority" is
  structurally achievable. Accepted.
* The duplicate-reference owner is stated twice (M4).

=== 3.3 Pre-Run authority boundary

Current structure: `_preflight()` performs every refusal and returns; only then
does `main()` allocate `RUN-<uuid>`, call `new_run()`, `mkdir` the state root and
write `operator-plan.json` (`operator.py:626-643`); checkout registration,
adapter construction, dispatch marker and provider call follow later. The A2
coherence helper (pure), environment snapshot (`os.environ` copy) and
resolution (`stat`/`access` reads) are side-effect-free and fit after
`_admit_a1()` and before `_preflight()` returns. No existing side effect moves
earlier. Representative rejection remains zero-side-effect. Accepted.

Evidence execution itself remains at evidence time; the contract does not
require pre-Run execution.

WFC-SEC-01/03/06 and the readiness artifact: trust attaches to definition and

== 12. Findings

=== I1 (IMPORTANT) -- Post-evidence Git state is neither disclosed nor re-observed

Observation:: A2 executes consumer-defined commands, explicitly permitted to run
agent-modified repository code, with Coordinator host authority after the Hop's
trusted Git observation (`vertical.py:231` `observe_hop`, then evidence at
`vertical.py:243-245`, then `record_hop`/reduction). Nothing re-observes Git after
evidence. The trust text mentions host/worktree mutation but not Git
metadata/ref mutation.
Evidence:: The accepted Slice-4B authority model rests on the agent sandbox
making `.git` read-only and the Coordinator owning mechanical Git mutation
(FTR 11.4.7). An evidence process has no such restriction. Intermediate Hops
would catch a HEAD move or dirty worktree at `preflight_hop()` in
`run_serial_hops()`, but the terminal path gates only on status and worktree
cleanliness (`operator.py:680-682`), not on `facts.head == final_run.current_head`.
Risk:: On the terminal Hop an evidence command (for example an agent-modified test
harness) can create an unattributed commit -- including one touching A1-protected
governance such as the policy that defines evidence commands -- while the Run is
recorded `completed` with a stale `current_head`, `commits` omits it, and the
operator exits 0. This is an authority path around the commit-intent contract and
around A1's governance exclusion, and a durable-record truth problem. Not
reachable with today's two read-only `git` definitions, hence not BLOCKING.
Recommended correction (contract text only)::
. Trust model: state that evidence commands may also mutate Git metadata, refs,
  index and configuration outside the commit-intent contract, and that A2 does
  not contain this.
. Require one post-evidence Git re-observation per Hop using existing
  observation helpers: HEAD must equal the Hop's observed end HEAD and the
  worktree must remain clean (with resolved submodules). Divergence is projected
  as the existing `MechanicalFacts.repository_anomaly` (no reducer change, no new
  schema).
. State that ref/config changes not visible through HEAD/cleanliness remain
  outside A2 detection (sandbox concern, non-scope).
. Add one acceptance case: an evidence definition that commits or dirties the
  worktree yields mechanical preemption and a non-zero operator result.
Disposition:: Bounded correction before implementation authorization.

=== M1 (MINOR) -- Observation record shape and projection versioning unspecified

Observation:: The contract lists durable facts but does not state the fate of the
existing `Observation.command` (full argv) and combined `digest` fields, which
are persisted in checkpoint `evidence` (`persistence.py:178-187`) and in
`execution-evidence.json`/`operator-summary.json` records (`operator.py:454-457`,
`"schema_version": 1` at `operator.py:480`). The operator plan must carry
"definition/argv digests", but "definition digest" is defined nowhere.
Evidence:: `observation_error()` rejects any empty `command` item
(`evidence.py:90-92`), while section 13.2 makes empty later argv items valid. If
full argv is retained, a valid definition becomes "malformed trusted evidence"
and hard-stops. If `digest` is retained with new meaning, or keys are removed,
the write-only projections change shape under an unchanged `schema_version: 1`
-- the same shape-lie the v3 decision itself rejects.
Recommended correction:: Enumerate the exact observation record keys; say
whether full argv is persisted (it is non-secret committed policy content; either
choice is safe); require observation validation to accept empty later argv items;
bump `execution-evidence.json` (and the embedding `operator-summary.json`) to
`schema_version: 2` if any existing key is removed or changes meaning, otherwise
declare the change purely additive; define "definition digest" or drop it.
Disposition:: Bounded correction.

=== M2 (MINOR) -- Non-completed attempt facts and timeout scope imprecise

Observation:: Per-stream counts/digests are defined for "each complete captured
byte stream" but not for resolution/spawn errors (no stream) or timeouts. On
POSIX, `subprocess.run(timeout=...)` kills and waits for the child and does not
return captured output. "Terminate and reap the child" does not say that
descendants are not signalled.
Risk:: Implementers choose inconsistent null/partial/empty-digest encodings; a
reader could mistake child reaping for process-tree containment (a descendant
holding the pipes can also turn a zero exit into a timeout).
Recommended correction:: State that stream facts are `null` when no complete
stream was captured (resolution, spawn, timeout, infrastructure error), and that
timeout termination applies to the direct child only; descendants are neither
tracked nor contained, consistent with WFC-SEC-06.
Disposition:: Bounded correction.

=== M3 (MINOR) -- Resolution precision: empty PATH, stat target, repository-resolvable bare names

Observation:: "An explicitly empty PATH remains empty" plus "empty PATH entries
are interpreted from repository root" leaves `PATH=""` ambiguous between zero
entries and one empty entry. The standard library diverges:
`os.get_exec_path({"PATH": ""})` returns `['']` (cwd), while
`shutil.which("git", path="")` returns `None` (verified on the review host). The
stat fingerprint does not say `stat` (follows symlinks) versus `lstat`.
Risk:: Admission outcome for `PATH=""` depends on the helper chosen; the stat
fingerprint of a symlinked executable is ambiguous. Additionally, the contract
does not say plainly that a relative or empty PATH entry makes a *bare* name
resolvable to a repository file, which may be agent-authored.
Recommended correction:: Pin `PATH=""` as exactly one empty entry resolved against
repository root (POSIX `execvp` / `os.get_exec_path` semantics) or as zero entries
-- one choice; specify `os.stat` of the invocation path (i.e. the canonical
target); add one sentence that relative/empty PATH entries can make bare names
resolve to repository files, disclosed only through the recorded invocation
path. Add the chosen empty-PATH case to the acceptance matrix.
Disposition:: Bounded correction.

=== M4 (MINOR) -- Duplicate-reference owner stated twice; minor acceptance gaps

Observation:: Section 13.2 "Admission" puts duplicate phase-reference validation in
the pure operator helper; "Implementation seams" puts it in `serialization.py`.
The positive acceptance list omits "empty later argv item preserved at
execution"; the negative list does not name "unknown reference rejects even with
an injected runner".
Recommended correction:: Name one owner (either is fine; the other must not
re-implement it). Add the two acceptance bullets.
Disposition:: Bounded correction.

=== INFO / WATCH (non-gating)

W1:: The migrated `git diff --check` / `git --version` definitions do not execute
agent-authored code under the observed read-only-`.git` agent sandbox, but "git
only" is not a general guarantee: repository Git configuration can invoke
programs. Future repository-code commands (pytest, make) change this materially;
I1 matters from the first such consumer.
W2:: Inherited `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` etc. can redirect
evidence Git away from the cwd repository; only PATH is audited. This is operator
launch context under the stated policy, not a finding.
W3:: Command-name validation must use `re.fullmatch` (`re.match(...$)` accepts a
trailing newline). Consumers must quote argv items YAML would type (dates,
numbers, booleans, `null`); they reject, as intended.
W4:: Remove the defaulted `evidence_runner=PRODUCTION_EVIDENCE_RUNNER` parameters
(`vertical.py:143`, `slice4.py:158`, `operator.py:183,467`) or make any default
fail closed; the proof harness should call the same `evidence.py` preparation
helper, not re-implement resolution.
W5:: The neutral fixture's definition must be host-resolvable (for example
`[git, --version]`) because admission resolution is Coordinator-owned even when a
fake simulates execution.
W6:: If an exception occurs after evidence ran (`slice4.py:214` recovery), those
attempts are not appended to `execution-evidence.json`. Pre-existing; the path
ends in reconciliation with no further adapter call.
W7:: `git diff --check` after a trusted commit compares a clean worktree to the
index and is largely vacuous. Existing consumer meaning, intentionally preserved;
not A2 scope.
W8:: Moving evidence admission from the phase loop (before A1) to after
`_admit_a1()` changes which diagnostic appears first for multiply-invalid inputs;
tests that pin messages may need updating.
W9:: The operator plan will contain host-absolute executable paths; this matches
existing plan content (repository and state-root paths) and is non-secret.
