== 3. F1 -- both clone-transfer boundaries

The commissioned correction is to replace the defective guarded `git update-ref
-d refs/remotes/origin/HEAD` with the proven `git symbolic-ref --delete
refs/remotes/origin/HEAD` at both transfer sites, leaving the existing `git
symbolic-ref -q` guard in place.

Site 1 -- scratch to staging (plan lines 691--695), verbatim:

[source,bash]
----

# Git 2.47.3 can leave this broken symbolic ref after removing origin/main.
if git -C /ABSOLUTE/SCRATCH/standalone-staging symbolic-ref -q \
  refs/remotes/origin/HEAD >/dev/null 2>&1; then
  git -C /ABSOLUTE/SCRATCH/standalone-staging symbolic-ref --delete \
    refs/remotes/origin/HEAD
fi
----

Site 2 -- staging to target (plan lines 738--743), verbatim:

[source,bash]
----
git -C /home/stefan/repos/spreadsheet-handling/workflow-coordinator \
  remote remove origin
if git -C /home/stefan/repos/spreadsheet-handling/workflow-coordinator \
  symbolic-ref -q refs/remotes/origin/HEAD >/dev/null 2>&1; then
  git -C /home/stefan/repos/spreadsheet-handling/workflow-coordinator \
    symbolic-ref --delete refs/remotes/origin/HEAD
fi
----

Both sites now use the proven command, both retain the unchanged `symbolic-ref
-q` guard, both retain the preceding `remote remove origin`, and neither
acquired any other option, redirection, or ordering change. The guard remains a

predicate that still sees a broken symref, so the guard stays true in exactly
