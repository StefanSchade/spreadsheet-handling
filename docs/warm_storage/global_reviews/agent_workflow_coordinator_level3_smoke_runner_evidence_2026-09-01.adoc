== Implemented boundary

`scripts/workflow_coordinator/codex_adapter_smoke.py` is the smallest
repository-controlled, file-launchable smoke runner for a future separately
authorized Level-3 Codex compatibility smoke. It constructs one fresh
provider-neutral `Invocation` (`H001`), a minimal `AgentExecutionRequest`, and
then calls `CodexCliAdapter.execute()` exactly once. If a candidate is returned,
the runner passes it to the existing provider-neutral `validated_result()`.
`CodexCliAdapter` remains the owner of the emitted OpenAI structured-output
schema; the durable summary records the requested contract and, when emitted, a
SHA-256 fingerprint of that schema.

The runner creates a fresh ordinary workspace below a required new smoke root.
It does not initialize or inspect Git, invoke coordinator Git facts, construct a
Run or Hop, call a reducer, persist Run/Hop state, dispatch/reconcile, or use
`proof_harness.py`.

== One-shot and truthful outcomes

An existing smoke root returns failure before the adapter is constructed or an
executable is launched; it is deliberately not modified. For every outcome after
the new root exists where setup permits, `smoke-summary.json` records the
correlation IDs, configured adapter facts, bounded transport outcome, candidate
presence, and separate semantic-validation outcome. The adapter's result carrier
remains in the runner-owned result directory.

The smoke succeeds only when the one invocation returns code zero, does not time
out, supplies a candidate, and `validated_result()` accepts its correlation and
semantics. Return code zero is a smoke-specific transport criterion; it does not
change the existing coordinator rule that a correlated candidate can remain
semantically meaningful after a nonzero return code. No retry, resume, or second
invocation is implemented.
