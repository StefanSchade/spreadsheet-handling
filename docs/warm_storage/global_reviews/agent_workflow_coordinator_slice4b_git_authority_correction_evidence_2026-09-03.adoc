== S4B-R1 correction: trusted execution isolation

`trusted_commit()` now routes every Git subprocess it starts through one private
trusted-write helper. The helper keeps ordinary process settings such as `PATH` and
locale, but removes every inherited `GIT_*` variable. It executes with
`shell=False` and fixed command-local configuration:

* `core.hooksPath=/dev/null`, a fixed non-agent-writable non-directory, so Git's
  hook lookup cannot resolve an executable repository or worktree hook;
* `commit.gpgSign=false`, preventing configured commit-signing subprocesses;
* `core.fsmonitor=false`, preventing configured fsmonitor helper execution; and
* `git commit --no-verify` as additional defense in depth, not as the hook-control
  mechanism.

This uses only command-line Git configuration for the trusted subprocess. It does
not change repository configuration, delete hooks, or designate an agent-writable
hook directory as trusted.

The required real temporary-Git regression configures a worktree-relative
`core.hooksPath=.githooks`. Its agent-authored, in-scope `pre-commit` hook would
write `hook-executed`; the hook itself is included in the explicit intent along
with an authorized source change. `trusted_commit()` creates the intended ordinary
commit and `hook-executed` is absent. Thus the test proves absence of execution,
not merely commit success.

== S4B-R2 environment policy

The helper copies the Coordinator environment except names beginning `GIT_`.
Accordingly `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_CONFIG_COUNT`,
`GIT_CONFIG_KEY_*`, `GIT_CONFIG_VALUE_*`, `GIT_CONFIG_SYSTEM`,
`GIT_CONFIG_GLOBAL`, and related Git routing/configuration controls cannot steer a
trusted write. Git's normal system/global/repository configuration remains the
operator's policy unless explicitly neutralized above; no environment selection is
exposed to the agent.

The deterministic injection regression sets `GIT_CONFIG_COUNT=1` with
`GIT_CONFIG_KEY_0=core.hooksPath` and a worktree-relative injected hook path. The
hook is in the authorized scope and intent, would create
`injected-hook-executed`, and the commit succeeds. The side-effect file is absent,
proving the inherited configuration does not redirect hook lookup.

* Commit signing is neutralized by `commit.gpgSign=false`.
