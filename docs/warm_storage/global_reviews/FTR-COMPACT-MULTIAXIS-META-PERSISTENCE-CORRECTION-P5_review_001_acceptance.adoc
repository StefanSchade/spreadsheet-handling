== Maintainer-intent context

The Cold Storage bijective-composition note is explicit *maintainer intent and
architectural inquiry*, not an accepted runtime contract. Its operative bearing
on this review is narrow and twofold: (a) it endorses the current metadata
hygiene — "persistent metadata must not refer to a deleted temporary frame" and
"a diagnostics trace must not silently become inverse configuration" — both of
which this correction satisfies; and (b) it raises, as an open inquiry question,
whether Compact Multiaxis preserves XRef scoped recomposition through a
compacted `base_relation`. That inquiry is adjudicated below and routed to a
separate FTR. The note does *not* impose any new contract this correction must
meet to be accepted.

== Runtime inspection

*CM-1 restore-to-prior.* `expand_compact_multiaxis` and
`contract_compact_multiaxis` snapshot the caller's entire `_meta.xref_crosstable`
root (`_snapshot_xref_meta`, `deepcopy`, `_ABSENT` sentinel when the root is
absent) *before* delegating, and after all frame work + optional group
projection succeed, restore it (`_restore_xref_meta`): absent-or-empty prior →
whole root omitted; otherwise the deep-copied prior root is reinstalled. The
internal XRef leg (keyed by `config_id`, `relation` naming the deleted temp
frame `__compact_multiaxis_<id>_xref` / `_encoded`) is therefore never
persisted. The composite never rewrites the internal entry to a public-looking
frame (Option B correctly rejected).

*Whole-root vs per-config equivalence.* `_write_xref_meta`
(`operation.py:506-516`) copies the prior configs mapping and assigns *only* its
own `config_id` key; XRef performs no root-level normalization and writes no
other entry. For this composite (its sole XRef call uses `name=config_id`),
whole-root restore is behaviourally equivalent to per-config restore, and it
additionally cannot suppress a legitimate second XRef write because none exists.

*Diagnostics trace.* `_write_multiaxis_meta` copies the prior configs mapping,
`deepcopy`s the payload, and assigns the single `config_id` key — atomic
same-ID replacement, no history list, different IDs coexist, no pruning of
absent IDs. Payload records public frame names only; `value_columns` /
`column_keys` / `canonical_order` record authored value or `None` (no back-fill
of inferred XRef Resolution); normalized fields (`mode`, `code_groups` keys)
record effective values; collections defensively copied.

*No trace consumption.* No runtime path reads `_meta.compact_multiaxis`; the
only operation on the root is the local write. The reverse column-order fallback
is XRef-owned (`_column_keys_from_meta_or_relation`), reading
`_meta.xref_crosstable[config_id].column_keys`, not the compact trace.

*Atomicity.* Both functions operate on `dict(frames)` copies and shallow-copy
`_meta`; the trace write and XRef restore run only after frame work succeeds; no
primitive exception is caught or weakened.

== CM-1 XRef restore review

*Focused concern 1 — whole-root restore.* Sound and intentionally bounded.

* XRef currently changes only its own `config_id` entry
  (`_write_xref_meta` copy-and-assign); it performs no root-level normalization
  and no additional XRef write. Whole-root restoration therefore cannot suppress
  legitimate root-level normalization or a second XRef write — there is none to
  suppress.
* Per-config restoration would be *no more truthful* here and would be strictly
  more code; the whole-root snapshot is the simpler correct form and is exactly
  equivalent for this composite. It becomes non-equivalent only if XRef later
  gains root-level side effects — an observation for that future change, not a
  current defect.
* Malformed prior roots are *preserved*, not mishandled: the snapshot is an
  opaque `deepcopy`; the composite neither normalizes nor repairs caller state
  (`test_prior_same_id_xref_entry_is_restored_exactly_and_defensively` restores
  a nested `dense_axes` mapping verbatim and defensively).
* Empty-root omission is canonical: an explicitly empty `{}` prior maps to
  root-absent (`test_empty_prior_xref_root_is_omitted_after_internal_leg`),
  matching the boundary's omission semantics for empty roots.

Caller-supplied prior entries survive exactly (same-id restored; unrelated ids
untouched — `test_unrelated_xref_entries_survive_without_internal_config_entry`),
and defensive copies mean the restored root does not alias caller-owned
collections.

*Conclusion:* acceptable as-is. No change required.

== Config-identity and pipeline binding review

*Focused concern 2.* The implementation review's claim is verified against
source. `pipeline/build.py` pops YAML `name` and passes it to the step factory;
`make_frames_target_step` (`pipeline/steps.py`) captures `name` as a
*keyword-only BoundStep label*, not in `**kwargs`, so it is *not* forwarded to
the callable `expand/contract_compact_multiaxis(name=...)`. Therefore:

* Pipeline authors *cannot* set a stable callable `config_id` via the registered
  step; `config_id` deterministically defaults to `output` (expand) /
  `relation` (contract).
* The step registry lists `name` because it faithfully mirrors the *callable
  signature*; the binder-intercepts-`name` behavior is a repository-wide
  convention, not a Compact-specific inaccuracy, so the registry is not
  untruthful.
* In a normal roundtrip, expand's `config_id` (=`output`) and contract's
  (=`relation`) coincide when the contract consumes the frame expand produced;
  a frame rename can leave a stale diagnostic trace ID. This affects *only* the
  diagnostics trace (non-authoritative, unread), never correctness.
* This residual is adequately owned by
  `FTR-COMPACT-MULTIAXIS-TRACE-LIFECYCLE-COMMANDS-P5` (explicit `config_id`
  drop/rename). No additional follow-up is required for the correction to be
  accepted. Recorded here as an Observation.

== Scoped-recomposition inquiry

*Focused concern 3.* The five-point analysis is confirmed against live source
and probe:

. Compact Multiaxis exposes `value_columns` and the matrix frame itself, which
  can present a *partial* projection of a larger canonical relation. CONFIRMED.
. `expand_compact_multiaxis` calls `expand_xref` with no `base_relation` and
  exposes no codec-contracted base parameter
  (`compact_multiaxis.py` expand-xref call). CONFIRMED.
. XRef *does* own scoped recomposition: `expand_xref(..., base_relation=...)`
  appends out-of-scope base rows after in-scope matrix rows
  (`xref_crosstable/operation.py`). CONFIRMED.
. Therefore a partial projection reimported and used to replace the full
  canonical relation loses out-of-scope rows. Independent probe: expanding a
  1-column partial matrix yields only the visible address; `P-002`/`P-003`
  canonical rows are unrecoverable from that call. CONFIRMED.
. The fix is to compose existing primitives (Cell Codec encode of the canonical
  base → XRef `base_relation` scoped recomposition → Cell Codec decode), i.e.
  wire an existing capability through the composite; no new merge algorithm.
  CONFIRMED.

*Did this correction introduce or worsen the gap?* No. The correction touches
only `_meta.xref_crosstable` *persistence* (restore-to-prior) and the
diagnostics trace — never the row-data merge path. Before the correction, no
`base_relation` was passed either; the suppressed metadata entry was inverse
*intent* (frame names / keys), never a source of out-of-scope *row data*.
Restore-to-prior removes metadata, not rows. The gap is pre-existing and
independent.

*Verdict:* `CONFIRMED — SEPARATE FTR CREATED — NON-BLOCKING FOR THIS
CORRECTION`. Recorded as
`docs/backlog/FTR-COMPACT-MULTIAXIS-SCOPED-RECOMPOSITION-P4A.adoc`, sequenced
before the final broad Compact Multiaxis acceptance review, reusing the existing
Cell Codec and XRef `base_relation` contracts and prohibiting parallel merge
logic.
