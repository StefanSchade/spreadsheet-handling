== 3. Pure admission sufficiency

* `work_item` supplies mutation scope and the requested Hop limit;

* `policy` supplies governance roots, WorkItem ceilings, and the policy Hop
  ceiling; and
* `governing_paths` supplies the five selected input paths plus every selected
  component path after manifest resolution.

That is sufficient for path-shape checks on admission operands, governing-input
containment, symmetric phase/governance exclusion, WorkItem-scope domination,
and Hop domination. No relation needs file contents, existence, Git state, or a
new model. Keeping pinned/tracked reads and repository/side-effect checks in
`_preflight()` is therefore coherent rather than hidden I/O.

The integration boundary is likewise executable as written: worktree YAML is
read and parsed through the supported serializers, selected component paths are
resolved from the parsed manifest, and the same pure function is called. This
tests committed consumer coherence without coupling the test to worktree
cleanliness or duplicating admission logic.
