== 1. Review goal and method

Determine whether `6d4caea` correctly removes durable v2 FK relation policy
as independent physical deletion authority from
`fk_helpers/drop.py::_columns_to_drop_by_sheet`, while preserving the
transient-provenance happy path, the missing-policy precondition/error,
safe absent-column behavior, and Slice-3 composition, per the accepted
design's Sections F/G/I/J/N/O and the twelve-area brief for this review.

Method: read the diff against the design's Section G/J text; trace
`drop_helpers`'s full call graph (not only the edited lines) for any
remaining durable-policy-to-drop-set path; re-run the changed and adjacent
test suites; construct a direct empirical repro by running the new/inverted
tests against the pre-Slice-4 production code in an isolated git worktree
to confirm they would have failed before this commit. No production or
test code was modified.

== 2. Area-by-area findings

=== Area 1 -- deletion-candidate source

`_columns_to_drop_by_sheet` (`drop.py:84-96`) now takes only
`provenance_by_sheet` and returns
`{sheet: {entry["column"] for entry in entries if entry.get("column")}}` --
built exclusively from `derived_helper_columns_by_sheet(frames)` (transient
provenance). `resolve_v2_fk_relations`'s only two call sites in the module
are the pre-existing `missing_fk_policy_error` precondition
(`relations is None and not provenance_by_sheet`) and the new
`_log_durable_policy_only_survivors` diagnostic, which reads `relations` but
never writes into `columns_to_drop` -- it is a separate function invoked
after `columns_to_drop` is already fully computed. No path reconstructs
candidates from durable policy, physical column-name pattern, or
value/formula shape. No finding.

=== Area 2 -- transient-provenance happy path

`TestDropHelpersWithProvenance` (4 tests: single/multiple helper removal,
provenance cleanup, non-helper `_`-prefixed column retention) is untouched
by the diff and passes unmodified. `_clean_helper_provenance`'s call site
and signature (`drop.py:80`) are unchanged from Slice 3. No finding.

=== Area 3 -- durable-policy-only fail-closed path

`test_drop_survives_v2_policy_only_column_when_provenance_missing`
(inverted from `test_drop_removes_columns_from_v2_policy_when_provenance_missing`)
asserts `_B_name` survives when only v2 policy exists (no transient
provenance). Confirmed empirically: running this test (and the file's other
8 tests) against the pre-Slice-4 production code
(`6d4caea^` == `cd5746c`, verbatim Slice 3 code) in an isolated worktree,
this test *fails* (`AssertionError: assert '_B_name' in ['id']` --
i.e. the old code deleted it), while the other 7 pre-existing tests still
pass unchanged. The inversion is genuine, not merely renamed. No finding.

=== Area 4 -- genuine same-label replacement

`test_drop_survives_genuine_same_label_replacement_after_decoupled_rebind`
(`TestDropHelpersDeletionAuthority`) reproduces the Slice-3-review Area 8
confirmatory repro end-to-end: FK materializes `_B_name` on `A` with
matching transient provenance; `enrich_lookup(source="C", output="A",
helpers=None)` decoupled-rebinds `A` with caller-owned content from `C`
that happens to reuse the literal label `_B_name` (traced through
`operation.py`: `helpers=None` with no lookup-side fields projects only the
join key, so `enriched` reduces to `C`'s own columns -- confirmed by the
test's own `list(rebound["A"]["_B_name"]) == ["caller-x", "caller-y"]`
assertion, `C`'s original values, not `B`'s). Slice 3 strips `A`'s stale FK
record as part of that write (`"A" not in
rebound["_meta"]["derived"]["sheets"]`, asserted directly). Durable v2
policy still names `_B_name` for `source_frame="A"` (untouched by
`enrich_lookup`). `drop_helpers` is then run over `rebound`.

Confirmed empirically in the same pre-Slice-4 worktree run: this test also
*fails* against pre-Slice-4 code (same assertion shape, caller's `_B_name`
deleted via the durable-policy fallback), and passes against `6d4caea`.
This is the composition the Slice-3 review flagged as "exactly the deferred
defect... assigned to Slice 4" -- now closed, verified against the actual
historical failure mode rather than a merely similar shape. No finding.

=== Area 5 -- missing-policy error

`test_no_policy_and_no_provenance_raises_with_actionable_message` is
untouched by the diff. The precondition
(`relations is None and not provenance_by_sheet: raise
missing_fk_policy_error(...)`, `drop.py:54-55`) is unchanged from Slice 3;
`resolve_v2_fk_relations`'s two call sites (precondition and diagnostic) are
its only uses in this module, per Area 1. No finding.

=== Area 6 -- diagnostic

`_log_durable_policy_only_survivors` (`drop.py:99-132`): no exception is
raised (log-only); public `drop_helpers`/`Frames` return contract is
unchanged; the function runs after `columns_to_drop` is finalized and
cannot influence it; the message ("durable FK policy names it but no
truthful transient provenance authorizes deletion") does not claim FK
ownership of the surviving column; it is skipped for any sheet present in
`provenance_by_sheet` (`if ... source_frame in provenance_by_sheet:
continue`), so it does not fire on the ordinary transient-provenance
deletion path; it is guarded by both frame presence
(`frame_by_name.get(source_frame)` is `None` -> skip) and physical-column
presence (`source_frame_has_column(df, column)`), so a durable relation for
a sheet that never materialized, or no longer carries, the column produces
no warning. Logger name `logging.getLogger("sheets.fk_helpers")` matches
the repository's existing `sheets.<module>` convention (`sheets.ods`,
`sheets.cleanup`, `sheets.column_roles`, `sheets.pipeline`,
`sheets.validation`). No finding.

=== Area 7 -- `_columns_to_drop_by_sheet` contract

Signature reduced to `provenance_by_sheet` only (the `frames`/`relations`
parameters are gone); the durable-fallback branch (`known_sheets` /
relation-bucket accumulation) is removed entirely, not relocated --
confirmed by the diagnostic function's independent, additive shape rather
than a call from within `_columns_to_drop_by_sheet`. Returned sets
correspond exactly to `{entry["column"] for entry in entries if
entry.get("column")}` per sheet with transient provenance; a sheet with no
provenance entries and no relations produces an empty `columns_to_drop`,
which the main loop's `if not drop_columns: out[sheet] = df; continue`
already treats as a safe no-op. The function only reads `entries` (dicts)
and builds new local containers; no provenance/meta structure is mutated.
No finding.

=== Area 8 -- stale provenance, absent physical column

`test_drop_is_safe_noop_when_provenance_names_absent_column`: transient
provenance names `_B_name`; the column is removed from the physical frame
before `drop_helpers` runs. The main loop's `keep = [c for c in df.columns
if _visible_label(c) not in drop_columns]` is a no-op against an already-
absent label (nothing to filter out, no error). `_clean_helper_provenance`'s
call site and body are untouched by this diff (not present in the Slice-4
diff at all), so metadata cleanup behavior is exactly the pre-Slice-4/
Slice-3 behavior -- this test is a stability regression, not a new-behavior
proof, and correctly confirms Slice 4 did not destabilize it. No finding.

=== Area 11 -- compatibility narrowing

The behavior change is exactly the intended one: before, durable policy
alone (with no transient provenance) could authorize `drop_helpers`
deletion of a matching column; after, it cannot -- the column survives with
a non-raising diagnostic. No broader behavior change was found (Areas 2, 5,
8 confirm the surrounding contract is otherwise unchanged). This narrowing
is the accepted design's own deliberate safety fix (Section I), not a
regression. No finding.

`domain/validations/fk_helpers.py`); none treat durable relation policy as

`derived_helper_columns_by_sheet` for its own (unrelated) validation
findings, not for cleanup authorization. No maintained caller or documented
contract contradicts the accepted design. No finding.
