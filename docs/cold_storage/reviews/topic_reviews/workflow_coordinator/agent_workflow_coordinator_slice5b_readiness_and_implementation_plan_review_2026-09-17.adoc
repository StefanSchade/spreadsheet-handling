== 3. Findings

=== P5B-R1 -- IMPORTANT -- Same-state Finding citations let non-disposing authority rewrite supersession successor and disposition attribution

Claim challenged:: Plan 5.2 "Other transitions fail closed"; 5.3 "The reducer is
already the correct authority owner for ... gate/human-only Finding disposition";
15 answer 5; 12.2 test list covers only "correction cannot resolve".
Evidence:: `reducer.py:173-181`: when `_finding_operation(previous, proposed)` is
`None` and the proposed state equals the previous state, no authority check runs.
`reducer.py:189-197` then overwrites `disposition` (`"{authority}: {state}"`),
`successor_ref` (taken from the delta), and `changed_by_hop`. Scratchpad probe
(in-memory reducer only):
+
----
P1 gate supersedes F001 -> successor X1, disposition "gate: superseded"
   ordinary agent re-asserts superseded with successor X2
   -> successor X2, disposition "agent: superseded", changed_by_hop H009
P2 gate resolves F001 ("gate: resolved"); agent re-asserts resolved
   -> disposition "agent: resolved"
----
+
The same path lets a gate lacking `supersede` authority rewrite a successor, and
lets any agent attach an arbitrary `successor_ref` to an open Finding.
Consequence if ignored:: 5B is the first slice that projects the full ledger,
including resolved/superseded IDs, into correction and re-review prompts and asks
agents to cite IDs. A correction agent can then perform a reclassification
(WFC-FIND-03: gate/human only) and erase authoritative attribution, while the
plan's before/after-ledger derivation would attribute that Finding to the
correction Hop as "affected". The 5B acceptance claim "closes only under declared
gate authority" would pass while authority leaks.
Classification:: Plan defect (incorrect sufficiency claim) over a pre-existing
Slice-1 implementation defect that 5B makes reachable on the supported path.
Smallest correction:: Add one reducer rule to plan sections 6/12.2: a citation
that does not change state may, without disposing authority, only append
evidence refs; it must not alter `disposition` or `successor_ref` (and an open
Finding may not acquire a successor outside `supersede`). Define whether an
evidence-only citation counts as an affected ID. Add negative tests for agent
and under-authorized gate.
One-slice impact:: None.

=== P5B-R2 -- IMPORTANT -- Failed-gate routing collides with the accepted CommitIntent/outcome rule and required review artifacts; `outcome` is never interpreted by reduction

Claim challenged:: Plan 7 "a valid gate result with `outcome=changes_required`
and a declared `goto` can route to correction because the reducer does not
otherwise interpret outcome"; plan 10 requires review artifacts
`reviews/initial.adoc` and `reviews/rereview.adoc`; 15 answer 7.
Evidence:: `vertical.py:127-153`: a CommitIntent is permitted only when
`outcome == completed`; otherwise `trusted_commit_error` becomes a repository
anomaly and mechanical human preemption. Accepted Slice-4B test
`test_slice4b_git_authority.py::test_failed_result_with_intent_never_synthesizes_a_commit`
pins that rule. Without the intent, `vertical.py:84-87` reports the required
artifact missing, again a preemption. `serialization.py` `_check_action_coherence`
forces every `required` phase to hold `edit` and `commit`. `reduce_result`
(`reducer.py:238-339`) never reads `result.outcome`; probe P3:
`outcome=failed` requesting `complete` yields `completed`.
Consequence if ignored:: The plan's own happy path cannot pass: H003's broad gate
reporting `changes_required` cannot land `reviews/initial.adoc`, so the Run stops
for human at the exact edge 5B exists to prove. The implementer must then either
make gates report `completed` while demanding correction (emptying the
WFC-OUTPUT-02 vocabulary of meaning) or relax an accepted Slice-4B Git authority
rule without contract review. Independently, `failed`/`blocked` results can still
`complete` whenever no open blocking Finding exists. Because required artifacts
give gates `edit`/`commit`, a gate whose `authorized_scope` covers payload paths
can author the correction and resolve its own blocker in one Hop.
Classification:: Plan defect (missing interaction with accepted contract).
Smallest correction:: The plan must record one explicit disposition for gate
Hops: (a) permit CommitIntent on `changes_required` restricted to the current
phase's declared artifact paths; or (b) define `outcome` for review phases as Hop
execution status so a failing verdict is `completed` plus Finding/route; or (c)
make initial review artifacts `optional`. It must also state whether
`failed`/`blocked` may take `complete`, and require the fixture's gate
`authorized_scope` to equal its declared artifact paths (profile property, not a
new permission model).
One-slice impact:: None.
