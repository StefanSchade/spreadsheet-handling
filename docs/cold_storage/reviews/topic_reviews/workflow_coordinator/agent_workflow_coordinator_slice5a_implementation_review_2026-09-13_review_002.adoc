== 3. F1 closure -- post-provider failure accounting

*CLOSED.* `main()` replaces the always-`None` `real` sentinel with
`latest_run`/`latest_invocation_id`/`latest_outcome` plus a `remember_progress`
callback threaded into `run_serial_hops` as `progress=` (`operator.py:388-406`).
`run_serial_hops` invokes `progress(run, invocation_id, outcome)` *immediately
after* `run = first.run` and again after `run = second.run`, before any evidence
publication, gate logic, H002, or summary construction (`operator.py:241-249,
280-288`). The exception handler now reports `latest_run`,
`invocation_id=latest_invocation_id or "not_dispatched"`, and
`outcome=latest_outcome` (`operator.py:417-423`); `_best_effort_failure_summary`
and `_summary` both gained `current_head`.

Verification against the seven F1 requirements:

. After H001 returns, the authoritative Run/invocation/outcome are captured
  before any later operation -- YES (`progress` precedes evidence append/publish
  and the gate).
. Same after H002 -- YES.
. A failure in execution-evidence publication, inter-Hop continuation,
  `stop_continuation` persistence, H002 execution, final summary construction,
  or final Git observation cannot regress to the pre-H001 Run -- YES, because
  `latest_run` already holds the last completed-Hop Run at each of those points.
. The failure summary truthfully reports `run_status`, `hop_used`,
  `current_head`, `final_head` (via best-effort `observe_repository`), the actual
  latest invocation ID, transport outcome, and consumed-attempt semantics -- YES.
. A post-provider failure is not represented as `hop_used=0` / `ready` /
  `unknown`/`not_dispatched` when an attempt occurred -- YES (probes below).
. The strengthened N=1 regression test genuinely reproduces the former F1
  failure: `test_post_provider_summary_failure_is_attempt_failure_with_evidence`
  now asserts `run_status=="completed"`, `hop_used==1`,
  `invocation_id.startswith("INV-")`, and `current_head==final_head==HEAD`. All
  four assertions fail against the pre-correction code (which produced
  `ready`/`0`/`"unknown"`), so the test exercises the exact defect, not a nearby
  branch.
. N=2 post-Hop failure proof -- adequate. `progress` fires identically after
  H001 and H002; the N=1 `main()` test proves the except branch consumes
  `latest_*`; the mechanism is symmetric. Confirmed by probe (below). No extra
  symmetry-only test is required.

*Probe (N=1, `_summary` forced to raise after a charged completed Hop):*
persisted `operator-summary.json` = `run_status='completed'`, `hop_used=1`,
`invocation_id='INV-...'`, `current_head==final_head==HEAD`. (Pre-correction:

== 7. Governing-input path correction

*SOUND -- and a necessary latent-bug fix.* The prior code built
`governing = {path: _governing_digest(text) for path, text in texts.items()}`,
but `texts` is keyed by *logical names* (`work_item`, `profile`, `policy`,
`components`, `task`), so the five YAML digests were keyed by non-path labels.
`_governing_inputs_unchanged` then called `_pinned_text(repository, B,
"work_item", ...)`, which cannot resolve a file literally named `work_item` at B
-> `OperatorPreflightError` -> `False` -> `stop_continuation`. The prior
happy-path N=2 test passed `governing={}` directly to `run_serial_hops`, so this
defect was latent and would have stopped *every* supported `main()` N=2
continuation with a spurious `governing_input_changed`.

The correction keys by `input_paths[name]` (`operator.py:162-165`), so every
governing entry is now the actual validated repository-relative path. Verified:

* every YAML input (WorkItem, profile, policy, component manifest, task) plus
  every selected component path is included;
* H002 re-reads exactly those original paths at B via `_pinned_text`;
* no logical label can be interpreted as a path;
* duplicate physical paths (e.g. a component whose path equals an input path)
  collapse to one dict entry with an identical digest read at the same HEAD --
  no unsafe result;
* the content-identity guarantee is unchanged (SHA-256 over pinned content); the
  governing-drift test still proves `awaiting_human` on real drift.

This is why the new `main()` N=2 test can complete: H001 mutates only the
payload `PROOF.md` (not a governing input), so the corrected governing check
passes and H002 proceeds.

GOVERNING-INPUT PATH IDENTITY CORRECTION SOUND:: YES.
