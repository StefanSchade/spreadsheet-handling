== 4. Review 2 -- WATCH-7 code/test correction `c11cc2f5`

The commit edits only `operator.py` and `test_operator.py`.

=== 4.1 Top-level `commits` -- run-level semantics

`_summary` now iterates `for hop in run.hops: for commit in hop.actual_commits`,
aggregating every recorded Hop's commits in Hop-then-commit order. `run.hops` is
in execution order and `actual_commits` is per-Hop ordered, so the aggregate is
deterministic. The empty-`run.hops` case yields `[]` without indexing (the old
`run.hops[-1]` guard is no longer needed). Per-Hop `actual_commits` in `hops[]`
is untouched. Correct.

=== 4.2 Top-level `changed_paths` -- net committed delta

`changed_paths` is now unconditionally `git diff --name-only
baseline_head..final_head`. The removed guard (`run.hops[-1].actual_commits
and ...`) was exactly the WATCH-7 defect: a run ending in an observation-only
Hop reported `[]` even when an earlier Hop mutated. For the N=2 mutating-H001 /
read-only-H002 shape the net delta is `PROOF.md`; for a fully observation-only
run `baseline == final`, so the diff is `[]`. Both are asserted by tests.
Correct and truthful.

=== 4.3 Console `LAST RUN COMMIT`

`last_run_commit = next((commit for hop in reversed(final_run.hops) for commit
in reversed(hop.actual_commits)), "none")` returns the last commit of the last
Hop that produced any commit, and `"none"` only when no Hop produced a commit.
The label is renamed from `LAST COMMIT` to `LAST RUN COMMIT`, which correctly
drops the misleading implication that the value is tied to the final Hop or that
final HEAD was necessarily produced by the last Hop. Semantics match WATCH-7's
recommended correction.

=== 4.4 Failure / best-effort summary unchanged

`_best_effort_failure_summary` still hardcodes `commits: []` / `changed_paths:
[]` (operator-known-facts-only on an aborted attempt) and is not touched by this
commit. No inconsistency is introduced between the normal and best-effort paths.

=== 4.5 Schema / compatibility

`operator-summary.json` keeps `schema_version: 1`. The field *shape* is
unchanged; only the derived meaning of two existing fields is corrected from a
buggy last-Hop reading to the intended run-level reading, and one human-facing
console label is renamed (console text is not part of the JSON contract). The
FTR's own WATCH-7 disposition states no supported consumer relied on the former
last-Hop interpretation; a repository grep confirms the only other `LAST
COMMIT` occurrences are throwaway `tmp/` scratch scripts (their own prints) and
documentation/review prose, not summary-field consumers. Under the project's
current compatibility policy this is a defect correction, not a
behavior-contract change, so no schema bump is required. This matches the
"Run-summary disposition (WATCH-7)" text in `7a60c559`.
