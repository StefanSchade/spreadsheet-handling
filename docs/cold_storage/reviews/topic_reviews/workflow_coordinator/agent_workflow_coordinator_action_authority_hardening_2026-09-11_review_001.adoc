== Verdict

*B -- BOUNDED CORRECTION REQUIRED BEFORE ACCEPTANCE.*

The hardening correctly gives `edit` and `commit` Coordinator meanings rather
than shell-command meanings; correctly derives `edit => commit` and
`durable_artifact: required => commit` for the accepted clean-boundary N=1
model; correctly makes phase actions narrow repository-policy actions on the
accepted declarative operator path; and correctly refuses a non-null
`CommitIntent` before `trusted_commit()` when the current phase lacks `commit`.
The historical WI02 shape is closed both statically and at runtime.

The implementation is nevertheless incomplete at that same authority boundary.
A strictly serialized phase containing only `authorized_actions: [commit]`,
paired with a policy containing only `actions: [commit]`, passes serialization
and operator preflight. The provider may then mutate an in-scope file, return a
valid `CommitIntent`, and the trusted Coordinator commits it because runtime
checks only `commit`. A disposable fake-executable probe exercised the complete
accepted operator path and returned exit `0`, `run_status=completed`, moved
`HEAD`, and ended clean despite neither phase nor policy granting `edit`.

That contradicts the new normative split: `edit` is the authority for semantic
worktree mutation, while `commit` is only the authority for Coordinator-owned
materialization. Since every current trusted commit begins at a clean observed
HEAD and commits exactly the agent-created dirty path set, a real trusted commit
necessarily consumes both capabilities. This is a genuine authority bypass on
the normal operator path, not a hypothetical future entry point. The correction
is small and does not require a provider invocation or redesign of the open
action vocabulary.

== 1. Accepted semantic contract

The current Slice-4B authority supersedes the historical pre-Slice-4B wording in
WFC-GIT-03 and the older architecture document that assigned commits to the
agent. Section 11.4.7 is explicit: the agent owns semantic worktree mutation and
a bounded semantic `CommitIntent`; the trusted Coordinator alone owns
mechanical `git add` / `git commit`. `CommitIntent` remains only `paths +
subject`, distinct from `claimed_commits`, and supplies neither arbitrary argv
nor an authoritative commit hash.

The new constants in `model.py` accurately name that split. The target does not
change `git_facts.trusted_commit()`, the Codex adapter, its sandbox, or any Git
surface. Consequently `commit` does not grant the agent direct Git authority.

The capability split also has a necessary conjunction at the trusted commit
boundary:

----
semantic worker changes a clean worktree  ->  phase/policy `edit`
Coordinator lands those exact changes     ->  phase/policy `commit`
----

The target enforces only the second line at runtime. It therefore implements
the definition of `commit`, but not the independence of the two grants.

== 2. `edit => commit`

*EDIT => COMMIT IS ARCHITECTURALLY VALID: YES.*

WFC-GIT-01 requires a clean independently observed starting commit. Under the
accepted Slice-4B replacement for historical agent-created commits, any semantic
worktree mutation that is to survive successfully must be represented by a
non-null `CommitIntent` and materialized by the Coordinator. A surviving dirty
worktree without that commit is an anomaly and stops autonomous routing. A phase
may still observe without mutation, and a successful committed Hop may route to
`await_human`, `stop`, or a prerequisite boundary; those route effects do not
require uncommitted semantic state.

No current accepted profile, current YAML caller, or maintained test contract
establishes temporary tracked edits, edit-then-review dirty carryover, or a
suspended phase that deliberately retains uncommitted semantic changes as a
successful phase result. Ignored scratch is a separate cleanliness policy, not
an authorized durable repository edit. The implication is therefore justified
for current serialized phase capabilities and does not rely merely on updated
fixtures.

The serializer's wording that such a phase can "only ever fail closed" is
slightly absolute--an invocation may simply make no edit--but this does not
invalidate the capability-coherence rule: if the declared `edit` capability is
actually exercised and is to land successfully, `commit` is required.

== 3. Required durable artifact => commit

*REQUIRED DURABLE => COMMIT IS ARCHITECTURALLY VALID: YES.*

WFC-OUTPUT-04 requires an in-scope versioned artifact reference and states that
a successful mutating Hop commits it. Git is the accepted durable repository
history, and no second artifact store or successful uncommitted-artifact state
exists in the current N=1 model. A failed/preempted invocation may leave an
observable worktree file, but that is not satisfaction of a required durable
artifact. Therefore a required-durable phase must possess `commit` authority.

Separately, producing that artifact also exercises `edit`; this is exactly the
missing half of finding AAH-R1. The correctness of `required => commit` does not
make `commit` an implicit substitute for `edit`.

== 4. Phase actions narrow repository policy

*PHASE ACTIONS ⊆ POLICY IS CORRECT.* WFC-POLICY-03 assigns repository/action
authority to operator/Run policy and workflow semantics to the profile; a phase
may narrow that grant but cannot enlarge it. Literal subset comparison is also
meaningful for open descriptive tokens: generic code need not implement
`publish` for the policy to forbid a phase from claiming it.

`operator._preflight()` deserializes all pinned inputs, then checks every phase's
action set before Run construction or provider-capable execution. The new
operator regression adds `publish` only to the phase, observes the specific
diagnostic, and asserts that its fake-executable counter was never created. That
test genuinely exercises the cross-input check.

== 5. Runtime phase-commit check

For a valid non-null `CommitIntent`, `vertical.run_one_hop()` checks the current
phase before entering the `trusted_commit()` branch. When `commit` is absent it
records a trusted-commit error, calls observe-only `observe_hop()`, retains the
agent's dirty file, records the unchanged HEAD, and passes a repository anomaly
to `reduce_result()`. Mechanical preemption precedes finding or route handling,
so the result becomes `awaiting_human`, not completed. No later reducer path can
materialize a commit.

The check is also independent of `claimed_commits`. Those claims remain hints
about already-observed Git reality and cannot cause `trusted_commit()` to be
called. The historical direct-agent-commit path remains constrained by the
accepted production sandbox and was not expanded by this target. Malformed
results fail validation before this logic; failed/blocked/escalated results with
intent retain the existing non-permitted-disposition behavior.

The committed test is meaningful. Its fake adapter makes the exact in-scope
dirty change and returns a fully correlated valid intent whose subject and path
would commit successfully. The unchanged-HEAD assertion would fail if
`trusted_commit()` ran; the preserved file and `awaiting_human` assertions prove
the observe/preemption disposition. The one-line-log assertion is redundant,
but not the source of confidence.

== 6. Static versus runtime placement

The intended split is architecturally reasonable:

* strict serialization owns intra-profile coherence;
* operator preflight owns the relation among independently serialized pinned
  inputs;
* runtime owns factual current-phase authority immediately before trusted Git.

AAH-R1 is not a layering objection. It is a missing coherence/runtime condition
inside those selected layers. The normal operator accepts the bad shape because
`commit` without `edit` violates neither existing static implication nor subset
comparison, and runtime checks only `commit`.

`Run` intentionally stores policy ID/revision but not policy actions. That is
adequate for the explicitly operator-scoped transitive guarantee, but makes the
lower API unable to defend a caller that skips cross-input preflight (WATCH-1).

== 7. Open vocabulary and non-mutating phases

Keeping action values open is correct. Only exact `edit` and `commit` tokens
activate Coordinator meaning; arbitrary strings do not select routes, invoke
Git, expand scope, or bypass the literal `commit` guard. Closing the vocabulary
would reject descriptive phase capabilities without resolving AAH-R1 and would
be an unjustified redesign.

A genuinely non-mutating phase such as `authorized_actions: [review]` with
`durable_artifact: none` still serializes. Such a phase has no trusted-commit
authority; unexpected dirty state remains an observed anomaly. A material review
that must write a required repository artifact needs `review,edit,commit`: review
describes the semantic role, edit permits artifact creation, and commit permits
the Coordinator to land it. The target's updated fixture has that correct shape,
but serialization currently fails to require its `edit` member.

== 8. WI02 regression

The actual bad shape is closed as claimed:

* strict YAML parsing rejects `durable_artifact: required` plus
  `authorized_actions: [edit]` before a Run exists;
* an independent normal-operator disposable probe supplied matching policy
  `actions: [edit]`, a valid durable-artifact argument, and a fake executable;
  the operator returned `2`, the counter proved zero fake invocations, and HEAD
  remained unchanged;
* a directly constructed Phase with `authorized_actions=("edit",)` and a valid
  non-null intent reaches the runtime phase check but not `trusted_commit()`;
  the committed real-Git regression proves unchanged HEAD and human preemption.

The WI02 runtime test omits `durable_artifacts`, which would independently cause
a post-acceptance durable-artifact anomaly. That does not make the test vacuous:
its unchanged-HEAD assertion still fails if the trusted commit occurs, before
the reducer disposition can mask it. A direct spy on `trusted_commit()` would be
clearer but is not necessary for the established property.

== 9. Agent Git authority

The target changes only model constants, profile serialization, operator
preflight, vertical authority gating, fixtures/tests, and documentation.
`git_facts.py`, `slice4.py`, and the Codex adapter are unchanged. No direct agent
`git add`, `git commit`, reset, rebase, merge, push, fetch/pull, config, hook,
arbitrary argv, or Git-metadata authority is added. The single
`trusted_commit()` surface remains path/subject/HEAD bounded and uses the already
accepted trusted Git execution policy.

== 10. Finding

=== AAH-R1 -- `commit` silently grants missing semantic `edit` authority

Severity:: *BLOCKING* for acceptance of this authority hardening.

Violated contract/invariant:: FTR 11.4.7's separate capability definitions;
WFC-POLICY-03's rule that no layer silently grants authority owned by another;
the accepted Slice-4B ownership model in which the agent owns semantic worktree
mutation and the Coordinator owns only its mechanical landing. A `commit` grant
cannot substitute for an absent `edit` grant.

Exact execution path:: Pinned YAML profile
`durable_artifact: none, authorized_actions: [commit]` plus pinned policy
`actions: [commit]` -> `workflow_profile_from_yaml()` accepts ->
`operator._preflight()` accepts subset -> provider/fake mutates an authorized
file and returns completed correlated `CommitIntent` ->
`vertical.run_one_hop()` sees `commit` and calls `trusted_commit()` -> exact
dirty path is staged/committed -> reducer completes -> operator returns `0`.

Evidence:: `serialization._check_action_coherence()` checks only
`edit-without-commit` and `required-without-commit`; `vertical.run_one_hop()`
checks only `COMMIT_ACTION` before trusted Git. `prompt._header()` does not
project actions, so there is not even an advisory phase-action instruction that
could compensate (and deterministic enforcement is required regardless). The
independent disposable full-operator fake-executable probe reported:

----
OPERATOR_EXIT: 0
OPERATOR_COMMIT_WITHOUT_EDIT_HEAD_MOVED: True
OPERATOR_RUN_STATUS: completed
OPERATOR_WORKTREE_CLEAN: True
----

This is not merely direct construction: the strict serializer and current
accepted declarative operator both accepted the shape.

Smallest bounded correction:: Require `edit` as well as `commit` immediately
before `trusted_commit()` can run, so directly constructed phases fail closed;
make strict phase coherence reject a commit-capable or required-durable phase
that lacks `edit`; and add real-temporary-Git regressions for both the normal
operator and direct in-process paths. Do not close the vocabulary, add policy
state merely for convenience, broaden Git authority, or change the sandbox.

Another real provider invocation required:: *NO*. Local fake executables and
real temporary Git repositories fully exercise the correction.

== 12. Minor / WATCH

=== WATCH-1 -- lower composition APIs do not retain or enforce policy actions

`new_run()` checks repository membership but does not check phase actions against
policy actions. `Run` persists only `policy_id` and `policy_revision`, and neither
`run_real_one_hop()` nor `run_one_hop()` receives RepositoryPolicy. A direct
in-process probe created a profile with `edit,commit`, a policy with only `edit`,
successfully called `new_run()`, and completed a trusted commit through
`run_one_hop()`.

This is *not classified as a current supported-path bypass*: the accepted
declarative operator performs the cross-input check; the fixed proof harness has
matching hard-coded values and its proof authority is consumed; the historical
task launchers are explicitly unsupported; and the lower functions are trusted
composition/test seams rather than a documented human-authored authority
ingress. The FTR accurately limits its transitive claim to the operator path.

The API remains an authority footgun if a future supported caller is added.
Before any such caller is accepted, it must reuse the operator check or move the
subset invariant into the canonical validated Run-construction boundary. That is
not needed to correct AAH-R1 and is not a request to implement Slice 5.

== 13. Documentation assessment

FTR 11.4.7 is accurate about workflow-effect semantics, agent/Coordinator commit
ownership, `edit => commit`, required-durable => commit, phase subset policy on
the operator path, and the phase-`commit` runtime refusal. It is not accurate in
claiming the described action authority is deterministically enforced as a
whole, because a successful normal commit-only Run grants the semantic mutation
that the same paragraph assigns to `edit`.

The implementation note similarly overclaims that the hardening removes the
ambiguity at the model/validation boundary. Its residual-limitation example says
a phase declaring neither `edit` nor required durability remains safe through
the runtime `commit` check, but omits the accepted `commit`-only phase that
bypasses `edit`. Its narrower statement that policy `commit` is transitively
guaranteed "for the operator path" is truthful.

The commissioning diary remains a concise, explicitly non-normative historical
record rather than implementation documentation. Its final assertion that
deterministic rejection was added at the appropriate boundaries inherits
AAH-R1's incompleteness, but does not create a second normative contract.
