== Implementation shape

The supported declarative operator remains the sole authority ingress.  It now
accepts `max_autonomous_hops` one or two and rejects larger values before Run
creation or provider-capable execution.  The existing one-Hop vertical and
Slice-4 boundary are reused serially; there is no second Coordinator and no
workflow-model two-node special case.

Before H001 the operator validates repository admission, every phase action
against policy actions, and every normalized phase scope beneath normalized
`WorkItem.scope`.  Repository-policy scope remains repository identity only.
The same strict repository-relative normalizer rejects absolute, `..`, and
ambiguous path spelling.

For N=2, H001 completes its existing run/checkpoint/marker publication order.
Only then does the driver independently validate checkout association, clean
exact expected Git HEAD, and content hashes of every originally pinned
repository-backed governing input.  A content mismatch publishes the existing
`awaiting_human` disposition; incomplete/uncertain persistence remains under
existing `reconcile_required` recovery semantics.  H002 has a new invocation
ID, a per-invocation trivial binding record, and a fresh phase-correct prompt
containing bounded H001 summary context.  The driver has no loop beyond H002.

The canonical provider-capable boundary also now rejects a non-ready or
exhausted Run before dispatch-marker creation or adapter entry.  It deliberately
does not duplicate reducer, authority, Git-identity, or prompt policy.
