== Purpose

State the exact, terminal scope decision for the encapsulation hypothesis so a
future implementation context does not have to re-derive it.

== Decision

*No encapsulation is warranted.* `project_by_role` remains a public,
consumer-facing pipeline step, composed around -- not inside -- the normal
XRef-crosstable forward/inverse capability (assessment Option A). No Core or
worldbuilding runtime work is authorized by this investigation, and no
implementation FTR is opened.

== Why this is a terminal "not ready", not deferred complexity

The "not ready" verdict names concrete design reasons, not repository size:

. *Outbound is not adjacent to the XRef forward.* `contract_xref` is separated
  from `project_by_role` by a `join_frames` that adds the display helper
  `title`. The projection adapts a view-enriched matrix; the XRef forward never
  owns the helper, so there is nothing to fold into `contract_xref`.
. *The canonical XRef model has no display-helper slot.* `contract_xref`
  requires the relation to be exactly `row_keys + column_key + value`;
  `expand_xref` melts every non-key column. Encapsulating helper
  ordering/dropping would conflate canonical relation transformation with
  workbook-view adaptation.
. *`expand_xref` is a protected foundational primitive.* Grouped-XRef and
  `expand_compact_multiaxis` both build on it. Adding view-helper awareness
  there would ripple into protected surfaces.
. *No symmetric composite fits all five surfaces.* Four use
  `contract_xref`/`expand_xref`; one (`story_group`) uses `contract_xref`
  forward and `expand_compact_multiaxis` inverse.
. *The resolver has a second consumer.* Validation role targeting also imports
  `resolve_column_roles`, so the role model stays shared regardless.

== Exact contract (settled, for the record)

Because no implementation is authorized, the contract is a set of *negatives*
that a future context must honor rather than redesign:

* *Owning callable(s):* unchanged -- `project_by_role` remains the single
  role-based projection callable.
* *Public pipeline step name(s):* unchanged -- `project_by_role` stays
  registered and public.
* *Existing ordinary XRef steps:* unchanged. `contract_xref` / `expand_xref` /
  `expand_compact_multiaxis` signatures and semantics are not modified; no new
  composite is added.
* *Internal callability:* not applicable -- `project_by_role` is not demoted to
  internal.
* *Public registry entry:* retained.
* *Forward / inverse parameter mapping:* unchanged (in-place `frame:`,
  `direction:`, optional `helper_columns` / `key_columns` / `role_order`).
* *Helper/key overrides:* remain explicit consumer inputs at all ten sites.
* *Metadata reads/writes:* unchanged; the shared resolver remains the single
  role-detection path for projection and validation targeting.
* *Mutation/copy semantics:* unchanged (copy-based `(Frames) -> Frames`).
* *Migration of the ten call sites:* none required; they stay as composed
  today.
* *Compatibility policy:* fully backward compatible -- nothing changes.
* *Docs and registry changes:* none beyond this investigation's artifacts.
* *Removal/deprecation strategy:* none.
* *Protected surfaces:* grouped-XRef, axis mapping, `ExactTable`, WorkbookIR,
  render composer/flow, XLSX/ODS parsers and renderers, persistence boundary,
  schema maintenance, validation targeting semantics, shared resolver taxonomy,
  Project Memory, unrelated worldbuilding data.

== Terminal verdict
