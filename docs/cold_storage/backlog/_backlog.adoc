* `BUG-NUMPY-TIMEDELTA64-NUMBER-MISCLASSIFICATION-P4A` — *Done*; archived at
  `ftrs_done/BUG-NUMPY-TIMEDELTA64-NUMBER-MISCLASSIFICATION-P4A.adoc`, review
  at `ftrs_done/BUG-NUMPY-TIMEDELTA64-NUMBER-MISCLASSIFICATION-P4A_review.adoc`.
  Definition `9d3b55d`, fix `022f651`, evidence `6cc8b94`, independent review
  accepted (0 Blocking, 0 Important, 1 Minor documentation-only finding).
  Result: `numpy.timedelta64` subclasses `numpy.signedinteger`/`numpy.integer`
  (unlike `numpy.datetime64`), so `core.scalar_values.scalar_category`'s
  Number branch silently accepted a non-`NaT` `numpy.timedelta64` value as
  `"number"`, stripped of its unit; the same `np.generic` breadth separately
  let `numpy.timedelta64('NaT')` classify as Missing (IVM-REVIEW-F7). Fixed
  with two explicit `isinstance(value, np.timedelta64)` guards (one in
  `is_missing_carrier`, one in `scalar_category`, independently confirmed
  both necessary and correctly ordered); every `numpy.timedelta64` value, NaT
  or not, now uniformly raises `UnsupportedScalarError`. `numpy.datetime64`
  behavior is unchanged, unaffected. No production code path calls
  `core.scalar_values` yet, so no release note was needed.
