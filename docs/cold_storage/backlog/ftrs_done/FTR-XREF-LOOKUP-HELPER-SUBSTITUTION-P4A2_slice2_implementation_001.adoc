== 3. Inspected identity timeline

Reproduced directly from source (not only Assessment 001):

----
logical frame before export        role_matrix
  -> visible sheet name in workbook   Matrix View     (configure_workbook_view + render)
  -> visible frame name after read    Matrix View     (backend read_multi)
  -> logical frame name after mapping role_matrix     (apply_workbook_view_sheet_mappings)
----

`_meta.sheets` is keyed by the *visible sheet name* from
`configure_workbook_view` onward and is *never re-keyed* by
`apply_workbook_view_sheet_mappings` (`domain/workbook_views.py:276` copies
`_meta` unchanged and only re-keys frames). Therefore the durable helper carrier
`_meta.sheets.<visible-sheet>.helper_columns` is addressable by the visible
sheet name after readback and is *not* addressable by the logical frame name
after mapping.

Confirmed metadata keying:

* `configure_workbook_view` (`workbook_views.py:55`, `_merge_sheet_options`):
  writes `_meta.sheets[<sheet.sheet>].helper_columns` — visible sheet name.
* `apply_derived_column_policy` (`derived_column_policy.py:244`,
  `_safe_durable_helper_names`): reads `_meta.sheets[source].helper_columns` —
  so the `source` argument must be the visible sheet name after readback.
* `validate_references` `no_helper_columns` (`reference_validations.py:337,615`,
  `_durable_helper_columns`): reads `_meta.sheets[frame].helper_columns` — same
  visible-sheet keying.
* Persistence boundary (`pipeline/persistence_boundary.py:112`): prunes
  top-level `derived` (transient `enrich_lookup` provenance) but preserves
  `sheets`.

== 4. Binding-route decision

*Preferred route selected: visible-sheet cleanup before mapping.* The already
proven route (`drop by visible sheet name` before
`apply_workbook_view_sheet_mappings`) is expressible entirely through the
registered public pipeline. Identity ownership is explicit:

* workbook boundary / durable carrier: visible sheet identity;
* after mapping: logical frame identity;
* canonical XRef inverse: logical frame identity.

== 5. Why visible-sheet cleanup was selected (alternative rejected)

The alternative provenance re-key (mutating `apply_workbook_view_sheet_mappings`
to re-key `_meta.sheets` to logical names) was *rejected*. It is unnecessary:
the preferred route satisfies the public configured pipeline on both backends
without any runtime change. Existing mapping behavior and tests preserve `_meta`
unchanged; re-keying would be a wider semantic change to a protected surface and
is explicitly gated behind a stop/reconfirm condition that did not fire.

== 8. Durable versus transient provenance

* *Transient* `_meta.derived.sheets.<output>.enrich_lookup.helper_columns`:
  written in-run by `add_lookup_helpers`; *pruned at the persistence boundary*
  (`RUNTIME_ONLY_TOP_LEVEL_META_KEYS`). Not the inbound carrier.
* *Durable* `_meta.sheets.<visible-sheet>.helper_columns`: written by
  `configure_workbook_view`; survives XLSX and ODS roundtrip; the carrier the
  inbound drop and the `no_helper_columns` postcondition both bind to.

Proven through the real orchestrator projection
(`project_meta_to_persistable_contract`) plus the real XLSX/ODS backends:
`_meta.derived` is absent after readback while
`_meta.sheets["Matrix View"].helper_columns == ["title"]` and `title` is
physically present in the payload.

== 9. Workbook View declaration dependency

The binding works only when the outbound `configure_workbook_view` sheet spec
declares `helper_columns: [title]`. Core cannot infer that `title` is a display
helper from its name; the removal binds only to the declared durable carrier. If
the declaration is omitted, `_meta.sheets` carries no helper columns after
readback, the drop is a safe no-op, and `title` survives unclassified.

== 10. Declaration-guard ownership

NOTE: The guard-scope wording in this section and section 11 was corrected in
`FTR-XREF-LOOKUP-HELPER-SUBSTITUTION-P4A2_slice2_correction_001.adoc`
(R001-IMP-001). The `no_helper_columns` postcondition is *declaration-bound*: it
cannot detect a *missing* declaration. The Slice-3 static declaration check
below remains the completeness gate.

* Core verifies and documents the generic carrier behavior (this slice).
* The configured integration test asserts the helper declaration survives the
  roundtrip and drives removal.
* Inbound pipelines may pair cleanup with `no_helper_columns` as a
  *declaration-bound* postcondition — defense in depth against a cleanup that was
  omitted or left a *declared* helper behind, not a declaration-completeness
  check (see section 11).
* *Slice-3 handoff:* a consumer-owned static/configuration guard must prove each
  of the five Worldbuilding matrix sheets declares `helper_columns: [title]`.
  Core does not add a new API to infer that a consumer column should have been
  declared a helper (a negative test makes the dependency visible instead).

== 11. Postcondition validation

`validate_references(mode=fail, rules=[{type: no_helper_columns, frame: Matrix
View}])` reads the *same* durable declaration
`_meta.sheets["Matrix View"].helper_columns` that cleanup reads. It is therefore
a declaration-bound cleanup postcondition, not a declaration-completeness check
(corrected in Correction 001, R001-IMP-001):

* with the declaration present, it *fails closed* (`ValueError: Helper columns
  must be absent after cleanup`) while the declared helper is still present and
  *passes* after successful cleanup, without mutating caller frames or `_meta`
  (`test_declaration_present_guard_fails_before_and_passes_after_cleanup`,
  `test_no_helper_columns_postcondition_fails_when_helper_present`);
* with the declaration absent, cleanup is a no-op and the guard also *passes*
  while `title` survives unsafe for the inverse — it cannot detect the missing
  declaration (`test_no_helper_columns_guard_cannot_detect_omitted_declaration`).

== 12. Correct-order versus wrong-order evidence

* *Correct order* (`drop by visible sheet` -> `apply_workbook_view_sheet_mappings`)
  removes `title` before the inverse; the relation matches the original.
* *Wrong order* (`apply_workbook_view_sheet_mappings` ->
  `apply_derived_column_policy(source=<logical frame>)`) cannot find the
  visible-sheet-keyed `_meta.sheets` provenance and leaves `title`; the inverse
  then melts it into `column_key`. `test_wrong_order_mapping_before_cleanup_leaves_title`
  demonstrates the concrete downstream harm (title melted) and that the correct
  order drops it — it does not celebrate the silent failure.

This is recorded as an explicit public sequencing contract in the
supporting-steps user guide and release notes.

== 25. Residual risks

* The binding depends on the outbound `configure_workbook_view` declaration; a
  dropped or mistyped declaration silently leaves `title` unclassified. The
  `no_helper_columns` postcondition does *not* mitigate this: it is
  declaration-bound and passes when the declaration is missing (corrected in
  Correction 001, R001-IMP-001). The mitigation is the Slice-3 consumer-owned
  static declaration check; a negative test
  (`test_no_helper_columns_guard_cannot_detect_omitted_declaration`) makes the
  limitation visible and tracked.
* (Closed in Correction 001, R001-IMP-002.) The original focused integration
  test exercised the persistence boundary through the orchestrator's own
  projection function plus the real backends rather than the end-to-end
  application entry point. Correction 001 adds
  `test_orchestrated_public_roundtrip_edited_title_discarded`, a maintained
  end-to-end proof of the exact route through `orchestrate()` across a real XLSX
  carrier with a physical workbook-cell edit.
* Sparse Worldbuilding surfaces yield `rows=0` after `drop_empty`; equality with
  the reference still holds, but row-count is not an independent signal on those
  three surfaces (columns-preserved and edited-title checks compensate).
