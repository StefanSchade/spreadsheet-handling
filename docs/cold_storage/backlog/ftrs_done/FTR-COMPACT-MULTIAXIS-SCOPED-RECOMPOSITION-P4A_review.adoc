== Scope

Independent acceptance of the opt-in
`expand_compact_multiaxis(base_canonical_relation=...)` capability for
reimporting partial spreadsheet projections without losing canonical rows
outside the visible matrix scope.

The accepted boundary is narrow:

* the public base is canonical
  `[*row_keys, column_key, code (, group)]`;
* Compact Multiaxis Cell-Codec-encodes that base to the compact
  `[*row_keys, column_key, value]` relation consumed by XRef;
* XRef alone owns scoped recomposition through `base_relation`;
* Cell Codec decodes the recomposed relation to canonical rows;
* optional `group` is recomputed as the existing generic projection;
* the encoded base and XRef relation are local temporary frames;
* the base input is opt-in and no-base behavior retains the prior
  full-replacement semantics and metadata shape.

Out of scope and not reopened: redesign of XRef or Cell Codec, a second
merge/dedup algorithm, dense-axis implementation, diagnostics-trace lifecycle
commands, YAML/callable `name` forwarding, a composite plan object, the
ontology-removal umbrella, or promotion of the Cold Storage inquiry into a
universal architecture rule.

== Runtime composition inspection

`expand_compact_multiaxis` rejects unsupported `dense_axes`, resolves row keys
and output fields, snapshots the caller's prior XRef metadata, then takes one
of two paths:

* with no canonical base, it delegates from the caller mapping as before and
  passes `base_relation=None`;
* with a canonical base, it calls `encode_cell_values` with
  `group_by=[*row_keys, column_key]`, stores the compact result in a unique
  local `__compact_multiaxis_<id>_base` frame, and passes that exact frame name
  as `expand_xref(base_relation=...)`.

The wrapped XRef call is always `drop_empty=False`. This is required for a
cleared matrix cell to remain an in-scope address and suppress the corresponding
base row. Caller `drop_empty` is then applied only by `decode_cell_values`.

After decode, both temporary frames are removed, optional group projection
finishes, prior XRef metadata is restored, and the diagnostics trace is written.
There is no exception handler and no write to the caller mapping: every
intermediate is installed only in returned mapping copies.

AST/source inspection found no Compact-owned loop or operation that calculates
addresses, joins visible/base rows, deduplicates them, chooses precedence, or
orders recomposed rows. Those mechanics remain exclusively in
`expand_xref`.

== Canonical-to-compact base boundary

The public parameter deliberately names the representation:
`base_canonical_relation`, not XRef's compact `base_relation`.

Source inspection and an independent monkeypatch probe established:

[source,text]
----
canonical base: [id, axis, code]
  -> encode_cell_values(group_by=[id, axis], code=code, value=packed)
compact base:   [id, axis, packed]
  -> expand_xref(base_relation=<temp compact base>)
----

The probe captured the frame at the XRef call. Its columns were exactly
`["id", "axis", "packed"]`; it contained no canonical `code` column; and the
XRef `base_relation` argument named the local base temporary frame. The
canonical base is never passed directly to XRef.

The temp frame is generated by `_temp_frame_name`, removed from the successful
result, and absent recursively from metadata. Encoding and XRef failure probes
also found no temp frame in caller state because the caller mapping is never
mutated.

`canonical_order` exists only on the contract/encode public direction, not on
`expand_compact_multiaxis`; the scoped base path therefore preserves the
canonical base's first-occurrence token order. This is deterministic and
roundtrips all values. It does not discard a token or invent a new order
authority, and the active scoped-recomposition contract does not promise to
reapply a separately authored forward `canonical_order` on reverse. No public
gap or data-loss finding results.

Both `whole_cell_code` and `split_tokens` are covered. A split-token independent
probe preserved out-of-scope `S`, `K` in base first-occurrence order while
decoding a newly visible token independently.

== XRef scoped-recomposition review

XRef defines scope as the Cartesian set of every physical matrix row identity
and selected `value_columns`. It records an address before considering whether
the cell is empty. Its existing base append loop emits only base addresses not
in that set.

The wrapper passes the compact base and otherwise delegates without inspecting
row identities or axis values. Consequences verified against source and probes:

* visible content wins for a matching visible/base address;
* a new visible address is added;
* a fully visible matrix suppresses all matching base addresses without
  duplicates;
* base row identities absent from the matrix remain out of scope and survive;
* matrix row identities absent from the base are emitted normally;
* duplicate canonical rows for one address follow Cell Codec grouping rules
  (`split_tokens` preserves them as tokens; invalid multiple whole-cell codes
  reject);
* duplicate visible matrix row identities retain XRef's primitive behavior;
  Compact introduces neither a new rejection nor a precedence rule;
* `dense_axes` remains explicitly unsupported by Compact and rejects before
  composition.

This is XRef ownership, not replicated wrapper policy.

== Preservation, replacement, and deletion

Independent behavioral probes covered:

* partial axis projection: visible `A=Z` replaced base `A=E`, while base `B`
  and an entirely absent base row identity survived;
* exact replacement: only one canonical row remained for the matching address;
* new address: a visible address absent from the base was added;
* clear with `drop_empty=True`: the matching base row was suppressed and the
  empty decoded row was removed; it did not resurrect;
* clear with `drop_empty=False`: the matching base row was suppressed and one
  truthful canonical row with `code=""` remained.

The last case exposed a durable test-coverage gap during review. Runtime was
already correct, and `4c6ff60` added
`test_deletion_with_drop_empty_false_keeps_truthful_empty_row`.

== Scope and ordering edge cases

The review checked the adversarial scope cases requested:

* explicit partial `value_columns` select only those axis addresses;
* a present-but-empty selected column owns and clears its addresses;
* partial matrix rows preserve every base row identity absent from the matrix;
* an empty matrix with declared columns covers no row addresses and therefore
  preserves the base;
* matrix rows absent from the base are added;
* base row keys absent from the matrix survive;
* visible/base duplicate addresses resolve visible-first with no surviving
  base duplicate;
* dense-axis configuration rejects explicitly;
* in-scope output follows matrix row order then selected matrix-column order;
* out-of-scope rows follow base address first occurrence after Cell Codec
  grouping.

The independent mixed-order probe used physical matrix columns `B`, `A`,
selected in that order, two matrix row identities, present-empty cells, one
new address, and one orphan base identity. The result followed XRef order and
preserved only the genuinely out-of-scope base row.

Relation-row ordering and token ordering are distinguishable. XRef owns
in-scope-then-out-of-scope relation address order. Cell Codec owns token order
within one address. Both are deterministic from authored inputs; no Compact
ordering layer exists.

== Group semantics

The optional canonical `group` column is not part of `group_by` and is not the
encoded value. It is intentionally omitted during canonical-base encode and
recomputed over the complete decoded output by `_with_group_column`.

This is truthful because current Compact documentation defines `group` as a
generic projection from Legend entries or explicit `code_groups`, not
caller-authored business meaning. The behavior is visible and tested for
out-of-scope base rows. A deliberately conflicting Legend/code-groups probe
failed during the final group-recompute leg and left the caller mapping, prior
trace, and source DataFrames unchanged.

== Metadata and failure atomicity

Metadata inspection established:

* the complete prior `_meta.xref_crosstable` root is snapshotted defensively
  and restored after success;
* absent and explicitly empty prior XRef roots are canonically omitted;
* same-ID and unrelated prior XRef entries survive;
* different Compact trace IDs coexist and same-ID success replaces one entry;
* the Compact trace is diagnostics-only and no runtime code reads it;
* with a base, the trace records only the authored public base frame name;
* without a base, the optional field is omitted, preserving the prior trace
  shape;
* no internal temp name appears recursively in returned or persisted metadata.

Independent failures exercised all post-validation stages:

* invalid base code: base encode rejection;
* missing selected matrix column: XRef rejection after successful base encode;
* invalid visible code: decode rejection after successful base encode and XRef;
* conflicting group lookup: group-recompute rejection after decode;
* unsupported dense axes: wrapper validation rejection.

In every case the caller's keys, DataFrames, `_meta`, prior same-ID trace, and
unrelated frames remained unchanged. No output, temporary frame, internal XRef
metadata, or partial Compact trace was installed.

== Documentation review

The Functional Model, User Guide, Technical Model, and release note consistently
distinguish:

* local data-shape `expand`/`contract` names from project-level directions;
* canonical public base from XRef's compact base boundary;
* opt-in partial recomposition from no-base full replacement;
* out-of-scope preservation, in-scope replacement, and clears as deletion;
* primitive ownership from wrapper composition;
* diagnostics from operative intent;
* the Cold Storage inquiry from accepted universal architecture.

The initial implementation used `byte-for-byte` and recorded a null optional
trace field even though no-base output metadata had therefore changed. That
overclaim and mismatch were corrected in `4c6ff60`: the field is omitted when
absent and documentation now states the supported behavioral and metadata-shape
compatibility. Documentation covers both current codec modes through the
delegated Cell Codec contract without claiming the composition is universally
lossless.

== Findings

=== Blocking

None.

=== Important

* *I-1 — CLOSED (`4c6ff60`): no-base diagnostics changed while documentation
  claimed byte identity.* The initial implementation unconditionally recorded
  `base_canonical_relation: null`, observably changing the no-base
  `_meta.compact_multiaxis` payload. Risk: an opt-in feature would alter output
  metadata for every existing caller and contradict acceptance criterion 3.
  Correction: omit the optional diagnostics field when no base is supplied,
  assert omission, and replace literal byte claims with precise behavioral and
  metadata-shape compatibility.

=== Minor

* *M-1 — CLOSED (`4c6ff60`): no durable clear test for `drop_empty=False`.*
  Runtime correctly suppressed the matching base row and retained a truthful
  empty canonical row, but the FTR explicitly required the interaction to be
  tested. A focused regression test now pins it.

=== Observation

* *O-1 — base token ordering.* The expand surface has no `canonical_order`;
  preserved multi-token base addresses retain canonical-base first-occurrence
  order. This is deterministic, value-preserving Cell Codec behavior and is
  within the active contract.
* *O-2 — duplicate visible identities.* XRef does not add a Compact-specific
  uniqueness policy for duplicate physical matrix row identities. The wrapper
  correctly inherits that primitive behavior; no new rejection belongs in this
  slice.

No Blocking, Important, or Minor finding remains open.
