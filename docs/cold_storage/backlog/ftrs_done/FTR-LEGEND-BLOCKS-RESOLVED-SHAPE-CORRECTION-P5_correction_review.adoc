== Findings corrected

=== I-1 -- explicit `null` escaped the mapping-only contract

*Root cause:* the Legend ingress rule interpreted `None` as absent by returning
the original Frames, leaving the explicitly present key non-canonical. The
persistence projector's tolerant non-mapping fallback could consequently emit
`legend_blocks: null`.

*Correction:* an explicitly present `None` is compatibility syntax for an
absent declaration and now canonicalizes to an empty mapping while preserving
the key. This is the smallest deterministic representation satisfying “when
the key exists, its value is a mapping” and matches the existing empty-list
result. The persistence boundary also maps `None` to `{}` defensively, so even
a bypassing caller cannot emit a null Legend root. Mapping and list behavior,
ordering, identity resolution, and Entry Contract semantics are unchanged.

Evidence covers rule-level immutability, application-returned Frames, the JSON
directory `_meta.yaml` sidecar, and direct persistence projection.

=== I-2 -- `apply_overrides` was not failure-atomic

*Root cause:* `get_meta` copied only the top-level mapping.
`apply_overrides` then obtained the caller-owned nested `sheets` mapping through
`setdefault` and wrote merged per-sheet options into it before ingress
validation. A later duplicate-identity failure therefore leaked a partial
sheet update.

*Correction:* `apply_overrides` now copies the existing `sheets` mapping before
performing any per-sheet merge, completes all workbook and per-sheet merges on
that candidate, runs ingress on the complete candidate, and calls `set_meta`
only after success. The existing recursive `deep_merge` remains the merge
implementation and precedence is unchanged.

Adversarial tests introduce duplicate Legend identities through `defaults`
while also changing an existing sheet's scalar and nested options. They assert
value equality and object identity at Frames, `_meta`, `sheets`, per-sheet
metadata, and nested-option levels after failure. A configured pipeline test
also proves saver suppression. A successful nested merge test proves existing
values, override precedence, and untouched sheets remain correct.

`bootstrap_meta` was inspected but not changed: it already uses only pure
`deep_merge` candidates and writes after ingress succeeds. Its failure test now
checks the same complete caller graph, distinguishing that already-atomic path
from the corrected override path.

=== I-3 -- ingress was indirectly YAML-invokable through `plugin`

*Root cause:* registry guards covered only ordinary step names. The public
plugin factory resolved every dotted callable without classifying
framework-owned macro-flow namespaces, so package exports, the coordinator,
and individual ingress rules were importable.

*Correction:* the plugin factory now rejects the complete
`spreadsheet_handling.domain.ingress` namespace before importing a callable.
The rule is package-ownership based rather than tied to one function name and
emits the explicit diagnostic “framework-internal and not
plugin-addressable.” Framework invocation modules now import the package rather
than incidentally re-exporting the coordinator under alternate dotted paths.
No generic permission framework or alternate ingress callable was introduced.

Unit and architecture tests cover the package export, coordinator module, and
Legend rule module, plus absence of call-site aliases. Existing short-name
registry guards remain. An external test plugin and the existing internal
domain-contract workbook plugin both still build and execute.

== Documentation and coverage observations

The FTR is restored to `_ftrs_open.adoc` under immediate review closure and is
marked pending acceptance re-review; no completion cleanup or archival was
performed.

No YAML/XML/CSV sidecar tests were duplicated. In the current simple-backend
implementations those savers discard `_meta`; JSON directory is the distinct
structured backend that writes `_meta.yaml`. All savers receive the same
orchestrator-owned persistence projection, while the JSON application test
proves the actual structured sidecar path. The FTR now states that capability
boundary rather than implying four metadata sidecars.

== Compatibility impact

* External mapping and list authoring are unchanged.
* External `legend_blocks: null` keeps its prior no-Legend meaning but canonical
  runtime and persistence now contain `{}` instead of `null`.
* Valid `apply_overrides` merge precedence and successful in-place Frames
  update are unchanged; only leaked partial mutation on failure is removed.
* Ordinary external plugins, existing framework utility plugins, and registered
  steps are unchanged. Only framework-internal `domain.ingress` callables are
  no longer plugin-addressable, matching the reviewed architecture contract.
* Legend Entry token/label/group policy and `placement.target` maintenance were
  not changed.

== Remaining risks

Direct low-level transformation/render/backend callers still have the
documented precondition to provide canonical mapping-form metadata or invoke
ingress explicitly. The persistence boundary's `None` defense does not create
a second list-form compatibility surface. Arbitrary plugins remain responsible
for returning canonical Frames.

Legend Entry value semantics, `placement.target` schema maintenance, generic
metadata validation, and a future `domain.egress` remain owned by their
separate decisions and were not pulled into this correction.
