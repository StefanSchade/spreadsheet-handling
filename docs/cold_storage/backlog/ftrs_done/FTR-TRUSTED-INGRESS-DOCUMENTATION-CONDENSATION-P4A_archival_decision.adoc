== 6. Umbrella FTR disposition and lifecycle ordering

`docs/backlog/FTR-TRUSTED-INGRESS-P4A.adoc` is *ARCHIVE NOW* (class A), executed
by `DOC-CLOSE-LIFECYCLE-1`.

Justification against the umbrella rule (an umbrella moves only when all
sub-features are done *and* its integration acceptance is met): E1-E7 are each
independently accepted and Phase E integration acceptance is met (Phase E
COMPLETE). The umbrella carries construction/correction history only; its
current architectural meaning is fully owned by the §2 permanent documents, and
`DOC-COMP-TEST-1` reconstructed that architecture without opening it.

Why it is not "keep active temporarily": the closure-lifecycle *recording
vehicle* is the *condensation FTR* (class B) plus Project Memory, not the
umbrella. Retaining the umbrella active would keep it only for "useful history",
which the archive location preserves. The exact ordering is therefore:

[source,text]
----
this decision (ARCHIVE-DECISION-1, no moves)
-> DOC-CLOSE-LIFECYCLE-1:
     set condensation FTR status Done + delivery table   (records completion)
     remove Trusted-Ingress includes from _ftrs_open.adoc
     move the §4 archive-now set + condensation family + this decision
       to cold_storage/backlog/ftrs_done/ with index.json
     update Project Evolution (phase granularity) + curate Project Memory (§9)
-> Domain Maintainer Contract -> Phase F / first family pilot / D-T3
----

The umbrella and the condensation family thus physically move in the *same*
closure curation; the only difference is that the condensation FTR shell must
first be marked Done by that curation, whereas the umbrella needs no further
active state before its move.
