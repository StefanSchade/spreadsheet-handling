===== FTR-COMPACT-MULTIAXIS-SCOPED-RECOMPOSITION-P4A -- Wire XRef scoped recomposition (`base_relation`) through Compact Multiaxis so partial spreadsheet projections preserve out-of-scope canonical rows

*Status:* Done (accepted)

*Implementation state:* Complete. Accepted by independent review
`docs/cold_storage/backlog/ftrs_done/FTR-COMPACT-MULTIAXIS-SCOPED-RECOMPOSITION-P4A_review.adoc`
(2026-07-29): verdict ACCEPTED, no open blocking, important, or minor
findings. The diagnostics-trace lifecycle and YAML/callable `name` concerns
remain active and are not part of this acceptance.

*Priority:* P4A

*Type:* Composition capability preservation (reverse/forward roundtrip
correctness for partial projections). Reuses existing Cell Codec and XRef
`base_relation` contracts; introduces *no* new merge algorithm inside Compact
Multiaxis.

*Source and maintainer intent:*::

* Raised by
  `docs/warm_storage/global_reviews/FTR-COMPACT-MULTIAXIS-META-PERSISTENCE-CORRECTION-P5_review_001_acceptance.adoc`

* Maintainer intent recorded in
  `docs/cold_storage/working_context/functional_model_inquiry/bijective_frame_transformation_composition.adoc`:
  a composite may compose arbitrarily many reversible frame-to-frame
  transformations, applying the inverses in reverse order; intermediate
  representations are real contract boundaries; and *a composite wrapper must
  not discard the reversible semantics of the primitives it composes merely
  because it hides the intermediate frame*.

*Maintainer-intent composition (for reference):*::

Forward:

[source,text]
----
canonical relation
  → Cell Codec contract/encode → compact encoded relation
  → XRef contract               → spreadsheet matrix
----

Reverse:

[source,text]
----
spreadsheet matrix
  → XRef expand   → compact encoded relation
  → Cell Codec expand/decode → canonical relation
----

A base frame, merge input, or inverse-state input belongs to the representation
boundary of the transformation that consumes it. XRef owns the matrix↔relation
boundary, so a base relation supplied to XRef must have the *compact encoded
relation* shape (codec-contracted), not the canonical pre-codec shape and not
the final spreadsheet shape.

*Problem statement:*::

Compact Multiaxis exposes parameters (`value_columns`, and the matrix frame
itself) that can present only a subset of a larger canonical relation -- a
*partial spreadsheet projection*. On the reverse/import path,
`expand_compact_multiaxis` delegates to `expand_xref` but does *not* pass or
derive a `base_relation`
(`src/spreadsheet_handling/domain/transformations/compact_multiaxis.py`; the
`expand_xref` call omits `base_relation`, and the composite exposes no
codec-contracted base parameter). The underlying XRef primitive *does* support
scoped recomposition: `expand_xref(..., base_relation=...)` appends out-of-scope
base rows after the in-scope matrix rows
(`src/spreadsheet_handling/domain/transformations/xref_crosstable/operation.py`,
out-of-scope append loop).

Consequently, when a partial Compact Multiaxis projection is reimported and its
resulting relation replaces the full canonical relation, rows outside the
visible matrix scope are lost. The composite hides the intermediate compact
relation frame, and in doing so hides XRef's scoped-recomposition capability
from the pipeline author.

*Confirming evidence:*::

Adversarial probe (`PYTHONPATH=src`): expanding a partial matrix
(`feature_id=f1`, only column `P-001`) yields only
`[{feature_id: f1, column_key: P-001, code: Z}]`; canonical rows for `P-002`,
`P-003` outside the visible projection are not recoverable from that call. XRef
`base_relation` (already covered by XRef tests) is the primitive capability that
would preserve them.

*Required correction (reuse, not reinvention):*::

The detailed non-wrapper composition can already preserve out-of-scope rows by:

. contracting the canonical base relation with the Cell Codec to the *compact
  encoded relation* shape XRef expects;
. passing that compact intermediate relation as the XRef `base_relation`;
. applying XRef scoped recomposition (in-scope matrix rows replace the
  represented scope; out-of-scope base rows are preserved);
. decoding the merged compact relation back to the canonical relation with the
  Cell Codec.

The correction therefore *wires an existing primitive capability through the
composite*. It must:

* expose an explicit composite-level base input (e.g. a canonical
  `base_relation` frame name and/or a pre-compacted base frame), owned and
  documented by Compact Multiaxis;
* derive the correct codec-contracted intermediate base frame at the XRef
  boundary by running the forward Cell Codec encode on the canonical base
  before delegating to `expand_xref`;
* forbid any parallel merge/dedup logic inside Compact Multiaxis -- the merge is
  XRef's scoped recomposition and the shape transform is Cell Codec's;
* preserve caller-input and failure atomicity and the accepted temporary-frame
  discipline (the intermediate base frame is a locally-created temp, deleted
  before return, and never leaks into persisted metadata -- consistent with
  `FTR-COMPACT-MULTIAXIS-META-PERSISTENCE-CORRECTION-P5`).

*Forward/reverse and intermediate-frame shapes:*::

* Canonical relation: `[*row_keys, column_key, code (, group)]`.
* Compact encoded relation (XRef boundary): `[*row_keys, column_key, value]`.
* Spreadsheet matrix: `[*row_keys, <one column per column_key value>]`.
* The composite-supplied base for XRef expand must be the *compact encoded
  relation*, produced by encoding the canonical base with the same codec
  configuration used for the current run.

*Scope of behavior to define and test:*::

* Deletions inside the visible scope: an emptied/removed in-scope cell replaces
  (removes) exactly that address; it must not resurrect from the base.
* Preservation outside the visible scope: base rows whose `(row_id,
  column_key)` address is not covered by the visible matrix survive unchanged.
* Ordering: deterministic column order (explicit `column_keys` → derived first
  occurrence) and deterministic row order for in-scope-then-out-of-scope.
* Empty values / `drop_empty` interaction with scoped recomposition.
* Duplicate `(row, column)` addresses across visible and base: deterministic
  rejection or defined precedence (visible wins).
* Codec modes (`whole_cell_code`, `split_tokens`) both honored on the base
  encode and the merged decode.
* Failure atomicity: a failure in base encode, XRef expand, or decode leaves
  caller state, the prior successful trace, and prior XRef metadata unchanged;
  no temp base frame leaks.
* Persistence: no intermediate base or temp frame reference appears in any
  persisted metadata root; the diagnostics trace remains diagnostics-only.
* Consumer tests: a partial-projection roundtrip that preserves out-of-scope
  rows, exercised through the pipeline binder and at least one carrier
  (structured JSON and/or XLSX/ODS).

*Compatibility and migration:*::

* When the visible matrix covers the whole canonical scope, matrix-owned
  addresses suppress matching base rows without duplication. When no base is
  supplied, the pre-FTR full-replacement semantics and metadata shape are
  preserved.
* The base input is opt-in; existing pipelines that expand a full matrix are
  unaffected.
* Current in-repo consumers (the single Worldbuilding
  `expand_compact_multiaxis` pipeline) expose the full matrix and do not rely on
  scoped recomposition today; verify this remains true and that the reverse
  chain is structurally compatible with its forward chain.

*Non-goals:*::

* No new merge/garbage-collection/ontology mechanism inside Compact Multiaxis.
* No redesign of XRef or Cell Codec.
* No promotion of `_meta.compact_multiaxis` to operative inverse intent.
* No composite plan object.
* No change to the accepted metadata-persistence correction contract.

*Acceptance criteria:*::

. A partial Compact Multiaxis projection reimported against a supplied base
  relation preserves out-of-scope canonical rows and replaces exactly the
  visible scope.
. The preservation is achieved solely by composing Cell Codec encode + XRef
  `base_relation` scoped recomposition + Cell Codec decode; no parallel merge
  logic exists in Compact Multiaxis.
. Full-projection and no-base behavior preserves the pre-FTR full-replacement
  semantics and returned metadata shape.
. Deletions inside scope, ordering, empty/`drop_empty`, duplicates, and both
  codec modes are covered by tests.
. Caller-input and failure atomicity hold; no temp/base frame or temp-frame
  reference leaks into returned or persisted metadata.
. Persistence and at least one workbook carrier roundtrip the corrected
  behavior.
. Demo and current Worldbuilding flows remain green; release-note impact is
  determined and recorded.

*Implementation evidence:*::

Final public API (`src/spreadsheet_handling/domain/transformations/compact_multiaxis.py`):

* `expand_compact_multiaxis` gains one opt-in keyword-only parameter
  `base_canonical_relation: str | None = None`. It names a frame holding the
  *canonical* relation `[*row_keys, column_key, code (, group)]` -- the pre-codec
  shape this composite produces on the forward path -- deliberately *not* the
  compact XRef-boundary shape that `expand_xref`'s own `base_relation` takes. The
  name states the representation the caller provides so it cannot be mistaken for
  an XRef-shaped base. `contract_compact_multiaxis` is unchanged.

Exact intermediate-frame composition (reverse direction,
`expand_compact_multiaxis`):

[source,text]
----
base_canonical_relation frame  (canonical: [*row_keys, column_key, code (, group)])
  → encode_cell_values(group_by=[*row_keys, column_key], code, value, mode, …)
      → temp __compact_multiaxis_<config_id>_base
        (compact encoded relation: [*row_keys, column_key, value])

matrix + temp base
  → expand_xref(output=__compact_multiaxis_<config_id>_xref,
                base_relation=temp base, drop_empty=False)
      → recomposed compact relation (in-scope matrix rows, then out-of-scope base rows)

  → decode_cell_values(source=xref temp, output, mode, drop_empty=caller, …)
      → canonical result   (+ optional group column recomputed over all rows)
----

When `base_canonical_relation is None` the encode leg is skipped, `expand_source`
is the caller mapping, and `expand_xref` is called with `base_relation=None`.
The optional field is omitted from the diagnostics trace, preserving the
pre-FTR no-base returned metadata shape.

How the canonical base is encoded: via the existing Cell Codec forward path
(`encode_cell_values`, historical code-row mode) using the *same effective codec
configuration* passed to the run (`mode`, `delimiter`, `allowed_codes`,
`allowed_tokens`, `allowed_from_legend`, `normalize_case`, `strip`) and
`group_by = [*row_keys, column_key]`. This is the identical forward encode leg
that `contract_compact_multiaxis` uses, so the base reaches XRef in exactly the
shape XRef consumes. An optional `group` column on the base is ignored by the
encode (it is not in `group_by` nor the `code` selector) and is recomputed for
every output row by the existing `_with_group_column` step.

How XRef scoped recomposition is invoked: the wrapped `expand_xref` is called
with `base_relation` set to the temp encoded base and `drop_empty=False`. XRef
builds `in_scope_addresses` for every `(row_id, value_column)` of the matrix and
appends only base rows whose address is *not* in that set -- the accepted,
unmodified XRef `base_relation` append loop. No merge/dedup/scope logic was added
to Compact Multiaxis.

How deletions and out-of-scope preservation work: because `expand_xref` runs with
`drop_empty=False`, a cleared in-scope cell still marks its address in-scope
(suppressing any base row at that address) and yields an empty-value in-scope
record; the composite's `decode_cell_values` then drops that empty record under
the caller's `drop_empty` (default `True`), so the address disappears rather than
resurrecting from the base. Base rows whose address is outside the visible matrix
survive unchanged. The compact encoded base is unique per `(row_keys,
column_key)` (encode groups by that key), so "visible wins" holds and no
duplicate base row can survive in-scope.

Metadata behavior: unchanged from the accepted P5 correction. The internal XRef
leg is still snapshotted/restored (`_snapshot_xref_meta`/`_restore_xref_meta`);
`expand_xref`'s payload never records `base_relation`, so no temp base name
enters XRef metadata; `encode_cell_values` writes no `_meta`. The diagnostics
trace `_meta.compact_multiaxis[config_id]` records the authored
`base_canonical_relation` public frame name when supplied and omits the optional
field when absent. It remains non-authoritative and unread by runtime. No temp
frame name leaks into returned or persisted metadata (asserted recursively).

Compatibility when the base argument is omitted: the pre-FTR full-replacement
semantics and returned metadata shape are preserved; existing full-matrix
pipelines (including the single Worldbuilding `expand_compact_multiaxis` step,
which passes no base) are unaffected.

Tests and validation:

* `tests/unit/domain/transformations/test_compact_multiaxis_scoped_recomposition.py`
  (19 tests): out-of-scope preservation; full-projection no-duplicates;
  visible-scope replacement, deletion under both `drop_empty` policies, and
  new-address addition; ordering; duplicate-address visible-wins;
  `whole_cell_code` + `split_tokens` codec modes; legend-group recomputation

  the compact `[*row_keys, column_key, value]` shape (not the canonical `code`

* `tests/integration/pipeline/test_compact_multiaxis_scoped_recomposition_carrier.py`
