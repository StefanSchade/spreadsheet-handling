[[capability]]
== Exact public capability

GX-2 adds two public, directional pipeline composites in the existing
`grouped_xref` package, wrapping *unchanged* XRef plus the accepted GX-1
primitives:

* `contract_grouped_xref` -- canonical relation -> (unchanged `contract_xref`) ->
  private flat canonical-string matrix -> (GX-1 `build_grouped_header`) ->
  *published grouped-matrix representation* (flat matrix + `GroupedHeader`).
* `expand_grouped_xref` -- grouped-matrix representation -> (GX-1
  `restore_flat_matrix`) -> private flat canonical-string matrix -> (unchanged
  `expand_xref`) -> canonical relation.

GX-2 is the *public-surface slice*: it applies the YAML/registry gate, closes the
Slice 2 F-1 follow-up, and adds a user guide entry and a release note. It does
*not* begin XLSX/ODS carrier work (GX-3/GX-4), touch rendering/IR, alter XRef, the
Slice 1 resolver, the Slice 2 flat steps, or the accepted GX-1 primitives.

[[representation]]
== Runtime representation (question 1)

*Decision: GX-2 publishes a dedicated feature-owned grouped-matrix carrier --
call it `GroupedMatrix` -- that bundles the flat canonical-string DataFrame and
its `GroupedHeader` descriptor as a single Frames value under the composite's
`output` name.* This is the smallest honest embodiment, at the Frames boundary,
of the architecture's "grouped matrix representation = flat DataFrame +
`GroupedHeader` descriptor" (architecture section 2/3).

[source,python]
----
# grouped_xref/matrix.py  (illustrative, not final code)

@dataclass(frozen=True, eq=False)
class GroupedMatrix:
    """Opaque Frames-boundary carrier: a flat canonical matrix + its descriptor.

    Built only by contract_grouped_xref; unwrapped only by expand_grouped_xref
    and (later) the GX-3/GX-4 carriers. It is a *carrier*, not a value object:
    it deliberately does NOT claim value-equality or hashability, because it
    holds a mutable pandas DataFrame (identical to how Frames already hold
    mutable DataFrames as values).
    """
    frame: pd.DataFrame        # flat, canonical-string headers (contract_xref output)
    header: GroupedHeader      # the trusted, immutable GX-1 descriptor
----

Why this over the assessed alternatives:

[cols="1,3",options="header"]
|===
| Candidate | Assessment

| Dedicated grouped-matrix carrier value (chosen)
| One Frames value; frame+descriptor are trusted-by-construction (solves the
  pairing question, <<pairing>>). Consumable later by GX-3/GX-4 (they unwrap it
  to drive the header grid) and reversible by `expand_grouped_xref`.

| Feature-owned Frames entry + descriptor sidecar frame
| *Rejected.* A sidecar under a magic name (e.g. `output + "::grouped_header"`)
  reintroduces name-coupled mispairing (GX1-A-M2 at the Frames level), pollutes
  the frames namespace with a non-DataFrame value, and has no trusted pairing.

| Structured wrapper / opaque pair held in one Frames value
| *This is the chosen option* -- `GroupedMatrix` is exactly "an opaque pair held
  in one Frames value".

| Transient `_meta`
| *Rejected by task constraint and on merit.* The descriptor is not run-local
  scheduling state; storing it in generic `_meta` for convenience is prohibited.

| New durable domain representation / persisted mapping
| *Rejected.* No resolved mapping is persisted (architecture section 9); header
  depth is configured, not persisted.
|===

The honesty caveat the GX-1 confirmation raised -- *do not freeze a DataFrame
into a value object claiming immutability/hashability/value-equality* -- is
respected: `GroupedMatrix` is an *opaque carrier* with identity semantics
(`eq=False`, no value hash), mirroring how a bare DataFrame already lives as a
mutable Frames value. This does *not* contradict the GX-1 decision to keep the
DataFrame out of the frozen descriptor: the descriptor
(`GroupedHeader`) stays a pure frozen value object; `GroupedMatrix` is a separate,
GX-2-owned Frames-boundary carrier, not a second identity model. `pandas.MultiIndex`
is still never the source of truth.

Within GX-2 no other step consumes `output`; the carrier is produced by the
forward and consumed by the inverse only. GX-3/GX-4 later teach the render/carrier
path to unwrap it -- a natural, additive extension, not a GX-2 obligation.

[[pairing]]
== Pairing solution (questions 4, 12)

*The `GroupedMatrix` carrier is the pairing solution.* GX1-A-M2 (the GX-1 inverse
trusts the descriptor and ignores the paired frame's own labels, so a mispaired
same-width frame is silently relabelled) is closed *structurally*:

* `contract_grouped_xref` is the *only* producer of a `GroupedMatrix`; it builds
  the frame and descriptor together from one resolution and one `contract_xref`
  output, so they are a trusted pair by construction.
* `expand_grouped_xref` reads the pair from `frames[matrix]`; *it exposes no
  descriptor parameter*, so a caller cannot supply a descriptor paired with a
  foreign frame. The mispairing path GX1-A-M2 probed is unreachable through the
  public composite surface.
* The only way to mispair is to hand-construct a `GroupedMatrix` with a
  mismatched frame/header in-process -- arbitrary hostile in-process Python, which
  Domain Boundary Robustness level 4 places out of scope.

This satisfies the policy "do not rely only on developer discipline if the public
API allows arbitrary mispairing": the public API *does not* allow mispairing.

*GX-1 hardening decision (question 12): no GX-1 runtime change is required, and
none should be made in GX-2.* The wrapper pairing fully solves GX1-A-M2. The cheap
row-key `(position, label)` cross-check that acceptance noted as *available* would
(a) not catch pure dynamic-column reordering anyway, (b) go beyond the accepted,
frozen GX-1 count-only contract, and (c) add a runtime change to an accepted slice
for a hazard the wrapper already makes unreachable. It is explicitly declined. No
redundant canonical keys are added to `GroupedHeader`. `expand_grouped_xref` must
still validate that `frames[matrix]` *is* a `GroupedMatrix` (type check ->
`GroupedXrefError`), so a non-grouped or foreign frame under `matrix` fails
cleanly rather than reaching `restore_flat_matrix`.

== Exact public signatures (question 5)

Confirmed, refined from architecture section 6 to expose only genuinely required
parameters and to avoid misleading symmetry (contract-only vs expand-only XRef
parameters are kept asymmetric, exactly as the underlying primitives are).

[source,python]
----
def contract_grouped_xref(
    frames, *,
    relation: str,                       # canonical relation frame name (in)
    output: str,                         # grouped-matrix frame name (out)
    row_keys: str | Iterable[Any],       # -> contract_xref AND build_grouped_header
    source_frame: str,                   # -> AxisMappingIntent (live source)
    key_column: str,                     # -> AxisMappingIntent
    label_columns: Iterable[str],        # -> AxisMappingIntent (arity N)
    column_key: str = "column_key",      # -> contract_xref (relation axis-id col)
    value: str = "value",                # -> contract_xref
    column_keys: Iterable[Any] | None = None,   # -> contract_xref
    dense_axes: Mapping[str, Any] | None = None, # -> contract_xref
    fill_value: Any = "",                # -> contract_xref
    level_names: Iterable[str] | None = None,    # -> build_grouped_header (default label_columns)
    order_policy: Any = "source_row",    # -> resolver
    order_columns: Iterable[Any] = (),   # -> resolver
    drop_source: bool = False,
    name: str | None = None,             # -> contract_xref config id
) -> Frames: ...

def expand_grouped_xref(
    frames, *,
    matrix: str,                         # grouped-matrix frame name (in)
    output: str,                         # canonical relation frame name (out)
    row_keys: str | Iterable[Any],       # -> expand_xref
    source_frame: str,                   # -> AxisMappingIntent (live source)
    key_column: str,                     # -> AxisMappingIntent
    label_columns: Iterable[str],        # -> AxisMappingIntent (arity N)
    column_key: str = "column_key",      # -> expand_xref
    value: str = "value",                # -> expand_xref
    value_columns: Iterable[Any] | None = None,  # -> expand_xref
    base_relation: str | None = None,    # -> expand_xref
    order_policy: Any = "source_row",    # -> resolver
    order_columns: Iterable[Any] = (),   # -> resolver
    drop_source: bool = False,
    name: str | None = None,             # -> expand_xref config id
) -> Frames: ...
----

Parameter dispositions:

* *Forwarded XRef parameters, unchanged semantics:* `row_keys`, `column_key`,
  `value`, `column_keys` (contract), `value_columns` (expand), `dense_axes`
  (contract), `fill_value` (contract), `base_relation` (expand). `drop_empty` is
  *not* exposed: the grouped roundtrip contracts a fresh matrix each run and the
  fill/empty policy is an XRef flat-path concern; omit it unless GX-3/GX-4 prove a
  need (avoid unused symmetry).
* *Axis-mapping parameters:* `source_frame`, `key_column`, `label_columns`
  (arity N; note the *plural* -- unlike Slice 2's flat single `label_column`),
  `level_names`, `order_policy`, `order_columns`. These build one
  `AxisMappingIntent` per call.
* *Defaults stated exactly:* `column_key="column_key"`, `value="value"`,
  `column_keys=None`, `dense_axes=None`, `fill_value=""`, `value_columns=None`,
  `base_relation=None`, `level_names=None` (-> `mapping.label_columns`),
  `order_policy="source_row"`, `order_columns=()`, `drop_source=False`,
  `name=None`.
* *No mode-heavy unified API; no descriptor parameter on the inverse* (pairing).
* Slice 2's `project_axis_labels` / `restore_axis_keys` stay unchanged and remain
  the correct choice when no grouping is wanted.

[[composition]]
== XRef composition (question 2)

*GX-2 calls the existing public `contract_xref` / `expand_xref` and the public
GX-1 primitives; it factors no new helper and duplicates no XRef logic.*

Forward `contract_grouped_xref`:

. validate composite parameters and the `relation` frame at ingress (reuse the
  Slice 2 `_prepare`-style precheck: `relation`/`output`/`column_key` non-empty
  strings, distinct output under `drop_source`, relation present and physically
  valid);
. `interim = contract_xref(frames, relation=relation, output=output,
  row_keys=row_keys, column_key=column_key, value=value, column_keys=column_keys,
  dense_axes=dense_axes, fill_value=fill_value, drop_source=drop_source,
  name=name)` -- the flat matrix is `interim[output]`, a *component of the
  representation*, never a separately addressable published frame;
. resolve the mapping *once* from the live `frames` with `used_keys` = the
  matrix's dynamic (non-row-key) headers (<<resolution>>);
. `header = build_grouped_header(interim[output], row_keys=row_keys,
  mapping=mapping, level_names=level_names)`;
. publish: `out = dict(interim); out[output] = GroupedMatrix(frame=interim[output],
  header=header)`. `interim` already carries the XRef `_meta` and (under
  `drop_source`) the relation cleanup mark, both produced atomically inside the
  discardable copy.

Inverse `expand_grouped_xref`:

. validate parameters; require `frames[matrix]` to be a `GroupedMatrix`
  (`GroupedXrefError` otherwise);
. resolve the mapping *once* from the live `frames` (no `used_keys`; per-tuple
  completeness is enforced by `key_for_labels`);
. `flat = restore_flat_matrix(gm.frame, gm.header, mapping=mapping)`;
. `interim = dict(frames); interim[matrix] = flat` -- rebind the *real* `matrix`
  name locally to the unwrapped flat DataFrame, so no private frame name is ever
  created;
. `result = expand_xref(interim, matrix=matrix, output=output, row_keys=row_keys,
  column_key=column_key, value=value, value_columns=value_columns,
  base_relation=base_relation, drop_source=drop_source, name=name)`;
. if `drop_source` is false, restore the grouped representation:
  `result[matrix] = gm` (keep the wrapper, not the transient unwrapped frame).

Private-frame handling (question 2 requirements):

* *Never leaks:* the flat matrix is only ever the wrapper's `frame` field
  (forward) or a local rebinding of the real `matrix` name (inverse). No
  throwaway frame name is introduced, so nothing private can appear in the
  returned Frames or in `_meta.xref_crosstable`.
* *Never collides with user frames:* GX-2 uses only the caller-supplied `output`
  / `matrix` names.
* *Never partially published on failure:* both directions operate on the copied
  dict returned by `contract_xref` / `expand_xref` (each does `dict(frames)`
  internally) and build the wrapper before the final assignment (<<atomicity>>).

[[resolution]]
== Mapping resolution (question 3, honours GX1-A-M1)

* *Exact `AxisMappingIntent`:* `AxisMappingIntent(source_frame=source_frame,
  key_column=key_column, label_columns=tuple(label_columns),
  order_policy=_order_policy(order_policy), order_columns=order_columns)`.
  `label_columns` is arity N (plural), the grouped generalization of Slice 2's
  one-element intent.
* *Resolved once per call, both directions* (GX1-A-M1 / GX1-M1). GX-2 owns the
  single `resolve_axis_mapping` call and hands the immutable `ResolvedAxisMapping`
  to GX-1; GX-1 never resolves (verified: `grouped_xref` imports only
  `ResolvedAxisMapping`).
* *`used_keys` completeness on forward:* pass the matrix's dynamic headers (the
  canonical keys that become grouped columns) as `used_keys`, so a used canonical
  key missing from the source fails *before* any publication -- the tightest
  completeness check. (`build_grouped_header` also rejects unknown keys via
  `labels_for_key`; `used_keys` makes the completeness guarantee explicit and
  owned by the composite, as the confirmation requires.)
* *Reverse resolution:* re-resolve from the live source; `restore_flat_matrix`
  rejects unknown / wrong-arity / incomplete / duplicate visible tuples via
  `key_for_labels`.
* *Conditional bijection across separate runs:* forward and inverse are exactly
  invertible when both resolve the *same* key/label bijection from the *same*
  live source frame and intent (identical to Slice 2). A changed or absent source
  frame breaks losslessness -- declared as `conditionally_bijective` in the
  registry with that reason.
* *Diagnostics on source-mapping drift:* an absent source frame -> resolver
  "source frame was not found"; a used key dropped from the source -> "used
  canonical axis key(s) ... are missing"; a visible tuple whose components changed
  -> `key_for_labels` "unknown complete visible label tuple". Non-guessing
  throughout.
* *No resolved mapping is persisted* (architecture section 9).

[[metadata]]
== Metadata and `name` contract (question 6)

* *Grouped composites expose `name`*, forwarded verbatim to the internal
  `contract_xref` / `expand_xref`, where it becomes the XRef `config_id`
  (`name or relation` on contract, `name or output` on expand -- unchanged XRef
  behaviour).
* *XRef metadata describes only the internal flat XRef operation*, never the
  grouped composite. `_meta.xref_crosstable.<config_id>` is written by unchanged
  XRef exactly as today; grouped-XRef adds nothing to it and repurposes none of
  its facets (architecture section 9). *Metadata ownership remains entirely
  XRef-owned.*
* *No temporary/private name can leak into `_meta`:* because the internal
  `contract_xref` writes `output` as its `matrix` (the composite's real public
  name) and the inverse rebinds the real `matrix` name, the `_meta` payload only
  ever references caller-supplied names. Verified live: `contract_xref` with
  `output="mtx"` wrote `_meta.xref_crosstable["rel"]` with `matrix="mtx"` and left
  the caller frames and `_meta` untouched.
* *Inverse finds the correct existing XRef config* the same way flat XRef does --
  via a forwarded `name`. A basic grouped roundtrip does *not* require the config
  (`expand_xref` infers `value_columns` from the matrix columns); the config only
  carries dense-axis intent, exactly as in flat XRef.
* *No new grouped-XRef metadata root* -- not proven necessary.

[[dropsource]]
== `drop_source` contract (question 7)

* *Forward:* `drop_source=True` asserts the grouped matrix supersedes the
  `relation`. GX-2 forwards `drop_source` to the internal `contract_xref`, which
  applies its existing value-loss guards (relation must contain no fields beyond
  `row_keys + column_key + value`; matrix columns must cover every relation column
  key) and marks the *relation* for cleanup. Grouping only relabels headers, so
  XRef's value-loss profile is exactly correct -- no separate grouped value-loss
  guard is needed, and duplicating one would be wrong.
* *Inverse:* `drop_source=True` asserts the expanded relation supersedes the
  grouped matrix. GX-2 forwards `drop_source` to the internal `expand_xref`, which
  marks the *`matrix`* name for cleanup (its existing guard rejects an explicit
  `value_columns` subset that would strand matrix columns).
* *Source/output distinction:* `drop_source and relation == output` (forward) /
  `matrix == output` (inverse) is rejected at ingress before any work, mirroring
  Slice 2 and XRef.
* *Cleanup marking only after complete success:* the cleanup mark is written by
  the internal primitive *into the discardable copied dict*; GX-2 publishes it
  only after the grouped projection succeeds. A failure after `contract_xref`
  discards the whole copy, mark included (<<atomicity>>).
* *No private frame marking:* the marked frame is always the caller's `relation` /
  `matrix` name, never a private frame.
* *Compatible with XRef's own cleanup behaviour:* GX-2 reuses `mark_frames_for_cleanup`
  transitively through the primitives; it adds no second cleanup mechanism.

[[atomicity]]
== Atomicity (question 10)

*Build-then-publish holds without a bespoke transaction, because the internal
primitives already return copied Frames.* Verified live: `contract_xref` does
`out = dict(frames)`, builds a fresh matrix, writes `_meta`, and returns a *new*
dict; the caller's `frames` and `_meta` are untouched. `expand_xref` behaves the
same.

Consequently:

* *Forward:* `resolve_axis_mapping` (read-only) and `build_grouped_header`
  (read-only, build-then-return) run *after* `contract_xref` on its discardable
  `interim` copy. A failure at resolution or header build simply discards
  `interim` and raises -- leaving *no* private output frame, *no* private XRef
  `_meta`, *no* cleanup command, and the caller's Frames/`_meta` unchanged. The
  wrapper is assigned only on the last line, after everything succeeds.
* *Inverse:* `resolve_axis_mapping` and `restore_flat_matrix` run *before* the
  `interim` rebinding and the `expand_xref` call; a failure there mutates nothing.
  `expand_xref` builds its own copy, so its failure leaves the caller untouched.
* The task's stated failure point -- "after `contract_xref` but before grouped
  publication" -- is exactly the resolution/`build_grouped_header` window on the
  discardable copy: it leaves no private frame, no private XRef metadata, no
  cleanup command, and caller Frames/`_meta` unchanged. *Confirmed.*

GX-2 must not pre-mutate the caller's `frames`, must resolve/build before the
final wrapper assignment, and must never forward a partially built dict.

[[validation-diagnostics]]
== Validation and diagnostics (question 11)

* *Feature-owned error type:* a `GroupedXrefError` (a `ValueError` subclass,
  mirroring `AxisMappingError` / `GroupedHeaderError`) for composite-owned
  failures: missing/invalid composite parameters, `frames[matrix]` not a
  `GroupedMatrix`, output collisions, `drop_source` with `relation == output` /
  `matrix == output`.
* *Do not wrap deliberate domain errors:* resolver failures stay
  `AxisMappingError`; GX-1 header/tuple failures stay `GroupedHeaderError`; XRef
  failures stay `ValueError` from XRef. Wrap only where additional composite
  context is genuinely needed (e.g. relabelling "frame not found" for the grouped
  `matrix` input). Reuse the safe-diagnostic discipline (constant detail; never
  execute a rejected value's `repr`/`type`/`hash`/`eq`/iteration).

=== Minor

* *GX2-C-M1 (roundtrip fixture must be dense).* A *sparse* canonical relation does
  not survive `contract_grouped_xref -> expand_grouped_xref` unchanged, because

  DataFrame; it must *not* be a frozen value object claiming value-equality /

  (`eq=False`, no value hash), and test that it is not treated as a hashable value
  object.
* *GX2-C-M3 (F-1 guard generality).* Prefer one data-driven
  registered-parameters-match-signature guard over the whole `frames_target`
  family; if a fully generic sweep trips a pre-existing entry, scope it to the
  axis/grouped/compact family rather than weakening the assertion. *Action:*
  implement the reusable form; do not duplicate a per-step guard.

* *GX2-C-O1.* GX-2 introduces exactly one new public type (`GroupedMatrix`); the

* *GX2-C-O2.* The inverse's "rebind the real `matrix` name to the unwrapped flat
