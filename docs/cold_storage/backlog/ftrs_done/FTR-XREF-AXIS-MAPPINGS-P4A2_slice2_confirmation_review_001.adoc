== Dependencies on Slice 1

Slice 2 depends only on the accepted internal package
`spreadsheet_handling.domain.transformations.xref_axis_mapping` and its public
symbols:

* `AxisMappingIntent`, `AxisOrderPolicy` -- to declare the source frame, key
  column, single label column, and ordering policy;
* `resolve_axis_mapping(frames, intent, *, used_keys=...)` -- to resolve the
  ordered, immutable, bijective mapping from live source frames, with completeness
  checked against the relation's actually-used axis keys;
* `ResolvedAxisMapping.labels_for_key` (outbound) and
  `ResolvedAxisMapping.key_for_labels` (inbound) -- for exact forward/inverse
  substitution;
* `AxisMappingError` -- the deliberate diagnostic already carrying
  frame/row/role/column context.

The resolver is pure, read-only, returns no Frames, and writes no metadata; it
already fails atomically before returning. Slice 2 is a genuine *second*
in-repo consumer of this resolver, but it consumes the resolver's public API --
it does *not* re-implement the exact-string, exact-tuple, safe-diagnostic, or
NumPy-integer contracts, so no helper extraction is triggered (see robustness
review below).

Slice 2 also legitimately reuses the already-shared physical-table boundary
helpers in `spreadsheet_handling.domain.tabular`
(`ensure_unique_physical_column_labels`, `ensure_unique_field_declaration`) for
its own parameter/frame validation, consistent with their existing multi-consumer
status.

== Validation / ownership / diagnostic / atomicity contract

Under the accepted Domain Boundary Robustness policy (level-2 competent-user
workflow input at the transform boundary; the resolver already owns value-level
validation):

* *Validate at ingress, simplify internally.* Validate the transform's own
  parameters (frame names, `column_key`, output name, `drop_source` collisions)
  and the relation's physical labels via the shared `domain/tabular` helper.
  Delegate all axis-value validation (exact strings, ordering vocabulary,
  bijection, arity) to `resolve_axis_mapping`. Do not re-defend the value object
  model a second time.
* *Ownership.* Copy the Frames mapping; produce a new output DataFrame; never
  mutate input frames or the caller's mapping (respect pandas copy semantics).
  Resolved values returned by the resolver are already exact built-in strings.
* *Diagnostics.* Raise feature-specific errors (reuse `AxisMappingError` or a
  thin projection-local subclass) carrying frame/column/row context. Do not run
  a rejected value's `repr`/type/hash/eq/iteration merely to describe it; a
  constant type detail plus surrounding context is the accepted pattern.
* *Atomicity (scope: Frames dict, the output DataFrame, and `_meta`).* Resolve
  the full mapping and validate every used key/label *before* assigning the
  output frame. On any failure, publish no partial output frame, no partial
  substitution, and no `_meta` mutation. The promise is not extended to
  arbitrary caller iterator side effects (consistent with Slice 1's scoped
  promise).
* *No fake sandbox.* Add no hostile-object introspection beyond what the
  resolver already performs; hostile in-process Python is a level-4 non-goal.

== Adversarial correctness obligations vs. out-of-scope hostile cases

*Explicit correctness obligations (must be tested and must fail cleanly):*

* outbound: a canonical key present in the relation's axis column but missing
  from the mapping source fails (resolver `used_keys` completeness);
* inbound: a visible label present in the expanded relation but not resolvable to
  a canonical key fails (`key_for_labels` "unknown complete visible label
  tuple");
* duplicate source keys, duplicate complete labels, wrong arity, empty labels,
  and invalid ordering data fail before any output frame is published
  (resolver);
* a missing/absent source frame fails rather than trusting stale or visible
  text;
* exact flat-string roundtrip identity is preserved end to end (see tests).

*Out of scope (do not expand the threat model):* arbitrary hostile in-process
objects beyond the resolver's narrow value contract; multi-level tuple handling;
grouped-header carrier attacks. Report a genuine violation of an explicit
guarantee (atomicity, non-mutation, exact identity, deterministic order) if a
probe finds one -- that remains a correctness finding, not threat-model
expansion.

== Failure-atomicity scope required

The output Frames mapping, the substituted output DataFrame, and `_meta` must
never be partially published on failure. Because the resolver raises before
returning and the transform assigns `out[output]` only after successful full
substitution, atomicity is achievable by construction (build-then-publish). This
must be asserted by a focused test (a failing key/label leaves the input frames
and `_meta` unchanged and creates no output frame).

== Shared-helper (semantic DRY) assessment

No new shared helper is justified by Slice 2. Slice 2 consumes the Slice 1
resolver through its public API; it does not duplicate the exact-string,
exact-tuple, safe-diagnostic-detail, or exact-NumPy-integer contracts, so the
robustness policy's "two genuine consumers of the same accepted/rejected
vocabulary, normalization, ownership, diagnostics, and layer" bar is not met for
any new extraction. Reuse of the existing multi-consumer `domain/tabular`
physical-label helpers is legitimate and is *not* a new extraction. Validation
that is specific to axis projection stays feature-local.

== Settled design decisions (implementation contract)

The FTR left two decisions open; both are settled here so the implementation
agent does not re-litigate them. Final public names are confirmable at the
acceptance gate (low risk).

. *Output model: source-to-output.* Each transform takes an input relation and
  writes a distinct `output` frame, with an optional `drop_source`, matching
  `contract_xref` / `expand_xref` and `compact_multiaxis`. Not in-place.
. *Recommended names and parameter shape:*
+
[source,text]
----
project_axis_labels(               # outbound: canonical keys -> visible labels
    frames, *,
    relation,                      # input relation frame (canonical keys)
    output,                        # output relation frame (visible labels)
    source_frame, key_column, label_column,   # -> AxisMappingIntent (arity 1)
    order_policy="source_row", order_columns=(),
    column_key="column_key",       # relation column holding axis identity
    drop_source=False, name=None,
)

restore_axis_keys(                 # inbound: visible labels -> canonical keys
    frames, *,
    relation,                      # input relation frame (visible labels)
    output,                        # output relation frame (canonical keys)
    source_frame, key_column, label_column,
    order_policy="source_row", order_columns=(),
    column_key="column_key",
    drop_source=False, name=None,
)
----
+
Both build one `AxisMappingIntent` with `label_columns=(label_column,)`, call
`resolve_axis_mapping` with `used_keys` = the distinct axis-column values
(outbound) or with the relation's labels checked via `key_for_labels`
(inbound), then substitute. `_meta` is passed through untouched.

== Recommended implementation sequence

. Implement outbound (`project_axis_labels`): resolve, completeness-check used

. Implement inbound (`restore_axis_keys`): resolve, substitute label ->

. Add focused unit tests (substitution, pure Frames roundtrip, failures,
  ownership/atomicity, `_meta` pass-through).
. Register both steps in `registry.py` and add symmetric

. Add the XLSX and ODS flat-string roundtrip integration test.
. Add the user-guide catalog entry and the release-note bullet; run the full
  suite, ruff, source-style guard, and Asciidoctor.

== Findings

=== Blocking

None.

=== Important

* *I-1 (design decision to settle, not a defect).* The FTR leaves public names
  and in-place-versus-output open. Left unsettled, an implementation agent could
  re-open design mid-slice. *Resolved in this review* by settling source-to-output
  and the recommended names/parameter shape; the acceptance gate confirms final
  names. No FTR edit is required.

=== Minor

* *M-1.* Slice 2 must consciously *not* introduce a persisted mapping `_meta`
  root; doing so would silently drag in meta-registry, persistence-boundary, and
  schema-maintenance obligations the FTR defers to a separate gated slice. The
  contract above makes `_meta` pass-through explicit.
* *M-2.* `SOURCE_ROW` ordering is deterministic only relative to caller-supplied
  row order (recorded residual risk in acceptance review 003). Slice 2 does not
  need to change this, but its public parameter documentation should state that
  ordering follows the resolver's declared policy rather than promising a
  serialized ordering vocabulary (that remains a later decision).

=== Observations

* The `compact_multiaxis` composite is a close and current structural precedent
  (composes XRef primitives, copies Frames, keeps intermediates out of persisted
  metadata, registered symmetrically). Following it will keep Slice 2 idiomatic.
* Slice 2 is comfortably sized for one implementation context and one acceptance
  gate: two single-purpose transforms, flat one-level only, no new metadata, no
  new carrier behavior beyond proving existing flat-string roundtrip.
