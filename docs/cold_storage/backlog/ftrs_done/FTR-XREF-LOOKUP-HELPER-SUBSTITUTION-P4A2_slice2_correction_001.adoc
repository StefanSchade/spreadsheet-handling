== 3. Exact declaration-bound guard contract

`apply_derived_column_policy` and `validate_references`'s `no_helper_columns`
rule read the *same* durable declaration,
`_meta.sheets.<visible-sheet>.helper_columns`. The guard is therefore a
*declaration-bound cleanup postcondition, not a declaration-completeness check*.

Declaration present (`helper_columns: [title]`):

* cleanup removes `title`;
* the guard *fails* before cleanup while the declared helper remains and *passes*
  after successful cleanup;
* the guard catches an omitted or ineffective cleanup that leaves a *declared*
  helper behind.

Declaration absent or mistyped:

* Core does not infer `title` by name; cleanup obtains an empty helper set and
  does nothing;
* the guard *also* obtains an empty helper set, reports no finding, and *passes*;
* `title` survives and the state is unsafe for the inverse though the guard
  passed.

Because both steps bind to the same declaration, pairing the drop with
`no_helper_columns` cannot detect a missing declaration.

== 4. Missing-declaration drop-plus-guard result

`test_no_helper_columns_guard_cannot_detect_omitted_declaration` runs the exact
documented sequence with the declaration omitted, through public config-built
steps and a real XLSX roundtrip:

* durable helper list absent/empty after readback;
* transient `_meta.derived` absent (and not recreated by cleanup);
* `apply_derived_column_policy(source="Matrix View", policy=drop)` is a no-op —
  `title` survives (no name inference);
* `validate_references(mode=fail, no_helper_columns on "Matrix View")` *passes*
  (does not raise) while `title` is still present;
* the same rule under `mode=warn` emits an empty findings frame;
* the surviving unclassified `title` is then melted into `character_name` by
  `expand_xref`, proving the unguarded state is genuinely unsafe.

This is recorded as a negative contract test of the current limitation, not a
desired safety outcome.

== 6. Selected orchestration entry point

`spreadsheet_handling.application.orchestrator.orchestrate(input=, output=,
steps=)` — the maintained application entry point used by `sheets-run` and the
existing orchestrator persistence-boundary integration tests. It loads frames
from the input backend, runs the configured steps, applies the orchestrator-owned
persistence-boundary projection, and writes the output backend. Because
`orchestrate()` owns one configured direction per invocation, the forward and
reverse directions are two invocations connected by a real XLSX carrier — an
arrangement the review explicitly permits. No test-only orchestration wrapper was
invented; the convention mirrors
`tests/integration/pipeline/test_orchestrator_persistence_boundary.py`.

/ loader routing (`ExcelBackend`). One backend is sufficient for the macro-flow
proof; direct Slice-2 tests already prove XLSX and ODS parity.

Edit: a *physical workbook-cell edit* between export and import — `openpyxl`

carrier read-in state is then independently inspected (public backend read)
before the reverse orchestration runs.
