= GX-4 Acceptance Review 001: ODS Grouped Workbook Carrier
:revdate: 2026-08-01

Independent acceptance review of GX-4, the ODS adapter implementation of the
accepted exact-header / `GroupedMatrix` workbook contract. Reviewed commits:
`8d9761b` (runtime and tests) and `1a6f067` (implementation review and release
note). The supplied `git show` material was the primary review evidence and was
verified against the repository read-only. No runtime or test change was made by
this review. GX-1, GX-2, GX-3a, and GX-3b were treated as accepted foundations;
GX-5 was out of scope.

== Verdict

*GX-4 is accepted.* The ODS adapter faithfully implements the accepted
backend-neutral contract:

* configured-depth exact header reads are explicitly opt-in;
* `TableBlock.header_grid` carries the exact ODS header cells without delimiter
  encoding;
* `workbookir_to_frames` publishes the existing `core.ExactTable` carrier;
* the unchanged `reconstruct_grouped_matrix` and `expand_grouped_xref` path
  restores the canonical relation;
* the ordinary ODS read path and all protected surfaces remain unchanged.

No blocking or important finding was identified. One minor test-evidence gap is
recorded; independent probes confirmed the corresponding runtime behavior, so it
does not block acceptance.

== Key conclusions

=== ODS exact-header parser

For a configured sheet, the configured depth bypasses merge-based inference and
sets the first data row directly below that depth. Column width is measured from
the leaf header row, so blank upper row-key cells cannot truncate the table.
Header reads use the existing bounded `ParsedTable` grid and `_grid_value` merge
resolution: merged or spanned cells resolve to their master value, ordinary
blanks remain `""`, repeated unmerged labels remain repeated, and literal
`" / "` text remains literal. The exact path performs no join, split, or hidden
delimiter encoding.

=== Legacy compatibility

The feature is opt-in through `exact_header_depths`, either directly on the ODS
parser or through `options.extra["exact_header_depths"]` on `OdsBackend`. With no
configured depths, the backend supplies the unmodified parser callable and the
parser follows the legacy table branch. Empty mappings are no-ops; malformed
non-positive or non-integer values fail under the same validation contract as
XLSX. Ordinary ODS reading continues to return the legacy DataFrame projection.

=== Backend seam

The ODS option seam mirrors the accepted XLSX implementation. ODS-specific work
ends at the neutral `TableBlock.header_grid`; the shared projection produces the
existing `ExactTable`, and only the existing grouped domain step interprets it.
No grouped-XRef domain semantics are duplicated in the adapter. No new carrier,
registry surface, pipeline step, metadata expansion, or writer path was added.

=== End-to-end losslessness

The reviewed integration path is:

[source,text]
----
GroupedMatrix
-> compose_workbook
-> ODS
-> parse_workbook(exact_header_depths)
-> ExactTable
-> reconstruct_grouped_matrix
-> expand_grouped_xref
-> canonical relation
----

The tests reproduce the canonical relation after an untouched roundtrip and
also cover an edited data value, dynamic-column reorder, valid dynamic-column
deletion, and arity three. Parser-level tests separately prove repeated and
merged labels, blank row-key uppers, and literal delimiter preservation. The
accepted reconstruction path never derives identity from merge geometry or a
flattened header string.

=== Layering

The runtime hand-off remains rendering -> `io_backends` -> shared exact-table
projection -> `domain.grouped_xref`. The ODS adapter imports the generic
spreadsheet contract and rendering IR, while grouped-domain modules import
neither rendering nor I/O backends. `core.ExactTable` remains leaf-only. No
forbidden dependency direction or import cycle was introduced.

=== Protected surfaces

The two-commit delta contains no runtime modification to GX-1, GX-2, GX-3a,
GX-3b, `xref_crosstable`, `xref_axis_mapping`, persistence, schema maintenance,
application, CLI, or XLSX. Architecture and regression validation confirms those
surfaces remain green. GX-4 does not reopen any accepted decision.

=== Documentation

The GX-4 implementation review accurately describes the runtime: configured

remain unchanged without the gate. The release-note update accurately records
grouped workbook carriers for XLSX and ODS and closes the earlier consolidated
release-note checkpoint. It does not claim or begin GX-5 functionality.
