less-trusted-protected; `load_app_config`'s table row is unchanged from the
original and continues to state loading an untrusted file "does not make its
I/O descriptors E7-safe." E7 scope was not expanded into top-level I/O/sink
authorization anywhere in the diff.

*M-2 RESOLVED.*

Responsibility split after the correction: `pipeline.build` performs
description authorization and `BoundStep` construction;
`application.orchestrator` executes already-bound steps and is unaware of

`AppConfig.pipeline` (now explicitly through an authorized builder call) and
then invokes the unchanged `orchestrate`. The correction removes a proposed
API surface (`orchestrate(step_specs=..., description_authorization=...)`)
and does not add a replacement convenience wrapper; the documented
composition (`build_steps_from_config(...) ` then `orchestrate(steps=...)`)
uses only entry points the design (and, for `orchestrate`/`build_steps_from_
config`, the current unmodified source) already exposes.

*NO REPLACEMENT PUBLIC-SURFACE EXPANSION.*
