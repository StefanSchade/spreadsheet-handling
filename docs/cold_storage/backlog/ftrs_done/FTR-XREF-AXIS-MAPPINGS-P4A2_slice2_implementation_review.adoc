== Verification against the confirmation contract

=== Exact implementation vs. contract

* *Public names / output model:* settled `project_axis_labels` /
  `restore_axis_keys`, source-to-output with a distinct `output` frame and
  optional `drop_source`.
* *Flat one-level only:* the intent is built with a single-element
  `label_columns=(label_column,)`, so every resolved label tuple has arity one
  and is unwrapped (`labels_for_key(key)[0]`); inbound wraps each label as a
  one-element tuple (`key_for_labels((value,))`). No tuple/MultiIndex/grouped
  behavior is introduced.
* *Consumes Slice 1 resolver only:* the module calls `resolve_axis_mapping`,
  `labels_for_key`, and `key_for_labels`, and reuses `AxisMappingError`,
  `AxisMappingIntent`, and `AxisOrderPolicy`. It does not re-implement the
  exact-string / exact-tuple / safe-diagnostic / NumPy-integer contracts, so no
  new shared helper is extracted (semantic-DRY bar unmet).

=== Two evidence-driven refinements to the recommended parameter shape

The confirmation review settled names and output model and explicitly noted the
parameter shape was "confirmable at the acceptance gate (low risk)". Two minor
refinements were made because implementation exposed concrete issues; both are
recorded here for the acceptance reviewer:

. *`name` parameter omitted.* The recommended signature listed `name=None` by
  analogy to XRef, where `name` keys a persisted `_meta.xref_crosstable.<id>`
  config. These steps write no feature-owned `_meta`, so `name` would be an
  unused, misleading public parameter. Omitting it keeps the public surface
  honest. This is the only settled-signature deviation.
. *`order_policy` / `order_columns` retained but documented as substitution-
  irrelevant.* They are forwarded to the resolver unchanged, but value
  substitution does not consume member order, so a projection roundtrip is
  identical under both policies. This is documented in the module, the
  user-guide entry, and the registry `notes`, and asserted by
  `test_roundtrip_result_is_order_policy_independent`. `SOURCE_ROW` is
  documented as relative to caller-supplied source-frame row order, with no
  serialized ordering contract, per the task instruction.

Neither refinement re-opens a settled decision; both keep the contract's intent
while removing misleading or unused surface.

=== Ownership and failure atomicity

* *Ownership:* the output frame is `df.copy()` with the substituted column; the
  input relation DataFrame is never mutated in place, and `dict(frames)`
  shallow-copies the mapping. `mark_frames_for_cleanup` copies `_meta` before
  mutating. Verified by `test_inputs_are_not_mutated` and
  `test_drop_source_marks_relation_without_mutating_input_meta`.
* *Build-then-publish atomicity (scope: Frames dict, output DataFrame, `_meta`):*
  the full mapping is resolved and every value substituted (raising on any bad
  key/label) before `_publish` creates the output frame or marks cleanup.
  Verified by `test_failure_publishes_no_output_frame` (an unknown key leaves the
  frame set unchanged and creates no output frame). Arbitrary caller-iterator
  side effects remain outside the promise, consistent with Slice 1.
