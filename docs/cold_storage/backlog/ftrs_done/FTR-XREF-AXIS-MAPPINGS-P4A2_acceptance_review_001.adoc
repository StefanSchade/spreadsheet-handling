= Independent Acceptance Review: XRef Axis Mapping Resolver Slice 1
:revdate: 2026-07-30
:toc:

== Verdict

Slice 1 is not accepted. The ordinary string and scalar paths implement much
of the intended bijection, but three adversarial contract defects remain:
configured ordering accepts a non-transitive comparator, configured field
resolution can map several absent string fields to one unusual physical label,
and accepted `str` subclasses invalidate the claimed diagnostics and effective
immutability. The focused tests do not cover these required cases.

This verdict applies only to the internal pure model and resolver. It does not
judge or request any deferred XRef integration, pipeline, YAML, metadata,
persistence, MultiIndex, rendering, XLSX, or ODS work.

== Model-invariant assessment

For exact built-in strings, the model provides a complete-key/complete-tuple
bijection, arbitrary positive label arity, exact forward and inverse lookup,
contiguous zero-based member positions, and immutable tuple-backed members.
Repeated values at one label level remain valid when complete tuples differ.
Direct construction rejects booleans as positions, negative/non-contiguous
positions, wrong arity, duplicate keys, duplicate complete tuples, malformed
members, and non-tuple member labels.

Lists supplied for Intent field declarations are copied to tuples; generators
are deliberately rejected because declarations require an ordered sequence.
Lists and generators supplied as the Resolution member collection are
materialized to a private tuple. These conversions do not retain mutable
caller-owned containers.

The two mapping proxies have no externally retained mutable backing mapping.
Excluding them from dataclass equality is sound only while keys and labels are
stable values, because both mappings are uniquely derived from `members`.
Finding I-3 shows that the current accepted `str`-subclass domain does not
preserve that premise.

The strings-only identity contract agrees with the reviewed FTR and the
accepted carrier-stable XRef matrix-axis contract. Numeric keys and labels are
correctly rejected. Whitespace-only strings fail; otherwise leading/trailing
whitespace, case, and delimiter text are preserved exactly. No normalization,
stripping, case folding, concatenation, or delimiter parsing occurs.

== Ordering assessment

`SOURCE_ROW` is used only when explicitly selected. It is stable relative to
the supplied DataFrame row order and makes no cross-source determinism promise;
callers needing cross-source stability must supply stable row order or select
configured ordering.

`COLUMNS` compares configured fields in declaration order and appends canonical
key as the final tie-breaker. Tied configured values are intentionally valid:
this is correct settled FTR behavior, not a uniqueness requirement or an
undocumented fallback. Empty and singleton mappings resolve correctly, and
ordinary mixed-incomparable values fail deliberately.

The double sort plus adjacent strict-less check is not a proof of a total
order. A cyclic `str` subclass implementing `a < b`, `b < c`, and `c < a`
passed all checks for every one of the six source permutations. The resolver
returned three different rotations for the same records. This is finding I-1.

== Validation, completeness, and atomicity assessment

Ordinary source values are validated before bijection construction and sorting.
The shared physical-label boundary runs before configured-column matching and
positional pandas reads. Missing, non-string, empty, unhashable, and
equality-ambiguous source identities generally receive `AxisMappingError`.

That boundary validates a physical label against itself but does not establish
safe comparison against configured strings. A one-column frame whose hashable,
reflexive physical label compares equal to every string passed the boundary;
`_column_position` then selected that one column as both absent configured
fields `key` and `label`. Resolution incorrectly succeeded as
`"actual" <-> ("actual")`. This is finding I-2.

Used-key completeness is a suitably small later-integration primitive:
missing used keys fail, repetitions are harmless, used keys do not filter the
complete Resolution, a generator is materialized exactly once, and malformed
elements fail deliberately. Argument-shape validation occurs before source
validation; unknown-key completeness is checked only after the complete source
mapping and ordering have validated, which is appropriate.

For normal built-in values the resolver does not assign into the Frames
mapping, source DataFrame, index, columns, `_meta`, or nested caller objects on
success or failure. It constructs private records and returns a new
Resolution. A stateful accepted `str` ordering value nevertheless had its
comparison counter changed from `[0, 0]` to `[3, 5]` during a successful
resolution. This observable caller-graph change belongs to finding I-1's
unrestricted comparator problem and limits the blanket purity claim.

== Test-quality assessment

All 64 focused tests were inspected. Their ordinary bijection, exact matching,
used-key, failure-atomicity, and one-/two-/three-level cases are useful.
The graph checks combine retained identities with deep/frame equality and are
not merely identity assertions.

The suite nevertheless omits direct malformed construction of
`ResolvedAxisMember` and `ResolvedAxisMapping`, cyclic/asymmetric/stateful
comparators, accepted hostile `str` subclasses, and configured-string matching
against unusual physical labels. Its only non-total comparator returns
`False` for every less-than comparison, which the implementation's adjacent
check is specifically able to reject. Thus 90% branch-aware coverage masked
the semantic paths that produced I-1 through I-3.

== Findings

=== Blocking

None.

=== Important

I-1 -- configured ordering accepts non-transitive and stateful comparisons::
The six-permutation cyclic-comparator probe was accepted and produced three
different orders. A successful stateful-comparator probe also changed
caller-owned comparison state. Risk: later projections can emit source-order-
dependent member positions while claiming configured deterministic order, and
the pure/non-mutating claim is not true for accepted values. Restrict order
values to a defensible total-order domain or validate a true total order
without relying on sort observations, then add cyclic, asymmetric,
exception-raising, and stateful regression tests.

I-2 -- physical labels can impersonate multiple configured fields::
The shared boundary accepts a hashable/reflexive unusual scalar label, while
`_column_position` trusts one-way equality with each configured string. One
physical column was therefore selected for both missing configured columns.
Risk: the resolver can construct a plausible but false mapping from the wrong
source data. Establish exact/symmetric safe matching for configured string
fields after the physical boundary and reject ambiguous or non-string aliases.

I-3 -- accepted `str` subclasses break diagnostics and effective immutability::
Overridden `strip` and `repr` methods leaked raw `RuntimeError` from direct
construction and lookup. A mutable-hash `str` used as a member key built a
frozen Resolution successfully, but mutating its hash state made lookup by that
same key fail while lookup by the plain string still succeeded. Risk:
Resolution is not effectively immutable and failures are not consistently
feature-specific. Copy accepted text into exact built-in `str` values or reject
subclasses before calling overridable/hash/equality methods, and cover direct
constructors plus both lookup directions.

I-4 -- focused tests omit the required adversarial semantic branches::
The supplied suite stayed green while I-1 through I-3 reproduced. Risk:
coverage percentage and the current comparator test give false acceptance
confidence. Add direct-constructor, hostile-string, physical-alias, cyclic,
asymmetric, non-transitive, and stateful comparator regressions with assertions
on deliberate exception type and caller-graph state.

=== Minor

M-1 -- physical-label exception translation is over-broad::
`_require_source_frame` catches every `Exception` from
`ensure_unique_physical_column_labels`. A simulated `AssertionError` from the
helper was relabelled as `AxisMappingError`, which can conceal an unrelated
implementation defect. Catch the helper's documented validation exception
instead; separately harden adversarial diagnostic rendering where needed.

=== Observations

* The canonical-key tie-breaker is correct settled behavior and configured
  order-field values need not themselves be unique.
* Complete-tuple uniqueness, repeated individual levels, arbitrary positive
  arity, exact lookup, normal empty/singleton behavior, and used-key
  completeness otherwise match Slice 1.
* Deferred projection, XRef, metadata, persistence, carrier, and grouped-header
  work was not counted as a defect.
