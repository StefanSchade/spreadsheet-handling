== 2. Contract independently reconstructed

Read the FTR (969 lines) and its review (737 lines, including the `3bc46cf`
disposition section 12, verdict *A. ACCEPTED*) in full, independently of the
implementation. The accepted contract:

* General physical-label authority (Class A, `physical_labels.py`) is
  unchanged everywhere a column is not nominated as a selector.
* The moment a physical label is nominated as `row_keys`
  (`contract_xref`/`expand_xref`) or dense-axis
  `rows_from`/`columns_from.key`/`.keys` -- directly, or inherited through

  no list-of-records migration.
* The rejection path must not call `repr`/`str`/equality/hashing/iteration on

* Every current authority layer naming the retired non-string example must be
  atomically corrected in the same commit, preserving the unqualified Class A
  statement.

This matches the implementation's own stated intent (commit message,
docstrings). No divergence between my independent reading and the
implementer's summary was found at the contract level.

== 3. Runtime helper (`primitives.py`)

`_is_durable_selector_reference`: `return type(value) is str and value != ""`
-- exact predicate match, `type(...) is str` (not `isinstance`), confirmed by
direct read and by probe that a `str` subclass and `numpy.str_` both fail
`type(value) is str` while passing `isinstance`.

`_ensure_selector_reference_labels`: builds `invalid_positions` by iterating
and testing `_is_durable_selector_reference`; on failure raises `ValueError`
with only `field_name` and `invalid_positions` (an `int` list) in the message
-- never `value!r}` or any candidate-derived text. Independently confirmed:
calling it directly with a hostile object whose `__repr__`/`__str__`/`__eq__`/
`__hash__`/`__iter__` all raise produces *zero* candidate protocol calls when
invoked in isolation. The helper itself is safe.

== 4. CRITICAL -- the complete pre-gate path (falsification target)

This section is the primary adversarial target the governing review
instructions named. The helper in isolation is safe; the question is whether
anything upstream of it, inside the real `contract_xref`/`expand_xref`/
`_axis_source_config` call chain, touches an unclassified candidate first.

Call order in both `contract_xref` (`operation.py:268-273`) and `expand_xref`
(`operation.py:91-96`):

....
row_key_cols = _as_list(row_keys, "row_keys")
_ensure_flat_axis_labels(row_key_cols, "row_keys")        # isinstance(value, tuple) only
_ensure_unique_field_list(row_key_cols, field_name="row_keys")  # <-- see below
_ensure_selector_reference_labels(row_key_cols, "row_keys")     # the new gate
....

`_ensure_flat_axis_labels` uses `isinstance(value, tuple)` only -- no protocol
calls on a non-tuple candidate. Safe, confirmed by probe.

`_ensure_unique_field_list` aliases `ensure_unique_field_declaration`
(`domain/tabular/physical_labels.py:192-217`), which de-duplicates by walking
the list and calling `_values_equal(value, existing)` (`bool(value == existing)`)
against every element already accepted into a local `seen` list. For a
*single-element* `row_keys` list, `seen` is empty when the sole element is
processed, so the comparison generator is never entered -- zero calls. This is
exactly why the shipped adversarial test
(`test_rejection_never_invokes_hostile_candidate_protocols`, which uses
`row_keys=[bomb]`, a one-element list) reports zero calls: the chosen list
shape structurally cannot exercise the comparison branch, not because the
production code is safe in general.

*Independently reproduced counterexample* (composite `row_keys`, hostile
candidate *not* first):

[source,python]
----
class ProtocolBomb:
    def __eq__(self, other):
        calls.append("eq"); raise AssertionError("equality must not run")
    def __repr__(self): ...  # (all raise, per the shipped test's own bomb)

contract_xref(frames, relation="rel", output="matrix",
              row_keys=["region", ProtocolBomb()])
----

Result: `AssertionError: equality must not run`, `calls == ["eq"]`. The
duplicate-field scan reaches `_values_equal(bomb, "region")`, which evaluates
`bomb == "region"`, invoking `bomb.__eq__` -- before
`_ensure_selector_reference_labels` ever runs. Reproduced identically for
`expand_xref` with `row_keys=["region", bomb]`. A "quiet" well-behaved
non-string object (no exception, just `__eq__` returning `False`) is still
*compared* once before rejection -- the safe-rejection discipline is violated
even when the candidate does not crash. `_meta` is not left in `frames` in
either case (no partial publication), but the intended clean domain
diagnostic is bypassed by an unrelated, uncontrolled exception for a genuinely
adversarial candidate.

The dense-axis `key`/`keys` seam (`_axis_source_config`, `dense_axes.py:97-135`)
does *not* call `_ensure_unique_field_list` at all -- only
`_ensure_flat_axis_labels` then `_ensure_selector_reference_labels` -- so a
composite `dense_axes.rows_from.keys` list with a non-first hostile candidate
is unaffected; independently reproduced (`keys=["period", bomb]` raises the
clean selector-reference `ValueError`, zero protocol calls). The defect is
scoped exactly to the two `row_keys` seams (`contract_xref`, `expand_xref`)
and everything that forwards a composite `row_keys` list through them
(Compact Multiaxis both directions, Grouped XRef forwarding) -- confirmed by
direct reproduction through `contract_compact_multiaxis` as well (same
`AssertionError`, `_meta` not leaked).

See Finding F1 (section 9).

== 15. Findings

=== XREF-SELECTOR-IMPL-REVIEW-F1 -- Blocking -- composite `row_keys` reaches candidate-controlled equality before the new gate

*Evidence:* Section 4. `contract_xref`/`expand_xref` call
`_ensure_unique_field_list` (duplicate-field scan, `==`-based) before
`_ensure_selector_reference_labels` (the new exact-`str` gate). For a
composite `row_keys` list, the duplicate scan compares every later element
against every earlier-accepted element via `_values_equal`
(`bool(value == existing)`). When an invalid, non-first selector defines a
raising or side-effecting `__eq__`, that method runs before the candidate is
ever classified as invalid. Independently reproduced for `contract_xref`,
`expand_xref`, and (by inheritance) `contract_compact_multiaxis`; the dense-
axis `key`/`keys` seam is unaffected (no duplicate scan there). The shipped
"rejection never invokes hostile candidate protocols" test uses a
single-element `row_keys=[bomb]` list, which structurally cannot enter the
duplicate scan's comparison branch (`seen` is empty on the only iteration),
so it does not exercise -- and does not disprove -- this path.

*Affected accepted criterion:* FTR section 7.2, third bullet and the
"Normalization ownership" paragraph: "it must not call `repr`, `str`,
arbitrary equality, or hashing on a rejected candidate merely for
diagnostics." The primitives.py docstring for
`_ensure_selector_reference_labels` states the same guarantee unconditionally
("A rejected candidate is never inspected").

*Counterexample:*

[source,python]
----
contract_xref(frames, relation="rel", output="matrix",
              row_keys=["region", ProtocolBomb()])
# -> AssertionError: equality must not run  (raised inside ProtocolBomb.__eq__)
# instead of the intended ValueError("... selector reference ...")
----

*Smallest required correction:* Make the duplicate-field scan safe against an
unclassified `row_keys` candidate before the new gate runs -- either evaluate
`_ensure_selector_reference_labels` on each element ahead of the duplicate
scan specifically for the two `row_keys` seams (dense-axis already does this
and is unaffected), or harden the duplicate-detection comparison so it does
not invoke a candidate's `__eq__` until the candidate's own type has been
established as comparable/nominated. Add a composite-list regression test
(hostile candidate at a non-first position) alongside the existing
single-element hostile test, since the two are not equivalent.

=== XREF-SELECTOR-IMPL-REVIEW-F2 -- Minor -- carrier-list parenthetical omits YAML directory

*Evidence:* Section 13. Four prose passages (Technical Model, Functional
Model, User Guide, release notes) phrase the carrier-neutrality claim as
"every currently maintained carrier (JSON directory, XLSX, ODS)". YAML
directory is also a maintained frame-plus-metadata carrier (`yaml_backend.py`,
registered in `io_backends/router.py`) and was already carrier-neutral for
non-string selectors per the FTR's own section 8.1 evidence, so it was
correctly excluded from the regression test but is imprecisely omitted from
the prose enumeration.

*Affected accepted criterion:* Section 10's documentation-truthfulness
requirement, read strictly on the parenthetical's literal completeness claim;
does not affect the normative "exact `str` is the only carrier-neutral
selector vocabulary" statement, which remains true with or without YAML named.

*Smallest required correction (optional, non-blocking):* Reword the
parenthetical to "(for example, JSON directory, XLSX, ODS)" or add "; YAML
directory is unaffected because it was already carrier-neutral for these
values" in the four prose locations, at the next low-touch documentation
pass. No release-relevance and no runtime implication.
