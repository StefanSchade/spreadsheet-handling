== 2. Independently reconstructed E2 contract

The authoritative FTR plus accepted `d2af3c` clarification establish the
following bounded obligations:

* ordinary Frames is an exact built-in `dict` with exact built-in `str` frame
  names; empty names remain allowed and exact name `_meta` is reserved;
* initial ordinary payload carriers are DataFrame-family values and exact
  `ExactTable`; unsupported top-level values, including external
  `GroupedMatrix`, reject;
* DataFrame data cells are visited completely and deterministically by
  physical row/column ordinal, through accepted E1 scalar admission;
* E2 enforces the existing physical-column predicate unchanged:
  non-missing-like, hashable, truthfully and unambiguously self-comparable,
  and unique. It creates no String-only, Scalar-only, tuple-only, or other
  closed axis grammar;
* row-index values are positional locations only. They are neither E1 cells
  nor a new grammar or diagnostic value;
* exact `ExactTable` ingress owns only exact identity, exact non-negative
  integer geometry, header-grid/row-width consistency, genuine String-family
  headers, and E1 admission of every data cell. Reconstruction meaning remains
  local;
* rejection diagnostics retain safe validated names and ordinal context, not
  rejected cells or physical labels. The required physical-label predicate
  operations remain distinct from unnecessary diagnostic rendering;
* validation is read-only and atomic with no partial result published. Caller
  Frames, DataFrames, ExactTables, and metadata remain unchanged; a DataFrame
  deep copy is not required solely to validate it;
* FormulaSpec remains invalid in ordinary cells and controlled structural
  carriers remain invalid at external ordinary ingress. Factory origin,
  dataclass shape, ancestry, location, and identity do not establish an E4
  role;
* exact `_meta` is recognized and left completely opaque for E3, including
  arbitrary and cyclic values; and
* E2 is an internal structural primitive only. It does not implement metadata
  semantics, controlled roles, orchestration, or the E5 macro-flow.

The accepted E1 robustness principle also applies to E2 classification: an
unclassified boundary candidate must not participate in proving its own
admissibility through candidate-controlled instance protocol/type machinery.
This does not forbid the accessors and carrier behavior used after genuine
DataFrame-family or String-family membership is safely established.

== 3. Frames and carrier dispatch

`_dispatch_payload_entries` safely establishes the exact top-level contract
with `type(frames) is dict` and `type(frame_name) is str`. A dict subclass and
non-String key reject without rendering the candidate; an empty exact String
name admits. Equality with `_meta` occurs only after exact String membership,
and the corresponding value is skipped without access, classification,
copying, recursion, or normalization.

Exact `ExactTable` identity is safely checked with
`type(carrier) is ExactTable`; subclasses and shape-only values reject. The
DataFrame-family test is different: `isinstance(carrier, pd.DataFrame)` can
consult an opaque candidate's instance `__class__`. Finding F1 records the
result.

== 4. DataFrame traversal and E1 diagnostics

Independent monkey-patching observed this exact visit order:

[source,text]
----
a00, a01, a10, identity-cell,
b00, b10,
e00, e10
----

The first two carriers were DataFrames and the third was an `ExactTable`.
Every DataFrame access used `iat[row_ordinal, column_ordinal]`; the accepted
String-subclass object cell reached E1 by identity. Late cells, multiple
frames, mixed dtypes, empty DataFrames, and zero-width cases all completed as
required.

A DataFrame with duplicate hostile-looking row-index objects was traversed
without passing an index value to E1 or rendering/comparing/hashing it during
admission. Duplicate, odd, and non-monotonic indexes remained unchanged.

The complete hostile cell path produced
`OrdinaryStructureAdmissionError(kind="unsupported_scalar_carrier")` with
frame/row/column ordinals. `str(error)` was deterministic; `vars(error)` held
only the six stable context fields; neither the E2 error nor its safely hidden
E1 context retained the cell. `__cause__` was `None`, context display was
suppressed, and the hostile `__repr__`, `__str__`, `__eq__`, `__hash__`,
`__iter__`, `__array__`, and instance `__class__` hooks were never called.

== 5. Current physical-axis authority

`ensure_unique_physical_column_labels` remains the physical-axis owner. E2
calls it with `include_label_values=False`; all other callers omit the new
argument and retain the default `True` behavior.

Independent representatives confirmed:

* unique Strings, numeric labels, and valid hashable tuples admit;
* `NaN` and `pandas.NA` labels reject as missing-like;
* ndarray labels reject for ambiguous self-equality;
* list labels reject as unhashable; and
* duplicate labels reject.

The default messages for all four rejection categories are byte-for-byte the
prior message shapes, including label values. `_duplicate_labels` is an exact
extraction of the old inline `duplicates`/`seen` algorithm, with the same
ordering and `_values_equal` calls. Existing focused callers and the full
suite show no semantic or diagnostic regression.

With `include_label_values=False`, a rejected label whose `repr` and `str`
raise produced only positional detail and no callback. The option changes no
predicate or predicate ordering.

One existing qualification remains: a label's required self-equality or hash
operation can itself raise a foreign exception outside the helper's bounded
`TypeError`/`ValueError` handling. That behavior predates E2 and follows from
the accepted open predicate authority and same-process non-sandbox posture.
E2 adds no diagnostic reflection to it. Broader physical-axis exception
hardening is therefore not inflated into an E2 finding.

== 6. ExactTable generic structure

Independent valid and forged carriers confirmed exact identity and these
checks in deterministic structure-before-data order:

* `header_rows` and `n_cols` must be exact built-in, non-negative integers;
  `bool` values reject;
* `header_rows == len(header_grid)`;
* every header and data row width equals `n_cols`;
* every header cell must be String-family; and
* every data cell reaches E1 in row-major order, including late cells.

Zero columns, zero header rows, empty data, and zero-width rows admit when
self-consistent. Late header-grid, row-width, and data-cell failures carry
only owned ordinal context and leave the exact carrier unchanged.

No grouped row key, label depth, tuple uniqueness, axis mapping, source
relation, blank/fill reconstruction, or workbook-view invariant appears in
the E2 module. ExactTable subclasses reject as required. The generic header
String test itself is unsafe against spoofed candidates; finding F2 records
that distinct defect.

== 7. Controlled roles, `_meta`, layering, and leakage

A factory-produced `GroupedMatrix`, a shape-only grouped lookalike, and an
`ExactTable` subclass all rejected as unsupported top-level carriers even at
a declared-looking frame location. Factory-produced `LookupFormulaSpec`
rejected through E1 in both DataFrame and ExactTable ordinary cells. No role
was inferred from origin, shape, ancestry, location, or identity.

Exact `_meta` accepted an opaque access bomb and a cyclic mapping without any
inspection, and both identities were preserved. A non-exact name or
non-String key cannot obtain this handoff. This is the deliberate E2/E3 seam.

`domain.ingress.structural_admission` is a cohesive internal owner: E1 remains
the scalar primitive, `domain.tabular` remains the physical-axis owner, and
the module imports no application, I/O, rendering, or pipeline layer. There
is no public re-export, validator framework, role implementation, metadata
behavior, orchestration call, or E5 wiring.

== 8. Failure atomicity

Early unsupported dispatch, late DataFrame structure, late DataFrame cell,
late ExactTable geometry, and late ExactTable cell failures were exercised.
For all ordinary cases, mapping order/content, DataFrame values/axes,
ExactTable fields, metadata, nested identities, and top-level identities were
unchanged. No result was returned or published. The implementation performs
no assignment through pandas and needs no validation-only deep copy.

F1 creates an important exception to that result: an unsupported object's
instance `__class__` property ran during DataFrame dispatch and was able to
mutate the caller mapping before the owned rejection. This is not a demand to
sandbox genuinely admitted DataFrame subclass behavior; it is a direct
consequence of invoking an unclassified candidate during membership testing.
Atomicity is therefore rejected overall until F1 is corrected.

== 10. Findings

=== TRUSTED-INGRESS-E2-REVIEW-F1 -- DataFrame `isinstance` lets an unclassified top-level candidate execute instance `__class__` and prove DataFrame membership

*Severity:* Blocking

*Location:* `domain.ingress.structural_admission._dispatch_payload_entries`,
the `isinstance(carrier, pd.DataFrame)` branch.

*Accepted obligation:* DataFrame-family subclasses remain supported, but an
unclassified boundary value cannot participate in proving its own membership
through candidate-controlled Python protocol/type machinery. Unsupported
carrier rejection must be owned and failure must not mutate the caller graph
through ingress's work.

*Reproduction:* An opaque object with an instance `__class__` property
returning `pd.DataFrame`, a `columns` object returning an empty list, and
`shape == (0, 0)` made `isinstance` true and was returned as an admitted
top-level payload. Its `__class__` and `columns.tolist` hooks both ran. A
second object's raising `__class__` propagated its foreign `RuntimeError`
instead of `OrdinaryStructureAdmissionError`. A third lookup mutated the
input dict before eventual rejection.

*Preservation control:* Ordinary DataFrame subclasses, a genuine subclass
whose instance `__class__` lookup raises, and a genuine subclass with a
hostile metaclass all admitted without invoking the hostile classification
hooks. The contract does not require exact DataFrame identity; corrections
must preserve genuine subclass semantics.

*Impact:* An opaque external object can cross ordinary structural admission as
a DataFrame and can execute arbitrary instance behavior during dispatch. This
is the same candidate-controlled classification weakness previously closed by
`TRUSTED-INGRESS-E1-REVIEW-F1`, now reintroduced at the E2 carrier layer. It
also breaks the owned-error and failure-atomicity guarantees.

*Smallest correction owner:* Replace the `isinstance` boundary test with a
bounded actual-runtime-type family check anchored by `type(carrier)` against
the fixed DataFrame superclass, using an appropriate shared/boundary carrier-
classification primitive rather than a generic validator framework. Add the
spoofing, raising, mutation, genuine-subclass, and hostile-metaclass controls
to the focused E2 suite.

=== TRUSTED-INGRESS-E2-REVIEW-F2 -- ExactTable header `isinstance` lets an unclassified cell execute instance `__class__` and prove String membership

*Severity:* Blocking

*Location:*
`domain.ingress.structural_admission._validate_exact_table_structure`, the
`isinstance(cell, str)` header branch.

*Accepted obligation:* Each header cell must have genuine String-family
membership. A header candidate cannot prove that membership through its own
instance `__class__`; rejected header diagnostics must remain owned and safe.
Headers must not be routed blindly through E1 because E1 classifies `""` as
Missing while the ExactTable header contract admits empty String content.

*Reproduction:* An opaque header cell whose `__class__` property returned
`str` passed the complete exact-header check and remained in the admitted
forged exact carrier. A header whose lookup raised propagated its foreign
`RuntimeError`. No `repr`, `str`, equality, or hash hook was required for the
spoof to pass.

*Preservation control:* Ordinary `str`, empty `str`, and a genuine `str`
subclass with hostile `repr`, `str`, and equality hooks all admitted without
calling those hooks.

*Impact:* E2 does not establish the required genuine String header substrate,
and arbitrary instance behavior can execute during a structural membership
test. This is the String form of the same candidate-controlled weakness
previously closed in E1, not novel generic security work.

*Smallest correction owner:* Use the same bounded actual-runtime-type family
classification approach as F1 for the String family, while retaining the
header-specific empty-String semantics and genuine subclasses. Add spoofed,
raising, hostile-hook, empty-String, and genuine-subclass controls to the E2
suite.

No separate finding is created for the existing physical-label predicate's
foreign-exception boundary, broader parser/sink/resource concerns, metadata
ontology, E4/E5 role work, or generic framework hardening. None contradicts a
separate accepted E2 obligation beyond the two reproduced findings above.

=== 13.4 Helper duplication judgment

the same bounded primitive as the already-accepted
`core.scalar_values._actual_type_is_subclass_of` (E1), not a shared import.

and duplication of two lines does not by itself warrant extraction per the
