== Interfaces and Approval Gates

=== Consumer-facing surface

Treat these as product API even in beta — do not change without explicit user approval.
The project is currently pre-beta, so misleading historical names may be removed when
the developer explicitly accepts the breaking change.

==== User-facing surfaces

CLI entry points::
* `sheets-run` is the generic main entry point.
* `sheets-schema-maintain` is the dedicated schema-maintenance command for
  explicit one-shot column maintenance over loaded Frames. Its public operation
  names and flags are gated surface: `--op`, `--frame`, `--source-column`,
  `--target-column`, `--default`, `--insert-before`, `--insert-after`,
  `--column`, `--reorder-mode`, `--prune`, `--dry-run`, `--write`,
  `--report`, `--in-kind`, `--in-path`, `--out-kind`, and `--out-path`.
  This CLI builds a private programmatic step and does not expose a public
  `sheets-run` YAML step.

YAML pipeline/config surface::
* registered step names
* step parameter shapes
* top-level and nested `io`, `pipeline`, `pipelines`, and `profiles` fields
* `add_validations` rule targets may use optional `roles` and `frame` fields
  for role-based column targeting. `roles` accepts only `row_identity`,
  `display_helper`, and `matrix_value`, and is mutually exclusive with
  explicit `column` / `columns` targets. This is a gated YAML-surface change
  introduced by `FTR-DYNAMIC-VIEW-COLUMN-TARGETING-IMPL-P5`.

Dotted callable extension surface::
* plugin steps may call user-provided Python functions via dotted paths
* registry entries may bind to dotted callables internally
* this protocol is part of the intentional extension surface

Python import surface::
* keep intentionally small
* do not treat every internal module or barrel export as public API
* prefer `orchestrate(...)`, CLI mains, and documented pipeline builders as
  intentional imports
* Programmatic-surface contract (Trusted Ingress slice E6,
  `FTR-TRUSTED-INGRESS-P4A.adoc` sections 23/46): `application.orchestrator.
  orchestrate` (and the `spreadsheet_handling.orchestrator` compatibility
  shim), `pipeline.runner.run_app`, and `application.schema_maintenance.
  run_schema_maintenance` are the framework-managed entry points --
  every router-backed path (`sheets-run`, `run_app`, the shim,
  `sheets-schema-maintain`) automatically establishes E1-E3 ordinary Trusted
  Ingress conformance before any configured step and applies E4/E5
  controlled-role transition/authorization around each step and at the
  final sink.
* `pipeline.execution.run_pipeline` and the documented step builders
  (`pipeline.build.build_steps_from_config`/`build_steps_from_yaml`, and the
  six `pipeline.steps.make_*_step` factories named in `pipeline.__all__`)
  are supported but explicitly *caller-precondition* surfaces: building a
  step never establishes conformance by itself, and `run_pipeline` performs
  no automatic ingress and no E4/E5 tracking before, during, or after any
  step. A caller reaching either directly (bypassing `orchestrate`) owns
  every conformance/preservation/re-establishment decision itself; neither
  is a safe shortcut around the managed macro.
* Direct backend read/write (`io_backends.BackendBase` and its concrete
  backends/`make_backend`) is pre-existing supported surface, unchanged by
  E6, but is likewise not equivalent to `orchestrate`: a direct loader
  returns a raw carrier-level representation and a direct saver does not
  authorize E4 controlled roles or apply the persistence-boundary
  projection.
* `domain.ingress` (including `run_domain_ingress` and
  `structural_admission.admit_ordinary_frames`) is internal/importable-only.
  No explicit public conformance-establishment helper is promised: Phase-E
  E6 evaluated the need against actual consumer evidence (in-repo tests,
  the demo-consumer smoke suite, docs) and found none -- every maintained
  programmatic caller already reaches Trusted Ingress through the
  framework-managed entry points above. Supported direct Domain
  transformation functions (e.g. under `domain.transformations.*`) carry no
  general public-import promise either; they are normally reached through a
  pipeline step, and a caller importing one directly must independently
  satisfy that transformation's own local Domain contract, which is a
  separate concern from Trusted Ingress conformance.
* Phase-E slice E7 adds an opt-in less-trusted-description contract to
  `pipeline.build.build_steps_from_config`, `build_steps_from_yaml`, and
  `pipeline.runner.run_app`'s construction of `AppConfig.pipeline`. A trusted
  caller supplies the narrowly exported
  `pipeline.LessTrustedDescriptionAuthorization`, normally through its closed
  `from_mapping(...)` grammar; authorization failures use the narrowly
  exported `pipeline.DescriptionAuthorizationError`. Omitting
  `description_authorization` preserves the existing trusted-description
  behavior.
* E7 does not authorize `AppConfig.io`: the `run_app` caller must already trust
  and approve that I/O descriptor. Nor does E7 govern `orchestrate`,
  `run_pipeline`, direct `BoundStep` composition, schema maintenance, or the
  initial `sheets-run` CLI surface. In particular, `sheets-run` does not yet
  advertise less-trusted YAML protection.
* An E7-authorized plugin is trusted same-process Python under its complete
  current argument contract. E7 allowlists its exact canonical textual target;
  it is not a Python sandbox and does not infer generic path, network, command,
  environment, or other permissions from plugin arguments.
* The E7 implementation is awaiting fresh independent implementation review.
  Its presence does not by itself complete Phase E or establish a broader
  claim that arbitrary pipeline YAML is safe.

Shortcut commands::
* Shortcut commands are an intended pattern from which real product surfaces may
  later be built.
* There are no placeholder example shortcut commands in the current public CLI
  surface. `sheets-schema-maintain` is the maintained dedicated CLI outside
  normal `sheets-run` pipeline execution.
* The project is pre-beta; removing misleading historical or placeholder
  shortcut names is intentional and preferable to carrying compatibility debt.

Consumer-facing examples in `spreadsheet-handling-demo` are also gated.

=== Actions that require explicit approval before implementation

* Any rename or removal of public CLI entry points or flags
* Any structural change to the YAML config schema
* Any reshape of consumer-visible function signatures
* Any behavior change in documented plugin step contracts
* Internal refactors that would silently break any of the above
* Changes to integration assumptions in `spreadsheet-handling-demo`
