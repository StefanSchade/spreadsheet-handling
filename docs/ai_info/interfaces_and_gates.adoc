== Interfaces and Approval Gates

=== Consumer-facing surface

Treat these as product API even in beta — do not change without explicit user approval.
The project is currently pre-beta, so misleading historical names may be removed when
the developer explicitly accepts the breaking change.

==== User-facing surfaces

CLI entry points::
* `sheets-run` is the generic main entry point.
* `sheets-schema-maintain` is the dedicated schema-maintenance command for
  explicit one-shot column maintenance over loaded Frames. Its public operation
  names and flags are gated surface: `--op`, `--frame`, `--source-column`,
  `--target-column`, `--default`, `--insert-before`, `--insert-after`,
  `--column`, `--reorder-mode`, `--prune`, `--dry-run`, `--write`,
  `--report`, `--in-kind`, `--in-path`, `--out-kind`, and `--out-path`.
  This CLI builds a private programmatic step and does not expose a public
  `sheets-run` YAML step.

YAML pipeline/config surface::
* registered step names
* step parameter shapes
* top-level and nested `io`, `pipeline`, `pipelines`, and `profiles` fields
* `add_validations` rule targets may use optional `roles` and `frame` fields
  for role-based column targeting. `roles` accepts only `row_identity`,
  `display_helper`, and `matrix_value`, and is mutually exclusive with
  explicit `column` / `columns` targets. This is a gated YAML-surface change
  introduced by `FTR-DYNAMIC-VIEW-COLUMN-TARGETING-IMPL-P5`.

Dotted callable extension surface::
* plugin steps may call user-provided Python functions via dotted paths
* registry entries may bind to dotted callables internally
* this protocol is part of the intentional extension surface

Python import surface::
* keep intentionally small
* do not treat every internal module or barrel export as public API
* prefer `orchestrate(...)`, CLI mains, and documented pipeline builders as
  intentional imports
* *Programmatic-surface contract.* Trusted Ingress (Phase E, E1-E7,
  independently accepted and complete) fixes what every supported
  programmatic entry point does and does not establish automatically. Full
  mechanism, current controlled-role set, and threat model:
  link:../technical_model/ch06_architectural_layers/architectural_layers.adoc#trusted-ingress-establishment[Architectural
  Layers, "Establishing and Re-establishing the Domain Scalar Language"] and
  link:../technical_model/ch06_architectural_layers/architectural_layers.adoc#description-and-resource-authority[
  "Description and Resource Authority"]. The table below is the compact
  caller-facing summary; it does not replace that chapter.

Supported direct Domain transformation functions (e.g. under
`domain.transformations.*`) carry no general public-import promise either;
they are normally reached through a pipeline step, and a caller importing
one directly must independently satisfy that transformation's own local
Domain contract, separate from Trusted Ingress conformance.

*Less-trusted description authorization.* `pipeline.build.
build_steps_from_config`, `build_steps_from_yaml`, and `pipeline.runner.
run_app`'s construction of `AppConfig.pipeline` accept an opt-in,
fail-closed authorization boundary for a less-trusted pipeline description
(dotted plugin targets, resource-writing steps). A trusted caller supplies
the narrowly exported `pipeline.LessTrustedDescriptionAuthorization`,
normally through its closed `from_mapping(...)` grammar; authorization
failures use the narrowly exported `pipeline.DescriptionAuthorizationError`.
Omitting `description_authorization` preserves the existing
trusted-description behavior. An authorized plugin is trusted same-process
Python under its complete current argument contract: authorization
allowlists its exact canonical textual target, is checked before import/
binding/resource activation, and is not a Python sandbox -- it does not
infer generic path, network, command, environment, or other permissions
from plugin arguments. `sheets-run` does not yet advertise less-trusted
YAML protection at the CLI surface. Full mechanism, the current
resource-sensitive census, and the security-trust/robustness distinction:
link:../technical_model/ch06_architectural_layers/architectural_layers.adoc#description-and-resource-authority[Architectural
Layers, "Description and Resource Authority"].

Shortcut commands::
* Shortcut commands are an intended pattern from which real product surfaces may
  later be built.
* There are no placeholder example shortcut commands in the current public CLI
  surface. `sheets-schema-maintain` is the maintained dedicated CLI outside
  normal `sheets-run` pipeline execution.
* The project is pre-beta; removing misleading historical or placeholder
  shortcut names is intentional and preferable to carrying compatibility debt.

Consumer-facing examples in `spreadsheet-handling-demo` are also gated.

=== Actions that require explicit approval before implementation

* Any rename or removal of public CLI entry points or flags
* Any structural change to the YAML config schema
* Any reshape of consumer-visible function signatures
* Any behavior change in documented plugin step contracts
* Internal refactors that would silently break any of the above
* Changes to integration assumptions in `spreadsheet-handling-demo`
