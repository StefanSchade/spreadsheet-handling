IOR-04-FORMULA-SINK-CAPABILITY -- FormulaSpec-capable sink authority
=====================================================================

CURRENT DEFECT
--------------
Independent architecture review finding IOR-04 records that managed execution
authorizes FormulaSpec roles with a maintained sink-name set parallel to the
router/saver authority. At the pinned baseline, that set includes `xlsx` and
`ods`, while `io_backends.router.SAVERS` also accepts `calc` as an alias for the
ODS saver. A managed FormulaSpec role can therefore be rejected for `calc`
before the capable ODS saver is reached. The defect is duplicate capability
authority / parallel sink-name vocabulary, not merely a missing string.

IMPLEMENTATION INTENT
---------------------
Implement only this bounded IOR-04 correction:

* `calc` must receive the same legitimate FormulaSpec-capability treatment as
  the ODS sink it aliases.
* Incapable sinks must remain fail-closed.
* Do not merely add `calc` to another manually synchronized duplicated set.
  Prefer the smallest existing seam that makes FormulaSpec capability derive
  from, or live with, the actual maintained saver/router authority.
* Preserve public API and configuration behavior except the intended false
  rejection of `calc`.
* Add focused regression coverage proving `ods` remains accepted, `calc` is
  accepted, and at least one incapable sink remains rejected.

The allowed implementation/correction paths are exactly:

* `src/spreadsheet_handling/io_backends/router.py`;
* `src/spreadsheet_handling/pipeline/execution_state/projection.py`;
* `tests/integration/pipeline/test_trusted_ingress_e5_managed_lifecycle.py`; and
* `tests/unit/pipeline/execution_state/test_projection_transition.py`.

The review phase may create or modify exactly this required durable artifact:

    docs/warm_storage/global_reviews/ior04_formula_sink_capability_useful_loop_review_2026-09-17.adoc

The rereview phase is non-mutating. Do not modify any other path.
