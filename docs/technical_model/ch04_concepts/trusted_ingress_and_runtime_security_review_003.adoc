== Backend and typing assessment

The corrected backend inventory is coherent:

* XLSX and ODS visible spreadsheet payload is deliberately stringified at the
  accepted substrate boundary.
* ODS alone has current framework dimension limits; XLSX, CSV, JSON, YAML, and
  XML do not gain a shared resource guarantee by implication.
* CSV-directory reading retains pandas inference/missing behavior; JSON and
  YAML both normalize pandas-recognized missing values to `""` after DataFrame
  construction, while their non-missing behavior remains different.
* Safe YAML blocks Python-specific custom constructors but still admits rich
  standard structures, aliases/cycles, bytes, dates, and sets and imposes no
  resource ceiling.
* JSON alone has a mapping-shaped directory `_meta.yaml` sidecar contract;
  YAML loads the same-named file as a DataFrame, while CSV/XML have none.
* Cell Codec is a reversible compact-string transformation controlled by
  explicit step configuration. It is not native-type preservation and does
  not read or produce `_meta.cell_codecs`.

These are current carrier observations, not a chosen framework-wide scalar or
missing-value contract.

== Threat and policy assessment

The corrected concept preserves the useful trust model without promoting it:

* trusted runtime/operator control is a fixed precondition;
* payload authority and pipeline-description authority are orthogonal;
* sink exposure is a separate capability/consumer concern rather than another
  authoring-trust actor;
* all four payload/pipeline combinations are representable, and named profiles
  are conveniences rather than a total-order ladder;
* operator policy is authoritative, pipeline requests can only narrow it, and
  combination/rejection semantics differ by policy kind;
* forbidden resolution, invocation, and sink use must be rejected before the
  capability is exercised; and
* namespace/addressability guards, allowlists, and validation are not a Python
  sandbox or process-isolation mechanism.

Nothing in the concept claims that these illustrative policy fields or profiles
exist in the runtime.

== Value and lifecycle assessment

The value/lifecycle vocabulary remains internally consistent after correction:

* backend-specific normalization is not canonical domain semantics;
* the accepted spreadsheet string substrate is not generalized domain typing;
* missing, unresolved-reference, and spreadsheet-error semantics remain
  undecided and the NaN BUG cause remains unpinned;
* `FormulaSpec` is authored backend-neutral Intent, not an executable
  capability and not the exclusive route to an XLSX formula cell;
* persistable projection remains an output boundary, distinct from runtime
  metadata after ingress and from materialized Resolution;
* `ExactTable` and `GroupedMatrix` remain existing controlled carriers; and
* resolved callables and `BoundStep.fn` remain executable runtime capabilities
  outside payload value categories.

The NaN BUG gates only final missing/unresolved/error semantics and dependent
ingress enforcement, not already-stable Intent, Resolution, or carrier
documentation.

== Boundary architecture and candidate map

The five boundary owners remain qualified by actual timing and data/policy
flow: parser/load, structural/scalar ingress, configuration resolution,
step invocation, and sink output. Separate ownership is not falsely presented
as independent execution. Direct `run_pipeline` and direct `BoundStep`
composition remain explicit programmatic paths rather than silently receiving
or being promised orchestrator ingress guarantees.

The candidate map remains non-authorizing and dependency-separated:

. the existing unresolved-helper BUG;
. minimal value/lifecycle contracts;
. trusted payload ingress;
. operator policy representation;
. payload-axis enforcement;
. dotted-surface assessment before untrusted-pipeline capability enforcement;
. per-format resource work, including XLSX;
. independent sink-local work;
. a separate public `run_pipeline` boundary decision; and
. the roadmap-owned first family pilot.

It creates no umbrella FTR and does not preselect the open dotted-extension
assessment, the ingress coordinator mechanism, a public policy API, a formula
escape policy, or a missing-value representation.
