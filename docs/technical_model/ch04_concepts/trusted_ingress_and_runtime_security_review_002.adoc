== New finding

=== N-I-001 -- current Cell Codec authority is misrepresented as `cell_codecs` metadata

*Severity:* Important.

*Exact locus:* Section 1, lines 51--58, especially “typing is opt-in metadata
layered on top (`cell_codecs`)”; section 3.1, lines 325--327, which says a
consumer declares a `cell_codecs`-family codec as metadata.

*Problem:* The corrected concept makes the accepted string-substrate ADR
load-bearing, but repeats the ADR's historical body text without applying its
later status note. The accepted ADR's 2026-07-20 status note says the
registry-declared `cell_codecs` metadata family has been retired because it had
no runtime reader. Current Cell Codec intent lives in explicit step
configuration and is string-oriented. A future opt-in typing layer would be a
new explicit contract, not revival of that retired family.

This does not reopen the accepted string substrate, but it materially
misstates the current mechanism a consumer uses and suggests that a retired,
inert metadata family remains the active layering point. That is especially
problematic in a concept whose value-model/FTR map is intended to guide future
typing work.

*Evidence:* `ADR-VISIBLE-CELL-TYPING-STRING-SUBSTRATE.adoc` lines 5--11;
`domain/transformations/cell_codec/frame.py` lines 8--19; the current Cell
Codec concept and registry notes; maintained tests proving that no
`_meta.cell_codecs` entry is produced and legacy payload is inert sediment.

*Required correction:* Preserve the hard string-substrate decision, but replace
both current-mechanism statements with the current authority: Cell Codec intent
is explicit step configuration and string-oriented; `_meta.cell_codecs` is a
retired, unread metadata family; any future opt-in typing layer is a new
explicit contract subject to the ADR's revisit criteria. Do not imply that a
consumer can obtain typed JSON/native booleans/datetime preservation today by
declaring `cell_codecs` metadata.

*Gates acceptance:* Yes.

== Required correction summary

A narrow documentation-only correction is sufficient:

. In every YAML current-state/value-model statement, account for the actual
  post-DataFrame `df.where(pd.notnull(df), "")` normalization. Preserve the
  separate true claims that standard rich YAML shapes, aliases/cycles, bytes,
  and no resource ceiling remain.
. Replace the two active-`cell_codecs` metadata claims with the accepted ADR's
  current status note and current explicit step-configuration contract.
. Correct the JSON ownership sentence: pandas reads payload JSON; stdlib
  `json.dump` writes ordinary JSON payload files; PyYAML reads/writes the
  `_meta.yaml` sidecar. Keep workbook metadata carriers separate.

No runtime, test, ADR, FTR, BUG, roadmap, registry, or public-API change is
needed or authorized by these corrections.

== Security and boundary assessment after correction 1

Apart from the findings above, the corrected concept's security claims are now
appropriately narrow:

* ODS dimension limits are never generalized to XLSX.
* Safe YAML is described as constructor protection, not a closed value or
  resource contract.
* Dotted resolution's namespace exclusion is architecture ownership, not a
  sandbox or general policy.
* Runtime/operator trust is a fixed precondition; payload and pipeline
  authority vary independently; sink exposure is capability/consumer specific.
* Ordinary XLSX leading-`=` text is explicitly recognized as formula-capable
  output outside `FormulaSpec`.
* Direct `run_pipeline` composition is trusted by caller contract and preserved
  as a separate public decision.
* Existing registered-writer path containment is documented without treating
  main backend output paths as already root-contained.

The concept still does not promise hostile-code containment, parser protection
where none exists, or implementation of its illustrative profiles/policy.

== Conclusion

Correction 1 successfully removes the false XLSX parser-limit guarantee, the
spreadsheet-string-substrate contradiction, the false inert-XLSX/formula
guarantee, and almost all Important inventory and architecture defects from
Review 001. Review 002 cannot accept it yet: YAML missing-value behavior is
still materially wrong in the ingress/value model, and the active typing
mechanism contradicts the accepted ADR's current status note by presenting the
retired `cell_codecs` metadata family as current. The remaining stdlib-JSON
sidecar sentence is minor but should be corrected in the same narrow pass.

Until a corrected concept receives a fresh independent review, accepted ADRs,
the normative Domain Boundary Robustness concept, maintained code and tests,
the dotted-extension FTR, the unresolved-helper BUG, and the hardening roadmap
remain authoritative.
